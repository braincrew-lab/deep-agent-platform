Deep Admin 전체 에이전트와 배포 심사

Deep Agent Builder의 커뮤니티에는 회사 전체가 함께 쓰는 "전체 에이전트"가 있습니다. 직원이 자기가 만든 에이전트를 전체 에이전트에 공유해 달라고 요청하면, 관리자가 Deep Admin에서 심사해 승인하거나 반려합니다. 이 페이지는 배포 요청 심사와 배포된 에이전트의 공개 상태 관리, 그리고 도구·모델·스킬 등록 요청을 다루는 승인 관리를 설명합니다.

이 페이지에서 할 수 있는 일

  • 직원의 에이전트 공유(배포) 요청을 검토하고 승인하거나 반려합니다.
  • 배포된 에이전트의 공개 상태를 바꾸고, 활용 현황을 봅니다.
  • 리소스 등록 요청을 승인 관리에서 처리합니다.

공유 요청이 올라오는 흐름​

단계누가어디서상태
1. 공유 요청직원(예: 김그루 사원)Deep Agent Builder의 커뮤니티 에이전트 관리 > 배포 요청심사중
2. 심사관리자Deep Admin 전체 에이전트 > 배포 요청 심사심사중
3-1. 승인관리자심사 화면의 승인 → 승인 확정등록완료. 전체 에이전트에 배포됩니다.
3-2. 반려관리자심사 화면의 반려 → 반려 확정(사유 필수)등록반려. 직원이 사유를 보고 고쳐 다시 요청합니다.
4. 운영관리자배포된 에이전트 탭공개, 비공개(관리자 처리), 비공개(요청자 처리)

직원이 같은 에이전트를 고쳐 다시 요청하면 요청 유형이 재배포로 들어오고, 승인하면 새 버전이 배포됩니다.

배포 요청 심사​

에이전트 > 전체 에이전트를 누르면 "전체 에이전트 관리"가 열리고 배포 요청 심사 탭이 먼저 보입니다.

배포 요청 심사 목록

번호항목기능이런 때 사용하세요
1배포 요청 심사 탭심사할 요청 목록입니다. 옆 배포된 에이전트 탭은 이미 배포된 에이전트입니다.오늘 할 심사부터 볼 때
2전체 상태상태(심사중, 등록완료, 등록반려, 취소됨, 준비 중)로 거릅니다. 옆 전체 요청 유형은 신규, 재배포로 거르고, 검색창은 에이전트명·요청자 이름·사번으로 찾습니다.심사중 요청만 볼 때
3상태 열요청마다 심사중, 등록완료 같은 상태입니다. 같은 표에 에이전트명, 배포 ID, 버전, 요청 유형, 요청자(사번), 요청일시가 있습니다.처리할 요청을 고를 때
4심사심사 화면을 엽니다. 옆 이력은 반려·취소를 포함한 배포 이력을 최근순으로 보여 줍니다.심사하거나 지난 요청을 볼 때

심사 화면​

심사를 누르면 요청 하나를 자세히 봅니다.

배포 요청 심사 상세

번호항목기능이런 때 사용하세요
1상태(심사중)요청의 현재 상태입니다. 승인하면 등록완료로 바뀌고 배포 ID와 심사 결과(일시, 심사자, 승인 사유)가 채워집니다.요청이 아직 처리되지 않았는지 볼 때
2요청 유형신규 또는 재배포. 요청 정보에는 요청자(사번), 요청일시, 버전도 있습니다.새 에이전트인지, 고친 버전인지 볼 때
3고정 구성의 모델요청 시점에 고정된 모델입니다. 위쪽에 지침 원문이 함께 보입니다.비용에 맞는 모델인지 볼 때
4고정 구성의 도구요청 시점에 고정된 도구 수입니다. 아래 지식, 그리고 전체 설정 보기로 모든 설정을 펼칠 수 있습니다.회사 전체가 써도 되는 도구·지식만 쓰는지 볼 때

화면 아래에는 서브에이전트·상위 에이전트 참조, 노출 정보(전체 에이전트 목록에 보일 에이전트명, 설명, 태그. 관리자가 고칠 수 있습니다), 심사 패널이 이어집니다. 심사 패널에 사유(반려 시 필수, 승인 시 선택)를 적고 승인 또는 반려를 누른 뒤 승인 확정 또는 반려 확정으로 마칩니다. 실제 화면은 에이전트 공유 승인 사례에 있습니다.

심사 기준 예시는 다음과 같습니다.

확인할 것통과로 볼 수 있는 상태
목적이 분명한가설명만 읽고 누가 언제 쓰는 에이전트인지 알 수 있습니다.
회사 전체가 써도 되는 도구·지식만 쓰는가특정 부서에만 열린 지식 컬렉션이나 개인 키가 필요한 도구가 없습니다.
비용이 적절한가단순 작업에 고가 모델을 쓰지 않습니다.
답변 품질대표 질문 두세 개를 직접 해 보고 결과가 업무에 쓸 만합니다.

배포된 에이전트​

배포된 에이전트 탭은 전체 에이전트에 올라간 에이전트 목록입니다.

배포된 에이전트 목록

번호항목기능이런 때 사용하세요
1전체 공개 상태공개, 비공개(사용자), **비공개(관리자)**로 거릅니다.내려 둔 에이전트만 볼 때
2공개 상태 열공개, 비공개(관리자 처리), 비공개(요청자 처리). 같은 표에 에이전트명, 설명, 태그, 요청자(사번), 최종 배포일, 최초 배포일이 있습니다.누가 내렸는지 볼 때
3상세보기노출 정보 수정, 배포 회차, 활용 현황을 봅니다.실제 사용자 수를 확인할 때
4비공개로 전환전체 에이전트 목록에서 잠시 내립니다. 옆 삭제는 배포 회차 기록까지 지우고 되돌릴 수 없습니다.문제가 있는 에이전트를 잠시 내릴 때

상세에서는 노출 정보(에이전트명, 설명, 태그)를 고쳐 저장하고, 배포 회차와 활용 현황(메인으로 쓰는 사람, 다른 에이전트의 서브에이전트로 쓰는 곳)을 봅니다. 삭제는 배포 회차 기록까지 지우고 되돌릴 수 없으므로, 보통은 비공개로 전환을 씁니다.

승인 관리: 리소스 등록 요청​

사용자·승인 > 승인 관리는 워크스페이스에서 올라온 도구, 모델, 스킬, 미들웨어의 등록·수정 요청을 처리합니다. 위쪽 카드에서 대기중, 승인됨, 거부됨 건수를 보고, 목록에서 요청마다 승인 또는 거부를 누릅니다. 승인할 때는 코멘트(선택), 거부할 때는 사유(권장)를 남깁니다. 스킬 요청은 상세 화면에서 요청 정보, 배포 이력, 스킬 파일까지 확인할 수 있습니다.
