Deep Admin LLM 토큰 사용량

사용자·승인 > LLM 토큰 사용량은 Deep Agent Builder 에이전트가 LLM을 부를 때 DeepGateway(플랫폼의 LLM 관문)를 거친 요청을 한 건 단위로 모아 보여 주는 화면입니다. 기간, 사용자, 모델, 에이전트, 워크스페이스, 실행별로 토큰과 비용을 보고, 요청 기록을 CSV 파일(.csv)로 내려받습니다. 예시는 브레인크루 직원 7명이 최근 3주 동안 보고서 초안, 이메일 초안, 회의록 요약, 판매 데이터 분석 같은 업무로 보낸 요청 112건입니다.

이 페이지에서 할 수 있는 일

  • 최근 7일·14일·30일의 전체 토큰, 성공 요청, 사용한 사람 수를 봅니다.
  • 날짜·사용자·모델별 토큰과 에이전트·워크스페이스·실행별 토큰과 비용을 비교합니다.
  • 조건을 걸어 요청을 한 건씩 찾고, 필요하면 질문과 답변 본문을 엽니다.
  • 요청 기록을 CSV 파일(.csv)로 내보내 월별 리포트에 씁니다.

이 화면이 보여 주는 범위​

구분내용
집계 대상DeepGateway를 거친 Builder 요청. 성공한 요청만 토큰 합계에 들어갑니다.
날짜 기준한국 시간 달력 날짜
비용LLM 관문에 모델마다 등록한 100만 토큰당 입력·출력 단가로 계산한 금액(달러)
대시보드·사용자별 통계와의 차이대시보드와 사용자별 통계의 토큰은 Builder 실행 기록을 기준으로 셉니다. 이 화면은 LLM 관문이 실제로 받은 요청을 셉니다. 두 숫자는 같은 기간이어도 다를 수 있습니다.
필요한 권한LLM 토큰 사용량 조회. 질문·답변 본문은 LLM 요청 본문 열람 권한이 함께 있어야 열립니다.

배포에 DeepGateway가 연결되어 있지 않으면 각 구역에 "정보를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요."가 나옵니다. 이때는 플랫폼 운영 담당에게 LLM 관문 연결을 요청합니다.

사용량 요약​

화면을 열면 최근 30일 요약이 먼저 나옵니다.

LLM 토큰 사용량 요약

번호항목화면에 보이는 내용이런 때 확인하세요
1최근 30일조회 기간입니다. 최근 7일, 최근 14일도 고를 수 있고, 기간 표시(예: 2026-10-14 ~ 2026-11-12 · KST)가 함께 바뀝니다.주간·월간 보고 기간을 맞출 때
2전체 토큰기간 안 성공 요청의 입력·출력 토큰 합계입니다. 그림은 38,975토큰(입력 23,787 · 출력 15,188)입니다.한 달 동안 회사가 쓴 LLM 양을 볼 때
3성공 요청성공한 요청 건수입니다. 실패한 요청은 빠집니다. 옆 사용한 사용자는 기간 안에 요청 기록이 있는 사람 수입니다.실제로 몇 명이 쓰는지 볼 때
4일별 토큰 추이날짜별 토큰 그래프입니다. 주말은 낮고 보고서를 몰아 쓰는 날은 높게 보입니다.특정 날에 사용이 몰렸는지 볼 때

"토큰 사용량이 미확정인 요청 N건이 있습니다"가 보이면, 응답이 끊기는 등으로 토큰 수를 확정하지 못한 요청이 있다는 뜻입니다. 화면은 미확정 요청을 0으로 계산하지 않고 합계에서 뺍니다.

일별·사용자별·모델별 탭​

요약 아래 탭으로 기준을 바꿉니다. 탭마다 전체 토큰, 입력 토큰, 출력 토큰, 성공 요청 건수, 집계 상태가 나옵니다.

모델별 사용량

번호항목화면에 보이는 내용이런 때 확인하세요
1모델별 탭모델마다 한 줄입니다. 옆 탭 일별은 날짜마다, 사용자별은 사람마다 한 줄입니다.비싼 모델에 사용이 몰렸는지 볼 때
2전체 토큰 열모델별 토큰 합계입니다. 모델은 LLM 관문에 등록된 식별자(gpt-4.1, gpt-4.1-mini, Deepseek-V4-Flash-Exp)로 보입니다. 예시에서는 gpt-4.1이 가장 많고 gpt-4.1-mini, Deepseek-V4-Flash-Exp 순입니다.모델 비중을 보고서에 옮길 때
3집계 상태 열확정(모두 확정), 미확정 포함(확정 못 한 요청이 섞임), 기록 없음숫자를 그대로 보고해도 되는지 볼 때

사용자별 탭의 사용자는 LLM 관문이 붙인 사용자 ID로 보입니다. 아래 요청 목록의 사용자 열은 사번 디렉터리(인사 원장)가 연결된 배포에서만 이름과 사번으로 보이고, 연결되지 않으면 "이름 미확인 (사번 미확인)"으로 나옵니다. 그때는 CSV 파일을 인사 자료와 맞춥니다.

에이전트·워크스페이스별 사용량​

어떤 에이전트, 어떤 부서 워크스페이스, 어떤 실행이 토큰을 많이 썼는지 봅니다. Builder가 에이전트·워크스페이스·실행 식별값을 함께 보낸 요청만 집계합니다.

에이전트·워크스페이스별 사용량

번호항목화면에 보이는 내용이런 때 확인하세요
1에이전트별 탭에이전트마다 한 줄입니다. 워크스페이스별은 부서 워크스페이스마다, 실행별은 에이전트를 한 번 실행한 단위마다 한 줄입니다.사용량이 많은 에이전트를 찾을 때
2총 토큰 열많이 쓴 순서로 정렬됩니다. 같은 표에 입력·출력 토큰, 성공 요청, 실패 요청, 집계 미확정, 마지막 요청 시각이 있습니다.상위 에이전트를 고를 때
3비용 열모델 단가로 계산한 금액입니다. 단가가 없는 모델은 비어 보입니다.비용 순위를 볼 때

표가 너무 길면 "사용량이 많은 상위 N개만 표시합니다."가 나옵니다. 식별자 열에는 에이전트·워크스페이스·실행의 내부 ID가 보이므로, 이름은 에이전트 실행 로그나 아래 요청 목록에서 맞춰 봅니다.

검색 조건과 요청 목록​

화면 아래쪽에서 요청을 한 건씩 찾습니다.

검색 조건과 요청 목록

번호항목기능이런 때 사용하세요
1사용자 ID사번(사용자 ID)으로 한 사람의 요청만 찾습니다. 옆에 모델 칸이 있습니다.한 직원의 사용 내역을 볼 때
2결과전체, 성공, 실패, 취소, 진행 중, 거절 중에서 고릅니다.실패한 요청만 볼 때
3조회조건으로 목록을 다시 불러옵니다.조건을 바꾼 뒤
검색 조건뜻과 기본값
시작(KST, 포함), 종료(KST, 미포함)시각 범위입니다. 시작은 처음 열 때 일주일 전 시각으로 채워져 있고, 종료 시각은 포함하지 않습니다. 비우면 기간 제한 없이 최신순입니다.
에이전트 ID, 워크스페이스 ID, 실행 ID정확히 일치하는 값만 찾습니다. 에이전트·워크스페이스별 표의 식별자를 그대로 붙여 넣습니다.

요청 목록에는 시각, 사용자, 에이전트, 워크스페이스, 실행, 모델, 결과, 입력 토큰, 출력 토큰, 소요 시간, 본문이 나옵니다. 본문의 보기 버튼은 LLM 요청 본문 열람 권한이 있는 관리자에게만 열립니다. 요청 목록 조회와 본문 열람은 모두 감사 기록에 남습니다. 권한이 없으면 "본문 열람 권한이 없습니다"가 나옵니다.

토큰 사용량 내보내기​

맨 아래 토큰 사용량 내보내기에서 요청 기록을 CSV 파일(.csv)로 받습니다.

토큰 사용량 내보내기

번호항목기능이런 때 사용하세요
1제품Builder 또는 DeepWork. DeepWork는 Deep Work 관리 권한이 있는 관리자에게만 보입니다.Deep Work 사용량도 함께 보고할 때
2시작일(KST, 포함)처음 열면 오늘부터 30일 전입니다. 옆 **종료일(KST, 포함)**은 오늘입니다. 두 날짜 모두 포함하며 최대 92일까지입니다.지난달 1일부터 말일까지 받을 때
3CSV 내보내기조건에 맞는 요청을 최신순으로 한 줄에 한 건씩 담아 내려받습니다. 끝나면 "N행을 내보냈습니다."가 나옵니다.리포트용 원자료를 받을 때
설정 항목기본값범위와 주의
제품BuilderDeepWork는 권한이 있을 때만
시작일, 종료일최근 30일최대 92일. 종료일이 시작일보다 앞서면 내보낼 수 없습니다.
사용자 ID, 에이전트 ID, 워크스페이스 ID비움(전체)에이전트·워크스페이스 조건은 Builder에서만 씁니다.
행 수배포에서 정한 상한넘으면 "상한 N행까지만 포함했습니다."가 나옵니다. 기간을 나눠 다시 받습니다.

받은 파일 이름은 "token-usage-builder-시작일-종료일.csv" 형식이고, 열은 다음과 같습니다. 엑셀에서 열면 피벗 표로 부서별·모델별 합계를 바로 만들 수 있습니다.

열뜻
request_id요청 한 건의 번호
started_at, finished_at요청 시작·끝 시각(세계 표준시)
productbuilder 또는 deepwork
managed_user_idLLM 관문의 사용자 ID
model_id모델(예: gpt-4.1, gpt-4.1-mini)
statussucceeded(성공), failed(실패) 등
agent_id, run_id, workspace_id에이전트, 실행, 워크스페이스 식별값
input_tokens, output_tokens, total_tokens입력·출력·합계 토큰
final_charge단가로 계산한 비용(달러)
usage_completenesscomplete(확정) 등 집계 상태
error_category실패한 요청의 오류 분류

내보내기도 감사 기록으로 남습니다. 파일에 개인 식별 정보가 들어 있으므로 사내 보관 규정에 맞게 다룹니다.

이럴 때 쓰세요: 브레인크루 AI혁신팀 김그루 사원은 매월 1일 "AI 도구 사용 현황" 보고를 맡고 있습니다. 최근 30일과 모델별 탭으로 모델 비중을 먼저 보고, 에이전트별 탭의 비용 상위 3개 에이전트를 표로 옮긴 뒤, 지난달 1일~말일 CSV 파일을 받아 엑셀 피벗 표로 부서별 합계를 만듭니다. 30분이면 팀장 보고 자료가 완성됩니다.
