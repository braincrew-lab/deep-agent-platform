Deep Admin 실습 3: 한도

브레인크루는 11월부터 플랫폼을 시범 운영하며, 1인당 월 토큰 한도를 처음 정하기로 했습니다. 이 실습에서는 전 사용자 월 한도를 저장하기 전에 미리보기로 새로 차단될 인원을 확인하고, 변경 이력에 근거를 남기고, 한도를 넘은 직원에게 추가 토큰을 주는 절차를 따라 합니다. 화면 전체 설명은 토큰 사용량과 한도에 있습니다.

이 페이지에서 할 수 있는 일

  • 월 한도를 입력하고 저장 전 미리보기로 영향을 확인합니다.
  • 변경 사유를 남기고 저장한 뒤 변경 이력에서 확인합니다.
  • 한도를 넘은 직원을 사용자별 통계에서 찾고 추가 부여를 준비합니다.

목표​

항목내용
만들 것전 사용자 월 한도 8,000토큰과 그 변경 이력
결과물변경 이력 한 줄, 사용자별 통계의 한도 초과 1명
걸리는 시간10분
난이도★★☆☆☆

실습 숫자 8,000토큰은 연습 환경의 사용량에 맞춘 값입니다. 실제 운영에서는 직원 한 명이 한 달에 수십만~수백만 토큰을 쓰는 경우가 많으므로, 지난달 사용자별 통계의 사용량 분포를 보고 정합니다.

준비물​

준비물내용
관리자 계정토큰 한도 설정 변경 권한이 있는 계정. 권한이 없으면 입력란이 잠겨 보기만 할 수 있습니다.
사용 기록이번 달 사용 기록이 있는 직원. 미리보기의 "판정 인원"은 사용량을 아는 직원 수입니다.
정할 것한도 값과 변경 사유 한 줄

1단계. 월 한도 입력과 미리보기​

사이드바 사용자·승인 > 토큰 한도 설정을 누릅니다. 아직 한도를 저장한 적이 없으면 "전사 기본 한도가 아직 설정되지 않았습니다"가 보입니다.

월 한도 미리보기

번호메뉴입력하거나 확인할 값
1전 사용자 월 한도8000을 적습니다. 입력 토큰과 출력 토큰을 더한 값의 한도입니다.
2미리보기 안내"이미 새 한도를 초과한 사용자는 저장 즉시 차단됩니다. 현재 기준 1명이 새로 차단됩니다."와 판정 인원, 저장 전·후 차단 인원, 경고 인원이 나옵니다.
3변경 사유11월 시범 운영 기준 한도 설정(1인 월 8천 토큰)
4저장누르면 바로 적용됩니다.
설정 항목이 실습의 값기본값과 범위
전 사용자 월 한도8,000미설정. 0은 "전원 차단"이라는 별도 의미입니다.
초기화 주기바꿀 수 없음매월 1일 00:00(한국 시간)
다음 초기화바꿀 수 없음다음 달 1일. 개인 추가 부여분도 함께 사라집니다.
변경 사유위와 같음필수. 공백만 넣으면 저장할 수 없습니다.

한도를 너무 낮게 넣으면 미리보기의 "새로 차단" 인원이 늘어납니다. 실제 운영에서는 이 숫자가 0이 되도록 값을 올리거나, 차단될 직원에게 미리 알린 뒤 저장합니다.

2단계. 변경 이력 확인​

저장하면 오른쪽 변경 이력 카드에 한 줄이 쌓입니다.

변경 이력

번호확인할 것기대 값
1한도 값"기본 한도 최초 설정 8,000"
2변경 사유1단계에서 적은 문장

3단계. 한도 초과 직원 찾기​

사용자·승인 > 사용자별 통계에서 워크스페이스를 AI혁신팀으로 고르고 토큰 사용량 탭을 엽니다.

한도 초과 직원 확인

번호메뉴확인할 것
1한도 초과 카드1명. 이 카드는 화면 위 워크스페이스·기간 필터와 관계없이 이번 달 누적입니다.
2토큰 사용량 탭사용자별 입력·출력·합계 토큰과 한도가 나옵니다.
3사용률 열한도 대비 사용 비율입니다. 100%를 넘으면 한도 초과입니다.
4상태 열정상(90% 미만), 경고(90% 이상), 한도 초과, 판정 불가

4단계. 개인 추가 부여 준비​

한도 초과 직원이 월말 보고서를 마쳐야 한다면 토큰 한도 설정의 개인 토큰 추가 부여로 이번 달에만 쓸 토큰을 더 줍니다.

개인 토큰 추가 부여

번호메뉴입력할 값
1대상 사용자사번이나 이름으로 찾아 고릅니다. 목록에 이름·사번·소속과 당월 사용량, 상태가 함께 보입니다.
2부여할 토큰5000(1 이상)
3부여 사유11월 경영진 보고서 작성 지원(월말 마감)
4부여즉시 반영됩니다. 당월 사용량이 새 실효 한도(월 한도 + 부여분)보다 적어지면 차단이 풀립니다.

부여 대상은 사번으로 확인합니다. 사번 디렉터리(인사 원장)가 연결되지 않은 배포에서는 대상 사용자를 고른 뒤 "대상 사용자를 찾을 수 없습니다."가 나오고 부여되지 않습니다. 연습 환경이 이 경우이며, 이때는 월 한도 자체를 올려 해결합니다.

결과​

확인 위치기대 결과
토큰 한도 설정 > 기본 한도전 사용자 월 한도 8,000, 다음 초기화 다음 달 1일
변경 이력기본 한도 최초 설정 8,000과 사유
사용자별 통계 > 토큰 사용량한도 열 8,000, 한도 초과 1명
감사 로그한도 정책 변경 1건(성공), 부여를 시도했다면 부여 1건(성공 또는 실패)

흔한 실수​

실수증상바로잡기
0을 넣고 저장모든 직원이 바로 차단됨0은 "전원 차단"입니다. 바로 원래 값으로 다시 저장합니다.
미리보기를 보지 않고 저장많은 직원이 갑자기 차단됨미리보기의 "새로 차단" 인원을 먼저 봅니다.
사유를 비우거나 공백만 넣음저장이 눌리지 않음한 줄이라도 이유를 적습니다.
부서별 한도를 기대함한도가 한 값뿐임월 한도는 전 사용자 공통 한 값입니다. 많이 쓰는 직원은 개인 추가 부여로 보완합니다.
다음 달에도 부여분이 남을 거라 생각1일에 다시 차단됨부여분은 매월 1일에 사라집니다. 매달 다시 줍니다.

응용 과제​

  1. 월 한도를 12,000으로 바꿔 미리보기의 "새로 차단" 인원이 0이 되는지 보세요(저장하지 않고 취소).
  2. 사용자별 통계의 토큰 현황 카드에서 "한도 90% 이상" 인원을 보고, 경고 단계 직원에게 보낼 안내 메일 초안을 써 보세요.
  3. 실습을 마쳤다면 한도를 운영 기준 값으로 되돌리고, 변경 이력에 두 줄이 쌓였는지 확인하세요.
