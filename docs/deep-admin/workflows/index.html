Deep Admin 반복 업무

플랫폼 관리자가 매일, 매주, 매월 되풀이하는 점검 업무를 순서대로 정리했습니다. 브레인크루 AI혁신팀 강혁신 팀장(플랫폼 관리자)이 쓰는 점검표를 예로 들었습니다. 회사 사정에 맞게 주기와 기준값을 바꾸어 쓰세요.

이 페이지에서 할 수 있는 일

  • 매일 아침 5분 안에 서비스 상태와 대기 중인 요청을 확인합니다.
  • 매주 사용량과 오류 추이를 보고 이상한 사용자나 에이전트를 찾습니다.
  • 매월 초에 사용량 리포트를 내보내고 한도와 권한을 정리합니다.
  • 입사·이동·퇴사 같은 인사 변동이 있을 때 권한을 정리합니다.

매일: 아침 점검​

순서메뉴확인할 것이상할 때
1대시보드 > 운영 요약기간을 오늘로 두고 실행 추이에 오류가 몰린 시간이 있는지 봅니다.오류 선이 튀면 에러/장애 모니터링으로 갑니다.
2에러/장애 모니터링최근 에러/타임아웃 로그에서 같은 에러 유형이 반복되는지 봅니다. 사용자 중지 제외를 켜 두면 직원이 직접 멈춘 실행은 빠집니다.행을 펼쳐 원인과 권장 조치를 확인하고, 필요하면 실행 상세 보기로 들어갑니다.
3전체 에이전트 > 배포 요청 심사상태가 심사중인 공유 요청이 있는지 봅니다.전체 에이전트와 배포 심사의 순서대로 심사합니다.
4승인 관리도구·모델·스킬·미들웨어 등록 요청 중 대기중이 있는지 봅니다.요청 내용을 열어 승인하거나 사유를 적어 거부합니다.

매주: 사용량과 품질 점검​

  1. 사용자별 통계에서 기간을 7일로 두고 실행 통계 탭을 실행 수 순으로 봅니다. 에러율이 유난히 높은 사용자가 있으면 행을 눌러 에이전트별 사용량과 상태 분포를 확인합니다.
  2. 같은 화면의 토큰 사용량 탭에서 한도 90% 이상 카드를 봅니다. 월말 전에 한도가 찰 직원이 있으면 미리 연락하거나 추가 부여를 검토합니다.
  3. LLM 토큰 사용량에서 최근 7일을 고르고 모델별 탭으로 모델별 토큰을 비교합니다. 비싼 모델에 사용량이 몰렸다면 에이전트·워크스페이스별 사용량의 에이전트별 기준으로 어떤 에이전트가 원인인지 찾습니다.
  4. 사용량 관리에서 주요 워크스페이스를 골라 상위 사용자 10명과 에러율을 확인합니다.
  5. 관리자 접근기록에서 결과를 권한 거부로 두고 지난주 기록을 봅니다. 같은 관리자가 반복해서 거부되면 권한 그룹이 업무에 맞는지 검토합니다.

매월: 리포트와 정리​

시점할 일메뉴
매월 1일지난달 사용량을 CSV 파일(.csv)로 내보내 보관하고 부서장 보고 자료를 만듭니다. 내보내기 범위는 한 번에 최대 92일입니다.LLM 토큰 사용량 > 토큰 사용량 내보내기
매월 1일월 한도가 초기화되었는지 확인합니다. 초기화 주기는 매월 1일 00:00(한국 시간)으로 고정이며, 지난달 개인 추가 부여분도 함께 사라집니다.토큰 한도 설정
첫 주지난달 한도 초과가 많았다면 전 사용자 월 한도를 조정합니다. 바꾸기 전 미리보기로 새로 차단될 인원을 확인하고, 변경 사유를 남깁니다.토큰 한도 설정 > 기본 한도
첫 주사용 기한이 지난 도구·지식 권한을 정리합니다. 상태 필터를 기한 만료로 두면 정리 대상만 보입니다.지식 컬렉션 권한, 사용자별 도구 권한
첫 주배포된 에이전트 중 쓰이지 않는 것을 찾아 비공개로 돌립니다. 상세의 활용 현황으로 실제 사용자 수를 봅니다.전체 에이전트 > 배포된 에이전트

인사 변동이 있을 때​

상황할 일
입사직원이 한 번 로그인한 뒤 사용자에서 찾아 역할(RBAC 그룹)을 배정하고, 워크스페이스 설정에서 워크스페이스 권한 그룹을 정합니다. 업무에 필요한 도구와 지식 컬렉션을 엽니다. 자세한 순서는 신규 입사자 사례를 따릅니다.
부서 이동이전 부서 업무용 지식 컬렉션과 도구 권한을 회수하고, 새 부서 것을 부여합니다. 회수 사유에 "부서 이동"처럼 이유를 남기면 이력에서 찾기 쉽습니다.
프로젝트 투입프로젝트 기간에만 필요한 컬렉션은 기한 지정으로 열어 두면 기한이 지나 자동으로 기한 만료가 됩니다.
퇴사그 직원에게 열린 도구·지식 권한을 회수하고, 사용자 상세의 보안 탭에서 남은 API 토큰을 폐기합니다. 그 직원이 요청자인 배포된 에이전트가 있으면 담당자를 정하고 공개 상태를 검토합니다.

점검 결과 남기기​

관리자 화면에서 바꾼 내용은 메뉴마다 이력이 남습니다. 토큰 한도는 변경 이력 카드, 도구·지식 권한은 행의 이력, 배포 심사는 요청 행의 이력과 심사 화면의 심사 결과에서 볼 수 있습니다. 월간 점검표에는 바꾼 메뉴와 사유만 적어 두고, 자세한 내용은 각 화면의 이력을 근거로 삼으면 됩니다.
