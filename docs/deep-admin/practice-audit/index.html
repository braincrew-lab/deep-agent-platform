Deep Admin 실습 5: 감사

월말이 되면 경영지원팀 윤지원 사원이 이번 달 관리자 작업을 점검합니다. 누가 권한 없는 화면을 열려고 했는지, 누가 언제 무엇을 바꿨는지 두 기록으로 확인합니다. 이 실습에서는 관리자 접근기록에서 권한 거부를 모아 보고, 감사 로그에서 실습 3의 한도 변경을 찾아 변경 전·후 값을 비교합니다. 화면 전체 설명은 모니터링과 감사 기록에 있습니다.

이 페이지에서 할 수 있는 일

  • 관리자 접근기록을 결과 권한 거부로 걸러 반복되는 거부를 찾습니다.
  • 감사 로그에서 특정 변경을 찾아 상세를 엽니다.
  • 변경 전·후 값과 변경 사유를 점검 기록에 옮깁니다.

목표​

항목내용
만들 것이번 달 관리 작업 점검 기록(권한 거부 요약 + 주요 변경 3건)
결과물아래 "결과"의 점검표
걸리는 시간15분
난이도★★★☆☆

준비물​

준비물내용
계정관리자 접근기록 조회와 감사 로그 조회 권한이 있는 계정. 실습 2의 "운영 감사 담당" 그룹에 감사 로그 조회가 들어 있습니다.
앞 실습실습 2(권한 변경)와 실습 3(한도 변경)을 해 두면 아래 화면과 같은 기록이 나옵니다.
감사 로그 주소감사 로그는 사이드바에 없습니다. 관리자 주소 끝에 감사 로그 경로를 붙여 엽니다. 플랫폼 운영 담당이 알려 준 주소를 즐겨찾기에 넣어 둡니다.
점검표엑셀 파일(.xlsx) 등 기록을 옮길 표

1단계. 권한 거부 모아 보기​

운영 현황 > 관리자 접근기록을 엽니다.

권한 거부 기록

번호메뉴고르거나 확인할 값
1결과권한 거부(다른 값: 전체, 성공, 요청 실패, 서버 오류)
2조회누르면 조건으로 다시 찾습니다. 초기화는 조건을 비웁니다.
3메뉴 열거부된 화면입니다. 예시에서는 "사용자별 통계"가 반복됩니다.
4결과 열"권한 거부 403". 옆 오류 코드 열에 ACCESS_DENIED와 "이 워크스페이스에 대한 접근 권한이 없습니다."가 보입니다.
검색 조건처음 값쓰는 법
사번전체한 관리자만 볼 때 그 관리자의 사번을 적습니다.
결과전체이번 실습은 권한 거부
메뉴비움화면 경로(예: 에이전트 실행 로그 화면 경로)로 좁힙니다.
요청 ID비움오류 화면에 나온 요청 ID로 한 건을 찾습니다.
시작, 종료비움이번 달 1일~말일

예시의 거부는 관리자가 사용자별 통계나 워크스페이스 설정을 열 때, 자신이 속하지 않은(WBAC 그룹이 없는) 워크스페이스나 전체 워크스페이스를 고른 경우입니다. 플랫폼 전체 관리자라도 워크스페이스 단위 화면은 그 워크스페이스의 WBAC 그룹이 있어야 합니다. 점검표에는 "워크스페이스 단위 화면 조회 거부 N건 — 소속 워크스페이스를 골라 조회하면 해결, 조치 불필요"처럼 원인과 판단을 적습니다.

2단계. 감사 로그에서 변경 찾기​

감사 로그 주소를 열고 기간을 오늘(또는 이번 달)로 둡니다. 목록에서 액션이 TOKEN_LIMIT_POLICY_UPDATE인 행을 찾습니다.

감사 로그 목록

번호메뉴확인할 것
1액션 열TOKEN_LIMIT_POLICY_UPDATE(월 한도 변경). 같은 표에 시각, 행위자, 사번, 접속 IP, 결과, 대상이 있습니다.
2상세누르면 오른쪽에 상세가 열립니다.

자주 보는 액션은 다음과 같습니다.

액션뜻
RBAC_GROUP_CREATERBAC 그룹 만들기(실습 2 1단계)
RBAC_PRIVILEGE_GRANT그룹에 권한 부여(실습 2 2단계)
RBAC_ASSIGN사용자에게 RBAC 그룹 배정(실습 1 2단계, 실습 2 3단계)
WBAC_ASSIGN_REPLACE구성원의 WBAC 그룹 바꾸기(실습 1 4단계)
TOKEN_LIMIT_POLICY_UPDATE전 사용자 월 한도 변경(실습 3 1단계)
TOKEN_LIMIT_GRANT_CREATE개인 추가 부여. 실패하면 결과가 실패로 남습니다.
AUDIT_LOG_VIEW감사 로그를 연 기록. 감사 로그를 본 일도 기록됩니다.

3단계. 변경 전·후 비교​

감사 로그 상세

번호메뉴읽을 값
1액션TOKEN_LIMIT_POLICY_UPDATE, 결과 성공, 대상 token_limit_policy(global)
2변경 전한도 값(default_limit_tokens)이 null, 즉 미설정
3변경 후한도 8000과 사유("11월 시범 운영 기준 한도 설정(1인 월 8천 토큰)")

변경 전·후 값과 대상 스냅샷은 이 상세 화면에서만 보입니다. 사번은 화면에서 가려서 보입니다.

결과​

점검표에 옮긴 예시입니다.

구분시각내용근거판단
권한 거부11-12 03:22~20:31사용자별 통계·워크스페이스 설정 조회 거부 12건관리자 접근기록조작 방법 문제, 조치 불필요
권한 변경11-12 20:22~20:24RBAC 그룹 "운영 감사 담당" 생성, 권한 5개 부여감사 로그 RBAC_GROUP_CREATE, RBAC_PRIVILEGE_GRANT감사 담당 지정, 승인 문서 있음
한도 변경11-12 20:26월 한도 미설정 → 8,000감사 로그 TOKEN_LIMIT_POLICY_UPDATE, 토큰 한도 변경 이력시범 운영 기준, 정상
부여 실패11-12 20:28김그루 사원 추가 부여 실패(대상 사용자를 찾을 수 없음)감사 로그 TOKEN_LIMIT_GRANT_CREATE 실패사번 디렉터리 미연결, 운영 담당에 전달

흔한 실수​

실수증상바로잡기
관리자 접근기록에서 "무엇을 바꿨는지" 찾음요청 본문이 없음접근기록은 요청 본문을 저장하지 않습니다. 바꾼 값은 감사 로그 상세나 각 화면의 이력에서 봅니다.
감사 로그를 사이드바에서 찾음메뉴가 없음운영 담당이 알려 준 주소로 엽니다.
실패한 변경을 빠뜨림점검표가 성공만 담음결과 필터를 모든 결과로 두고 실패도 함께 봅니다.
파일로 내보내려 함내보내기 버튼이 없음조건으로 좁힌 화면을 캡처하거나, 토큰 한도 변경 이력, 권한 이력, 배포 이력 같은 화면 기록을 함께 제출합니다.
캡처를 그대로 공유사번·IP가 드러남공유 전에 사번, IP, 요청 ID를 가립니다.

응용 과제​

  1. 관리자 접근기록에서 결과를 서버 오류로 바꿔 보고, 같은 메뉴에서 반복된 오류가 있으면 에러/장애 모니터링과 함께 운영 담당에게 전달할 메모를 써 보세요.
  2. 감사 로그에서 WBAC_ASSIGN_REPLACE 행의 상세를 열어, 실습 1에서 김그루 사원에게 준 그룹이 변경 후 값에 있는지 확인하세요.
  3. 실습 2 응용 과제 3에서 그룹 배정을 해제했다면, 그 해제 기록을 찾아 점검표에 한 줄 더 적으세요.
