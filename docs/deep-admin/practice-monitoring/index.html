Deep Admin 실습 4: 모니터링

매주 월요일 아침, 강혁신 팀장은 지난 한 달의 운영 상태를 30분 안에 훑고 팀장 회의에 낼 사용량 자료를 만듭니다. 이 실습은 그 순서를 그대로 따라 합니다. 대시보드로 전체 상태를 보고, 실패한 실행을 찾아 원인과 조치를 확인하고, LLM 토큰 사용량을 CSV 파일(.csv)로 받아 엑셀 표로 정리합니다. 화면 전체 설명은 시작하기, 모니터링과 감사 기록, LLM 토큰 사용량에 있습니다.

이 페이지에서 할 수 있는 일

  • 대시보드 시스템 탭으로 오류율과 응답 시간을 봅니다.
  • 실행 로그에서 오류 실행만 골라냅니다.
  • 에러/장애 모니터링에서 원인과 권장 조치를 읽습니다.
  • 한 달 사용량을 CSV 파일(.csv)로 받아 엑셀 파일(.xlsx)로 정리합니다.

목표​

항목내용
만들 것오류 원인 메모 1건, 최근 30일 사용량 CSV 파일, 모델별·부서별 합계 엑셀 표
결과물"token-usage-builder-시작일-종료일.csv" 파일과 그 파일로 만든 표
걸리는 시간20분
난이도★★★☆☆

준비물​

준비물내용
관리자 계정대시보드 조회, 실행 로그 조회, 에러 모니터링 조회, LLM 토큰 사용량 조회 권한
사용 기록최근 한 달 사이 실행 기록. LLM 토큰 사용량은 LLM 관문(DeepGateway)을 거친 기록이 있어야 합니다.
프로그램CSV 파일(.csv)을 열어 엑셀 파일(.xlsx)로 저장할 표 계산 프로그램
인사 자료사용자와 부서를 잇는 표(부서별 합계를 낼 때)

1단계. 대시보드로 전체 상태 보기​

운영 현황 > 대시보드에서 30일을 고르고 시스템 탭을 엽니다.

대시보드 시스템 탭

번호메뉴확인할 것예시 값
1시스템 탭오류율과 응답 시간을 모아 봅니다.–
224시간 오류율최근 하루 오류 비율0.8%
3p99가장 느린 1% 실행의 소요 시간약 126초
4에러 유형 열어떤 오류가 몇 건인지execute_error 1, secret_fetch_error 1

오류가 두 종류 있으니 다음 단계에서 어떤 실행이 실패했는지 찾습니다.

2단계. 오류 실행만 골라내기​

운영 현황 > 에이전트 실행 로그에서 30일을 누르고 상태를 오류로 바꿉니다.

오류 실행 목록

번호메뉴고를 값
130일최근 30일
2상태 선택오류(다른 값: 대기, 실행중, 성공, 취소됨, 시간초과)
3에이전트명 열오류가 난 에이전트(예: 이메일 초안 도우미, 주간 업무 보고서 도우미)

유형 열의 백그라운드, 스케줄은 직원이 화면을 닫은 뒤나 예약 시각에 돌아간 실행입니다. 행을 누르면 실행 상세가 열립니다.

3단계. 원인과 권장 조치 읽기​

운영 현황 > 에러/장애 모니터링에서 30일을 고르고, 아래 최근 에러/타임아웃 로그의 "이메일 초안 도우미" 행을 펼칩니다.

에러 원인과 권장 조치

번호메뉴읽을 내용
1에러 유형비밀값 조회 실패(secret_fetch_error)
2원인비밀값 조회 실패 때문에 실행이 실패했습니다.
3권장 조치에이전트와 도구에 연결된 비밀값(시크릿) 설정과 조회 권한을 확인합니다.
4실행 상세 보기그 실행의 상세 화면으로 갑니다.

권장 조치에 따라 시크릿과 키에서 그 워크스페이스 시크릿이 있는지 봅니다. 메모에는 "이메일 초안 도우미, 백그라운드 실행 1건, 비밀값 조회 실패, 브레인크루 워크스페이스 시크릿 확인"처럼 남깁니다.

4단계. 사용량을 CSV 파일로 받기​

사용자·승인 > LLM 토큰 사용량을 열고 최근 30일로 요약을 확인한 뒤, 맨 아래 토큰 사용량 내보내기로 내려갑니다.

토큰 사용량 내보내기

번호메뉴고를 값
1제품Builder
2시작일(KST, 포함)처음 값(오늘부터 30일 전) 그대로. 종료일은 오늘.
3CSV 내보내기누르면 파일이 내려받아지고 "N행을 내보냈습니다."가 나옵니다.
설정 항목이 실습의 값기본값과 범위
제품BuilderBuilder. DeepWork는 권한이 있을 때만
시작일·종료일최근 30일최근 30일, 최대 92일
사용자·에이전트·워크스페이스 ID비움비움(전체)

연습 환경에서 받은 파일은 112행이었습니다(요청 1건이 1행).

5단계. 엑셀로 정리하기​

  1. 받은 CSV 파일(.csv)을 엑셀로 열고 엑셀 파일(.xlsx)로 다시 저장합니다.
  2. status 열이 succeeded인 행만 남기도록 필터를 겁니다.
  3. 피벗 표를 만들어 행에 model_id, 값에 total_tokens와 final_charge의 합계를 놓습니다.
  4. managed_user_id 열과 LLM 토큰 사용량 화면의 사용자별 탭 사용자 ID를 맞춰 직원을 확인하고, 인사 자료로 부서를 이어 행에 부서를 추가합니다.
  5. 결과 표 아래에 3단계에서 남긴 오류 메모를 붙입니다.
모델성공 요청합계 토큰비용($)

흔한 실수​

실수증상바로잡기
내보내기 기간을 92일보다 길게 잡음"기간은 최대 92일까지 선택할 수 있습니다."분기 단위로 나눠 받습니다.
대시보드 토큰과 CSV 합계가 다르다고 보고숫자가 안 맞음대시보드는 Builder 실행 기록, CSV는 LLM 관문 요청 기록입니다. 보고서에는 기준을 함께 적습니다.
실패한 요청까지 합산합계가 화면보다 큼status가 succeeded인 행만 셉니다.
시각을 한국 시간으로 착각날짜가 하루 어긋남CSV의 started_at은 세계 표준시입니다. 9시간을 더해 봅니다.
화면에 "정보를 불러오지 못했습니다"LLM 관문 미연결플랫폼 운영 담당에게 연결을 요청합니다.

응용 과제​

  1. 에이전트·워크스페이스별 사용량의 워크스페이스별 탭에서 비용 1위 워크스페이스를 찾고, 5단계 표의 부서별 합계와 맞는지 비교하세요.
  2. 대시보드 사용자 통계 탭에서 실행 횟수 1위 직원을 찾아, 실행 로그를 그 직원으로 걸러 어떤 에이전트를 가장 많이 쓰는지 보세요.
  3. 다음 달 1일에 같은 순서로 "지난달 1일~말일" 파일을 받아 두 달을 비교하는 표를 만들어 보세요.
