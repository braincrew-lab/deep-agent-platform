Deep Admin 모니터링과 감사 기록

서비스가 정상으로 돌고 있는지, 누가 어떤 관리 작업을 했는지 확인하는 메뉴를 설명합니다. 에이전트 실행 로그와 생성 로그, 에러/장애 모니터링으로 운영 상태를 보고, 관리자 접근기록과 감사 로그로 관리 작업을 추적합니다.

이 페이지에서 할 수 있는 일

  • 에이전트 실행 기록을 찾아 실행 과정과 답변을 확인합니다.
  • 에러 유형별 원인과 권장 조치를 확인합니다.
  • 관리자가 어떤 관리 화면을 썼는지, 무엇을 바꿨는지 기록을 찾습니다.

에이전트 실행 로그​

운영 현황 > 에이전트 실행 로그는 모든 에이전트 실행 기록입니다.

에이전트 실행 로그

번호항목기능이런 때 사용하세요
130일조회 기간입니다. 오늘, 7일, 전체나 날짜 직접 지정도 됩니다.문의가 들어온 날을 볼 때
2전체 상태대기, 실행중, 성공, 오류, 취소됨, 시간초과로 거릅니다. 옆에 사용자 검색, 워크스페이스, 에이전트, 유형, 정렬 필터가 있습니다.특정 직원의 오류 실행만 볼 때
3에이전트명 열실행한 에이전트입니다. 같은 표에 사용자, 워크스페이스, 입력, 답변, 유형, 실행 시간, 토큰, 생성일시가 있습니다.실행을 훑어볼 때
4상태 열실행 결과실패한 실행을 찾을 때

행을 누르면 실행 상세가 열립니다.

실행 상세

번호항목화면에 보이는 내용이런 때 확인하세요
1상태(예: 성공)실행 결과입니다. 옆에 에이전트 버전과 실행 유형(실시간, 백그라운드, 스케줄)이 있습니다.실패한 실행인지 볼 때
2실행시간실행 시작부터 완료까지 걸린 시간입니다. 옆 대기시간은 요청 접수부터 실행 시작까지입니다. 대기시간이 길면 실행이 몰린 것입니다."답이 늦다"는 문의를 받았을 때
3실행 타임라인 탭실행이 어떤 단계를 거쳤는지 시간순으로 봅니다. 옆 도구 · 지식 호출은 부른 도구와 지식 검색, 입력 · 답변은 질문과 답입니다.어느 단계에서 시간이 걸렸는지 볼 때
4모델이 실행에 쓴 모델(예: gpt-4.1-2025-04-14 (openai))입니다. 같은 실행 정보에 Run ID, Thread ID, 에이전트, 사용자, 워크스페이스, 완료일시가 있습니다.비싼 모델로 실행됐는지 볼 때

직원이 남긴 "싫어요" 피드백도 개요에 보입니다. 입력과 답변의 민감한 내용은 별도 권한이 있는 관리자에게만 보입니다. 위쪽 목록으로를 누르면 실행 로그로 돌아갑니다.

이럴 때 쓰세요: 김그루 사원이 "주간 업무 보고서 도우미가 어제 오후 답을 30초 넘게 끌었다"고 알려 왔습니다. 강혁신 팀장은 실행 로그에서 김그루 사원의 어제 실행을 열어 대기시간과 실행시간을 비교합니다. 대기시간은 짧고 실행시간만 길면 실행 타임라인에서 오래 걸린 단계(예: 긴 문서 읽기)를 찾아 지침을 손보도록 안내합니다.

에이전트 생성 로그​

에이전트 생성 로그는 에이전트가 등록, 수정, 삭제된 기록입니다. "어제까지 잘 되던 에이전트가 오늘 이상하다"는 문의를 받으면 여기서 최근 수정이 있었는지 먼저 봅니다.

에이전트 생성 로그

번호항목기능이런 때 사용하세요
1워크스페이스 선택기록을 볼 워크스페이스입니다. 기본값은 전체 워크스페이스입니다.한 부서 에이전트만 볼 때
27일기간입니다. 오늘, 30일, 전체나 날짜 직접 지정도 됩니다. 오른쪽 전체 선택은 액션(등록, 수정, 삭제)을 거르고, 아래 칸은 사용자 이름으로 찾습니다.지난주 바뀐 에이전트를 볼 때
3액션 열등록, 수정, 삭제 중 하나입니다. 같은 표에 에이전트 ID, 에이전트 UID, 사용자, 워크스페이스, 발생일시가 있습니다.언제 누가 바꿨는지 볼 때
4요약 열무엇이 바뀌었는지 짧게 보여 줍니다.바뀐 내용을 훑어볼 때

에러/장애 모니터링​

에러/장애 모니터링은 실행 오류를 모아 원인과 조치를 보여 줍니다.

에러/장애 모니터링

번호항목기능이런 때 사용하세요
1사용자 중지 제외직원이 직접 멈춘 실행을 집계에서 뺍니다. 왼쪽 필터로 워크스페이스, 에이전트, 기간, 에러 유형도 고릅니다.진짜 오류만 볼 때
2에러율기간 안 실행 중 오류 비율입니다. 옆 카드에 총 실행 수, 오류 발생 수, 실행 시간, 평균 대기 시간이 있고 직전 기간과의 차이도 보입니다.오늘 오류가 늘었는지 볼 때
3에러 유형 안내화면에 표시되는 에러 이름마다 무슨 일이 있었는지와 이렇게 해 보라는 안내를 표로 보여 줍니다.직원에게 원인을 설명할 때
4일별 실행 · 오류 추이날짜별 실행과 오류 건수 그래프입니다. 옆에 에러 유형별 건수가 있습니다.특정 날에 오류가 몰렸는지 볼 때

화면 아래 최근 에러/타임아웃 로그에는 에이전트, 사용자, 입력, 에러 유형, 실패 단계, 실행 시간, 발생일시가 나오고, 행을 펼치면 원인, 권장 조치, 원본 메시지와 실행 상세 보기가 나옵니다.

관리자 접근기록​

관리자 접근기록은 관리 화면에서 관리자가 보낸 요청을 한 건씩 남긴 기록입니다. 성공, 실패, 권한 거부를 모두 기록하지만 요청 본문은 저장하지 않습니다.

관리자 접근기록

번호항목기능이런 때 사용하세요
1결과 필터전체, 성공, 권한 거부, 요청 실패, 서버 오류. 옆에 사번, 메뉴(화면 경로), 요청 ID, 시작, 종료 조건이 있습니다.권한 거부 기록만 볼 때
2조회조건으로 찾습니다. 옆 초기화는 조건을 비웁니다.조건을 바꿔 다시 찾을 때
3관리자 열요청을 보낸 관리자입니다. 같은 표에 시각, IP, 메뉴, 요청, 오류 코드, 요청 ID가 있습니다. 메뉴를 알 수 없는 요청은 "화면 밖 호출"로 표시됩니다.누가 어떤 화면을 열었는지 확인할 때
4결과 열성공, 권한 거부, 요청 실패, 서버 오류반복된 권한 거부를 찾을 때

감사 로그​

관리자 화면에서 일어난 변경 기록(감사 로그)은 기간, 결과(대기, 성공, 실패), 액션, 사번, 대상 유형으로 찾을 수 있습니다. 행의 상세를 누르면 대상의 변경 전과 변경 후 값을 비교해 볼 수 있습니다. 사번은 가려서 보입니다. 감사 로그는 사이드바 메뉴에는 나오지 않아 플랫폼 운영 담당이 알려 준 주소로 엽니다.

감사 로그

번호항목기능이런 때 사용하세요
1모든 결과결과(대기, 성공, 실패)로 거릅니다. 왼쪽에서 기간을, 옆에서 액션, 사번, 대상 유형을 정합니다.특정 날짜의 실패한 변경을 찾을 때
2액션 열어떤 변경이었는지 보여 줍니다. 같은 표에 시각, 행위자, 사번, 접속 IP, 결과, 대상이 있습니다.어떤 변경이 있었는지 훑어볼 때
3상세요청 ID와 대상 스냅샷, 변경 전, 변경 후 값을 엽니다.무엇이 어떻게 바뀌었는지 확인할 때

관리자 접근기록과 감사 로그는 화면에서 파일로 내보내는 기능이 없습니다. 감사 대응 자료가 필요하면 조건으로 좁힌 화면을 캡처하거나, 각 메뉴의 변경 이력(토큰 한도 변경 이력, 권한 이력, 배포 이력)을 함께 제출합니다.

Deep Connector와 Deep Work의 기록​

관리 화면 선택으로 제품을 바꾸면 그 제품의 기록 메뉴가 따로 있습니다. Deep Connector는 감사 로그(관리 기능 호출과 문서 변경 이력), Deep Work는 감사 묶음의 Desktop 감사 로그, 관리자 변경 이력, 사용자 접속기록, 관리자 접근기록입니다.
