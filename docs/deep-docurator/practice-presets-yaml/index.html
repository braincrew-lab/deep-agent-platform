Deep Docurator 실습 5: 프리셋 저장·불러오기와 YAML 내보내기/가져오기

검토를 마친 흐름은 프리셋으로 저장해 두면 다음 문서에서 노드를 다시 놓지 않고 같은 기준으로 시작할 수 있습니다. 이 실습은 실습 3에서 만든 영수증 필드 추출 흐름을 프리셋으로 저장하고, 새 플로우에서 불러오고, YAML 파일로 내보내 동료에게 전달하고, 받은 YAML을 가져오는 과정을 차례로 해 봅니다.

이 페이지에서 할 수 있는 일

  • 편집기에서 지금 흐름을 내 프리셋으로 저장합니다.
  • 새 플로우 만들기와 노드 추가 패널에서 내 프리셋을 불러옵니다.
  • 설정 화면에서 프리셋을 YAML 파일로 내보내고 가져옵니다.
  • 내보낸 YAML 파일의 구성을 읽습니다.

목표​

항목내용
다룰 흐름입력 → 파싱 → 청킹 → 메타데이터 → 메타데이터 평가(실습 3)
결과물내 프리셋 "영수증 행 단위 필드 추출 v1", 프리셋 YAML 파일
걸리는 시간10분
난이도★★☆☆☆

준비물​

준비물내용
실습 3의 플로우10월 영수증·견적 품목 표 만들기
시험 파일영수증_견적_모음.csv(새 플로우에서 다시 실행할 때). 표 파일은 csv, xlsx를, 문서는 pdf, doc, docx, hwp, hwpx, pptx, txt, md, html, htm을 넣을 수 있습니다.
가져올 YAML동료에게 받은 yaml 또는 yml 파일. 이 실습에서는 2단계에서 내보낸 파일을 그대로 씁니다.

1단계. 프리셋으로 저장하기​

프리셋으로 저장 대화상자

번호메뉴입력하거나 누를 것
1프리셋으로 저장편집기 위쪽 오른쪽 버튼입니다.
2이름 입력란영수증 행 단위 필드 추출 v1
3저장누르면 대화상자가 닫히고 저장됩니다.

이름에는 문서 종류, 기준, 판 번호를 함께 담습니다. 이름이 비어 있으면 저장이 눌리지 않습니다.

2단계. 설정 화면에서 확인하고 YAML로 내보내기​

설정 화면의 프리셋 목록

번호메뉴화면에 보이는 내용하는 일
1파이프라인 분류파이프라인 프리셋만 남습니다.저장한 흐름 프리셋을 찾습니다.
2프리셋 카드영수증 행 단위 필드 추출 v1, pipeline, input → parse → chunk → metadata → metadata_eval노드 순서가 실습 3과 같은지 봅니다.
3YAML 내보내기 (pipeline)지금 분류에 보이는 프리셋을 하나씩 파일로 내려받습니다.동료에게 보낼 파일을 만듭니다.
4YAML 가져오기파일 선택 창을 엽니다.받은 파일을 등록합니다.
  1. 사이드바 아래 설정을 누릅니다.
  2. 분류에서 파이프라인을 누릅니다.
  3. **YAML 내보내기 (pipeline)**를 누릅니다. 파이프라인 분류에 보이는 프리셋마다 "프리셋 이름.yaml" 파일이 하나씩 내려받아집니다. 프리셋 하나만 보내려면 내려받은 파일 중 그 이름의 파일만 고릅니다.

내려받은 파일을 메모장으로 열면 다음과 같은 구성이 보입니다. 예시는 "보고서 기본 청킹 v1" 파일입니다.

YAML 항목뜻
kind: pipeline, name프리셋 종류와 이름
flow > nodes노드마다 id, type(input, parse, chunk 등), options(전략, 청크 크기 등), position(캔버스 위치)
flow > edges노드 연결(source → target)

파일에는 노드 구성과 옵션만 들어 있고, 입력 파일과 API 키는 들어 있지 않습니다.

3단계. 새 플로우에서 프리셋 불러오기​

  1. 새 플로우 만들기에서 이름 "11월 영수증·견적 품목 표"를 적습니다.
  2. 시작점 프리셋을 누르고 선택 상자에서 "내 프리셋: 영수증 행 단위 필드 추출 v1"을 고릅니다. 시작점 아래 "내장 5개, 내 프리셋 N개"의 숫자가 하나 늘어난 것을 확인할 수 있습니다.
  3. 플로우 만들기를 누르면 다섯 노드가 연결된 채 열립니다.
  4. 입력 노드에 파일을 새로 넣고 실행합니다. 프리셋에는 파일이 들어 있지 않습니다.

편집 중인 플로우에 적용하려면 노드 추가 패널 아래 프리셋 선택 상자의 커스텀에서 고르고 캔버스에 적용을 누릅니다. "현재 캔버스의 내용이 대체됩니다. 계속하시겠습니까?"가 나오면 지금 노드와 결과가 사라진다는 뜻이므로, 남기고 싶으면 새 플로우에서 적용합니다.

4단계. YAML 가져오기​

이 실습에서는 2단계에서 내보낸 "보고서 기본 청킹 v1.yaml"을 동료가 받은 파일이라고 생각하고, 메모장에서 맨 위 id 줄 값을 preset_team_share_report_v1로, name 줄을 "보고서 기본 청킹 v1 (팀 공유본)"으로 고친 뒤 가져왔습니다.

  1. 설정 화면에서 YAML 가져오기를 누릅니다.
  2. 받은 yaml 또는 yml 파일을 고릅니다.
  3. "프리셋을 불러왔습니다. API 키는 포함되지 않으므로 Providers 탭에서 별도로 설정해주세요." 알림이 뜨면 확인을 누릅니다. 이 화면에는 키를 넣는 곳이 없으며, 모델 연결은 운영 담당자가 서버에 설정한 값을 씁니다.
  4. 프리셋 카드 맨 아래에 가져온 프리셋이 추가됐는지 확인합니다.

YAML로 가져온 프리셋

번호항목화면에 보이는 내용
1YAML 가져오기yaml, yml 파일만 고를 수 있는 선택 창을 엽니다.
2가져온 프리셋 카드보고서 기본 청킹 v1 (팀 공유본), pipeline, input → parse → chunk

가져오기는 파일 맨 위 id로 프리셋을 구분합니다. 이 실습 환경에서 내보낸 파일을 id를 바꾸지 않고 이름만 고쳐 가져왔더니, 새 카드가 생기지 않고 원래 "보고서 기본 청킹 v1" 카드의 이름이 바뀌었습니다(원래 파일을 다시 가져와 되돌렸습니다). 내가 내보낸 파일을 고쳐 다시 가져올 때에는 id를 바꿔야 원래 프리셋이 그대로 남습니다. id는 프리셋을 저장할 때마다 새로 만들어지므로, 다른 사람이 저장해 내보낸 파일은 보통 새 카드로 추가됩니다.

실패하면 "가져오기 실패:" 뒤에 이유가 표시됩니다. 대부분 YAML 형식이 깨졌거나 Deep Docurator에서 내보낸 파일이 아닐 때입니다.

흔한 실수와 해결​

증상원인해결
내보내기를 눌렀더니 파일이 여러 개 내려받아집니다.지금 분류에 보이는 프리셋마다 파일 하나씩 만들어집니다.필요한 이름의 파일만 골라 보냅니다.
파이프라인 프리셋 카드에 편집이 없습니다.흐름에서 저장한 파이프라인 프리셋은 화면에서 편집할 수 없습니다.플로우에서 고친 뒤 새 이름(예: v2)으로 다시 저장합니다.
프리셋으로 만든 플로우를 실행하면 입력 파일이 없다고 실패합니다.프리셋은 파일을 담지 않습니다.입력 노드에 파일을 넣고 실행합니다.
가져왔는데 새 카드가 없고 기존 프리셋 이름이 바뀌었습니다.파일의 id가 기존 프리셋과 같아 덮어썼습니다.원래 파일을 다시 가져와 되돌리고, id를 바꾼 파일을 가져옵니다.
캔버스에 적용했더니 기존 결과가 사라졌습니다.캔버스에 적용은 지금 캔버스를 대체합니다.새 플로우를 만들어 적용합니다.

응용 과제​

  1. 설정 화면의 새 프리셋에서 컴포넌트 타입 청킹을 고르고, 라벨 행 (권장)·최대 데이터 행 수 1 옵션만 담은 노드 프리셋을 만들어 보세요. 노드 하나의 옵션만 재사용할 때 씁니다.
  2. 실습 2의 전략 비교 흐름을 프리셋으로 저장해 부서 표준 비교 도구로 공유해 보세요.
  3. 내보낸 YAML의 청크 크기 값과 id를 메모장으로 바꾼 뒤 가져와, 새 프리셋에 바뀐 값이 들어갔는지 확인해 보세요.
