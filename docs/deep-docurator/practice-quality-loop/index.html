Deep Docurator 실습 13: 평가 점수로 반복 개선하는 흐름

고객지원팀이 크루 인사이트 FAQ를 고객 문의 에이전트의 지식으로 쓰겠다고 합니다. "대충 나눠서 올리면 되지 않나요?"라는 질문에 답하려면 숫자가 필요합니다. 이 실습은 일부러 거칠게 만든 1회차 설정으로 평가 노드와 메타데이터 평가 노드의 점수를 받아 본 뒤, 점수가 낮은 이유를 읽고 청킹 전략과 필드 설명을 고쳐 2회차 점수와 비교합니다. 설정을 한 번에 하나씩 바꾸고 점수로 확인하는 반복 개선의 기본 순서를 익힙니다.

이 페이지에서 할 수 있는 일

  • 청킹 결과를 평가 노드로, 메타데이터 결과를 메타데이터 평가 노드로 동시에 점검합니다.
  • 점수가 낮은 지표를 보고 고칠 곳을 고릅니다.
  • 고친 뒤 다시 실행해 1회차와 2회차 점수를 표로 비교합니다.
  • 고친 설정을 프리셋으로 남깁니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 청킹 → 평가, 청킹 → 메타데이터 → 메타데이터 평가
결과물1회차와 2회차의 평가 점수표, 질문과 답이 한 청크에 든 FAQ 청크 11개
걸리는 시간구성 15분, 실행 1회 20초 안팎, 비교 15분
난이도★★★★☆

실습 2는 세 전략을 한 번에 돌려 점수가 가장 높은 것을 자동으로 골랐습니다. 이 실습은 사람이 점수를 읽고 원인을 찾아 고치는 순서를 다루며, 메타데이터 평가까지 함께 봅니다.

준비물​

파일내용형식
크루인사이트-FAQ-2026.docx크루 인사이트 자주 묻는 질문 10개(가상). 질문마다 "Q." 제목과 두세 문장 답docx

질문 제목과 답 문단이 번갈아 나오는 문서면 됩니다. 입력 노드는 pdf, doc, docx, hwp, hwpx, pptx, xlsx, xls, txt, csv, md, html, htm, png, jpg, jpeg, tiff, tif, bmp, webp를 받습니다. 표 형식 FAQ(xlsx, xls, csv)는 실습 3의 표용 전략으로 나눕니다.

1단계. 노드 여섯 개 놓고 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: FAQ 청킹 품질 점검.
  2. 입력, 파싱, 청킹, 평가, 메타데이터, 메타데이터 평가를 놓습니다.
  3. 입력 → 파싱 → 청킹으로 잇고, 청킹 오른쪽 연결점에서 평가와 메타데이터로 두 번 끕니다. 마지막으로 메타데이터 → 메타데이터 평가를 잇습니다. 상태 표시줄에 노드: 6, 연결: 5가 보입니다.

점검 노드 두 개를 단 흐름

번호노드하는 일
1청킹점검할 대상입니다. 1회차에는 일부러 거친 설정을 씁니다.
2평가원문 보존, 제목 위치에서 잘렸는지, 의미 분할, 정보 보존을 점수로 매깁니다.
3메타데이터청크마다 질문, 답변 요약, 주제를 뽑습니다.
4메타데이터 평가필드마다 정확도와 채움률을 표본으로 판정합니다. 청크는 그대로 통과시킵니다.

2단계. 1회차 설정으로 실행하기​

노드설정1회차 값
청킹전략 / 최대 청크 크기 (글자 수) / 겹침 (글자 수)고정 크기 (문자 기준) / 120 / 0
평가평가 메트릭처음 값(원문 보존, Structure, 의미 기반, Statistics, Preservation)
평가원문 위치 표본 수 / 의미 판정 최대 호출 수 / 의미 판정 입력·출력 추정 토큰20 / 20 / 60000
메타데이터필드질문(문자열, 설명 "질문"), 답변_요약(문자열, 설명 "답"), 주제(문자열, 설명 "주제")
메타데이터 평가원문 위치 표본 수20(처음 값)

입력 노드에 크루인사이트-FAQ-2026.docx를 넣고 실행합니다. 예시는 20초 안팎에 끝났습니다. 평가 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

1회차 평가 점수

번호항목화면에 보이는 내용뜻
1청킹 노드고정 크기 (문자 기준), 11 청크, 경고 (11)글자 수만 보고 120자마다 잘랐습니다.
2Structure0청크 경계가 하나도 질문 제목 위치와 맞지 않았습니다. 질문과 답이 서로 다른 청크로 갈라졌다는 뜻입니다.
3의미 기반54표본 청크 중 절반 가까이가 의미가 끊긴 채 잘렸습니다.

원문 보존은 100이므로 글자가 빠지지는 않았습니다. 같은 실행에서 메타데이터 평가 노드는 정확도 42%, 채움률 91%였고, 답변_요약과 주제의 정확도가 15% 안팎으로 가장 낮았습니다. 청크가 질문 중간에서 잘리면 모델이 어느 질문의 답인지 알 수 없기 때문입니다.

3단계. 원인 하나씩 고치기​

점수가 낮은 순서대로 원인과 고칠 곳을 정합니다. 한 번에 다 바꾸면 무엇이 효과였는지 알 수 없으므로, 실제 업무에서는 청킹을 먼저 고쳐 실행하고 메타데이터 설명을 그다음에 고칩니다. 아래는 두 가지를 모두 고친 2회차 값입니다.

낮은 점수원인노드2회차 값
Structure 0, 의미 기반 54제목을 보지 않는 고정 크기 전략청킹전략 마크다운, 헤더 깊이 3, 헤더 제거 꺼짐. 질문 제목마다 한 청크가 됩니다.
답변_요약 정확도 낮음설명이 "답" 한 글자라 무엇을 뽑을지 모호함메타데이터답변_요약 설명 "질문 바로 아래 답변을 한 문장으로 줄인 것. 숫자와 기간은 원문 그대로 쓴다"
주제 정확도 낮음주제가 자유값이라 매번 다른 말로 나옴메타데이터주제에 허용 값 "요금=요금제와 청구, 데이터=데이터 갱신·업로드·보관, 공유=공유와 권한, 화면=화면 꾸미기와 알림, 지원=문의와 장애"
질문 정확도질문 위치를 알려 주지 않음메타데이터질문 설명 "청크 맨 앞 'Q.' 뒤의 질문 문장을 원문 그대로. 질문이 없으면 비워 둔다"

4단계. 2회차 실행하고 비교하기​

설정을 바꾼 뒤 다시 파이프라인 실행을 누릅니다. 입력 파일은 그대로 둡니다.

2회차 평가 점수

번호항목화면에 보이는 내용
1청킹 노드마크다운, 11 청크. 질문 10개와 문서 제목이 각각 한 청크
2Structure100
3의미 기반96

메타데이터 평가 노드를 누르면 필드별 점수가 보입니다.

2회차 메타데이터 평가

번호항목화면에 보이는 내용
1메타데이터 평가 노드정확도와 채움률 요약
2필드별 점수정확도 66%, 채움률 100%. 질문 100% · 91%, 답변_요약 60% · 91%, 주제 41% · 100%(앞 숫자가 정확도, 뒤 숫자가 채움률)

예시의 두 회차를 비교한 표입니다.

지표1회차2회차
Structure(제목 위치)0100
의미 기반5496
Preservation(정보 보존)90100
원문 보존100100
메타데이터 정확도42%66%
메타데이터 채움률91%100%

의미 기반과 메타데이터 평가는 모델이 표본을 판정하므로 같은 설정으로 다시 실행해도 몇 점씩 달라집니다. 예시에서도 1회차 정확도는 35%에서 42%, 2회차는 66%에서 68% 사이였습니다. 차이가 10점 이상일 때만 개선으로 보고, 비교할 때는 같은 파일과 같은 표본 수를 씁니다.

2회차에도 주제 정확도가 41%로 낮은 것은 문서 제목 청크(질문이 없는 청크)에도 주제를 붙였기 때문입니다. 이런 청크는 필터 노드로 빼거나 설명에 "질문이 없으면 비워 둔다"를 넣어 다음 회차에서 고칩니다.

5단계. 고친 설정을 남기기​

  1. 편집기 위쪽 프리셋으로 저장을 누르고 이름을 "FAQ 청킹 v2(마크다운)"처럼 회차를 붙여 저장합니다.
  2. 비교표를 팀 문서에 붙여 두면, 다음 FAQ 개정판에서 같은 기준으로 다시 점검할 수 있습니다.

흔한 실수와 해결​

증상원인해결
평가 노드가 "Input should be a valid integer"로 실패합니다.의미 판정 최대 호출 수와 추정 토큰이 비어 있습니다.두 칸에 20과 60000을 넣습니다.
메타데이터 평가 노드에 결과가 없습니다.메타데이터 평가를 청킹 뒤에 바로 이었습니다.메타데이터 노드 다음에 잇습니다.
청킹 노드에 경고 (11)가 보입니다.docx는 원본 위치 좌표가 없어 청크마다 안내가 붙습니다.점수에는 영향이 없습니다. pdf로 저장해 넣으면 경고가 사라집니다.
같은 설정인데 점수가 조금씩 다릅니다.의미 판정은 표본과 모델 판정에 따라 달라집니다.원문 위치 표본 수를 늘리고, 작은 차이는 개선으로 보지 않습니다.
마크다운 전략인데 청크가 한 개만 나옵니다.질문이 제목 서식이 아니라 굵은 본문으로 되어 있습니다.원본에서 질문 줄을 제목 스타일로 바꾸거나 재귀 전략으로 비교합니다.

응용 과제​

  1. 2회차 설정에서 평가 메트릭의 Boundary와 Independence(진단용)를 함께 체크해 청크 경계와 독립성 점수도 보세요.
  2. 마크다운 대신 재귀 (마크다운 인식) 전략에 최대 청크 크기 300을 넣은 3회차를 만들어 비교표에 한 줄을 더해 보세요.
  3. 실습 2의 전략 선택 노드를 붙여 1·2·3회차 설정을 한 번에 돌리고, 자동으로 고른 결과가 사람이 고른 것과 같은지 확인해 보세요.
