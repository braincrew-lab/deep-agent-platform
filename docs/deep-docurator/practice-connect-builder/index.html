Deep Docurator 실습 6: 에이전트·지식과 연결하는 흐름

Deep Docurator에서 만든 흐름은 Deep Connector(지식)의 문서 처리 방식이 되고, 그 지식은 Deep Agent Builder(에이전트)가 검색 도구로 씁니다. 이 실습은 사내 규정용 흐름을 만들어 배포하고, 새 출장비 규정을 그 흐름으로 지식에 올린 뒤, "사내 규정 Q&A 비서" 에이전트가 새 규정을 근거로 답하는지 확인합니다. 세 제품을 잇는 전체 흐름을 한 번에 익히는 실습입니다.

이 페이지에서 할 수 있는 일

  • 규정 문서용 흐름을 만들어 Deep Connector에 배포합니다.
  • 기존 컬렉션에 문서를 올릴 때 배포한 흐름을 고릅니다.
  • Deep Agent Builder 에이전트가 Deep Connector 검색 도구로 새 문서를 찾아 답하는지 확인합니다.
순서제품하는 일
1Deep Docurator규정용 흐름을 만들고 DeepConnect 배포로 공개합니다.
2Deep Connector컬렉션에 문서를 올릴 때 그 흐름을 골라 청크와 메타데이터를 만듭니다.
3Deep Agent Builder에이전트가 Deep Connector 검색 도구(MCP)로 청크를 찾아 근거로 답합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 청킹(재귀 500자) → 메타데이터(summary, 규정항목)
결과물새 규정이 들어간 사내 규정 컬렉션, 새 규정을 근거로 든 에이전트 답변
걸리는 시간흐름 5분, 업로드·처리 2분, 에이전트 질문 1분
난이도★★★★☆

준비물​

준비물내용
출장비규정-2026.pdf2026년 12월 시행 출장비 규정(가상). 일비 4만원, 숙박비 상한, 출장 2일 전 사전 승인, 복귀 후 10일 이내 정산
Deep Connector 컬렉션업로드 권한이 있는 "사내 규정" 컬렉션
Deep Agent Builder 에이전트Deep Connector 검색 도구(MCP)가 연결된 "사내 규정 Q&A 비서". 연결 방법은 Deep Connector 매뉴얼의 외부 연동과 Deep Agent Builder 매뉴얼의 도구 페이지에 있습니다.

규정 원본은 pdf 말고도 doc, docx, hwp, hwpx, md, html, htm으로 넣을 수 있습니다. Deep Connector 업로드가 받는 형식은 Deep Connector 매뉴얼에서 확인하세요.

1단계. 규정용 흐름 만들고 배포하기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 사내 규정 조항 청킹. Deep Connector의 파이프라인 목록에 이 이름이 보입니다.
  2. 입력 → 파싱 → 청킹 → 메타데이터를 놓고 잇습니다.
  3. 아래 값으로 설정한 뒤 출장비규정-2026.pdf로 한 번 실행해 결과를 확인합니다.
  4. 파이프라인 설정에서 DeepConnect 배포를 켜고 저장합니다. 화면은 실습 4의 2단계와 같습니다.
노드설정값
청킹전략 / 최대 청크 크기 (글자 수) / 최대 목표 겹침 (글자 수)재귀 (마크다운 인식) / 500 / 50
메타데이터필드 summary(문자열)청크 내용을 한국어 한 문장으로 요약
메타데이터필드 규정항목(배열(문자열))청크에 나오는 규정 항목 이름(예: 일비, 숙박비, 정산 기한)

2단계. 사내 규정 컬렉션에 올리기​

배포한 흐름을 골라 문서 올리기

번호항목확인하거나 고를 것
1위치Deep Connector의 사내 규정 컬렉션 업로드 화면인지
2파이프라인사내 규정 조항 청킹. 처음에는 컬렉션 기본값(기본 파이프라인)이 골라져 있으므로 직접 바꿉니다.
3문서 업로드 (1)누르면 처리가 시작됩니다.
  1. Deep Connector에서 사내 규정 컬렉션을 열고 문서 업로드를 누릅니다.
  2. 파일 추가로 출장비규정-2026.pdf를 고르고 "확인이 끝났습니다. 업로드할 수 있습니다."를 기다립니다.
  3. 파이프라인을 사내 규정 조항 청킹으로 바꾸고 **문서 업로드 (1)**을 누릅니다.
  4. 문서 목록에 출장비규정-2026.pdf가 청크 1, 페이지 1로 보이면 처리가 끝난 것입니다. 예시는 1분 안에 끝났습니다.

3단계. 에이전트에게 새 규정으로 물어보기​

  1. Deep Agent Builder에서 "사내 규정 Q&A 비서"를 엽니다.

  2. 아래처럼 질문합니다.

    프롬프트: 2026년 12월부터 시행되는 출장비 규정에서 출장 정산 기한과 사전 승인 기준을 알려 주세요. 근거 문서 이름도 함께 적어 주세요.

새 규정을 근거로 든 에이전트 답변

번호항목화면에 보이는 내용확인할 것
1검색 도구 호출deep_connector_kb__search_documents, 25.2s에이전트가 Deep Connector에서 문서를 찾았는지
2답변정산 기한: 복귀 후 10일 이내, 사전 승인: 출장 2일 전까지 시스템 승인원본 규정의 값과 같은지
3근거 문서명(가상) 브레인크루 국내 출장비 규정 2026년판 (파일명: 출장비규정-2026.pdf)방금 올린 문서가 근거인지

에이전트가 옛 규정을 근거로 들면 질문에 "2026년판", "12월 시행"처럼 새 규정을 가리키는 말을 넣거나, 옛 규정 문서에 시행일 메타데이터를 붙여 구분합니다.

흔한 실수와 해결​

증상원인해결
업로드 화면의 파이프라인 목록에 흐름이 없습니다.배포 스위치를 켜고 저장하지 않았습니다.1단계 4번을 다시 하고 업로드 화면을 새로 엽니다.
기본 파이프라인으로 올라갔습니다.업로드 화면에서 파이프라인을 바꾸지 않았습니다.문서의 다시 적재에서 파이프라인을 바꿔 다시 처리합니다.
에이전트가 문서를 찾지 못한다고 답합니다.에이전트의 검색 도구가 이 컬렉션을 읽을 권한이 없거나 처리가 끝나지 않았습니다.문서 목록의 청크 수가 채워졌는지, MCP 토큰의 컬렉션 범위에 사내 규정이 있는지 확인합니다.
답이 원본과 다릅니다.청크가 조건 문장 중간에서 잘렸습니다.흐름의 청크 크기를 키우거나 전략을 바꾸고 문서를 다시 적재합니다.

응용 과제​

  1. 메타데이터의 규정항목 필드에 허용 값(일비, 숙박비, 사전 승인, 정산 기한, 교통)을 넣고 다시 적재해, Deep Connector 검색 화면의 메타데이터 필터로 쓰는지 보세요.
  2. 실습 8의 개인정보 가리기 흐름을 고객지원 컬렉션에 배포해, 에이전트 답변에 고객 이름이 나오지 않는지 확인하세요.
  3. 같은 질문을 옛 규정(출장비규정-2025.pdf)도 올린 상태에서 물어 두 규정이 섞이지 않는지 점검하세요.
