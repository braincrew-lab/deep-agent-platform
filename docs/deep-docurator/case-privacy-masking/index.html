Deep Docurator 사례: 고객 문의 기록 개인정보 가리기

브레인크루 고객지원 담당자는 그동안 쌓인 고객 문의 기록을 "자주 묻는 질문" 지식으로 쓰고 싶어 합니다. 그런데 기록에는 고객 이름, 연락처, 이메일이 들어 있습니다. 김그루 사원은 내장 프리셋 PII + 필터 정제로 개인정보를 가리고, 지식에 남길 필요가 없는 기록을 거른 뒤 결과를 확인합니다.

이 페이지에서 할 수 있는 일

  • 내장 프리셋 PII + 필터 정제로 개인정보를 가리는 플로우를 만듭니다.
  • 문의 기록 한 건이 청크 하나가 되도록 나눕니다.
  • PII 결과에서 무엇이 어떻게 가려졌는지 확인합니다.
  • 필터로 지식에 남기지 않을 기록을 뺍니다.

목표​

항목내용
하고 싶은 일상담 기록에서 개인정보를 가리고, 필요한 기록만 지식으로 남기기
결과물이름·연락처·이메일이 [NAME], [PHONE], [EMAIL]로 바뀐 청크, 거른 뒤 남은 청크
노드 조합입력 → 파싱 → 청킹(라벨 행 (권장)) → PII → 필터
걸리는 시간실행 30초 안팎, 검토 10분

준비물​

파일내용형식
고객문의기록-2026-11.csv접수일, 고객명, 연락처, 이메일, 문의 유형, 문의 내용, 처리 결과 열과 5건의 기록. 이름과 연락처는 모두 가상입니다.csv

상담 기록은 csv, xlsx 외에 txt, docx, pdf, hwp, hwpx 등으로도 넣을 수 있습니다. 실제 고객 정보로 시험하기 전에 반드시 가상 자료로 결과를 먼저 확인하세요.

1단계. 플로우 만들고 기록 넣기​

  1. 새 플로우 만들기에서 시작점 프리셋의 "내장: PII + 필터 정제"를 고릅니다. 프리셋 미리보기에 입력 → 파싱 → 청킹 → 개인정보 마스킹 → 필터가 보입니다.
  2. 이름을 "고객 문의 기록 개인정보 가리기"로 정하고 플로우 만들기를 누릅니다.
  3. 입력 노드에 고객문의기록-2026-11.csv를 넣습니다.
  4. 청킹 노드의 전략을 라벨 행 (권장)으로 바꾸고, 고급 설정의 최대 데이터 행 수를 1로 바꿉니다. 기록 한 건이 청크 하나가 됩니다.

2단계. 가릴 정보와 거를 기준 정하기​

PII 노드의 설정 탭에서 처음 값을 확인합니다.

항목처음 값이 사례에서
전략(모드 아래 첫 선택 상자)LLM (고급, 모델 호출)그대로 둡니다. 규칙 기반, 규칙 + LLM으로 바꿔 비교할 수 있습니다.
마스킹 방식토큰그대로 둡니다. 이름은 [NAME], 전화번호는 [PHONE]처럼 바뀝니다.
PII 카테고리(고급 설정)name, email, phone, ssn, credit_card, address, date_of_birth그대로 둡니다.
커스텀 정규표현식(고급 설정)비어 있음회원번호처럼 회사마다 다른 형식이 있으면 적습니다.

필터 노드의 고급 설정에서 제외 키워드에 "비밀번호"를 적습니다. 계정 비밀번호 초기화 문의는 자주 묻는 질문 지식에 넣지 않기로 했기 때문입니다.

3단계. 실행하고 결과 읽기​

▶(파이프라인 실행) 버튼을 누르면 예시에서는 10초 안팎에 끝났습니다. PII 노드를 누르고 옵션 & 미리보기 탭에서 결과를 봅니다.

개인정보를 가린 문의 기록

번호항목화면에 보이는 내용확인할 것
1필터 노드4 유지(1 제외됨)비밀번호 문의 1건이 빠졌는지
2청크 칸다섯 칸 가운데 1번째입니다.기록마다 세 곳씩 가렸는지
3가린 뒤 본문접수일: 2026-11-02 | 고객명: [NAME] | 연락처: [PHONE] | 이메일: [EMAIL] | 문의 유형: 교육 일정 …문의 내용과 처리 결과는 그대로 남았는지

PII 결과 머리에는 "5 청크 · 5 마스킹 · 15 치환"과 처리 방식, PII 카테고리가 보입니다.

청크 칸 위의 숫자 3은 그 청크에서 가린 곳의 수입니다. 칸을 누르면 아래에 가린 뒤의 본문이 열립니다.

결과물 예시​

원본 기록가린 뒤 청크
가상 고객 이름, 휴대전화 번호, 이메일 주소가 적힌 교육 일정 문의고객명: [NAME], 연락처: [PHONE], 이메일: [EMAIL], 문의 유형: 교육 일정, 처리 결과: 3월 15일 납품 예정으로 안내
계정 비밀번호 초기화 요청필터에서 제외되어 결과에 없음

검토 기준​

확인 질문검토 방법
개인정보가 모두 가려졌나요?청크마다 이름, 연락처, 이메일이 남아 있지 않은지 하나씩 열어 봅니다.
필요한 내용까지 가려지지 않았나요?문의 내용과 처리 결과의 날짜·금액이 그대로인지 봅니다. 날짜가 생년월일로 오인되어 가려질 수 있습니다.
거른 기록이 맞나요?필터 노드의 유지·제외 수와 원본 기록을 대조합니다.
문의 내용 속 개인정보도 가려졌나요?문의 내용 칸에 고객이 직접 쓴 전화번호나 주소가 있으면 가려졌는지 봅니다.

응용 팁​

  • 규칙 기반은 모델을 부르지 않아 빠르고, 전화번호·이메일처럼 형식이 정해진 정보에 강합니다. 이름처럼 형식이 없는 정보는 LLM 또는 규칙 + LLM이 잘 찾습니다. 같은 파일로 바꿔 가며 비교합니다.
  • 마스킹 방식을 별표 (***), 해시 (####), 가림 (▓▓▓)으로 바꾸면 어떤 종류의 정보였는지도 감출 수 있습니다. 지식 검색에서 "이름이 있던 자리"를 알 필요가 없으면 이 방식을 씁니다.
  • 결과를 Deep Connector에 올릴 때는 이 플로우를 DeepConnect 배포로 공개하고 업로드 파이프라인으로 고릅니다. 가린 청크만 컬렉션에 들어갑니다.
  • 가린 결과를 한 번 더 점검하려면 필터의 정규식 방식으로 "010-" 같은 패턴이 남은 청크를 찾아 봅니다.
