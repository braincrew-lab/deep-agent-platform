Deep Docurator 문제 해결

실행하기 전에 막힐 때​

증상확인할 위치와 조치다시 확인할 것
실행 버튼이 비활성화됨캔버스에 노드가 있는지, 이미 실행 중이거나 에이전트 작업 중인지 확인작업 종료 후 실행 버튼 상태
서비스 설정 누락 안내상단 안내에서 필요한 서비스와 항목을 읽고 설정으로 이동담당자가 제공한 설정으로 누락 안내가 해소되는지
파일 크기 초과입력 파일 용량 확인, 500MB를 넘으면 필요한 부분을 별도 문서로 준비새 파일명과 용량이 맞는지
연결선이 만들어지지 않음앞 노드 오른쪽 출력점에서 다음 노드 왼쪽 입력점으로 연결했는지 확인입력 → 파싱 → 청킹의 두 연결선
파일이 없는 것으로 보임입력 노드를 열고 처리할 파일을 다시 선택선택한 파일명이 표시되는지

연결할 수 없는 노드 조합은 연결이 거부될 수 있습니다. 첫 작업에서는 시작하기의 세 노드 구성으로 돌아가 확인하세요. 설정이 누락되었다고 해서 아무 연결 값이나 입력하지 말고 제공받은 계정 설정을 확인합니다.

실행 실패나 노드 오류가 나타날 때​

오류가 난 노드와 앞 단계 결과를 함께 봅니다. 파싱 오류라면 입력 파일이 맞는지와 필요한 서비스 설정을 확인합니다. 청킹 오류라면 파싱 결과가 있는지, 선택한 전략에 필요한 옵션을 넣었는지 확인합니다. 상단 또는 상태 영역의 오류 문구를 읽고 원인을 해소한 뒤 전체 파이프라인을 다시 실행하세요.

진행 중 표시가 오래 지속되거나 재연결 중으로 표시되면 같은 작업을 연속으로 시작하지 않습니다. 화면 연결 문제와 실제 처리 실패를 구분할 수 있도록 시작 시각, 문서 형식과 용량, 마지막으로 진행된 노드를 기록합니다. 중지 후 화면의 실행 표시가 사라진 것만으로 서버의 모든 처리가 취소되었다고 판단하지 마세요. 계속 상태를 알 수 없으면 담당자에게 확인합니다.

완료인데 원하는 내용이 없을 때​

  1. 입력 노드에서 실제 선택한 파일이 맞는지 확인합니다. 프리셋을 불러온 뒤에는 이번 파일을 다시 지정해야 할 수 있습니다.
  2. 파싱 결과를 열고 원본의 핵심 문장이 있는지 봅니다. 없으면 분할 크기 변경보다 파싱 입력과 설정부터 점검합니다.
  3. 청크가 목표라면 청킹 노드가 존재하고 앞 단계와 연결되어 있는지 확인합니다. 파싱만 실행한 결과에서는 청크를 기대하지 않습니다.
  4. 청킹 결과의 앞뒤 조각을 읽습니다. 문장은 있으나 조건이 끊겼다면 크기나 겹침을 하나씩 바꾸어 비교합니다.
  5. 결과 목록 일부만 보고 누락이라고 판단하지 않도록 다른 청크도 확인합니다.

완료는 처리 상태입니다. 본문의 정확성과 업무 적합성은 원본과 대조해 따로 확인합니다.

실패 상태와 결과가 다르게 보일 때​

실패로 끝난 작업은 오류 코드와 메시지를 함께 확인합니다. 실패 정보가 보이지 않거나 작업이 계속 대기 중으로 보이면 작업 ID와 발생 시각을 기록해 담당자에게 전달하세요. 실패 상태를 임의로 완료로 해석하지 않습니다.

결과 일부만 비어 있으면 전체 작업 실패로 단정하기 전에 파싱 결과, 청킹 결과, 오류 메시지를 각각 확인합니다. 저장된 결과는 단계와 실행 인스턴스별로 나뉘므로 한 결과 필드에 문제가 있어도 다른 상태 정보가 남을 수 있습니다. 화면에서 확인되는 상태와 실제 본문이 일치하지 않으면 같은 작업을 반복 실행하기보다 입력 파일, 마지막으로 성공한 단계와 결과 화면을 함께 전달하세요.

완료 목록에 표시된 작업의 상태가 실제 결과와 다르게 보이는 경우에도 목록만으로 판단하지 않습니다. 해당 작업을 열어 상태와 결과 본문을 다시 확인하고, 불일치가 지속되면 작업 ID와 확인한 항목을 문의 내용에 포함합니다.

청크 원본 미리보기가 열리지 않을 때​

청크 결과 미리보기에는 실행 결과와 입력 파일이 필요합니다. 먼저 청킹 노드에 실제 결과가 있는지 확인하세요. 원본 PDF 대조는 PDF와 대응 결과가 준비된 경우에 사용할 수 있습니다. PDF가 아닌 문서에서 같은 화면을 기대하지 말고 청크 본문과 원본을 각각 열어 비교합니다.

PDF인데도 원본을 표시할 수 없거나 입력 파일을 찾지 못했다면 현재 작업의 입력 파일을 확인합니다. 새로 열린 작업이나 다시 불러온 구성에서 파일이 빠져 있는지 살펴보세요. 무조건 새 프리셋을 만들 필요는 없습니다.

문의할 때에는 발생 시각, 사용한 문서 형식·용량, 노드 순서, 바꾼 설정과 오류 문구를 전달하세요. 인증 값이나 업무 문서의 민감한 본문은 포함하지 않습니다. 복구 후 반복 업무의 원문 보존 기준으로 결과를 다시 확인합니다.
