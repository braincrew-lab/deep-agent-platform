Deep Docurator 문제 해결

이 페이지는 Deep Docurator에서 파일이 올라가지 않거나, 실행이 실패하거나, 완료로 표시됐는데 원하는 내용이 보이지 않을 때 확인할 순서를 정리합니다.

이 페이지에서 할 수 있는 일

  • 증상별로 어디를 보고 무엇을 고칠지 찾습니다.
  • 상태 표시줄과 노드에 나오는 안내 문구의 뜻을 압니다.
  • 파싱 문제와 청킹 문제, 메타데이터 문제를 나눠 점검합니다.
  • 운영 담당자에게 문의할 때 전달할 내용을 준비합니다.

파일이 올라가지 않을 때​

증상확인할 것과 조치
파일 선택 창에 파일이 보이지 않음지원하는 20가지 확장자인지 봅니다. ppt, xlsm, json 등은 입력 노드와 지원 파일 형식의 방법대로 바꿔 저장합니다.
"파일 크기가 500MB를 초과합니다."파일을 장별로 나누거나 필요한 부분만 저장해 다시 넣습니다.
"파일 업로드 실패:" 뒤에 숫자가 보임잠시 후 다시 올립니다. 반복되면 발생 시각과 숫자를 운영 담당자에게 알립니다.
xls 파일이 파싱에서 영문 오류로 실패함xls는 처리되지 않습니다. 엑셀에서 xlsx로 다시 저장해 넣습니다.
"업로드 기록을 찾을 수 없습니다"입력 노드에서 파일을 지우고 다시 올립니다.

실행이 시작되지 않거나 바로 실패할 때​

증상확인할 것과 조치
실행 버튼이 눌리지 않음이미 실행 중이거나, 에이전트가 작업 중이거나, 캔버스에 노드가 하나도 없습니다. "에이전트 작동 중입니다. 잠시 후 시도하세요"가 보이면 에이전트 상태가 입력 대기나 대기로 바뀐 뒤 실행합니다.
"파이프라인 실행 시작 실패:"입력 노드에 파일이 있는지, 노드가 연결되어 있는지 봅니다. 그래도 반복되면 운영 담당자에게 알립니다.
상태 표시줄에 실행 실패실패 문구를 그대로 읽습니다. 입력 파일, 노드 연결, 노드 옵션 순서로 확인합니다.
청킹 노드 옵션에 빨간 안내"정수를 입력하세요." 또는 범위 안내가 보이면 값을 고칩니다. 겹침은 청크 길이보다 작아야 합니다.
메타데이터 노드에 필드 안내"추출 필드를 하나 이상 추가하세요."가 보이면 고급 설정의 추출 필드에 필드를 하나 이상 넣습니다.
라우터 노드에 연결 안내"실행 전에 이 경로의 후속 노드를 연결하세요."가 보이면 경로마다 다음 노드를 연결합니다.
"순환 연결은 만들 수 없습니다."뒤 노드에서 앞 노드로 되돌아가는 연결선을 지웁니다.

입력 노드에 파일이 없는 상태로 실행하면 실행이 실패합니다. 플로우를 새로 열었거나 프리셋으로 만든 플로우는 입력 노드가 비어 있을 수 있으니, 실행 전에 입력 노드에 파일 이름이 보이는지 먼저 확인하세요. 에이전트에게 설정 변경과 실행을 맡겼을 때도 같습니다. 아래 화면은 입력 노드가 빈 플로우에서 에이전트에게 "청킹 노드의 최대 청크 길이를 500으로 바꾸고 다시 실행해 주세요."라고 요청한 뒤의 모습입니다.

입력 파일 없이 실행한 화면

번호항목화면에 보이는 내용조치
1입력 노드"파일을 드롭하세요"와 대기가 보입니다.입력 노드에 파일을 넣습니다
2청킹 노드에이전트가 바꾼 값(청크 크기 500)이 반영돼 있습니다.값이 의도대로인지 확인합니다
3에이전트 창상태 입력 대기. 문서가 없어 실행에 실패했으니 먼저 올려 달라고 안내합니다.파일을 넣은 뒤 다시 요청합니다
4상태 표시줄의 실패 문구"실행 실패: run has no input file or no nodes to execute"입력 파일이 없거나 노드가 없다는 뜻이니 입력 노드에 파일을 넣습니다

LLM (고급, 모델 호출) 청킹 전략은 문서에 따라 "실행 실패:"로 시작하고 "Conflicting boundaries"가 들어 있는 오류로 끝날 수 있습니다. 같은 설정으로 다시 실행해도 반복되면 문장, 마크다운, 재귀 같은 다른 전략으로 바꿉니다. 예시는 회의록 표준 양식으로 정리에 있습니다.

실행 중 오래 멈춰 있을 때​

상태 표시줄에 재연결 중...이 보이면 화면과 서버의 연결이 잠시 끊긴 것입니다. 같은 작업을 다시 시작하지 말고 연결됨으로 돌아오는지 기다립니다. "재시도 대기"나 "외부 작업 완료 확인 중"이 보이면 서버가 처리를 다시 시도하는 중입니다.

모델을 부르는 노드(LLM 청킹, 메타데이터, 시맨틱 태그, 평가, 기본 설정의 PII, LLM 방식 필터)는 문서가 길수록 오래 걸립니다. 처음에는 짧은 문서로 결과를 확인한 뒤 긴 문서로 넓히세요. 멈춘 것 같으면 파이프라인 중지를 누르고, 시작 시각과 문서 형식·용량, 마지막으로 완료된 노드를 기록합니다.

완료인데 원하는 내용이 없을 때​

  1. 입력 노드에서 실제로 올린 파일이 맞는지 확인합니다. 개정 전후 파일처럼 이름이 비슷하면 잘못 고르기 쉽습니다.
  2. 파싱 노드의 블록 수와 페이지 수가 원본과 맞는지 봅니다. 쪽수가 적으면 파싱 단계에서 빠진 것입니다.
  3. Parse 결과에서 찾는 문장이나 표를 찾습니다. 없으면 청킹 값을 바꿔도 해결되지 않습니다. 스캔 문서나 이미지라면 더 선명한 원본으로 다시 넣습니다.
  4. 파싱 결과에 있는데 청크에서 찾기 어렵다면 청크 칸을 앞뒤로 넘기며 다른 청크로 넘어갔는지 봅니다.
  5. 조건이 잘렸다면 반복 업무의 비교 순서대로 최대 청크 길이나 겹침을 하나씩 바꿔 다시 실행합니다.

완료는 처리 상태일 뿐입니다. 청크 본문의 금액·기간·조건이 맞는지는 원본과 대조해 따로 확인합니다.

메타데이터 값이 비어 있거나 틀릴 때​

증상확인할 것과 조치
값이 비어 있는 청크가 많음그 청크에 해당 내용이 원래 없는지 먼저 봅니다. 조항 하나에만 있는 값은 다른 청크에서 비는 것이 정상입니다.
값이 엉뚱함필드 설명을 더 구체적으로 적습니다. 예: 금액이면 "원 단위 숫자만, 부가세 별도 금액"
값의 표현이 제각각허용 값에 고를 값을 정해 둡니다. 예: 회의비, 교통비, 사무용품
원본에 없는 내용이 섞임요약 필드는 모델이 쓴 문장입니다. 청크 본문과 대조하고, 필요하면 설명에 "원문에 있는 내용만"을 적습니다.

원본 문서 보기가 열리지 않을 때​

원본 위치 강조는 PDF에서만 동작합니다. PDF가 아닌 파일은 "원본 PDF 를 표시할 수 없습니다."와 "PDF 가 아닌 파일이거나 파일이 없습니다."가 보입니다. 이때는 원본 파일을 따로 열어 두고 블록·청크 본문과 대조합니다. PDF인데도 "input 노드의 업로드 파일을 찾지 못했습니다."가 보이면 입력 노드에 파일을 다시 넣고 실행합니다.

Deep Connector의 청크 수가 여기와 다를 때​

같은 문서인데 Deep Connector 문서 탭의 청크 수가 Deep Docurator 청킹 노드의 청크 수와 다르면, 그 문서가 어떤 파이프라인으로 처리됐는지부터 확인합니다.

  1. Deep Docurator에서 플로우의 파이프라인 설정을 열어 DeepConnect 배포가 켜져 있는지 봅니다. 꺼져 있으면 Deep Connector에서 이 플로우를 고를 수 없습니다.
  2. Deep Connector 문서 업로드에서 이 플로우를 파이프라인으로 골랐는지 봅니다.
  3. 플로우를 고친 뒤에 올린 문서인지, 고치기 전에 올린 문서인지 확인합니다.

문의할 때 전달할 내용​

  • 플로우 이름과 발생 시각
  • 입력 파일 이름, 형식, 용량
  • 상태 표시줄이나 노드에 보인 문구 그대로
  • 마지막으로 바꾼 노드와 값(예: 청킹 노드 최대 청크 길이 1000에서 500)
  • 기대한 내용과 실제로 보인 청크 번호

고객 개인정보가 들어 있는 문서 본문이나 화면은 문의에 붙이지 않습니다. 필요하면 가상 자료로 같은 증상을 다시 만들어 전달합니다.
