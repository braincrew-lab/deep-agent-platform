Deep Docurator 실습 2: 청킹 전략 비교 흐름

같은 문서라도 나누는 방식에 따라 검색 근거의 모양이 달라집니다. 이 실습은 출장비 규정 한 개를 세 가지 청킹 전략으로 동시에 나누고, 평가 노드가 매긴 점수를 전략 선택 노드에서 비교해 가장 높은 점수의 결과를 자동으로 고르는 흐름을 만듭니다. 한 노드에서 여러 노드로 갈라지는 연결과, 여러 노드가 한 노드로 모이는 연결을 함께 익힙니다.

이 페이지에서 할 수 있는 일

  • 파싱 노드 하나에서 청킹 노드 세 개로 갈라지는 흐름을 만듭니다.
  • 청킹 노드마다 다른 전략과 크기를 정합니다.
  • 평가 노드의 표본 평가 예산을 정하고 실행합니다.
  • 전략 선택 노드의 점수표로 후보를 비교합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 청킹 3개(재귀, 마크다운, 문장) → 청킹마다 평가 → 전략 선택
결과물세 전략의 청크 수와 점수표, 점수가 가장 높은 전략의 청크
걸리는 시간노드 배치 10분, 실행 20초 안팎, 확인 10분
난이도★★☆☆☆

준비물​

파일내용형식
출장비규정-2026.pdf브레인크루 국내 출장비 규정 2026년판(가상). 적용 범위, 지급 기준(일비·숙박비 표), 정산 기한 조항 1쪽pdf

조항이 있는 규정·계약서라면 무엇이든 됩니다. pdf 말고도 doc, docx, hwp, hwpx, md, html, htm, txt를 넣을 수 있습니다. 표가 중심인 xlsx, xls, csv는 실습 3의 표용 전략으로 비교하세요.

1단계. 노드 아홉 개 놓기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름 예: 출장비 규정 청킹 전략 비교.
  2. 노드 추가에서 입력, 파싱을 한 번씩, 청킹을 세 번, 평가를 세 번, 전략 선택을 한 번 누릅니다.
  3. 아래 그림처럼 왼쪽에서 오른쪽으로 입력, 파싱, 청킹 세 개(세로로 나란히), 평가 세 개(세로로 나란히), 전략 선택 순서로 배치합니다.
  4. 연결점을 끌어 다음과 같이 잇습니다. 연결은 모두 열 개입니다.
    • 입력 → 파싱
    • 파싱 → 청킹 세 개 각각(파싱 오른쪽 연결점에서 세 번 끕니다)
    • 청킹 하나 → 바로 오른쪽 평가 하나(세 쌍)
    • 평가 세 개 → 전략 선택(전략 선택 왼쪽 연결점으로 세 번 끕니다)

갈라지고 모이는 노드 배치

번호노드 묶음하는 일
1청킹 세 개같은 파싱 결과를 서로 다른 전략으로 나눕니다.
2평가 세 개청킹 결과마다 원문 보존, 제목 위치, 의미 분할을 점수로 매깁니다.
3전략 선택평가 점수를 비교해 가장 높은 후보의 청크를 다음 노드로 넘깁니다.

상태 표시줄에 노드: 9, 연결: 10이 보이면 배치가 끝난 것입니다.

2단계. 노드별 설정값 넣기​

노드설정값
청킹(위)전략 / 최대 청크 크기 (글자 수) / 최대 목표 겹침 (글자 수)재귀 (마크다운 인식) / 400 / 50
청킹(가운데)전략마크다운(나머지는 처음 값: 헤더 깊이 3)
청킹(아래)전략 / 최대 문장 수문장 / 3
평가 세 개평가 메트릭처음 값(원문 보존, Structure, 의미 기반, Statistics, Preservation)
평가 세 개의미 판정 최대 호출 수 / 의미 판정 입력·출력 추정 토큰20 / 60000
전략 선택평가 메트릭 / 동점 우선순위비워 둠 / 비워 둠

청킹 노드는 노드를 누르고 설정 탭의 전략을 바꾼 뒤 고급 설정을 펼쳐 크기를 바꿉니다.

평가 노드의 표본 평가 예산

번호항목넣을 값
1의미 판정 최대 호출 수20
2의미 판정 입력·출력 추정 토큰60000

평가 노드를 누르고 설정 탭 아래 고급 설정을 펼치면 표본 평가 묶음이 보입니다. 두 칸을 비워 두면 실행할 때 평가 노드가 실패하므로 세 평가 노드 모두에 값을 넣습니다.

3단계. 실행하고 점수 비교하기​

  1. 입력 노드에 출장비규정-2026.pdf를 넣고 ▶(파이프라인 실행)을 누릅니다. 예시는 20초 안팎에 아홉 노드가 모두 완료되었습니다.
  2. 청킹 노드의 청크 수를 읽습니다. 예시는 재귀 2 청크, 마크다운 1 청크, 문장 3 청크였습니다.
  3. 전략 선택 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

전략 선택 노드의 점수표

번호항목화면에 보이는 내용확인할 것
1베스트 전략 선정베스트: 고른 후보의 평가 노드 이름(화면에서는 흐림 처리)어느 후보가 골라졌는지
21등 후보1청크, 1.000, 체크 표시마크다운 전략 결과가 골라졌는지
32등 후보3청크, 0.611문장 전략 결과. 의미 기반 점수가 0.833으로 낮았습니다

예시 결과를 정리하면 다음과 같습니다.

전략청크 수원문 보존의미 기반종합 점수
마크다운11.0001.0001.000
문장(3문장)31.0000.8330.611
재귀(400자, 겹침 50)21.0000.7500.583

점수는 표본 평가이므로 "표본 평가 · 전체 품질 보증 아님"이 함께 표시됩니다. 1쪽짜리 짧은 규정이라 통째로 한 청크가 된 마크다운이 가장 높았지만, 규정이 길어지면 결과가 달라집니다. 점수만 보지 말고 청킹 노드의 청크 본문을 눌러 조항이 중간에 잘리지 않았는지 꼭 읽어 보세요.

흔한 실수와 해결​

증상원인해결
평가 노드 세 개가 모두 실행 실패, 전략 선택은 UpstreamFailed의미 판정 최대 호출 수와 추정 토큰이 비어 있습니다.2단계 그림처럼 두 칸에 숫자를 넣고 다시 실행합니다.
전략 선택에 후보가 하나만 보입니다.평가 노드 일부가 전략 선택에 연결되지 않았습니다.상태 표시줄의 연결 수가 10인지 확인합니다.
청킹 노드를 평가 없이 전략 선택에 바로 이었습니다.전략 선택은 평가 결과만 받습니다.청킹 → 평가 → 전략 선택 순서로 다시 잇습니다.
세 청킹 노드의 청크 수가 같습니다.전략을 바꾸지 않고 처음 값(재귀)으로 두었습니다.각 청킹 노드의 전략을 다시 확인합니다.

응용 과제​

  1. 전략 선택 뒤에 메타데이터 노드를 이어 붙이면, 골라진 전략의 청크에만 요약·키워드가 붙습니다. 내장 프리셋 Select 파이프라인 (기본)과 같은 모양이 됩니다.
  2. 아래 청킹 노드를 LLM (고급, 모델 호출) 전략으로 바꾸고 프롬프트에 "조항 하나를 청크 하나로 나누세요"라고 적어 점수를 비교해 보세요.
  3. 더 긴 문서(예: 용역계약서-교육콘텐츠-제작.pdf)로 같은 흐름을 실행해 1등 전략이 바뀌는지 보세요.
