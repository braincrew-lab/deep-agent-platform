Deep Docurator 실습 12: 영어·일본어 문서를 한국어로 찾게 하는 흐름

해외 파트너가 보낸 제품 소개서는 영어로, 도입 안내서는 일본어로 되어 있습니다. 영업본부 동료들은 "크루봇 요금"처럼 한국어로 찾고 싶어 합니다. 이 실습은 영어·일본어 문서를 그대로 읽은 뒤, 시맨틱 태그 노드로 한국어 분류(대분류·중분류)를 붙이고, 메타데이터 노드로 언어 표시와 한국어 요약, 한국어 검색어를 붙이는 흐름을 만듭니다. 원문은 바꾸지 않고 한국어 정보만 더하므로 근거를 인용할 때는 원문이 그대로 보입니다.

이 페이지에서 할 수 있는 일

  • 시맨틱 태그 노드의 대분류·중분류 목록을 한국어로 정합니다.
  • 메타데이터 노드의 허용 값으로 언어를 ko, en, ja 중 하나로 받습니다.
  • 영어 pdf와 일본어 docx를 같은 흐름에 넣어 결과를 비교합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 시맨틱 태그 → 청킹 → 메타데이터
결과물블록마다 한국어 분류 태그, 청크마다 언어(en, ja), 한국어 요약, 한국어 검색어
걸리는 시간구성 15분, 실행 30초~1분, 확인 10분
난이도★★★★☆

준비물​

파일내용형식
CrewBot-Overview-EN.pdf크루봇 영문 제품 소개(가상). 기능, 요금 표, 보안, 도입 절차 다섯 절 1쪽pdf
クルーボット導入ガイド-JA.docx크루봇 일본어 도입 안내(가상). 개요, 도입 흐름, 요금, 자주 묻는 질문 네 절docx

언어와 상관없이 입력 노드가 받는 형식(pdf, doc, docx, hwp, hwpx, pptx, xlsx, xls, txt, csv, md, html, htm, png, jpg, jpeg, tiff, tif, bmp, webp)은 같습니다. 중국어 등 다른 언어 문서도 같은 방법으로 처리하되, 언어 필드의 허용 값에 그 언어를 더합니다.

1단계. 노드 놓고 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 해외 파트너 자료 한국어 정리.
  2. 입력, 파싱, 시맨틱 태그, 청킹, 메타데이터를 놓고 이 순서로 잇습니다. 시맨틱 태그는 파싱 결과의 블록에 태그를 붙이므로 청킹보다 앞에 둡니다.

2단계. 시맨틱 태그에 한국어 분류 정하기​

시맨틱 태그 노드를 누르고 설정 탭의 어휘 영역에서 필드 추가로 값과 설명을 한 줄씩 넣습니다.

목록값설명(모델이 고르는 기준)
대분류 목록 (domain)제품소개제품이 하는 일과 주요 기능
요금요금제와 가격
보안데이터 보관, 권한, 개인정보
도입절차도입 일정과 단계, 문의
중분류 목록 (aspect)기능설명무엇을 할 수 있는지 설명
가격조건금액, 요금, 계약 조건
절차순서와 일정이 있는 진행 방법
제한사항할 수 없거나 조건이 붙는 내용

소분류 목록 (topic) — 비우면 자동은 비워 둡니다. 비우면 본문의 명사구를 그대로 뽑습니다. 나머지 고급 설정은 처음 값을 씁니다.

한국어 대분류와 중분류

번호항목화면에 보이는 내용
1시맨틱 태그 노드실행 뒤 태그 12/12 블록
2대분류 목록 (domain)제품소개, 요금, 보안, 도입절차와 설명
3중분류 목록 (aspect)기능설명, 가격조건, 절차, 제한사항과 설명

3단계. 청킹과 메타데이터 설정값​

노드설정값
청킹전략 / 최대 청크 크기 (글자 수) / 최대 목표 겹침 (글자 수)재귀 (마크다운 인식) / 800 / 100
메타데이터필드 언어문자열, 허용 값 "ko=한국어, en=영어, ja=일본어", 설명 "청크 본문의 언어"
메타데이터필드 한국어_요약문자열, "청크 내용을 한국어 두 문장으로 요약. 제품명과 금액은 원문 그대로"
메타데이터필드 한국어_키워드배열(문자열), "한국어로 검색할 때 쓸 핵심 단어 3~5개"

4단계. 영어 문서로 실행하고 결과 읽기​

  1. 입력 노드에 CrewBot-Overview-EN.pdf를 넣고 실행합니다. 예시는 첫 실행이 1분, 다시 실행하면 15~35초였습니다.
  2. 시맨틱 태그 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

영어 블록에 붙은 한국어 태그

번호항목화면에 보이는 내용확인할 것
1시맨틱 태그 노드태그 12/12 블록모든 블록에 태그가 붙었는지
2블록 태그위치: 3. Pricing, 대분류 요금, 중분류 가격조건, 아래에 Plan, Standard 같은 원문 단어절 제목과 한국어 분류가 맞는지
  1. 메타데이터 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

영어 청크에 붙은 한국어 요약

번호항목화면에 보이는 내용확인할 것
1필드별 채움 수언어 2/2, 한국어_요약 2/2, 한국어_키워드 2/2빈 값이 없는지
2청크 결과#2 언어 en, 요금제 두 가지(월 KRW 29,000, KRW 59,000)와 보안 내용을 한국어로 요약, 키워드 가격 정책 등요약 속 금액이 원문과 같은지

5단계. 일본어 문서로 다시 실행하기​

입력 파일을 クルーボット導入ガイド-JA.docx로 바꿔 다시 실행합니다. 설정은 그대로 둡니다.

일본어 문서 결과

번호항목화면에 보이는 내용
1입력 노드일본어 파일 이름
2언어 필드언어 1/1
3청크 결과언어 ja, 요금(월 29,000원, 59,000원)이 든 한국어 요약, 한국어 키워드

예시에서는 일본어 문서의 "料金" 절이 대분류 요금·중분류 가격조건으로, "導入の流れ" 절이 도입절차·절차로 분류됐습니다. 이 흐름을 실습 4처럼 배포해 Deep Connector에 올리면 한국어 질문으로 원문 근거를 찾을 수 있습니다.

흔한 실수와 해결​

증상원인해결
시맨틱 태그 노드에 "태그 0/12 블록"과 "LLM 슬롯 미수행: vocab_missing:aspect"가 보입니다.중분류 목록이 비어 있습니다.중분류 목록에 값을 한 개 이상 넣습니다. 대분류와 중분류 목록이 모두 있어야 태그가 붙습니다.
메타데이터 노드를 시맨틱 태그 바로 뒤에 이었더니 결과가 비었습니다.메타데이터는 청크를 받는 노드입니다.시맨틱 태그 → 청킹 → 메타데이터 순서로 잇습니다.
언어에 "English", "영어"처럼 다른 값이 섞입니다.허용 값을 넣지 않았습니다."ko=한국어, en=영어, ja=일본어"처럼 허용 값을 정합니다.
한국어 요약에 오타나 어색한 번역이 있습니다.모델이 번역하며 생긴 오류입니다(예시에서 "이메일"이 "이메라"로 나온 적이 있습니다).요약은 검색용으로만 쓰고, 인용과 보고에는 원문을 씁니다.
청킹 노드에 경고가 하나 보입니다.docx는 원본 위치 좌표가 없어 생기는 안내입니다.결과에는 영향이 없습니다.

응용 과제​

  1. 메타데이터에 "원문_제목"(문자열, 청크가 속한 절의 원문 제목) 필드를 더해 한국어 요약과 원문 절을 짝지어 보세요.
  2. 라우터 노드를 메타데이터 다음에 두고 언어가 ja인 문서만 다른 경로로 보내 보세요.
  3. 한국어 문서(예: 실습 2의 출장비 규정)를 넣어 언어가 ko로 나오고 분류가 어떻게 붙는지 비교해 보세요.
