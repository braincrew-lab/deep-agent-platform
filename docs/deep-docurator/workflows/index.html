Deep Docurator 반복 업무

분할 조건을 하나씩 바꾸어 비교하기​

원본은 잘 읽혔지만 청크가 너무 짧거나 서로 다른 규칙이 한 조각에 섞일 때 사용합니다. 시작하기를 마친 구성과 같은 파일로 비교하면 입력 차이와 설정 차이를 구분하기 쉽습니다.

  1. 청킹 노드의 현재 전략, 청크 크기, 청크 겹침을 작업 메모에 적습니다.
  2. 파싱 결과에서 비교하려는 문장이 존재하는지 먼저 확인합니다. 여기서 빠졌다면 분할 비교를 멈추고 파싱부터 점검합니다.
  3. 청크 결과에서 조건 문장이 끊기거나 주제가 섞인 부분을 기록합니다. 원본의 어느 문장인지도 함께 적습니다.
  4. 전략과 겹침은 유지하고 청크 크기만 바꿉니다. 예를 들어 1000에서 500으로 바꾸어 짧은 조각의 결과를 비교할 수 있습니다.
  5. 같은 파일로 파이프라인을 다시 실행하고 청크 결과를 읽습니다. 앞뒤 조각에서 대상, 행동, 시점이 함께 이해되는지 확인합니다.
  6. 필요할 때만 크기를 유지한 채 겹침을 변경해 다시 비교합니다. 한 번에 여러 값을 바꾸지 않습니다.

재실행은 앞선 결과와 비교할 새 처리를 수행하는 것이므로, 이전 결과에서 중요했던 문장과 설정값은 미리 기록해 두세요. 제품 화면이 모든 비교 이력을 자동으로 정리한다고 가정하지 않습니다. 청크 수가 줄거나 늘었다는 것만으로 품질 개선을 판단하지 마세요.

검토한 구성을 프리셋으로 저장하기​

  1. 사용할 구성과 결과 검토를 마친 뒤 상단 프리셋으로 저장을 누릅니다.
  2. 이름에 “안내문 기본 분할”처럼 용도와 문서 유형을 입력하고 저장합니다. 빈 이름으로 저장하려 하면 이름을 요구하는 안내가 표시됩니다.
  3. 왼쪽 프리셋 선택 목록을 열어 방금 저장한 이름이 있는지 확인합니다.
  4. 플로우 목록에서 새로 만들기로 별도 작업을 열고, 왼쪽 프리셋 선택 목록의 저장됨 영역에서 방금 저장한 이름을 선택합니다.
  5. 선택된 이름이 맞는지 확인하고 캔버스에 적용을 누릅니다. 저장한 프리셋은 적용 전 구성 미리보기가 표시되지 않습니다. 기존 구성을 대체한다는 확인이 나오면 적용 대상을 다시 확인합니다.
  6. 적용된 캔버스에서 입력 → 파싱 → 청킹 노드와 연결선을 확인합니다. 각 노드를 열어 서비스 설정과 청킹 옵션이 저장한 값인지 확인합니다.
  7. 입력 노드에 이번에 처리할 파일을 지정하고 파일명을 확인한 뒤 실행합니다.

프리셋을 불러온 뒤 결과가 비어 있는 것은 실행 전에는 자연스러운 상태입니다. 구성을 불러오는 일과 새 파일을 처리하는 일을 구분하세요. 파일명과 실행 후 결과를 확인해야 재사용이 완료됩니다.

반복 검토의 기준 정하기​

점검 항목확인 방법
원문 보존원본의 핵심 문장이 파싱 결과에 있는지 대조
단독 이해청크만 읽어도 대상과 조건을 이해할 수 있는지 확인
경계 품질앞뒤 조각을 읽으며 문장이나 예외 조건이 끊겼는지 확인
재사용 가능성새 파일에서도 같은 검토 기준으로 결과를 확인

문서 길이와 구성이 달라지면 같은 프리셋도 다른 결과를 만들 수 있습니다. 표가 많은 문서에 짧은 안내문용 구성을 그대로 적용한 뒤 검토를 생략하지 마세요. 활용 사례의 조건 문장 연습으로 확인 기준을 익히고, 실행 오류가 나면 문제 해결로 이동합니다.
