Deep Docurator 반복 업무

이 페이지는 Deep Docurator를 매주 쓰는 담당자가 반복하는 세 가지 일을 순서대로 정리합니다. 설정을 하나씩 바꿔 결과를 비교하고, 검토를 마친 구성을 프리셋으로 저장해 다른 문서에 쓰고, 그 구성을 Deep Connector로 보내 지식으로 씁니다.

이 페이지에서 할 수 있는 일

  • 청킹 옵션을 한 번에 하나씩 바꿔 같은 파일로 비교합니다.
  • 검토한 구성을 프리셋으로 저장하고 새 플로우에 불러옵니다.
  • 새 문서를 같은 기준으로 처리하고 결과를 점검합니다.
  • 플로우를 Deep Connector에 공개하고 적재된 청크 수를 대조합니다.

1. 설정을 하나씩 바꿔 비교하기​

원본은 잘 읽혔지만 청크가 너무 잘거나, 서로 다른 내용이 한 청크에 섞일 때 씁니다. 같은 파일로 비교해야 입력 차이와 설정 차이를 나눌 수 있습니다.

  1. 청킹 노드의 지금 전략, 최대 청크 길이, 최대 목표 겹침과 청크 수를 메모합니다. 예: 재귀 (마크다운 인식), 1000, 200, 1 청크.
  2. 파싱 결과에 비교할 문장이 있는지 먼저 봅니다. 파싱 결과에 없으면 청킹 값을 바꾸지 말고 문제 해결로 갑니다.
  3. 청킹 노드의 설정 탭에서 고급 설정을 펼치고 최대 청크 길이 (글자) 값만 바꿉니다. 예: 1000에서 400으로.
  4. ▶(파이프라인 실행) 버튼을 누르고 청크 칸을 차례로 눌러 읽습니다.
  5. 필요하면 길이는 그대로 두고 **최대 목표 겹침 (글자 수)**이나 전략만 바꿔 다시 비교합니다.
  6. 더 나은 구성이 정해지면 2절대로 프리셋으로 저장합니다.
비교 예결과
보고서 1쪽, 재귀, 최대 청크 길이 10001 청크(평균 895 자)
같은 보고서, 마크다운6 청크(장 제목마다)
계약서, 재귀, 최대 청크 길이 400, 최대 목표 겹침 504 청크(평균 271 자)

예시 값은 시작하기, 보고서 요약본 만들기, 계약서 핵심 조항 추출에서 실제로 실행한 결과입니다. 청크 수가 줄거나 늘었다는 것만으로 품질을 판단하지 말고, 청크 본문을 읽어 조건이 끊기지 않았는지 봅니다.

2. 검토한 구성을 프리셋으로 저장하고 다시 쓰기​

  1. 검토를 마친 플로우에서 위쪽 프리셋으로 저장을 누릅니다.
  2. 이름에 문서 종류와 기준을 담아 저장합니다. 예: 보고서 기본 청킹 v1, 규정 비교 항목 추출 v1.
  3. 다음 문서를 처리할 때 새 플로우 만들기에서 시작점 프리셋을 고르고 "내 프리셋: 이름"을 고릅니다. 프리셋 미리보기의 노드 아이콘과 노드 수로 구성을 확인하고 플로우 만들기를 누릅니다.
  4. 프리셋은 노드와 옵션만 담으므로, 입력 노드에 새 파일을 넣고 실행합니다.

저장 화면과 설정 화면의 프리셋 관리는 프리셋과 템플릿 플로우에 있습니다. 같은 프리셋으로 두 문서를 처리해 비교한 예시는 여러 문서 비교표 만들기에 있습니다.

3. 새 문서를 같은 기준으로 점검하기​

점검 항목확인 방법
원문 보존원본의 표 숫자와 제목이 파싱 결과에 그대로 있는지 대조합니다.
단독 이해청크 하나만 읽어도 무엇에 관한 내용인지 알 수 있는지 봅니다.
경계 품질앞뒤 청크를 이어 읽으며 조건 문장이 중간에 잘리지 않았는지 봅니다.
뽑은 값메타데이터 값을 청크 본문과 몇 건 골라 대조합니다.

문서 길이와 표 구성이 달라지면 같은 프리셋도 다른 결과를 냅니다. 짧은 안내문용 구성을 표가 많은 문서에 그대로 쓴 뒤 검토를 생략하지 마세요.

4. Deep Connector로 보내기​

검토를 마친 플로우는 Deep Connector에 문서를 올릴 때 처리 파이프라인으로 고를 수 있습니다.

  1. 편집기 위쪽 파이프라인 설정을 누르고 DeepConnect 배포를 켠 뒤 저장을 누릅니다.
  2. Deep Connector에서 컬렉션을 열고 문서 업로드의 파이프라인 목록에서 이 플로우 이름을 고릅니다.
  3. 문서를 올린 뒤 문서 탭의 청크 수가 Deep Docurator 청킹 노드의 청크 수와 같은지 비교합니다.

화면과 메뉴 설명은 결과 확인과 내보내기에 있습니다. 소유자가 system인 "기본 파이프라인"은 Deep Connector의 기본 처리에 쓰이므로 고치지 말고, 바꾸고 싶으면 새 플로우를 만들어 배포합니다.
