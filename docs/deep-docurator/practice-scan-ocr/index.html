Deep Docurator 실습 11: 스캔·사진 문서 글자 읽기 흐름

경영지원팀에는 거래처가 종이로 보낸 거래명세서를 복합기로 스캔한 파일과, 출장 중에 휴대폰으로 찍은 사진이 함께 쌓입니다. 이 실습은 이미지 파일의 글자를 파싱 노드가 읽게 한 뒤, 글자 인식에서 생긴 잘못된 쉼표를 텍스트 치환 노드로 고치고, 메타데이터 노드로 거래일, 명세서 번호, 품목, 금액을 뽑는 흐름을 만듭니다. 스캔본과 사진의 인식 차이도 함께 비교합니다.

이 페이지에서 할 수 있는 일

  • 이미지 파일(png, jpg)을 입력 노드에 넣고 파싱 결과를 원본과 대조합니다.
  • 글자 인식에서 자주 생기는 오류를 텍스트 치환 노드로 일괄 고칩니다.
  • 메타데이터 노드로 금액을 숫자 필드로 뽑습니다.
  • 스캔본과 사진의 인식 결과 차이를 확인합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 청킹 → 텍스트 치환 → 메타데이터
결과물거래명세서 한 장에서 거래일 2026-11-10, 명세서 번호, 품목 4개, 공급가액 8090000, 합계 8899000을 뽑은 결과
걸리는 시간구성 10분, 실행 30~40초, 확인 10분
난이도★★★☆☆

준비물​

파일내용형식
거래명세서-스캔.png브레인크루가 가나다물산(가상)에 보낸 거래명세서를 스캔한 이미지. 회색 바탕, 약간 기울어지고 잡음이 있음png
거래명세서-사진.jpg같은 명세서를 휴대폰으로 찍은 사진. 한쪽이 어둡고 반대로 기울어짐jpg

이미지로는 png, jpg, jpeg, tiff, tif, bmp, webp를 넣을 수 있고, 글자가 이미지로만 든 스캔 pdf도 같은 방식으로 읽힙니다. 한 파일은 500MB까지입니다. 실습에는 실제 거래처 정보와 계좌번호가 없는 가상 자료를 쓰세요.

1단계. 노드 놓고 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 거래명세서 스캔본 읽기.
  2. 입력, 파싱, 청킹, 텍스트 치환, 메타데이터를 놓고 이 순서로 잇습니다.

텍스트 치환 노드는 청크를 고치는 노드이므로 반드시 청킹 뒤에 둡니다. 파싱 바로 뒤에 이으면 실행할 때 "연결 호환 불가: … → … (text_replace)"로 실패합니다.

2단계. 파싱 결과를 원본과 대조하기​

  1. 입력 노드에 거래명세서-스캔.png를 넣고 실행합니다. 예시는 40초 안팎에 끝났습니다.
  2. 파싱 노드를 누르고 옵션 & 미리보기 탭의 Parse 결과를 엽니다.

스캔본 파싱 결과

번호항목화면에 보이는 내용확인할 것
1파싱 노드4 블록 / 1 페이지제목, 표, 아래 문장 두 줄이 블록으로 나왔는지
2블록 요약4 블록 · bbox 4개블록마다 원본 위치가 붙었는지
3원본 문서원본 이미지를 보는 화면으로 바뀝니다.표 숫자를 원본 이미지와 나란히 볼 때

표는 표 블록 하나로 읽히고 펼치기를 누르면 칸마다 값이 보입니다. 예시 스캔본에서 확인한 차이는 다음과 같습니다.

원본스캔본(png) 인식사진(jpg) 인식
5,900,0005，900，000(넓은 쉼표)5，900，000(넓은 쉼표)
크루봇 Pro 연간 구독크루봇Pro연간구독(띄어쓰기 빠짐)크루봇 Pro 연간 구독
위 금액을 영수(청구)합니다.위 금액을 명수(청구)합니다.위 금액을 영수(청구)합니다.

숫자 쉼표가 넓은 쉼표(전각 쉼표)로 읽히면 엑셀에 붙이거나 검색할 때 숫자로 인식되지 않습니다. 다음 단계에서 일괄로 고칩니다. 글자가 다른 글자로 읽힌 곳(영수 → 명수)은 규칙으로 고치기 어려우므로 원본을 다시 스캔하거나 사람이 확인합니다.

3단계. 텍스트 치환과 메타데이터 설정값​

노드설정값
청킹전략 / 최대 청크 크기 (글자 수) / 최대 목표 겹침 (글자 수)재귀 (마크다운 인식) / 2000 / 0. 명세서 한 장이 한 청크가 되게 크게 잡습니다.
텍스트 치환찾기 방식일반 문자열
텍스트 치환찾을 문자열 또는 패턴，(넓은 쉼표. 파싱 결과에서 복사해 붙입니다)
텍스트 치환바꿀 문자열,(보통 쉼표)
메타데이터필드거래일(문자열, "거래일을 YYYY-MM-DD 형식으로"), 명세서_번호(문자열, "명세서 번호를 원문 그대로"), 품목(배열(문자열), "품목 이름 목록"), 공급가액(정수, "공급가액 숫자만, 원 단위"), 합계(정수, "합계 금액 숫자만, 원 단위")

넓은 쉼표를 보통 쉼표로 바꾸는 설정

번호항목화면에 보이는 내용
1텍스트 치환 노드실행 뒤 "전체 1개 · 변경 1개 · 치환 16회 · 빈 청크 0개"
2찾기 방식일반 문자열
3찾을 문자열 또는 패턴넓은 쉼표 한 글자
4바꿀 문자열보통 쉼표 한 글자

4단계. 다시 실행하고 결과 읽기​

  1. 설정을 마치면 다시 실행합니다.
  2. 텍스트 치환 노드에 치환 16회가 보이면 표 숫자 속 넓은 쉼표 16개가 모두 보통 쉼표로 바뀐 것입니다.
  3. 메타데이터 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

거래명세서에서 뽑은 값

번호항목화면에 보이는 내용확인할 것
1텍스트 치환 노드변경 1개, 치환 16회바꾼 횟수가 원본 숫자에 든 쉼표 개수와 같은지
2필드별 채움 수거래일 1/1, 명세서_번호 1/1, 품목 1/1, 공급가액 1/1, 합계 1/1빈 필드가 없는지
3뽑은 값2026-11-10, BC-2611-0042, 품목 4개, 8090000, 8899000공급가액 + 세액 = 합계(8,090,000 + 809,000 = 8,899,000)인지

입력 파일을 거래명세서-사진.jpg로 바꿔 다시 실행하면 같은 값이 나오고, 품목 이름의 띄어쓰기는 원본과 같았습니다. 예시에서는 기울어지고 어두운 사진보다 잡음이 낀 스캔본에서 띄어쓰기와 글자 오류가 더 많았습니다.

흔한 실수와 해결​

증상원인해결
"연결 호환 불가"로 실행이 실패합니다.텍스트 치환을 파싱 바로 뒤에 이었습니다.파싱 → 청킹 → 텍스트 치환 순서로 다시 잇습니다.
치환 0회입니다.찾을 문자열에 보통 쉼표를 적었습니다.파싱 결과의 넓은 쉼표를 복사해 붙입니다.
공급가액이 비어 있습니다.숫자에 넓은 쉼표가 남아 정수로 읽히지 않았거나 타입이 문자열입니다.치환 횟수를 확인하고 타입을 정수로 둡니다.
표가 표 블록이 아니라 글 줄로 나옵니다.이미지 해상도가 낮거나 많이 기울었습니다.300dpi 이상으로 다시 스캔하고, 사진은 정면에서 찍습니다.
품목 이름이 붙어서 나옵니다.스캔 잡음으로 띄어쓰기를 놓쳤습니다.검색에는 큰 문제가 없지만 보고서에 옮길 때는 원본을 보고 고칩니다.

응용 과제​

  1. 텍스트 치환 노드를 하나 더 이어 찾기 방식을 일반 문자열로 두고 "명수(청구)"를 "영수(청구)"로 바꿔, 자주 틀리는 글자를 규칙으로 고쳐 보세요.
  2. 메타데이터 필드에 세액(정수)을 더하고, 공급가액 + 세액과 합계가 같은지 직접 계산해 보세요.
  3. 영수증 사진 여러 장을 실습 4처럼 Deep Connector에 한 번에 올리고 금액 검색이 되는지 확인해 보세요.
