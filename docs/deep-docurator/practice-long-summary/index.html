Deep Docurator 실습 9: 긴 문서 장별 요약 흐름

연말이 되면 팀마다 수십 쪽짜리 연간 보고서가 쌓입니다. 팀장은 "장마다 세 줄로, 숫자만 따로 뽑아 달라"고 합니다. 이 실습은 8쪽 분량의 연간 업무 보고서를 목차 노드로 장·절 구조부터 잡은 뒤 범용 전략으로 장 경계를 지켜 나누고, 메타데이터 노드로 장마다 요약과 핵심 수치를 붙이는 흐름을 만듭니다.

이 페이지에서 할 수 있는 일

  • 목차 노드로 긴 문서의 장·절 구조를 먼저 만듭니다.
  • 범용 전략으로 장 경계를 넘지 않게 나눕니다.
  • 메타데이터 노드로 청크마다 장 제목, 요약, 핵심 수치를 뽑습니다.
  • 결과를 원본과 대조하는 순서를 익힙니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 목차 → 청킹(범용) → 메타데이터
결과물장·절마다 나뉜 청크 12개와 청크별 장 제목, 두세 문장 요약, 핵심 수치 목록
걸리는 시간구성 10분, 첫 실행 1분 30초 안팎(모델 호출 포함), 확인 10분
난이도★★★☆☆

시작하기와 사례: 보고서 요약본 만들기는 1~2쪽짜리 문서를 내장 프리셋으로 처리했습니다. 이 실습은 쪽수가 많고 장 안에 절이 있는 문서를 다루는 점이 다릅니다.

준비물​

파일내용형식
연간보고서-2026-AI혁신팀.pdf브레인크루 AI혁신팀 2026 연간 업무 보고서(가상). 목차 쪽, 7개 장, 3장 아래 절 4개, 표 2개로 된 8쪽 문서pdf

장 제목이 "1. 개요", "3.1 영업본부"처럼 번호로 시작하는 문서면 무엇이든 됩니다. 입력 노드는 pdf, doc, docx, hwp, hwpx, pptx, xlsx, xls, txt, csv, md, html, htm, png, jpg, jpeg, tiff, tif, bmp, webp를 받습니다. 목차 노드는 제목이 있는 문서형 파일(pdf, doc, docx, hwp, hwpx, md, html, htm, txt)에서 효과가 큽니다.

1단계. 노드 다섯 개 놓고 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 연간 보고서 장별 요약.
  2. 노드 추가에서 입력, 파싱, 목차, 청킹, 메타데이터를 차례로 누릅니다. 목차는 문서 처리 영역에 있습니다.
  3. 입력 → 파싱 → 목차 → 청킹 → 메타데이터 순서로 잇습니다. 상태 표시줄에 노드: 5, 연결: 4가 보이면 됩니다.

긴 문서 요약 흐름

번호노드하는 일실행 뒤 보이는 것
1목차파싱 결과의 제목 후보를 모아 장·절 구조(목차)를 만듭니다.결과 준비됨
2청킹목차의 장 경계를 지키며 토큰 예산 안에서 나눕니다.청크 수
3메타데이터청크마다 정한 필드를 모델로 뽑습니다.필드 이름 목록과 보강 수

2단계. 목차 노드 설정​

목차 노드를 누르고 설정 탭의 처리 옵션을 봅니다.

목차 노드 처리 옵션

번호항목값이유
1LLM 제목·구조 검토사용(처음 값)본문 글자 크기만으로는 "3.1 영업본부"가 장인지 절인지 헷갈릴 수 있어, 모델이 제목의 깊이를 다시 봅니다.
2목차 구조 예시첫 줄 L1 N. <장 제목>, 둘째 줄 L2 N.N <절 제목>이 문서의 번호 모양을 알려 줍니다. 숫자는 N, 자유 문구는 꺾쇠로 감쌉니다.

검토를 끄면 처리 옵션 위 안내가 "전체 파싱 결과의 목차 페이지를 먼저 읽고, 없으면 본문 제목으로 목차를 만듭니다. LLM을 호출하지 않습니다."로 바뀝니다. 모델을 쓸 수 없는 환경에서는 끄고 실행합니다.

3단계. 청킹과 메타데이터 설정값​

노드설정값
청킹전략범용 (구조 + 토큰 예산)
청킹청크당 최대 토큰 수 / 섹션 최소 토큰 수512 / 64(처음 값)
청킹긴 섹션 의미 분할 / 표 크기 여유 비율꺼짐 / 0.1(처음 값)
메타데이터필드 1이름 장_제목, 타입 문자열, 설명 "이 청크가 속한 장 또는 절의 제목을 원문 그대로"
메타데이터필드 2이름 요약, 타입 문자열, 설명 "이 청크 내용을 두세 문장의 한국어로 요약. 원문에 없는 내용은 쓰지 않는다"
메타데이터필드 3이름 핵심_수치, 타입 배열(문자열), 설명 "청크에 나온 숫자와 그 뜻을 '항목: 값' 형식으로. 없으면 빈 배열"

메타데이터 노드의 처음 필드(title, summary, keywords, category)는 제거로 지우고 필드 추가로 위 세 개를 넣습니다. 범용 전략은 섹션 최소 토큰 수보다 짧은 절을 다음 절과 합치므로, "3. 부서별 성과"처럼 머리말만 있는 장은 다음 내용과 한 청크가 될 수 있습니다.

4단계. 실행하고 결과 읽기​

  1. 입력 노드에 연간보고서-2026-AI혁신팀.pdf를 넣고 파이프라인 실행을 누릅니다.
  2. 파싱 노드에 30 블록 / 8 페이지, 청킹 노드에 12 청크가 보이는지 확인합니다. 예시는 첫 실행이 1분 30초 안팎, 같은 파일로 다시 실행하면 10초 안쪽이었습니다.
  3. 메타데이터 노드를 누르고 옵션 & 미리보기 탭을 엽니다.

장별 요약 결과

번호항목화면에 보이는 내용확인할 것
1필드별 채움 수필드 이름 옆의 채움 수. 장_제목 12/12, 요약 12/12, 핵심_수치 12/12모든 청크에 값이 들어갔는지. 표가 든 청크에는 tables 필드가 함께 붙습니다.
2청크 결과#2 장_제목 1. 개요, 요약 두 문장, 핵심_수치 월간 사용률: 78% 등 네 개요약 속 숫자가 원본 1장의 숫자와 같은지

결과를 읽는 순서는 다음과 같습니다.

  1. #1 청크가 목차 쪽이면 장_제목이 "목차"로 나옵니다. 요약 자료에는 빼고 씁니다.
  2. 장 순서대로 장_제목이 원본 목차와 같은지 봅니다. 예시에서는 1. 개요부터 7. 2027년 계획까지 빠짐없이 나왔습니다.
  3. 핵심_수치를 원본 표와 대조합니다. 예시의 2장 청크에는 부서별 정원, 월간 사용자, 사용률 등 수치 18개가 모두 들어 있었습니다.
  4. 표 내용이 많은 청크는 요약이 표를 다 담지 못하므로, 보고에 쓸 숫자는 핵심_수치나 원본 표에서 가져옵니다.

흔한 실수와 해결​

증상원인해결
목차 노드가 실패합니다.LLM 제목·구조 검토 요청이 하나라도 실패하면 노드가 실패합니다.검토를 끄고 다시 실행합니다.
장_제목에 절 제목이 아니라 장 제목만 나옵니다.목차 구조 예시에 L2 줄이 없습니다.둘째 줄에 L2 N.N <절 제목>을 넣습니다.
청킹 노드 머리글에 전략 이름이 Chunk.Strategy.Universal로 보입니다.범용 전략의 노드 표시 이름이 번역되지 않은 화면입니다.설정 탭의 전략이 범용 (구조 + 토큰 예산)이면 정상입니다.
요약에 원본에 없는 평가 문장이 섞입니다.필드 설명이 짧아 모델이 해석을 덧붙였습니다.설명에 "원문에 없는 내용은 쓰지 않는다"를 넣습니다.
청크가 한두 개만 나옵니다.전략이 재귀이고 최대 청크 크기가 큽니다.범용 전략으로 바꾸거나 청킹 전략과 옵션에서 크기를 줄여 비교합니다.

응용 과제​

  1. 메타데이터에 "후속_조치"(배열(문자열), 장에서 해야 할 일로 적힌 문장) 필드를 더해 6장 문제점과 7장 계획에서 할 일 목록을 뽑아 보세요.
  2. 목차 노드 다음에 시맨틱 태그 노드를 넣고 대분류를 "성과, 비용, 교육, 계획"으로 정해 장마다 주제 태그를 붙여 보세요.
  3. 이 흐름을 프리셋 "연간 보고서 장별 요약 v1"로 저장하고 다른 팀의 보고서에 그대로 써 보세요(실습 5).
