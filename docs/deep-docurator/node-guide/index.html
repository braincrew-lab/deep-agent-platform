Deep Docurator 노드 안내

편집기의 노드 추가를 누르면 노드 목록이 열립니다. 목록은 문서 처리와 가공 및 검증 두 묶음으로 나뉘고, 아래쪽에 프리셋 영역이 있습니다. 이 페이지는 노드마다 하는 일, 주로 놓는 위치, 화면에서 바꾸는 옵션을 정리합니다.

이 페이지에서 할 수 있는 일

  • 노드 추가 패널에서 노드를 캔버스에 놓고 연결합니다.
  • 문서 처리 노드 7개와 가공 및 검증 노드 7개가 각각 무슨 일을 하는지 압니다.
  • 모델을 호출하는 노드와 호출하지 않는 노드를 구별합니다.
  • 업무 목적에 맞는 노드 조합을 고릅니다.

노드 추가 패널​

노드 추가 패널

번호메뉴기능이런 때 사용하세요
1청킹문서 처리 영역의 노드입니다. 누르면 캔버스에 추가되고, 끌어 놓으면 놓은 자리에 추가됩니다.파싱 다음 단계로 나누기를 넣을 때
2메타데이터청크마다 정한 필드를 뽑는 노드입니다.요약·금액·기한 같은 값을 붙일 때
3PII가공 및 검증 영역의 노드입니다. 개인정보를 가립니다.고객 정보가 섞인 문서를 처리할 때
4프리셋 선택 상자캔버스에 적용할 프리셋을 고릅니다. 아래 프리셋 미리보기와 캔버스에 적용으로 이어집니다. 지금 캔버스는 대체됩니다.저장한 구성을 한 번에 넣을 때

패널 맨 위에는 "클릭하여 추가하거나 캔버스로 끌어 놓으세요."라는 안내가 있고, 오른쪽 위 X로 패널을 닫습니다. 내가 저장한 프리셋은 프리셋 선택 상자의 커스텀 아래에 있습니다.

노드를 놓고 연결하는 법​

  1. 편집기 오른쪽 위 노드 추가를 누릅니다. 패널에 "클릭하여 추가하거나 캔버스로 끌어 놓으세요."가 보입니다.
  2. 노드 이름을 누르면 캔버스에 추가되고, 끌어 놓으면 놓은 자리에 추가됩니다.
  3. 앞 노드 오른쪽의 연결점에서 다음 노드 왼쪽 연결점으로 끌어 연결선을 만듭니다.
  4. 노드를 누르면 오른쪽 작업 사이드바에서 설정, 옵션 & 미리보기, 출력 스레드, YAML 탭으로 옵션과 결과를 봅니다.
  5. 필요 없는 노드는 작업 사이드바 아래 노드 삭제로 지웁니다.

연결선은 앞에서 뒤로 한 방향으로만 이어집니다. 노드를 되돌아 잇는 순환 연결을 만들면 "순환 연결은 만들 수 없습니다."가 표시됩니다.

문서 처리 노드​

문서를 읽고 나누고 항목을 붙이는 노드입니다. 대부분의 플로우는 이 묶음만으로 만듭니다.

노드하는 일주로 놓는 위치모델 호출
입력처리할 파일 한 개를 받습니다.맨 앞없음
파싱PDF, HWP, 이미지 등에서 제목·본문·표를 읽어 블록으로 만듭니다. 프로바이더는 Brain Parser입니다.입력 다음문서 분석기 사용
목차문서의 목차 페이지를 먼저 읽고, 없으면 본문 제목으로 목차 구조를 만듭니다. 조항·장 구조가 있는 문서에 씁니다.파싱 다음LLM 제목·구조 검토를 켜면 호출
시맨틱 태그조각마다 대분류·중분류·소분류 태그를 붙입니다. 내가 적은 목록 안에서만 고릅니다.파싱 또는 목차 다음호출
청킹파싱 결과를 전략과 크기에 맞춰 청크로 나눕니다.파싱 다음LLM 전략과 일부 옵션에서 호출
전략 선택여러 청킹 결과의 평가 점수를 비교해 점수가 가장 높은 전략의 청크를 채택합니다.여러 청킹·평가 노드 다음없음(평가 노드 점수 사용)
메타데이터내가 정한 필드(요약, 금액, 기한 등)를 청크마다 뽑아 붙입니다.청킹 다음호출

목차​

LLM 제목·구조 검토는 처음에 켜져 있고, 제목 후보를 모델로 다듬습니다. 모델 요청이 실패하면 대부분 규칙으로 만든 목차를 쓰고 경고를 남기지만, 일부 실패는 노드 실패로 끝납니다. 모델을 쓸 수 없는 환경이라면 꺼서 불필요한 요청을 줄입니다. 검토를 켜 두면 목차 구조 예시 칸이 보입니다. 여기에 "L1 계약서 제목", "L2 제N조 조항 제목"처럼 한 줄에 하나씩 문서의 단계 구조를 적어 주면 그 모양에 맞춰 목차를 만듭니다.

시맨틱 태그​

대분류·중분류·소분류 목록에 이 문서 묶음에서 쓸 값을 모두 적습니다. 값마다 설명을 적으면 모델이 그 설명을 기준으로 고릅니다. 조각마다 대분류는 한 개, 중분류와 소분류는 여러 개 붙을 수 있고, 목록에 없는 값은 붙지 않습니다. 소분류 목록을 비우면 자동으로 정합니다. 붙은 태그는 검색할 때 범위를 좁히는 데 쓰입니다.

메타데이터​

설정 탭에서 고급 설정을 펼치면 추출 필드 아래 필드에서 뽑을 항목을 정합니다. 처음에는 title(제목), summary(요약), keywords(키워드), category(분류) 네 필드가 들어 있고, 필드를 더하거나 지울 수 있습니다.

항목뜻
필드 이름결과에 쓰일 항목 이름입니다. 예: 지급기한, 계약금액
타입문자열, 숫자, 정수, 불리언, 배열(문자열) 등 값의 형식입니다.
설명모델이 무엇을 뽑아야 하는지 적는 기준입니다. 구체적으로 적을수록 결과가 안정됩니다.
허용 값고를 수 있는 값 목록입니다. 비우면 자유 값이 되어 검색 필터에는 쓰이지 않습니다. 숫자·불리언 필드에 허용 값을 넣으면 실행이 실패합니다.

허용 값에 설명이 없으면 "허용값 N개에 설명이 없습니다"라는 안내와 함께 에이전트가 채우기가 보입니다. 누르면 편집기 에이전트가 각 허용 값에 한 줄 설명을 붙입니다. 에이전트 대화가 먼저 시작되어 있어야 합니다. 필드가 하나도 없으면 "추출 필드를 하나 이상 추가하세요."가 표시되고 실행할 수 없습니다. 배치 모드, 배치당 최대 항목 수(기본 30), 문서 구조(선택·필수)는 한 번에 모델에 보내는 양과 목차 정보 사용 여부를 정합니다. 처음에는 기본값으로 둡니다.

메타데이터는 청크마다 값을 하나씩 뽑습니다. 문서 전체를 한 문단으로 요약한 결과가 따로 만들어지지는 않으므로, 문서 단위 요약이 필요하면 청크별 요약을 이어 읽거나 청크 크기를 키워 비교합니다.

가공 및 검증 노드​

청크를 다듬거나 거르고, 품질을 점검하는 노드입니다.

노드하는 일주로 놓는 위치모델 호출
라우터문서 전체를 한 번 분류해, 조건에 맞는 경로 하나로 결과를 넘깁니다.파싱 다음, 경로마다 다른 노드 앞LLM 방식에서 호출
PII이름, 이메일, 전화번호, 주민등록번호, 카드번호, 주소, 생년월일 같은 개인정보를 찾아 가립니다.청킹 다음규칙 기반은 없음, LLM 방식은 호출
필터조건에 맞는 청크만 남기거나 지웁니다.청킹 또는 PII 다음LLM 방식에서 호출
텍스트 치환청크 수·순서·페이지는 그대로 두고 본문의 글자만 바꿉니다.메타데이터 앞없음
커스텀자연어로 설명하면 코드가 만들어져 청크를 가공합니다.필요한 위치코드를 만들 때만 호출
평가원문 누락과 최대 길이 초과를 점검하고, 의미 분할·추출 가능성·보존을 점수로 보여 줍니다.청킹 다음, 전략 선택 앞의미·원문 보존 판정에서 호출
메타데이터 평가뽑은 메타데이터를 표본 청크로 확인해 필드별 정확도와 채움률을 남깁니다. 청크는 그대로 통과합니다.메타데이터 다음호출

라우터​

분류 방식에서 규칙 또는 LLM을 고르고, 경로 추가로 경로를 만듭니다. LLM 방식에서는 경로마다 이 경로로 분류할 기준을 문장으로 적고, 규칙 방식에서는 조건 추가로 비교할 항목과 값을 정합니다. 위에서부터 검사해 처음 맞는 경로 하나를 고르며, 맞는 경로가 없으면 기본 경로로 갑니다. 경로마다 후속 노드를 연결해야 실행할 수 있습니다. 예를 들어 계약서와 견적서가 섞여 들어올 때, 계약서는 조항 단위로 나누고 견적서는 표 단위로 나누도록 경로를 가를 수 있습니다.

PII​

맨 위 선택 상자에서 찾는 방식을 규칙 기반, 규칙 + LLM, LLM 중에서 고릅니다. 처음 값은 LLM입니다. 마스킹 방식은 토큰, 별표 (***), 해시 (####), 가림 (▓▓▓) 중에서 고릅니다. PII 카테고리로 찾을 종류를 정하고, 커스텀 정규표현식으로 사번처럼 회사마다 다른 형식을 더할 수 있습니다. 카테고리와 정규표현식 같은 세부 옵션은 고급 설정을 펼치면 보입니다.

필터​

맨 위 선택 상자에서 거르는 방식을 고릅니다. 규칙 기반은 최소 길이, 최대 길이, 필수 키워드, 제외 키워드로 거릅니다. 정규식은 정규식 패턴과 매칭 정책으로 거릅니다. LLM 방식은 "업무와 관련된 내용만 유지"처럼 필터 기준을 문장으로 적고, 유지 정책에서 일치 청크 유지 또는 일치 청크 제거를 고릅니다. 이 옵션들은 고급 설정을 펼치면 보입니다.

커스텀​

옵션 & 미리보기 탭에서 **입력 스레드 (코드가 읽는 것)**와 **출력 스레드 (코드가 쓰는 것)**를 먼저 고릅니다. 그다음 자연어로 설명을 고르고 변환 의도 (자연어) 칸에 하고 싶은 가공을 적은 뒤 이 노드 실행을 누르면, 코딩 모델이 만든 코드가 코드 쪽에 들어가 청크를 가공합니다. 이후 실행할 때에는 모델을 부르지 않고 만들어진 코드만 돌아갑니다. 표만 추출, 짧은 청크 제거, 중복 제거, 공백 정리 같은 빠른 시작 예시를 고를 수 있고, 코드·선언 저장으로 저장합니다. 코드는 파일·네트워크에 접근하지 않는 순수한 데이터 변환만 할 수 있습니다.

목적별 노드 조합​

하고 싶은 일노드 조합참고
문서를 검색용 조각으로 나누기입력 → 파싱 → 청킹시작하기
조항별로 핵심 항목 뽑기입력 → 파싱 → 청킹 → 메타데이터이 페이지의 메타데이터
표를 행 단위로 정리하기입력 → 파싱 → 청킹(표용 전략) → 메타데이터청킹 전략과 옵션의 표용 전략
장별 요약 만들기입력 → 파싱 → 청킹 → 메타데이터(요약 필드)이 페이지의 메타데이터
개인정보를 가린 뒤 쓰기입력 → 파싱 → 청킹 → PII → 필터프리셋과 템플릿 플로우의 PII + 필터 정제
나누는 방식을 자동으로 고르기입력 → 파싱 → 여러 청킹 → 평가 → 전략 선택 → 메타데이터프리셋과 템플릿 플로우의 Select 파이프라인
