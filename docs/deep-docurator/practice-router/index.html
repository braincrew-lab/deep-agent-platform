Deep Docurator 실습 7: 조건 분기 흐름 만들기

부서 공유 폴더에는 규정 문서와 엑셀 표가 섞여 있습니다. 표는 행 하나씩, 문서는 글자 수 단위로 나눠야 검색이 잘 됩니다. 이 실습은 라우터 노드로 파일 확장자를 보고 경로를 갈라, 표 파일은 라벨 행 전략으로, 그 밖의 문서는 재귀 전략으로 나누는 흐름을 만듭니다. 이렇게 만든 흐름 하나를 실습 4처럼 배포하면 섞인 파일을 한 번에 올려도 종류별로 알맞게 처리됩니다.

이 페이지에서 할 수 있는 일

  • 라우터 노드에 경로 두 개와 규칙 조건을 정합니다.
  • 경로마다 다른 후속 노드를 연결합니다.
  • 실행 뒤 어느 경로가 골라졌는지 확인합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 라우터 → (표 자료) 청킹(라벨 행) / (일반 문서) 청킹(재귀 500자)
결과물csv는 표 자료 경로로 20 청크, 다른 문서는 일반 문서 경로로 처리되는 흐름
걸리는 시간구성 10분, 실행 20초 안팎
난이도★★★☆☆

준비물​

파일내용형식
영수증_견적_모음.csv10월 영수증·견적 20행 표csv
출장비규정-2026.pdf출장비 규정 1쪽pdf

표 경로 조건에는 csv와 xlsx를 넣습니다. xls는 파싱되지 않으므로 xlsx로 저장해 씁니다. 일반 문서 경로는 pdf, doc, docx, hwp, hwpx, pptx, txt, md, html, htm, png, jpg, jpeg, tiff, tif, bmp, webp 등 그 밖의 형식을 모두 받습니다.

1단계. 노드 놓고 경로별로 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 자료 종류별 나누기 분기.
  2. 입력, 파싱, 라우터, 청킹 두 개를 놓습니다. 라우터는 노드 추가 패널의 가공 및 검증 영역에 있습니다.
  3. 입력 → 파싱 → 라우터 순서로 잇습니다. 라우터에는 앞 노드 하나만 연결할 수 있습니다.
  4. 라우터를 누르고 2단계대로 경로를 만든 뒤, 각 경로의 후속 노드에서 청킹 노드를 하나씩 고릅니다. 캔버스에서는 라우터 오른쪽에 경로마다 생긴 연결점에서 청킹 노드로 선을 끌어도 됩니다.

경로 두 개로 갈라지는 흐름

번호노드화면에 보이는 내용
1라우터경로 이름 표 자료, 일반 문서와 기본 경로 표시
2청킹(위)표 자료 경로의 후속 노드. 라벨 행 (권장), 실행 뒤 20 청크
3청킹(아래)일반 문서 경로의 후속 노드. 재귀 (마크다운 인식), 이번 실행에서는 골라지지 않아 데이터 없음

2단계. 경로와 조건 정하기​

라우터의 설정 탭 아래 분기 설정에서 정합니다.

항목값
분류 방식규칙
경로 1 이름표 자료(처음 이름 "경로 1"을 누르고 고칩니다)
경로 1 조건 결합하나 이상 만족 (OR)
경로 1 조건 1입력 필드: 파싱 › 파일 확장자, 비교 방식: 같음, 비교 값: csv
경로 1 조건 2조건 추가 뒤 입력 필드: 파싱 › 파일 확장자, 같음, xlsx
경로 2 이름일반 문서(처음 이름 "기타"). 이 경로가 기본 경로입니다.

라우터 경로 조건

번호항목하는 일
1후속 노드이 경로로 갈 다음 노드입니다. 표 자료 경로는 위 청킹 노드를 고릅니다.
2조건 결합하나 이상 만족 (OR)이면 조건 중 하나만 맞아도 이 경로를 고릅니다.
3조건판정할 값(파일 확장자), 비교 방식(같음), 비교 값(csv)입니다. × 로 조건을 지웁니다.

경로는 위에서부터 검사해 처음 맞는 하나를 고르고, 맞는 경로가 없으면 기본 경로로 갑니다. 화살표(↑↓)로 우선순위를 바꿉니다.

3단계. 노드별 설정값과 실행​

노드설정값
청킹(표 자료)전략 / 최대 데이터 행 수라벨 행 (권장) / 1
청킹(일반 문서)전략 / 최대 청크 크기 (글자 수) / 최대 목표 겹침 (글자 수)재귀 (마크다운 인식) / 500 / 50
  1. 입력 노드에 영수증_견적_모음.csv를 넣고 실행합니다.
  2. 라우터 노드를 누르면 분기 설정 위에 "선택된 경로: 표 자료"가 보입니다. 위 청킹 노드에 20 청크가 생기고, 아래 청킹 노드는 실행되지 않습니다.
  3. 입력 파일을 출장비규정-2026.pdf로 바꿔 다시 실행합니다. 예시는 20초 안팎에 끝났고, 일반 문서 경로가 골라져 아래 청킹 노드에 1 청크가 생겼습니다. 위 청킹 노드는 실행되지 않고 "준비됨"으로 남습니다.

pdf를 넣었을 때 고른 경로

번호항목화면에 보이는 내용확인할 것
1선택된 경로선택된 경로: 일반 문서, no_match표 자료 조건(csv, xlsx)에 맞지 않아 기본 경로로 갔다는 뜻입니다. csv를 넣었을 때는 rule_match가 보입니다.
2일반 문서 경로기본 경로 표시와 후속 노드(청킹)이 경로의 청킹 노드에만 청크가 생겼는지

흔한 실수와 해결​

증상원인해결
"실행 전에 이 경로의 후속 노드를 연결하세요."가 보입니다.경로 하나에 다음 노드가 없습니다.모든 경로(기본 경로 포함)에 후속 노드를 하나씩 고릅니다.
"여러 노드에 연결되어 있습니다."가 보입니다.한 경로에 노드를 두 개 이었습니다.경로마다 노드 하나만 남깁니다.
"Router에는 상위 결과 하나만 연결할 수 있습니다."가 보입니다.라우터 앞에 노드를 두 개 이었습니다.앞 노드 하나만 남깁니다.
csv인데 일반 문서 경로로 갑니다.비교 값에 점을 붙였거나(.csv) 대문자로 적었습니다.비교 값을 csv처럼 점 없이 소문자로 적습니다.
조건을 둘 다 넣었는데 아무것도 맞지 않습니다.조건 결합이 모든 조건 만족 (AND)입니다.하나 이상 만족 (OR)으로 바꿉니다.

응용 과제​

  1. 분류 방식을 LLM으로 바꾸고, 경로마다 이 경로로 분류할 기준에 "계약서", "회의록"처럼 문장을 적어 내용으로 갈라 보세요. 분류에 사용할 입력에 파싱 › 본문을 추가해야 합니다.
  2. 일반 문서 경로 뒤에 메타데이터 노드를, 표 자료 경로 뒤에 실습 3의 필드 추출 메타데이터 노드를 이어 경로별로 다른 필드를 뽑아 보세요.
  3. 이 흐름을 배포하고 Deep Connector에 csv와 pdf를 한 번에 올려 문서별 청크 수를 비교해 보세요.
