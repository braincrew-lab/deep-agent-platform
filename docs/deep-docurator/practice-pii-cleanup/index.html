Deep Docurator 실습 8: 개인정보 가리기와 텍스트 치환 연쇄

가공 노드는 여러 개를 이어 붙이면 앞에서부터 순서대로 적용됩니다. 이 실습은 고객 문의 기록을 규칙 기반으로 가리고, 텍스트 치환 노드 두 개로 날짜 표기와 용어를 바꾼 뒤, 필터로 환불·견적 문의만 남기는 다섯 단계 연쇄 흐름을 만듭니다. 고객 문의 기록 개인정보 가리기 사례가 내장 프리셋과 모델(LLM) 탐지를 쓴다면, 이 실습은 모델을 부르지 않는 규칙 기반 탐지와 커스텀 정규표현식, 텍스트 치환 연쇄를 직접 구성합니다.

이 페이지에서 할 수 있는 일

  • PII 노드를 규칙 기반으로 바꾸고 커스텀 정규표현식으로 빠진 항목을 더 가립니다.
  • 텍스트 치환 노드를 두 개 이어 정규식 치환과 일반 문자열 치환을 순서대로 적용합니다.
  • 필터 노드의 정규식으로 남길 청크를 고릅니다.
  • 노드마다 결과 요약 숫자로 연쇄가 제대로 돌았는지 확인합니다.

목표​

항목내용
만들 흐름입력 → 파싱 → 청킹(라벨 행) → PII(규칙 기반) → 텍스트 치환(날짜) → 텍스트 치환(용어) → 필터(정규식)
결과물이름·연락처·이메일이 ▓▓▓로 가려지고, 날짜가 "2026년 11월 03일", "처리 결과"가 "답변"으로 바뀐 환불·견적 문의 2건
걸리는 시간구성 15분, 실행 20초 안팎
난이도★★★★☆

준비물​

파일내용형식
고객문의기록-2026-11.csv접수일, 고객명, 연락처, 이메일, 문의 유형, 문의 내용, 처리 결과 열과 가상 기록 5건csv

상담 기록이 문서 형태라면 pdf, doc, docx, hwp, hwpx, txt, md, html, htm으로도 넣을 수 있습니다. 이때는 청킹 전략을 문장이나 재귀로 바꿉니다.

1단계. 노드 일곱 개를 한 줄로 잇기​

  1. 빈 캔버스로 새 플로우를 만듭니다. 이름: 문의 기록 정리 연쇄.
  2. 입력, 파싱, 청킹, PII, 텍스트 치환, 텍스트 치환, 필터를 차례로 놓고 왼쪽에서 오른쪽으로 잇습니다. 상태 표시줄에 노드: 7, 연결: 6이 보입니다.
  3. 입력 노드에 고객문의기록-2026-11.csv를 넣습니다.

가공 노드 연쇄

번호노드실행 뒤 보이는 내용
1PII5 청크 · 5 마스킹
2텍스트 치환 두 개각각 전체 5개 · 변경 5개 · 치환 5회 · 빈 청크 0개
3필터2 유지 (3 제외됨)

2단계. 노드별 설정값 넣기​

노드설정값
청킹전략 / 최대 데이터 행 수라벨 행 (권장) / 1(기록 한 건이 청크 하나)
PII전략규칙 기반
PII마스킹 방식가림 (▓▓▓)
PIIPII 카테고리(고급 설정)name, email, phone
PII커스텀 정규표현식(고급 설정)(?<=고객명: )[가-힣]{2,4}
텍스트 치환 1찾기 방식 / 찾을 문자열 또는 패턴 / 바꿀 문자열정규식 / (\d{4})-(\d{2})-(\d{2}) / \g<1>년 \g<2>월 \g<3>일
텍스트 치환 2찾기 방식 / 찾을 문자열 또는 패턴 / 바꿀 문자열일반 문자열 / 처리 결과 / 답변
필터전략 / 정규식 패턴 / 매칭 정책정규식 / 환불|견적 / 일치 청크 유지

필터의 정규식 패턴은 환불, 세로 막대, 견적을 붙여 적습니다. 세로 막대는 "또는"이라는 뜻입니다.

규칙 기반 탐지는 모델을 부르지 않고 정해진 형식(전화번호, 이메일 등)만 찾습니다. 이 실습 환경에서는 커스텀 정규표현식 없이 실행했을 때 연락처와 이메일은 가려졌지만 "고객명: 이가상"의 이름은 그대로 남았습니다. 그래서 "고객명: " 바로 뒤의 한글 두~네 글자를 가리는 정규식을 더했습니다.

3단계. 실행하고 결과 읽기​

  1. ▶(파이프라인 실행)을 누릅니다. 예시는 20초 안팎에 일곱 노드가 모두 완료되었습니다.
  2. PII 노드의 옵션 & 미리보기에서 "5 청크 · 5 마스킹 · 15 치환"을 확인합니다. 기록마다 이름, 연락처, 이메일 세 곳이 바뀌었다는 뜻입니다.
  3. 두 번째 텍스트 치환 노드를 누르고 옵션 & 미리보기에서 청크 칸을 눌러 본문을 읽습니다.

연쇄 처리 뒤 청크 본문

번호항목화면에 보이는 내용확인할 것
1치환 요약전체 5개 · 변경 5개 · 치환 5회 · 빈 청크 0개모든 기록에서 한 번씩 바뀌었는지
2청크 칸다섯 칸 가운데 2번째견적 문의 기록을 골랐는지
3청크 본문접수일: 2026년 11월 03일 | 고객명: ▓▓▓ | 연락처: ▓▓▓ | 이메일: ▓▓▓ | 문의 유형: 견적 | … | 답변: 견적서 재발행 후 메일 발송날짜와 용어가 바뀌고 개인정보가 가려졌는지

마지막 필터 노드는 "5 → 2 유지 / 3 제외됨"으로, 환불 문의와 견적 문의 두 건만 다음 단계(예: Deep Connector)로 넘깁니다.

흔한 실수와 해결​

증상원인해결
이름이 가려지지 않습니다.규칙 기반은 이름처럼 형식이 일정하지 않은 값을 놓칠 수 있습니다.커스텀 정규표현식을 더하거나 전략을 규칙 + LLM으로 바꿉니다.
정규식 치환 결과에 \g<1>이 그대로 나옵니다.찾기 방식이 일반 문자열입니다.정규식으로 바꿉니다.
두 번째 치환이 아무것도 바꾸지 않습니다.앞 노드가 이미 글자를 바꿔 찾을 문자열이 없어졌습니다.연쇄 순서를 바꾸거나 찾을 문자열을 앞 노드의 결과에 맞춥니다.
정규식 오류로 실행이 멈춥니다.정규식을 /로 감쌌거나 괄호 짝이 맞지 않습니다./ 없이 적고 괄호를 확인합니다.
필터 뒤 청크가 0개입니다.매칭 정책이 일치 청크 제거입니다.일치 청크 유지로 바꿉니다.

응용 과제​

  1. 마스킹 방식을 토큰으로 바꿔 ▓▓▓ 대신 [EMAIL], [PHONE], [CUSTOM]이 들어가는지 보세요.
  2. 필터를 LLM (고급, 모델 호출)으로 바꾸고 필터 기준에 "고객이 금전 처리를 요청한 문의만"을 적어 결과를 비교하세요.
  3. 이 흐름을 배포해 고객지원 컬렉션에 올리고, 실습 6처럼 에이전트 답변에 개인정보가 나오지 않는지 확인하세요.
