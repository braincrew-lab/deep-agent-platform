Deep Connector 관리자: 검색과 AI

관리자 사이드바 검색과 AI 묶음은 검색 품질과 AI 기능을 회사 단위로 맞추는 화면입니다. 용어 사전, 메타데이터 관리, 컬렉션 태그, LLM 커넥션, MCP 도구, 도구 평가 여섯 메뉴가 있습니다. 이 페이지는 AI혁신팀 강혁신 팀장(Deep Connector 관리자)이 사내 용어를 검색에 반영하고, 언어 모델을 연결하고, 에이전트가 쓰는 검색 도구를 점검하는 순서로 설명합니다.

이 페이지에서 할 수 있는 일

  • 용어 사전과 전사 용어사전을 만들어 줄임말·동의어로도 검색되게 합니다.
  • 문서에서 뽑힌 메타데이터 항목과 값을 확인하고 정리합니다.
  • 여러 컬렉션에 태그를 한꺼번에 붙입니다.
  • 질의 재작성과 AI 답변에 쓸 언어 모델 연결(LLM 커넥션)을 만듭니다.
  • 에이전트에 제공하는 검색 도구의 설명을 고치고, 도구 호출 품질을 점검합니다.

메뉴 구성​

검색과 AI 묶음

번호메뉴기능이런 때 사용하세요
1용어 사전·메타데이터 관리·컬렉션 태그검색어 확장 사전, 문서 메타데이터 항목, 컬렉션 태그를 관리합니다.검색에 쓰이는 낱말과 분류를 정리할 때
2LLM 커넥션팀스페이스별로 언어 모델 접속 정보를 등록합니다.컬렉션에서 AI 답변을 켜기 전에
3MCP 도구·도구 평가에이전트에 제공하는 검색 도구의 설명과 호출 품질을 관리합니다.에이전트가 근거를 잘 못 찾을 때

용어 사전​

검색과 AI > 용어 사전은 동의어·코드·별칭을 하나의 항목으로 묶어 검색어를 넓히는 사전 목록입니다. 사전을 만든 뒤 컬렉션 설정의 연결된 사전에서 컬렉션에 연결하면, 키워드 검색에서 "법카"로 "법인카드"까지 찾습니다.

용어 사전 목록

번호메뉴기능이런 때 사용하세요
1새 사전새 용어 사전을 만듭니다.부서 전용 용어를 따로 관리할 때
2커스텀 사전 행관리자가 만든 사전입니다. 종류(커스텀), 버전, 항목 수가 보입니다. 행을 누르면 사전 상세가 열립니다.사전 내용을 고칠 때
3전사 용어사전 행회사 전체 용어를 모은 표준 사전입니다(포탈 원장). 행을 누르면 전사 용어사전 화면이 열립니다.회사 공통 용어를 등록할 때
4상태 스위치사전을 쓰거나 끕니다. 끄면 연결된 컬렉션에서도 검색어 확장에 쓰이지 않습니다.잘못 들어간 용어 때문에 검색이 어긋날 때 잠시 끌 때

새 사전을 누르면 이름과 종류를 정하는 창이 열립니다.

새 사전 만들기 창

번호메뉴기능이런 때 사용하세요
1이름사전 이름입니다."브레인크루 사내 용어"처럼 범위가 드러나게 지을 때
2종류사전 종류입니다. 관리자가 만드는 사전은 커스텀입니다.–
3만들기사전을 만듭니다. 만든 뒤 행을 눌러 용어를 넣습니다.이름을 다 적었을 때

사전 상세에서 CSV·엑셀 파일로 용어를 한꺼번에 넣거나 하나씩 추가합니다.

용어 사전 상세

번호메뉴기능이런 때 사용하세요
1파일 선택용어를 정리한 CSV나 엑셀 파일을 고릅니다(20 MiB까지).용어를 한꺼번에 넣을 때
2양식 내려받기·양식 예시 보기파일 양식을 받거나 예시를 봅니다. CSV는 canonical(대표어), code, description(설명), aliases(별칭, "|"로 구분) 열을 씁니다.처음 파일을 만들 때
3적재 방식병합은 표제어가 같은 항목은 갱신하고, 파일에 없는 기존 항목은 그대로 둡니다. 교체를 고르면 파일 내용으로 바꿉니다.기존 사전에 용어를 더할 때
4업로드파일을 적재합니다.파일을 고른 뒤

용어 사전 항목

번호메뉴기능이런 때 사용하세요
1항목 검색·항목 추가왼쪽은 대표어, 코드, 별칭, 설명으로 항목을 찾고, 오른쪽은 항목을 하나씩 직접 추가합니다.특정 용어가 있는지 보거나 용어 한두 개를 더할 때
2항목 목록대표어, 코드, 별칭, 설명과 수정·삭제 버튼입니다.잘못 들어간 별칭을 고칠 때

업로드가 끝나면 업로드 버튼 아래에 추가, 갱신, 삭제 건수가 적재 결과로 나옵니다. 이 예에서는 다음 CSV로 "브레인크루 사내 용어" 사전에 네 항목을 넣었습니다.

재택근무WFH회사 밖에서 근무하는 제도원격근무|리모트근무|재택

이럴 때 쓰세요: 김그루 사원이 "법카 한도"로 검색하면 아무것도 안 나온다고 알려 왔습니다. 강혁신 팀장은 사내 용어 사전에 법인카드의 별칭으로 "법카"를 넣고, 김그루 사원은 사내 규정 컬렉션 설정에서 그 사전을 연결합니다.

전사 용어사전​

용어 사전 목록의 전사 용어사전 행을 누르면 회사 전체 용어 원장이 열립니다. 여기 등재된 용어는 검색 질의 확장에도 그대로 쓰입니다. 용어명은 원장 전체에서 하나만 있을 수 있습니다.

전사 용어사전

번호메뉴기능이런 때 사용하세요
1용어 등록용어명, 정의, 약어, 유의어(쉼표로 구분), 부가 속성을 적어 용어를 하나 등록합니다.새 제도나 용어가 생겼을 때
2검색용어명·정의·약어·유의어로 찾습니다. 옆에서 분류를 고르고, 미사용 포함을 켜면 쓰지 않는 용어도 보입니다.용어가 이미 있는지 확인할 때
3파일로 일괄 등록엑셀(.xlsx)이나 CSV를 고르고 미리보기로 확인한 뒤 적재합니다. 용어명만 필수입니다. 양식 예시 보기와 양식 내려받기로 양식을 봅니다.부서에서 정리한 용어 목록을 한꺼번에 넣을 때
4용어 목록용어명, 약어, 정의, 유의어, 사용 여부, 최종 수정일과 수정·삭제 버튼입니다.정의를 고치거나 용어를 정리할 때

이 예에서는 법인카드(약어 법카), 재택근무(WFH), 연차휴가(연차), 출장비 네 용어를 등록했습니다.

메타데이터 관리​

검색과 AI > 메타데이터 관리는 문서를 처리할 때 뽑힌 메타데이터 항목(필드)과 그 값을 한곳에서 보는 화면입니다. 메타데이터는 검색 화면의 메타데이터 필터와 에이전트의 범위 지정에 쓰입니다.

메타데이터 관리

번호메뉴기능이런 때 사용하세요
1필드·관계메타데이터 항목 목록과, 항목끼리 묶은 관계 목록입니다. 옆 숫자는 필드 수입니다.어떤 항목이 쓰이는지 볼 때
2필드 등록새 메타데이터 항목을 등록합니다. 옆 버튼으로 시스템 키를 숨기고, 범위(문서·청크)와 컬렉션으로 목록을 좁힙니다.컬렉션에 공통으로 쓸 항목을 미리 정할 때
3필드 행필드 이름, 쓰는 컬렉션, 등록된 값 수입니다. 누르면 오른쪽에 키·경로·범위/타입·개정과 값 목록이 나오고 편집, 비활성화, 값 등록, JSON 업로드, 내보내기를 쓸 수 있습니다.keywords에 어떤 값이 모였는지 볼 때
대표 필드뜻
source문서 이름(원본 파일 이름)
title, summary문서 제목과 요약
keywords, entities청크에서 뽑힌 핵심어와 고유명사
hypothetical_questions그 청크로 답할 수 있는 예상 질문
contextual_path문서 안 제목 경로(장·절)
pii_detected개인정보가 감지되었는지 표시

이럴 때 쓰세요: 영업 자료 컬렉션을 고객사별로 걸러 보고 싶다면, keywords 필드 값에 "가나다물산"이 들어 있는지 여기서 먼저 확인한 뒤 검색 화면의 메타데이터 필터에 씁니다.

컬렉션 태그​

검색과 AI > 컬렉션 태그는 태그별로 어떤 컬렉션이 연결됐는지 보고, 여러 컬렉션에 태그를 한꺼번에 붙이거나 떼는 화면입니다.

컬렉션 태그

번호메뉴기능이런 때 사용하세요
1태그 검색태그 이름으로 왼쪽 목록을 좁힙니다.태그가 많을 때
2태그 목록태그와 연결된 컬렉션 수입니다. 누르면 오른쪽에 그 태그의 컬렉션이 나옵니다."사내규정" 태그가 어디에 붙었는지 볼 때
3태그 연결태그를 적고 컬렉션을 골라 한꺼번에 연결합니다. 태그는 컬렉션당 20개까지입니다.새 분류 태그를 여러 컬렉션에 붙일 때
4연결된 컬렉션이 태그가 붙은 컬렉션과 그 컬렉션의 다른 태그입니다. 행을 골라 태그를 뗄 수 있습니다.잘못 붙은 태그를 정리할 때

이럴 때 쓰세요: 직원 문의에 쓰는 컬렉션(사내 규정, 인사·복리후생 안내, 규정 Q&A)에 "직원문의" 태그를 한 번에 붙이면, 컬렉션 목록의 태그 필터로 그 컬렉션들만 모아 볼 수 있습니다.

LLM 커넥션​

검색과 AI > LLM 커넥션은 질의 재작성과 AI 답변 생성에 쓸 언어 모델 접속 정보를 팀스페이스(조직)별로 등록하는 화면입니다. 위쪽 조직에서 팀스페이스를 고르면 그 팀스페이스의 커넥션 목록(이름, 프로바이더, 모델, 자격 증명, 상태, 연결 테스트)이 나옵니다. 컬렉션은 소유자가 속한 팀스페이스의 커넥션만 쓸 수 있으므로 부서마다 하나씩 만들어 두는 것이 좋습니다.

새 커넥션을 누르면 접속 정보를 적는 창이 열립니다.

LLM 커넥션 생성 창(위쪽)

번호메뉴기능이런 때 사용하세요
1이름커넥션 이름입니다. 컬렉션 담당자가 보고 고를 이름입니다."브레인크루 GPT-4.1 mini"처럼 모델이 드러나게 지을 때
2프로바이더OpenAI 호환 또는 Azure OpenAI를 고릅니다.사내 모델 게이트웨이 종류에 맞출 때
3모델호출할 모델 이름입니다.비용과 속도에 맞는 모델을 고를 때
4Base URL모델 서버 주소입니다.사내 게이트웨이 주소를 넣을 때

LLM 커넥션 생성 창(아래쪽)

번호메뉴기능이런 때 사용하세요
1자격 증명서버에 저장된 비밀값 참조(secret_ref)나 API 키 중 하나를 반드시 적습니다. 둘 다 적으면 secret_ref가 우선합니다.키를 화면에 직접 남기지 않으려면 secret_ref를 쓸 때
2타임아웃 (ms)·첫 토큰 타임아웃 (ms)·최대 출력 토큰응답을 기다리는 최대 시간, 첫 글자가 올 때까지 기다리는 시간, 답변 길이 상한입니다.답변이 자주 끊기거나 너무 길 때
3저장커넥션을 만듭니다. 맨 아래 활성화를 끄면 만들어도 쓰이지 않습니다.입력을 마쳤을 때
항목뜻기본값
프로바이더모델 서버 종류OpenAI 호환
타임아웃 (ms)응답 전체를 기다리는 최대 시간20000(20초)
첫 토큰 타임아웃 (ms)첫 글자가 올 때까지 기다리는 시간10000(10초)

활성화이 커넥션을 쓸지 여부켜짐

만든 커넥션의 ID를 컬렉션 담당자에게 알려 주면, 담당자가 컬렉션 설정의 LLM 검색 보강에 넣어 씁니다(컬렉션과 폴더 참고). 화면 위 안내대로 청크는 저장할 때 가명화되어 원문 개인정보가 외부 모델로 가지 않지만, 사용자가 입력한 질의는 그대로 전송됩니다. 커넥션 화면에는 API 키 같은 비밀값이 들어가므로 화면을 캡처해 공유하지 마세요.

이럴 때 쓰세요: AI혁신팀이 사내 규정 컬렉션에서 AI 답변을 쓰고 싶어 하면, 강혁신 팀장이 조직에서 AI혁신팀을 고르고 "브레인크루 GPT-4.1 mini" 커넥션을 만든 뒤 ID를 김그루 사원에게 전달합니다.

MCP 도구​

검색과 AI > MCP 도구는 Deep Connector가 에이전트와 외부 AI 도구에 제공하는 검색 도구 목록입니다. 도구마다 설명을 고칠 수 있고, Deep Agent Builder(DAB)의 지식 도구 목록에 어떤 도구를 올릴지 정합니다.

MCP 도구

번호메뉴기능이런 때 사용하세요
1DAB 연동 상태Deep Agent Builder 도구함과의 동기화 상태(설정 안 됨, 동기화 필요, 동기화 완료, 동기화 실패)입니다.도구 변경이 Builder에 반영됐는지 볼 때
2DAB 설정DAB 지식 도구 목록에만 보일 표시 설명을 편집합니다.Builder 사용자에게 보일 안내 문구를 바꿀 때
3DAB 등록체크한 읽기 도구만 Builder 지식 도구로 등록됩니다. 쓰기 도구는 등록 대상이 아니고, 등록 도구는 1개 이상이어야 합니다.에이전트에 꼭 필요한 도구만 보여 줄 때
4설명도구 설명입니다. 행을 누르면 오른쪽 창에서 고칠 수 있고, 바꾼 설명은 모든 MCP 클라이언트의 도구 목록에 적용됩니다. 아래 수정 반영을 눌러야 저장됩니다.에이전트가 도구를 잘못 고를 때 설명을 다듬을 때

이 시연 환경은 Builder 도구함과 연결하지 않아 "설정 안 됨"으로 보이고, Builder 에이전트는 MCP 토큰으로 연결했습니다(에이전트에서 지식 쓰기 참고).

이럴 때 쓰세요: Builder의 "사내 규정 Q&A 비서"가 search_documents 대신 grep_documents를 자주 고른다면, 두 도구 설명에 "문장 질문은 search_documents, 정확한 문구는 grep_documents"처럼 쓰임새를 분명히 적고 수정 반영을 누릅니다.

도구 평가​

검색과 AI > 도구 평가는 에이전트와 외부 도구가 Deep Connector 검색 도구를 어떻게 부르고 있는지 모아 보는 운영 화면입니다. 실패율, 응답 시간, 빈 결과, 중복 호출을 보고 도구 설명이나 컬렉션 구성을 고칠 곳을 찾습니다.

도구 평가 개요

번호메뉴기능이런 때 사용하세요
1개요·도구별 상태·질문 흐름·도구 점검·비교요약 지표, 도구별 표, 대화별 호출 순서, 즉석 점검, 두 기간 비교 탭입니다.보고 싶은 관점을 고를 때
2기간1시간, 24시간, 7일, 직접 지정 중에서 고릅니다.지난주와 이번 주를 나눠 볼 때
3호출 범위에이전트 호출만 또는 모든 호출을 고릅니다. 옆에 에이전트 ID를 적으면 그 에이전트만 봅니다.MCP 도구 테스트 같은 사람의 호출까지 넣어 볼 때
4새로고침·내보내기최신 값으로 다시 불러오거나 결과를 파일로 받습니다.주간 점검 결과를 공유할 때

개요에는 호출 수, 실패율, 대화 수, Connector 실행 시간 합이 위에 나오고, 아래에 빈 결과율, 중복 호출률, 오류 후 회복률 같은 호출 진단과 시간대별 호출·실패, 실패 원인이 이어집니다. 지표 정의를 누르면 각 지표의 계산 방법이 나옵니다.

도구별 상태

번호메뉴기능이런 때 사용하세요
1도구별 상태도구마다 한 줄씩 보여 주는 탭입니다. 주의가 필요한 도구는 왼쪽 띠와 "주의 경보"로 표시됩니다.문제 있는 도구를 찾을 때
2도구별 표호출, 실패(율), 실행 시간 p50·p95, 응답 크기, 30,000자 초과, 빈 결과, 중복, 시간 구성, 주요 오류입니다.search_documents 실패가 어떤 오류로 몰리는지 볼 때

도구 점검

번호메뉴기능이런 때 사용하세요
1도구 점검요청한 관리자 권한으로 읽기 도구를 차례로 불러 보는 탭입니다. 10~60초 걸리고, 결과는 저장되지 않아 화면을 떠나면 사라집니다.배포나 설정 변경 직후 도구가 정상인지 확인할 때
2점검 실행점검을 시작합니다. 결과는 컬렉션 권한 일관성, 출력 스키마 준수, 오류 문구 품질, 검색 지연과 동시성, 시간 제한 정렬, 도구 정의 크기 같은 항목별로 통과·주의·건너뜀이 표시됩니다.주의 항목의 세부를 펼쳐 원인을 볼 때
탭보여 주는 것이런 때 보세요
개요호출 수, 실패율, 대화 수, 호출 진단, 시간대별 추이, 실패 원인주간 상태를 한눈에 볼 때
도구별 상태도구별 호출·실패·시간·응답 크기특정 도구가 느리거나 자주 실패할 때
질문 흐름에이전트 대화 하나에서 도구를 어떤 순서로 불렀는지와 입출력에이전트가 같은 도구를 되풀이해 부를 때
도구 점검읽기 도구를 즉석으로 불러 본 결과설정을 바꾼 직후
비교두 기간(묶음 A·B)의 지표 차이(B − A)도구 설명을 고치기 전과 후를 비교할 때

이 시연 환경에서는 에이전트 표시가 없는 호출만 있어서 기본값인 에이전트 호출만으로 보면 0건이고, 모든 호출로 바꿔야 search_documents, glob_paths, list_collections 기록이 보입니다.

이럴 때 쓰세요: 도구별 상태에서 search_documents 실패율이 36%로 높게 나왔고 주요 오류가 "그 밖의 인자 오류", "없는 경로·대상"이었습니다. 강혁신 팀장은 MCP 도구 화면에서 search_documents 설명에 검색 범위(path)를 꼭 넣으라는 안내를 더하고, 일주일 뒤 비교 탭으로 실패율이 줄었는지 봅니다.
