Deep Connector 관리자 메뉴

Deep Connector 관리자로 로그인하면 사이드바 아래쪽에 관리자 묶음이 보입니다. 이 페이지는 관리자 메뉴 전체 구성과, 묶음 없이 바로 열리는 대시보드, 적재 현황을 설명합니다. 나머지 묶음은 사용자와 팀스페이스, 검색과 AI, 시스템 페이지에 있습니다. 예시는 AI혁신팀 강혁신 팀장(Deep Connector 관리자)의 화면입니다. 일반 사용자에게는 이 메뉴가 보이지 않습니다.

이 페이지에서 할 수 있는 일

  • 관리자 메뉴 구성을 알고 원하는 화면으로 이동합니다.
  • 대시보드와 적재 현황에서 문서 처리 상황을 봅니다.
  • 업로드 묶음(배치)별 처리 기록을 봅니다.
  • 배포 전체의 적재 설정(기본 파이프라인, 파서 대기 시간, 파일 크기 상한, 배치 크기)을 바꿉니다.

관리자 메뉴 구성​

관리자 사이드바

번호메뉴기능이런 때 사용하세요
1대시보드·적재 현황전체 사용량 요약과 문서 처리 기록입니다. 이 페이지에서 설명합니다.매일 아침 처리 실패가 없는지 볼 때
2사용자와 팀스페이스누르면 사용자, 팀스페이스가 펼쳐집니다.업로드 한도를 바꿀 때
3검색과 AI누르면 용어 사전, 메타데이터 관리, 컬렉션 태그, LLM 커넥션, MCP 도구, 도구 평가가 펼쳐집니다.검색 품질과 AI 기능을 맞출 때
4시스템누르면 저장공간, 감사 로그, 브랜드 설정, 시스템 설정이 펼쳐집니다.용량·기록·화면 브랜드를 관리할 때
묶음메뉴하는 일자세한 설명
–대시보드전체 문서 수, 저장공간, 할당량 경고, 최근 14일 사용량 추이이 페이지
–적재 현황문서·배치별 처리 기록과 배포 전체 적재 설정이 페이지
사용자와 팀스페이스사용자, 팀스페이스사용자·부서별 사용량과 할당량사용자와 팀스페이스
검색과 AI용어 사전(전사 용어사전 포함), 메타데이터 관리, 컬렉션 태그검색어 확장 사전, 메타데이터 항목, 컬렉션 태그검색과 AI
LLM 커넥션질의 재작성·AI 답변에 쓸 언어 모델 연결검색과 AI
MCP 도구, 도구 평가에이전트에 제공하는 검색 도구 설명과 호출 품질 점검검색과 AI
시스템저장공간, 감사 로그, 브랜드 설정, 시스템 설정용량 현황, 작업 기록, 화면 로고·색, 문서 링크 유효시간시스템

관리자에게는 접근 요청 메뉴가 보이지 않습니다. 회사 계정 연동 방식이 지원하면 사용자와 팀스페이스 아래에 컬렉션 권한이 더 생기고, 거기서 접근 요청을 승인합니다.

대시보드​

관리자 대시보드

번호메뉴기능이런 때 사용하세요
1전체 문서모든 컬렉션의 문서 수입니다.도입 초기 문서가 얼마나 들어왔는지 볼 때
2전체 저장공간문서가 차지하는 저장 용량입니다.용량 증설 시기를 가늠할 때
3할당량 경고한도에 가까워졌거나 넘은 사용자 수입니다.업로드가 막힌 사용자를 찾을 때
4사용량 추이최근 14일 동안 날마다 업로드·삭제 건수와 늘어난 용량입니다.대량 업로드가 있었던 날을 확인할 때

이럴 때 쓰세요: 월말 운영 보고를 준비하는 강혁신 팀장은 대시보드의 전체 문서 수와 사용량 추이를 보고서에 옮기고, 할당량 경고가 0보다 크면 해당 사용자를 사용자 화면에서 찾아 한도를 조정합니다.

적재 현황​

모든 컬렉션의 문서 처리 기록을 한 화면에서 봅니다. 실패한 문서를 찾아 원인을 확인하는 데 씁니다.

적재 현황

번호메뉴기능이런 때 사용하세요
1문서·배치·설정문서별 기록, 업로드 묶음(배치)별 기록, 처리 설정 탭입니다.한 번에 올린 묶음 단위로 볼 때
2기간1시간부터 30일, 직접 지정, 기간 무관 중에서 고릅니다.어제 밤 처리분만 볼 때
3처리 요약적재 실패, 적재 중(그중 멈춤), 완료, 전체 건수와 비율입니다.실패율이 오르지 않았는지 볼 때
4새로고침최신 상태로 다시 불러옵니다.처리 중인 문서를 지켜볼 때

시각별 추이와 문서 목록

번호메뉴기능이런 때 사용하세요
1시각별 추이처리 시작 시각별 건수입니다. 아래 탭에서 실패 사유별, 컬렉션별 실패 상위 10을 봅니다.실패가 몰린 시간이나 컬렉션을 찾을 때
2문서 목록파일명, 컬렉션, 상태, 요청·시작·완료 시각, 시도 횟수입니다. 필터와 파일명 검색으로 좁힙니다.특정 파일의 처리 과정을 추적할 때
3CSV 내보내기목록을 CSV 파일로 내려받습니다.월간 처리 실적을 보고할 때

이럴 때 쓰세요: 강혁신 팀장은 매일 아침 적재 현황에서 기간을 24시간으로 두고 적재 실패 건수를 봅니다. 실패가 있으면 실패 사유별 탭에서 원인을 보고, 해당 문서 담당자에게 알립니다.

배치 탭​

배치 탭은 폴더 올리기, 일괄 삭제, 다시 적재처럼 여러 문서를 한 번에 처리한 묶음의 기록입니다.

적재 현황 배치 탭

번호메뉴기능이런 때 사용하세요
1배치묶음 단위 기록 탭입니다.한 번에 올린 폴더가 다 처리됐는지 볼 때
2보관 기간끝난 배치 기록을 보관하는 기간입니다(예: 보관 60일). 설정 탭에서 바꿉니다.오래된 기록이 왜 없는지 확인할 때
3전체 연산·전체 상태연산 종류(등록, 삭제, 재색인 등)와 상태(진행 중, 완료, 실패)로 좁힙니다.실패한 배치만 볼 때
4배치 표ID, 상태, 연산, 컬렉션, 항목 수, 처리 상태, 시작한 사람, 시작·종료 시각입니다. 지워진 컬렉션은 "볼 수 없는 컬렉션"으로 표시됩니다.누가 언제 대량 작업을 했는지 볼 때

이럴 때 쓰세요: 김그루 사원이 사례 자료 폴더를 통째로 올린 뒤 "몇 개가 안 들어간 것 같다"고 하면, 배치 탭에서 그 묶음의 처리 상태(완료·실패 건수)를 먼저 봅니다.

설정 탭​

설정 탭은 배포 전체의 적재 설정입니다. 저장하면 재기동 없이 수 초 안에 적용됩니다. 묶음마다 저장 버튼이 따로 있습니다.

적재 현황 설정 탭

번호메뉴기능이런 때 사용하세요
1파이프라인전역 기본 파이프라인입니다. 업로드 요청과 컬렉션에 파이프라인이 없을 때 씁니다. 저장값을 쓰는 중이면 기본값으로 되돌리기가 보입니다.회사 표준 처리 방식을 바꿀 때
2저장그 묶음의 설정을 저장합니다.값을 바꿨을 때
3숫자 입력칸각 설정값입니다. 아래에 사람이 읽기 쉬운 값(예: = 2초)이 보입니다.대기 시간이나 상한을 조정할 때

설정 항목과 기본값은 다음과 같습니다. 문서를 나누는 방식(청킹)과 임베딩은 이 화면이 아니라 파이프라인(Deep Docurator 플로우)과 배포 설정에서 정해집니다. 컬렉션마다 다르게 하려면 컬렉션 설정의 기본 파이프라인을 바꿉니다.

묶음항목뜻기본값
전역 기본 파이프라인파이프라인파이프라인이 지정되지 않은 문서에 쓰는 처리 방식기본 파이프라인
파서 폴링상태 확인 주기파싱 중인 문서의 상태를 한꺼번에 묻는 간격2000ms(2초)
폴링 시작 간격첫 상태 확인까지 기다리는 시간500ms
폴링 기본 간격상태를 확인하는 기본 간격5000ms(5초)
폴링 간격 상한확인 간격의 최대값30000ms(30초)
전송 오류 재시도 횟수통신 오류 때 다시 묻는 횟수8회
큐 대기 예산처리 시작을 기다리는 최대 시간. 넘으면 실패25시간
처리 예산처리 시작 뒤 완료를 기다리는 최대 시간. 넘으면 실패168시간
파서 접수접수 재시도 간격 상한파서 큐가 가득 찼을 때 기다리는 최대 시간15000ms(15초)
원본 URL 유효시간파서가 원본을 내려받는 주소의 유효시간3600초(1시간)
대량 적재 동시 처리 상한배치가 파서에 동시에 맡길 수 있는 문서 수. 0이면 상한 없음0
업로드파일 최대 크기업로드 파일 하나의 최대 크기200MB(이 시연 환경)
배치요청당 항목 상한배치 요청 하나의 항목 수2000
폴더 스캔 항목 상한폴더 반입 때 읽는 파일 수 최대값50000
처리 풀 크기배치에서 동시에 처리하는 항목 수20
재색인 풀 크기재색인 배치의 동시 처리 수2
배치 기록 보관 기간끝난 배치 기록 보관 일수. 0이면 지우지 않음60일

이럴 때 쓰세요: 스캔본처럼 처리 시간이 긴 문서가 "대기 시간 초과"로 실패한다면 큐 대기 예산이나 처리 예산을 늘립니다. 대량 이관 중 직원이 올린 문서가 늦게 처리된다면 대량 적재 동시 처리 상한을 파서 처리 능력보다 작게 둡니다.

AI 대시보드​

관리자는 사이드바에 없는 AI 대시보드도 볼 수 있습니다. 없는 주소로 들어갔을 때 나오는 화면의 대시보드로 돌아가기를 누르면 열립니다. MCP로 들어온 검색 호출을 확인할 때 씁니다.

AI 대시보드

번호메뉴기능이런 때 사용하세요
1요약 카드컬렉션 수입니다. 오른쪽으로 문서 수, MCP 토큰 수, MCP 호출 수 카드가 이어집니다.MCP 연결이 실제로 쓰이는지 볼 때
2MCP 서버 로그·분석도구, 권한, 결과, 실행 시간, 시각이 나오는 호출 기록과 호출 분석 탭입니다. 행을 펼치면 호출 내용이 보입니다.에이전트의 검색이 느리거나 실패할 때 원인을 볼 때
