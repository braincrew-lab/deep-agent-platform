Deep Connector 외부 연동

Deep Connector의 컬렉션은 화면 밖에서도 쓸 수 있습니다. 다른 AI 도구가 컬렉션을 검색하게 하거나, 사내 시스템이 문서를 자동으로 올리고 교체하게 할 수 있습니다. 이 페이지는 화면에서 하는 연동 준비와 확인, 곧 MCP 토큰 발급, MCP 도구 테스트, 외부 문서 API로 들어온 문서 확인을 설명합니다.

이 페이지에서 할 수 있는 일

  • 외부 연동 세 가지 방식의 차이를 이해합니다.
  • MCP 토큰을 만들 때 접근할 컬렉션과 권한을 좁혀 발급합니다.
  • MCP 도구 테스트에서 에이전트가 쓰는 검색 도구를 직접 실행해 봅니다.
  • 외부 시스템이 올린 문서를 화면에서 확인합니다.

외부 연동 세 가지​

방식하는 일화면에서 할 일누가
MCP 토큰Deep Agent Builder 에이전트나 다른 AI 도구가 MCP 방식으로 컬렉션을 검색하고 읽습니다.MCP 토큰에서 토큰을 만들고 접근 컬렉션을 정합니다.컬렉션 담당자, 연동 담당자
MCP 도구 테스트에이전트가 쓰는 도구를 같은 조건으로 직접 실행해 결과를 봅니다.실험 > MCP 도구 테스트컬렉션 담당자
외부 문서 API사내 시스템(예: 문서관리시스템, 게시판)이 문서를 자동으로 등록·교체·삭제합니다.컬렉션, 권한, 파이프라인을 준비하고 결과를 문서 목록에서 확인합니다.연동 담당자

외부 문서 API의 요청 형식과 오류 코드는 별도로 제공되는 "외부연동 문서 API 명세"를 따릅니다. 이 매뉴얼은 화면에서 준비하고 확인하는 일만 다룹니다.

MCP 토큰​

사이드바 MCP 토큰(또는 설정 > MCP 토큰)에서 토큰을 관리합니다. 토큰은 비밀번호처럼 다루세요. 토큰이 있으면 누구든 그 토큰이 허락한 컬렉션을 읽을 수 있습니다.

MCP 토큰 화면

번호메뉴기능이런 때 사용하세요
1일반언어와 테마 설정 탭입니다.화면 표시를 바꿀 때
2MCP 토큰토큰 관리 탭입니다.토큰을 발급하거나 정리할 때
3새 토큰 생성토큰 만들기 창을 엽니다.새 도구를 연결할 때
4토큰 요약전체 토큰과 활성 토큰 수입니다.쓰지 않는 토큰이 남아 있는지 볼 때

토큰 목록

번호메뉴기능이런 때 사용하세요
1토큰 정보상태(활성), 권한(READ 등), 발급일과 만료일입니다.만료가 가까운 토큰을 찾을 때
2접근 컬렉션이 토큰이 읽을 수 있는 컬렉션입니다.토큰 범위가 맞는지 볼 때
3접근 컬렉션 수정토큰이 읽을 컬렉션을 바꿉니다.새 컬렉션을 같은 도구에 더 연결할 때
4삭제토큰을 지웁니다. 그 토큰을 쓰는 연결은 바로 끊깁니다.연결을 끊거나 토큰이 노출됐을 때

토큰 만들기​

새 토큰 생성 창

번호메뉴기능이런 때 사용하세요
1유효기간 (일)토큰을 쓸 수 있는 날 수입니다. 지나면 토큰이 만료됩니다.시범 연결이라 짧게 줄 때
2권한 설정읽기 전용(조회와 검색만) 또는 읽기 / 쓰기(문서 추가·삭제까지)를 고릅니다.검색만 하는 도구에는 읽기 전용을 줄 때
3접근 컬렉션토큰이 읽을 컬렉션을 1개 이상 고릅니다. 옆에 고른 개수가 보입니다. 고른 컬렉션이 모두 지워지면 토큰도 자동으로 폐기됩니다.필요한 컬렉션만 열어 줄 때
4선택한 항목만고른 컬렉션만 보이게 목록을 좁힙니다.고른 것을 다시 확인할 때

접근 컬렉션 고르기와 생성

번호메뉴기능이런 때 사용하세요
1폴더·컬렉션 체크체크한 컬렉션이 토큰 범위에 들어갑니다. 폴더를 체크하면 안의 컬렉션이 모두 들어갑니다. 그림은 "규정 Q&A"가 든 경영지원 폴더를 고른 상태입니다.필요한 컬렉션만 열어 줄 때
2취소만들지 않고 닫습니다.–
3생성토큰을 만듭니다.설정을 마쳤을 때

생성을 누르면 토큰 생성 완료 창이 열립니다. 이 창이 닫히면 토큰을 다시 볼 수 없습니다.

토큰 생성 완료 창

번호메뉴기능이런 때 사용하세요
1요청 URL외부 도구에 적을 MCP 서버 주소입니다.도구의 서버 주소 칸을 채울 때
2토큰토큰 값입니다. 화면에는 가려져 보이고 복사로 복사합니다.도구의 인증 칸을 채울 때
3복사각 값을 클립보드로 복사합니다.값을 옮겨 적을 때

전체 URL과 닫기

번호메뉴기능이런 때 사용하세요
1전체 URL (URL + Token)주소와 토큰을 합친 값입니다. 토큰을 따로 적는 칸이 없는 도구에 씁니다.주소 하나만 받는 도구를 연결할 때
2클라이언트 연결 설정코드 편집기 같은 도구별 설정 예시를 보여 줍니다.도구 설정 방법을 모를 때
3닫기창을 닫습니다.값을 안전한 곳에 옮긴 뒤

토큰을 메신저나 메일에 붙여 넣지 마세요. 노출됐다면 바로 삭제하고 새로 만듭니다.

MCP 도구 테스트​

실험 > MCP 도구 테스트는 에이전트가 Deep Connector를 검색할 때 쓰는 도구를 직접 실행해 보는 화면입니다. 에이전트가 근거를 못 찾을 때 같은 도구를 여기서 실행해 보면 문서 쪽 문제인지 질문 쪽 문제인지 가를 수 있습니다.

MCP 도구 테스트 화면

번호메뉴기능이런 때 사용하세요
1도구 검색도구 이름으로 목록을 좁힙니다.쓰려는 도구를 빨리 찾을 때
2실행 범위도구를 실행할 컬렉션을 고르는 창을 엽니다. 고르지 않으면 접근할 수 있는 전체 컬렉션이 대상입니다.한 컬렉션 안에서만 시험할 때
3도구 목록의 search_documents누르면 가운데에 그 도구의 이름, 종류(읽기), 설명과 입력 규칙이 나옵니다.어떤 값을 넣어야 하는지 볼 때
4쓰기 도구문서·컬렉션을 만들거나 지우는 도구 5개입니다. 잠금 표시가 붙어 있고, 실행 전에 확인 창이 나옵니다.일반 점검에는 쓰지 않습니다

파라미터와 실행

번호메뉴기능이런 때 사용하세요
1파라미터도구에 넘길 값입니다. 별표(*)는 필수입니다.질문을 적을 때
2고급 파라미터결과 수, 검색 방식, 검색 범위(path, document_ids) 같은 선택값입니다.검색 범위를 정할 때
3실행·초기화왼쪽은 도구를 실행하고, 오른쪽은 입력값을 비웁니다.값을 다 넣었거나 다른 조건으로 다시 할 때

실행 결과

번호메뉴기능이런 때 사용하세요
1실행 결과 요약성공·실패, 도구 이름, 걸린 시간입니다.실행이 끝났는지 볼 때
2보기·Raw JSON결과를 읽기 쉬운 화면이나 원문으로 봅니다.결과를 담당자에게 그대로 전달할 때
3결과찾은 청크와 점수입니다. 맨 위에는 실제 적용된 검색 설정이 나옵니다.에이전트가 볼 근거를 미리 읽을 때

읽기 도구는 12개입니다. 자주 쓰는 도구는 다음과 같습니다.

도구하는 일
search_documents질문으로 청크를 찾습니다. 고급 파라미터의 path(예: "/규정 Q&A")나 document_ids로 범위를 정해야 실행됩니다.
list_collections접근할 수 있는 컬렉션 목록을 봅니다.
list_documents컬렉션의 문서 목록을 봅니다.
read_document문서 하나를 쪽이나 순서대로 읽습니다.
grep_documents정확한 문구가 들어 있는 곳을 찾습니다.
glob_paths폴더와 컬렉션 경로를 찾습니다. path 값을 모를 때 씁니다.

따라 해 보기​

  1. MCP 도구 테스트에서 search_documents를 고릅니다.
  2. query에 "재택근무 신청 마감"을 적습니다.
  3. 고급 파라미터를 펼치고 path에 "/규정 Q&A"를 적습니다.
  4. 실행을 누릅니다. 결과에 재택근무-운영-지침.docx 청크가 나오고 "전주 금요일 18시까지"가 보이면 됩니다.

검색 범위를 넣지 않으면 실행 결과에 검증 실패(ValidationError)가 나옵니다. 리랭커를 쓰는 환경에서는 결과가 나오기까지 시간이 걸릴 수 있습니다.

외부 문서 API로 들어온 문서 확인​

사내 시스템이 외부 문서 API로 문서를 올리면 화면에서 올린 문서와 똑같이 문서 목록에 나타납니다. 연동 문서에는 문서 이름 아래에 원천 시스템의 문서 번호(external_id)가 함께 보입니다.

연동 담당자가 준비할 것은 다음과 같습니다.

준비할 것화면이유
대상 컬렉션컬렉션과 폴더API 요청에 컬렉션 ID가 필요합니다. 컬렉션 ID는 연동 담당자가 컬렉션 목록 API로 확인합니다.
업로드 권한권한·공유·접근 요청연동 계정에 Level2 이상(교체는 업로드·수정, 삭제는 Level3)이 있어야 합니다.
파이프라인업로드 화면의 파이프라인API 요청에 처리 파이프라인 ID가 필요합니다.
토큰MCP 토큰연동 프로그램의 인증에 씁니다.

연동이 시작되면 다음을 확인합니다.

  • 문서 목록에 문서가 들어오고, 처리 상태가 완료가 되는지
  • 같은 원천 문서를 다시 보내면 새 문서가 생기지 않고 문서 상세의 버전이 올라가는지
  • 처리 실패한 문서가 있으면 오류 상세 보기의 내용을 연동 담당자에게 전달하는지
