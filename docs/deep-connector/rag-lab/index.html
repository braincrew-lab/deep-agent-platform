Deep Connector 실험: RAG 진단

사이드바 실험 > RAG 진단은 질문 하나로 질문 재작성, 검색, 답변에 쓸 청크 고르기, 답변 생성까지 단계별로 보여 주는 화면입니다. 에이전트가 이 컬렉션으로 어떻게 답할지 미리 볼 수 있습니다. 답변 생성은 컬렉션 설정에 LLM 커넥션이 연결되어 있어야 동작합니다(컬렉션과 폴더 참고).

이 페이지에서 할 수 있는 일

  • 질문 하나로 재작성·검색·답변 단계를 차례로 확인합니다.
  • 검색 파라미터를 바꿔 답변과 근거가 어떻게 달라지는지 봅니다.
  • 단계별 소요 시간과 토큰 수로 느린 단계를 찾습니다.

화면 구성​

RAG 진단 화면

번호메뉴기능이런 때 사용하세요
1컬렉션진단할 컬렉션을 고릅니다. 고르면 그 컬렉션의 검색 설정이 아래 검색 파라미터에 채워집니다.점검할 컬렉션을 정할 때
2질의질문을 적습니다.직원이 자주 묻는 질문을 넣어 볼 때
3max_context_chunks답변에 넘길 청크 수입니다.근거를 더 넓게 줄 때
4질의 재작성·답변 생성왼쪽은 검색 전에 질문을 검색하기 좋은 문장으로 바꾸고, 오른쪽은 검색 결과로 답변을 만듭니다.재작성 효과를 비교하거나 답변 문장까지 볼 때

실행과 검색 파라미터

번호메뉴기능이런 때 사용하세요
1실행진단을 실행합니다. 실행 중에는 중지로 바뀝니다.조건을 다 정했을 때
2검색 파라미터아래 검색 설정을 펼치거나 접습니다.검색 설정을 바꿔 볼 때

검색 파라미터

번호메뉴기능이런 때 사용하세요
1검색 방식semantic(의미), keyword, hybrid 중에서 고릅니다.방식별 답변을 비교할 때
2결과 수·점수 컷가져올 결과 수와, 이 점수보다 낮은 결과를 뺄 기준입니다.관련 없는 결과를 걸러 낼 때
3리랭킹결과 순서를 다시 매길지 정합니다.순위가 어색할 때

진단 결과

번호메뉴기능이런 때 사용하세요
1답변만들어진 답변입니다. 문장 끝 [1] 같은 번호가 근거 청크입니다.답이 문서와 맞는지 볼 때
2재작성·소요시간·토큰재작성된 질문, 단계별 걸린 시간, 입력·출력 토큰 수입니다.느린 단계를 찾을 때
3근거 문서답변에 쓰인 청크의 문서 이름입니다. 아래로 최종 프롬프트, 선택된 컨텍스트 청크, 검색 결과가 이어집니다.어떤 문서가 답에 쓰였는지 볼 때

이 예에서는 "연차는 며칠 전까지 신청해야 하나요?"에 "사용일 3영업일 전까지 그룹웨어 근태 메뉴에서 신청"이라고 답하고 근거로 "연차-사용-안내.md"를 들었습니다. 커넥션이 연결되지 않은 컬렉션에서는 검색 결과까지만 나오고, 답변과 최종 프롬프트에는 "아직 없습니다(답변 생성이 꺼져 있거나 LLM이 구성되지 않았을 수 있습니다)."가 표시됩니다.

프롬프트 바꿔 보기(관리자)​

관리자 계정으로 열면 검색 파라미터 아래에 프롬프트 구역이 더 있습니다. 답변을 만들 때 LLM에 보내는 지시문(system 프롬프트)과 질문·근거를 끼워 넣는 틀(user 템플릿)을 이번 진단에만 바꿔 볼 수 있습니다. 서버에 저장된 기본 프롬프트는 바뀌지 않습니다.

프롬프트 샘플 불러오기

번호메뉴기능이런 때 사용하세요
1프롬프트 상태"서버 기본값 사용 중"이면 서버의 기본 프롬프트로 실행합니다. 고치면 "수정됨 — override 전송"으로 바뀝니다.지금 어떤 프롬프트로 실행되는지 볼 때
2샘플 불러오기미리 만들어 둔 프롬프트 네 가지를 엽니다.처음부터 쓰지 않고 견본에서 시작할 때
3샘플 목록아래 표의 네 가지입니다. 고르면 두 칸이 그 내용으로 채워집니다.답변 형식을 비교할 때
샘플화면 설명이럴 때 고르세요
기본 (서버 기본값)서버가 실제로 쓰는 프롬프트. 여기서 출발해 고친다.기본 프롬프트를 조금만 고칠 때
엄격한 근거근거 밖 추론을 금지하고, 못 찾으면 못 찾았다고 답하게 한다.규정·계약처럼 틀리면 안 되는 답을 시험할 때
요약형 (3줄)핵심만 3줄 이내로. 긴 약관·규정을 빠르게 훑을 때.짧은 답이 필요한 질문을 시험할 때
표 형식항목·내용·근거 3열 표로. 조건이나 기준을 비교할 때.여러 조건을 한눈에 비교하는 답을 시험할 때

프롬프트 편집

번호메뉴기능이런 때 사용하세요
1수정됨 표시"수정됨 — override 전송". 이번 실행에 바꾼 프롬프트를 함께 보냅니다.바꾼 프롬프트로 실행되는지 확인할 때
2system 프롬프트LLM의 역할과 지켜야 할 규칙입니다. 그림은 엄격한 근거를 불러온 상태입니다.근거 표기, 말투, 금지 사항을 바꿀 때
3user 템플릿질문과 근거를 끼워 넣는 틀입니다. {context}에는 고른 청크가, {query}에는 질문이 들어갑니다. 두 치환자를 지우면 근거나 질문이 빠집니다.근거와 질문의 순서나 표현을 바꿀 때
4비우기고친 내용을 지우고 서버 기본값으로 돌아갑니다.비교를 마치고 원래대로 돌릴 때

같은 프롬프트 편집이 RAG 평가의 실행 폼에도 있어, 고친 프롬프트로 데이터셋 전체를 돌려 점수를 비교할 수 있습니다. 일반 사용자 화면에는 이 구역이 없고 항상 서버 기본 프롬프트로 실행됩니다.

이럴 때 쓰세요: "사내 규정 Q&A 비서"가 규정에 없는 내용까지 추측해 답한다는 의견을 받은 강혁신 팀장은, RAG 진단에서 엄격한 근거 샘플을 불러와 같은 질문을 실행해 봅니다. 근거에 없는 질문에는 "제공된 근거로는 답할 수 없습니다"라고 답하는지 확인한 뒤, 에이전트 지침에 같은 규칙을 넣도록 김그루 사원에게 안내합니다.

설정 항목과 기본값​

컬렉션을 고르면 아래 검색 파라미터가 그 컬렉션의 검색 설정으로 채워집니다. 컬렉션에 저장된 값이 없으면 다음 기본값을 씁니다. 여기서 바꾼 값은 이번 진단에만 쓰이고 컬렉션 설정은 바뀌지 않습니다.

항목뜻기본값
max_context_chunks답변에 넘길 청크 수5
질의 재작성검색 전에 질문을 다듬을지켜짐
답변 생성검색 결과로 답변을 만들지켜짐
검색 방식semantic(의미), keyword, hybridsemantic
결과 수검색에서 가져올 청크 수5
점수 컷이보다 낮은 점수의 결과를 뺌0(빼지 않음)
리랭킹결과 순서를 다시 매길지꺼짐(켜면 후보 30개 중 5개)
사전 확장연결된 용어 사전으로 검색어를 넓힐지(의미 검색에는 적용 안 됨)켜짐
융합 전략(hybrid일 때)두 검색 결과를 합치는 방식: rrf, srrf, dbsf, weightedrrf(rrf_k 60, srrf_beta 10, 의미 검색 가중치 0.5)
결과 수·점수 컷 범위화면에서 넣을 수 있는 값결과 수 1100, 점수 컷 01(0.05 단위), 리랭크 후보 1~200
프롬프트(관리자만)system 프롬프트와 user 템플릿서버 기본값

이럴 때 쓰세요: 김그루 사원이 "사내 규정 Q&A 비서"를 직원들에게 열기 전에, 자주 나올 질문 "연차는 며칠 전까지 신청해야 하나요?"를 RAG 진단에 넣어 봅니다. 답변의 근거가 연차 안내 문서이고 재작성된 질문이 원래 뜻을 유지하는지 확인한 뒤 공개합니다.
