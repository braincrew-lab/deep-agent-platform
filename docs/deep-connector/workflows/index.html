Deep Connector 반복 업무

같은 질문으로 검색 조건 비교하기​

문서가 정상 처리되었는데 원하는 근거가 잘 나오지 않을 때 사용하는 절차입니다. 자료를 새로 올리기 전에 검색 조건부터 비교합니다. 이미 시작하기를 완료한 컬렉션과 질문을 사용하세요.

  1. 실험 → 검색에서 대상 컬렉션을 선택합니다. 비교할 질문과 현재 검색 방식, 적용한 필터를 메모합니다.
  2. 자유 필터를 펼칩니다. Key-Value 버튼이 보이면 눌러 Key와 Value 입력칸이 있는 화면으로 전환합니다. 기존 필터 행 오른쪽의 휴지통 버튼으로 각 행을 제거합니다. 별도의 메타데이터 필터 영역에 선택한 필드가 있으면 필드 제거 버튼으로 해제합니다.
  3. 같은 질문으로 검색합니다. 원하는 문서가 나오는지, 답에 필요한 조건이 포함되는지 기록합니다.
  4. 검색 방식만 바꾸어 같은 질문을 다시 실행합니다. 예를 들어 문장으로 질문했다면 시맨틱 결과를 확인하고, 정확한 용어가 중요하다면 키워드 결과도 비교합니다.
  5. 다음에도 확인할 수 있도록 질문, 컬렉션 이름, 방식, 필터, 찾은 문서명을 작업 메모에 남깁니다.

검색 점수가 높아졌더라도 정답 조건이 빠졌다면 개선된 결과로 판단하지 않습니다. 같은 문서의 서로 다른 청크가 나올 수 있으므로, 제목만 비교하지 말고 본문까지 읽으세요. 최근 검색 항목을 다시 사용하더라도 현재 컬렉션 선택이 맞는지 확인합니다.

특정 문서로 검색 범위 좁히기​

같은 컬렉션에 비슷한 문서가 많다면 소스 값을 이용해 한 문서의 결과를 확인할 수 있습니다. 먼저 위 절차로 필터 없는 결과를 확인하고, 질문과 검색 방식은 그대로 유지하세요.

  1. 자유 필터를 펼치고 Key-Value 버튼이 보이면 눌러 입력 행 방식으로 전환합니다.
  2. 소스 로드를 누릅니다. 사용 가능한 소스 목록에서 찾으려는 문서의 실제 소스 값을 확인합니다. 목록을 불러오는 동작은 값을 보여주는 단계이며 필터를 자동으로 적용하지 않습니다.
  3. Add Filter를 눌러 행을 추가합니다. Key에는 source를, Value에는 목록에서 확인한 실제 소스 값을 그대로 입력합니다. 임의로 추정한 파일명 대신 표시된 값을 사용하세요.
  4. 별도의 메타데이터 필터 영역에도 선택 조건이 남아 있는지 확인합니다. 소스 하나만 비교하려면 각 필드를 제거합니다. 두 영역의 조건은 함께 적용되며, 같은 항목을 양쪽에 지정하면 메타데이터 필터의 값이 우선합니다.
  5. 검색 버튼을 눌러 같은 질문을 다시 실행합니다. 결과의 출처가 의도한 문서인지, 필요한 문장이 유지되는지 확인합니다.
  6. 자유 필터의 추가한 행 오른쪽 휴지통 버튼을 눌러 제거하고 같은 질문을 다시 검색합니다. 메타데이터 필터 영역도 비어 있는지 확인한 뒤 제한 전후 결과를 비교합니다.

소스 목록에 원하는 값이 없으면 해당 문서의 등록 상태와 메타데이터를 확인하세요. 소스 로드 목록에 보이지 않는다는 이유만으로 문서가 없다고 단정하지 않습니다. 결과가 없을 때에는 필터를 제거한 비교 결과부터 확인합니다.

개정 문서를 새 버전으로 반영하기​

규정의 숫자나 절차가 바뀌면 기존 문서를 삭제하기 전에 새 버전 업로드가 가능한지 확인하세요. 이 작업에는 문서 수정 권한이 필요합니다. 새 파일로 교체하면 문서가 다시 처리되고 직접 수정한 구성 단위는 새 결과로 바뀔 수 있으므로, 별도 보존이 필요한 수정 내용이 있는지 먼저 검토합니다.

  1. 대상 컬렉션의 문서 탭에서 개정할 문서를 열고 파일명과 현재 버전을 확인합니다.
  2. 새 버전 업로드를 누른 뒤 개정 파일 하나를 선택합니다. 다른 문서를 교체하지 않도록 대상 이름을 다시 확인합니다.
  3. 변경 사유에 “취소 신청 시점 변경”처럼 달라진 내용을 적습니다. 이 항목은 선택 사항이지만 이후 확인에 도움이 됩니다.
  4. 교체를 누릅니다. 동일한 파일이라는 안내가 나오면 실제로 수정한 파일을 선택했는지 확인하세요.
  5. 문서 목록에서 재처리가 완료되었는지 확인한 뒤 현재 버전의 내용을 읽습니다.
  6. 개정 전 확인했던 질문을 같은 컬렉션에서 다시 검색하고, 새 조건이 포함된 근거를 찾습니다.

이전 버전은 원본 열람과 변경 내용 대조에 활용합니다. 구성 단위와 검색은 현재 버전을 기준으로 확인하세요. 버전 번호 증가, 처리 완료, 개정 문장 검색을 각각 확인해야 반영을 판단할 수 있습니다.

반복 작업의 검토 기록 남기기​

비교 결과는 제품이 자동으로 판정해 주는 성공 보고서가 아닙니다. 담당자가 질문과 기대 근거를 정해 확인하는 작업입니다. 아래 정도를 기록하면 다음 개정 때 동일한 기준으로 점검할 수 있습니다.
