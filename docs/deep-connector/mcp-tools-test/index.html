Deep Connector 실험: MCP 도구 테스트

사이드바 실험 > MCP 도구 테스트는 에이전트가 Deep Connector를 검색할 때 쓰는 도구를 직접 실행해 보는 화면입니다. 에이전트가 근거를 못 찾을 때 같은 도구를 여기서 실행해 보면 문서 쪽 문제인지 질문 쪽 문제인지 가를 수 있습니다.

이 페이지에서 할 수 있는 일

  • 도구 목록에서 도구를 골라 설명과 입력 규칙을 읽습니다.
  • 파라미터를 넣어 도구를 실행하고 결과를 봅니다.
  • 도구 17개가 각각 무엇을 하는지 압니다.

화면 구성​

MCP 도구 테스트 화면

번호메뉴기능이런 때 사용하세요
1도구 검색도구 이름으로 목록을 좁힙니다.쓰려는 도구를 빨리 찾을 때
2실행 범위도구를 실행할 컬렉션을 고르는 창을 엽니다. 고르지 않으면 접근할 수 있는 전체 컬렉션이 대상입니다.한 컬렉션 안에서만 시험할 때
3도구 목록의 search_documents누르면 가운데에 그 도구의 이름, 종류(읽기), 설명과 입력 규칙이 나옵니다.어떤 값을 넣어야 하는지 볼 때
4쓰기 도구문서·컬렉션을 만들거나 지우는 도구 5개입니다. 잠금 표시가 붙어 있고, 실행 전에 확인 창이 나옵니다.일반 점검에는 쓰지 않습니다

파라미터와 실행

번호메뉴기능이런 때 사용하세요
1파라미터도구에 넘길 값입니다. 별표(*)는 필수입니다.질문을 적을 때
2고급 파라미터결과 수, 검색 방식, 검색 범위(path, document_ids) 같은 선택값입니다.검색 범위를 정할 때
3실행·초기화왼쪽은 도구를 실행하고, 오른쪽은 입력값을 비웁니다.값을 다 넣었거나 다른 조건으로 다시 할 때

실행 결과

번호메뉴기능이런 때 사용하세요
1실행 결과 요약성공·실패, 도구 이름, 걸린 시간입니다.실행이 끝났는지 볼 때
2보기·Raw JSON결과를 읽기 쉬운 화면이나 원문으로 봅니다.결과를 담당자에게 그대로 전달할 때
3결과찾은 청크와 점수입니다. 맨 위에는 실제 적용된 검색 설정이 나옵니다.에이전트가 볼 근거를 미리 읽을 때

도구 목록​

도구 목록에는 읽기 도구 12개와 쓰기 도구 5개가 있습니다. 쓰기 도구는 문서나 컬렉션을 실제로 바꾸므로 점검에는 읽기 도구만 쓰세요.

도구종류하는 일이런 때 실행해 보세요
search_documents읽기질문으로 청크를 찾습니다. 고급 파라미터의 path(예: "/규정 Q&A")나 document_ids로 범위를 정해야 실행됩니다.에이전트가 근거를 못 찾을 때 같은 질문으로
grep_documents읽기정확한 문구나 패턴이 들어 있는 곳을 찾습니다."E103" 같은 코드가 어느 문서에 있는지 볼 때
glob_paths읽기폴더와 컬렉션 경로를 이름으로 찾습니다.search_documents에 넣을 path 값을 모를 때
list_collections읽기접근할 수 있는 컬렉션 목록을 봅니다.토큰이 어떤 컬렉션을 볼 수 있는지 확인할 때
list_documents읽기컬렉션의 문서 목록을 봅니다. 처리에 실패한 문서도 나옵니다.문서가 실제로 들어 있는지 볼 때
list_chunks읽기컬렉션의 청크를 쪽 단위로 차례로 봅니다.문서가 어떻게 나뉘었는지 볼 때
read_document읽기문서 하나를 쪽 묶음이나 순서대로 읽습니다.검색으로 찾은 문서의 앞뒤 내용을 볼 때
explore_metadata읽기제품명, 기간, 코드처럼 정확한 조건으로 거를 수 있는 메타데이터 후보를 찾습니다.메타데이터 필터에 쓸 값을 정확히 알고 싶을 때
get_collection_metadata_schema읽기컬렉션에서 뽑힌 메타데이터 항목 구성을 봅니다.어떤 항목으로 거를 수 있는지 볼 때
get_collection_search_profile읽기컬렉션에 저장된 검색 설정과 실제 적용되는 설정을 봅니다.분석기·리랭커가 켜져 있는지 확인할 때
lookup_glossary_terms읽기전사 용어사전에서 용어의 정의, 약어, 유의어를 찾습니다.용어 사전이 검색에 반영되는지 볼 때
get_user_info읽기토큰이나 로그인한 사용자의 정보를 봅니다.누구 권한으로 실행되는지 확인할 때
add_document_text쓰기글 내용을 문서로 만들어 컬렉션에 넣고 처리를 시작합니다.점검에는 쓰지 않습니다
add_document_base64쓰기파일을 컬렉션에 올립니다. 받는 형식은 문서 올리기의 지원 형식과 같습니다.점검에는 쓰지 않습니다
create_collection쓰기새 컬렉션을 만듭니다.점검에는 쓰지 않습니다
delete_collection쓰기컬렉션과 안의 문서를 모두 지웁니다. 되돌릴 수 없습니다.점검에는 쓰지 않습니다
delete_document쓰기문서 하나를 지웁니다.점검에는 쓰지 않습니다

따라 해 보기​

  1. MCP 도구 테스트에서 search_documents를 고릅니다.
  2. query에 "재택근무 신청 마감"을 적습니다.
  3. 고급 파라미터를 펼치고 path에 "/규정 Q&A"를 적습니다.
  4. 실행을 누릅니다. 결과에 재택근무-운영-지침.docx 청크가 나오고 "전주 금요일 18시까지"가 보이면 됩니다.

검색 범위를 넣지 않으면 실행 결과에 검증 실패(ValidationError)가 나옵니다. 리랭커를 쓰는 환경에서는 결과가 나오기까지 시간이 걸릴 수 있습니다.

이럴 때 쓰세요: Builder의 "사내 규정 Q&A 비서"가 "재택근무 신청 마감"에 엉뚱한 답을 했다면, 김그루 사원은 이 화면에서 같은 질문으로 search_documents를 실행해 봅니다. 여기서도 재택근무 지침 청크가 안 나오면 문서 쪽(처리 결과, 검색 설정)을, 잘 나오면 에이전트 지침 쪽을 고칩니다.
