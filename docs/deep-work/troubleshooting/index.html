Deep Work 문제 해결

로그인할 수 없습니다​

브라우저에서 로그인을 눌렀는데 창이 열리지 않거나 로그인이 끝나지 않으면, 설정 화면의 연결 정보와 네트워크 상태를 먼저 확인합니다. 서버 주소는 제공 담당자에게 받은 값 그대로 입력해야 합니다. 주소가 다르면 로그인이 되지 않습니다.

화면의 오류 문구는 원인을 구별해 보여 줍니다. SSO 로그인을 완료하지 못했습니다라는 안내는 브라우저 로그인이 끝나지 않았을 때 나타납니다. 브라우저에서 로그인을 다시 시도하세요. 로그인 서버에 연결할 수 없다는 안내는 네트워크나 서버 주소 문제입니다. 회사 네트워크 연결 상태를 확인한 뒤 다시 시도하고, 반복되면 오류 문구와 발생 시간을 담당자에게 전달합니다. 비밀번호나 모델 키를 문의 본문에 넣지 않습니다. 해결 후에는 PC 에이전트를 선택할 수 있는 작업 화면까지 이동하는지 확인합니다.

메시지가 전송되지 않습니다​

새 스레드를 만들었는지 확인합니다. 응답이 진행 중이면 입력이 비활성화될 수 있습니다. 진행 상태와 오류 표시를 구별하고, 이미 전송한 요청을 여러 번 반복하지 마세요. 사용 가능한 모델이 없다는 안내가 나오면 모델을 설정한 뒤 다시 시도합니다.

작업 폴더를 아직 고르지 않았다면 대화 영역에 폴더 선택 안내가 나타납니다. 텍스트 요청은 바로 보낼 수 있지만, 파일을 첨부하거나 파일 작업을 맡기려면 작업 폴더가 필요합니다. 작업 폴더 선택에서 연습 폴더를 지정하고 입력란 아래에 폴더 이름이 나타나는지 확인하세요. 같은 오류가 반복되면 스레드 제목, 선택한 폴더 여부, 오류 문구를 기록합니다.

모델 목록이 없거나 키 등록 안내가 나옵니다​

설정의 모델 탭에서 제공자별 사용 가능한 모델 목록을 확인합니다. 목록이 비어 있으면 서버 연결 상태와 제공받은 모델 준비 여부를 담당자에게 문의합니다.

제공자에 키가 필요하다는 안내가 있으면 해당 공급자용으로 제공받은 키인지 확인합니다. 키를 등록한 뒤 목록에서 모델을 선택하고 선택 표시를 확인하세요. 키 저장만으로 사용 가능 여부를 확정하지 말고 짧은 요청에 실제로 응답하는지 확인합니다. 사용할 모델 자체가 없다면 임의의 모델 이름을 입력하지 말고 담당자에게 준비 상태를 문의합니다.

승인 요청에서 멈춘 것 같습니다​

대화 안에 승인 대기 작업이 있는지 확인합니다. 여러 요청이 보이면 각각의 대상과 내용을 읽습니다. 가능한 승인·거부 선택지는 작업에 따라 다를 수 있으므로 실제 표시된 동작을 사용합니다.

현재 업무와 맞는 요청인지 판단하기 어렵다면 진행을 허용하기 전에 담당자에게 작업 내용을 확인하세요. 버튼이 없다는 사실만으로 “아직 요청 생성 중”이라고 판단하지 않습니다. 승인 없이 진행되는 작업도 있습니다. 승인을 한 뒤에는 결과 응답과 실제 파일을 확인합니다. 승인이 완료되었다는 표시만으로 파일이 올바르게 완성된 것은 아닙니다.

완료했다고 하지만 파일이 없거나 내용이 다릅니다​

먼저 현재 스레드의 작업 폴더와 요청한 파일명을 확인합니다. 대화에서만 초안을 요청했는지, 실제 파일 저장까지 요청했는지도 읽어 보세요. 폴더를 바꾸어 요청했다면 이전 폴더에 파일이 생겼을 수도 있습니다. 폴더가 맞으면 컴퓨터에서 해당 폴더를 직접 열어 파일 존재 여부와 내용을 확인합니다.

파일이 없다면 “현재 작업 폴더에 요청한 파일이 있는지 확인하고 결과를 알려 주세요”처럼 확인부터 요청합니다. 파일이 있다면 열어서 누락된 내용을 구체적으로 지적합니다. 전체 작업을 다시 시키기 전에 이미 완료된 부분을 확인하면 불필요한 덮어쓰기를 줄일 수 있습니다.

작업이 느려졌거나 메모리 사용량이 커졌습니다​

화면 응답은 평소와 비슷한데 작업 중 메모리 사용량이나 PC 부담이 커진다면, 먼저 현재 사용 중인 빌드와 작업 상태를 담당자에게 확인하세요. 같은 환경에서 측정한 결과, 특정 변경 전후에 메인 프로세스의 메모리와 조작당 CPU 시간이 늘어난 사례가 있었고, 사용자가 느끼는 화면 응답성 자체는 크게 달라지지 않았습니다. 이 측정은 특정 Windows 환경의 결과이며 모든 설치 환경에 그대로 적용되지 않습니다. 이 현상만으로 파일 손상이나 메모리 누수를 단정하지 마세요.

다음 순서로 확인합니다.

  1. 같은 작업을 반복하기 전에 현재 버전, 작업 폴더, 스레드 상태를 기록합니다.
  2. 작업을 저장할 수 있다면 현재 결과와 파일을 먼저 확인한 뒤 앱을 다시 시작합니다.
  3. 다시 시작한 뒤 짧은 요청 하나로 응답 속도와 PC 부담이 달라졌는지 비교합니다.
  4. 문제가 계속되면 발생 시점, 반복 횟수, 사용한 작업 폴더, 스레드 상태, 앱 버전과 함께 담당자에게 전달합니다. 민감한 파일, 비밀번호, 모델 키는 보내지 않습니다.

다시 시작한 뒤에도 같은 작업에서만 문제가 반복되면 작업별 조건 차이를 확인할 필요가 있습니다. 파일 크기나 대화 기록이 영향을 주는지는 이 측정에서 확인하지 않았으므로 원인으로 단정하지 마세요. 빈 연습 폴더에서 짧은 요청으로 같은 현상이 나타나는지도 비교하면 담당자가 범위를 좁히는 데 도움이 됩니다. 연습 폴더에서는 정상이고 기존 작업에서만 느리다면 원본 작업을 덮어쓰지 말고 두 결과를 함께 전달합니다.

도움을 요청할 때​

PC 에이전트인지 원격 에이전트인지, 문제가 발생한 단계, 표시된 오류, 선택한 모델, 파일 존재 여부를 정리하세요. 폴더 전체 내용이나 원본 업무 자료 대신 가상 자료로 재현한 결과를 우선 전달합니다.

해결 후에는 막혔던 동작과 결과를 함께 다시 확인합니다. 첫 요청은 시작하기, 파일 검토 기준은 활용 사례에 있습니다.
