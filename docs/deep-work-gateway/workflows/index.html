Deep Work Gateway 반복 업무

변경 전에 대상과 이유 확인하기​

이 절차는 기존 사용자의 한도나 모델 권한을 바꾸는 관리자 업무입니다. 먼저 사용자 메뉴에서 이름 또는 사용자 ID로 검색하고 대상의 표시 이름과 ID를 확인합니다. 같은 이름의 다른 사용자를 변경하지 않도록 고정 ID도 함께 봅니다.

사용할 모델, 새 한도, 변경 이유를 조직의 기준에 맞춰 준비하세요. 아래 기록과 재확인 방법은 운영자가 수행하는 권장 절차이며 콘솔의 자동 승인 기능이 아닙니다.

한도 변경 후 다시 확인하기​

  1. 대상의 수정을 열고 현재 최대 예산, 예산 기간, 동시 요청 수를 기록합니다.
  2. 사용 한도 설정을 켜고 승인된 값을 입력합니다. 예를 들어 월 예산만 조정한다면 동시 요청 수와 기간을 함께 확인해 의도하지 않은 변경을 피합니다.
  3. 사용자 수정을 누른 뒤 목록의 예산 / 동시 요청을 확인합니다. 오류가 표시되면 저장됐다고 판단하지 말고 안내 내용을 확인하세요.
  4. 수정을 다시 열어 예산 기간과 각 값이 의도대로인지 확인합니다. 확인만 했다면 취소를 누릅니다.

설정을 끄거나 값을 지우면 제한을 없애는 결과가 될 수 있습니다. 이용 문제를 해결하려고 모든 한도를 무조건 해제하지 마세요. 기존 값으로 되돌릴 때도 조직에서 허용한 범위인지 확인합니다.

기존 키의 모델 배정 바꾸기​

  1. 사용자의 상세를 열고 변경할 키 별칭을 찾습니다. 새 키가 필요한 작업인지 기존 키의 권한 변경인지 먼저 구분합니다.
  2. 해당 키의 모델 권한 편집을 펼칩니다. 현재 선택과 “현재 비활성 배정” 안내 유무를 확인합니다.
  3. 앞으로 허용할 모델을 선택합니다. 목록에 없는 모델은 모델 메뉴의 게시 상태를 담당자와 확인합니다.
  4. 모델 권한 저장을 누릅니다. 저장 시 비활성 배정이 제거될 수 있으므로 경고가 있었다면 예상한 변화인지 확인하세요.
  5. 키의 배정 모델 수와 선택 상태를 다시 확인합니다. 모두 해제한 경우 모델 이용 권한이 없는 상태가 됩니다.

이 확인은 콘솔 설정에 관한 것입니다. 실제 이용 가능 여부를 확인하려면 해당 이용자의 사용 결과도 별도로 확인하세요.

특정 키의 이용을 중지해야 할 때​

대상 사용자의 상세에서 키 별칭을 확인하고 수동 차단을 누릅니다. 이후 “수동 차단” 상태와 수동 차단 해제 버튼이 나타나는지 확인하세요. 다시 허용할 근거가 있을 때 수동 차단 해제를 사용합니다.

“사용자 비활성으로 차단”이면 사용자 상태를 먼저 확인합니다. 수동 차단만 해제해도 사용자 비활성 상태가 남아 있으면 이용 준비가 된 것으로 판단할 수 없습니다. 승인된 변경인지 확인하고 사용자 수정에서 상태를 조정합니다.

변경 기록과 다음 점검​

사용자와 키 별칭, 바꾼 한도나 모델, 변경 시점, 저장 후 확인 결과를 별도 기록으로 남기는 것을 권합니다. 키의 비밀 값은 이 기록에 넣지 마세요.

이후 사용량을 살필 때는 비교 기간을 고정합니다. 활용 사례에서 기간별 확인을 연습하고, 저장 오류나 차단 상태가 해결되지 않으면 문제 해결을 따르세요.
