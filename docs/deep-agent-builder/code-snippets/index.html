Deep Agent Builder 코드 스니펫

코드 스니펫은 에이전트를 다른 호출 환경에서 재사용할 때 참고하는 실행 예시입니다. 스니펫을 확인하는 일과 에이전트를 실제로 실행하는 일은 별개입니다. 이 페이지는 스니펫의 대상과 입력을 확인하고, 인증 정보와 실행 결과를 안전하게 검증하는 방법을 설명합니다.

조회 전에 확인할 것​

먼저 사용하려는 에이전트가 맞는지 확인합니다. 목록이나 수정 화면에 보이는 이름만 비교하지 말고, 현재 업무에 사용할 대상과 설정을 함께 대조합니다. 에이전트의 지침, 모델, 연결된 도구와 스킬이 바뀌었다면 예전에 저장한 스니펫을 그대로 사용하지 않습니다.

스니펫을 조회할 수 있어도 에이전트를 실행할 수 있는 것은 아닙니다. 조회 권한, 실행 권한, 연결된 자원을 사용할 권한이 따로 적용될 수 있습니다. 대상이 보이지 않거나 조회가 거부되면 스니펫을 반복해서 요청하지 말고, 에이전트의 공유 범위와 필요한 권한을 먼저 확인합니다.

외부 호출에 사용할 계획이라면 다음 준비도 확인합니다.

  • 현재 에이전트가 사용하는 모델과 지침이 목적에 맞는지 확인합니다.
  • 스니펫에 표시된 입력 항목과 반환 형식을 읽습니다.
  • 호출하는 계정이 에이전트와 연결된 자원을 사용할 수 있는지 확인합니다.
  • 인증 헤더, 토큰, 주소처럼 환경에 따라 달라지는 값은 승인된 비밀 관리 경로로 연결합니다.

스니펫 가져오기​

스니펫 조회 화면이나 개발자용 호출 예시에서 먼저 대상 에이전트와 원하는 호출 형식을 선택합니다. 화면에서 확인할 수 없는 항목을 이름이나 설명만으로 추정하지 않습니다. 실제 화면에서 제공하는 형식과 입력 안내를 기준으로 판단합니다.

조회 결과가 나오면 다음 순서로 확인합니다.

  1. 결과가 의도한 에이전트에 대한 것인지 대상의 이름과 식별 정보를 대조합니다.
  2. 선택한 호출 형식이 현재 사용하는 환경과 맞는지 확인합니다.
  3. 필수 입력과 선택 입력을 구분합니다.
  4. 인증값과 환경 의존 값을 실제 비밀값과 분리합니다.
  5. 비식별 테스트 입력으로 응답 형식과 실패 동작을 확인합니다.

스니펫 안에 인증 헤더나 토큰 예시가 있어도 그 값을 공개 저장소, 문서, 채팅 기록이나 로그에 복사하지 않습니다. 예시 문자열은 구조를 확인하는 용도로만 보고, 실제 값은 실행 환경의 승인된 비밀 관리 절차로 주입합니다.

조회와 실행 결과를 구분하기​

스니펫을 정상적으로 받았다는 사실은 에이전트 호출의 성공을 의미하지 않습니다. 다음 세 결과를 따로 기록합니다.

  1. 스니펫 조회가 성공했는가
  2. 복사한 호출이 인증과 입력 검증을 통과했는가
  3. 에이전트가 현재 지침, 모델과 연결된 자원을 사용해 기대한 결과를 반환했는가

호출이 실패하면 인증과 권한, 입력 형식, 에이전트 상태, 연결된 자원 순서로 범위를 좁힙니다. 같은 요청을 바로 반복하지 말고 화면이나 응답에 표시된 실패 원인을 기록합니다. 스니펫에 적힌 주소와 설정이 현재 환경에서 지원되는지도 확인합니다.

정상 입력만 시험하지 말고 필수 입력이 빠진 경우도 별도로 확인합니다. 두 결과를 비교하면 호출 형식이 무엇을 요구하는지와 실패가 입력 문제인지 권한 문제인지 구분하기 쉽습니다. 테스트에는 고객 데이터나 실제 비밀값을 사용하지 않습니다.

설정을 바꾼 뒤 다시 조회하기​

에이전트의 지침, 모델, 도구, 미들웨어, 스킬 또는 연결 자원을 바꿨다면 변경 내용을 저장한 뒤 현재 설정을 다시 확인합니다. 저장된 설정과 이전 스니펫의 내용이 다르면 새 스니펫을 조회해 입력과 반환 형식을 다시 검토합니다.

저장 성공은 호출 결과나 답변 품질을 보장하지 않습니다. 저장된 설정이 화면에 다시 표시되는지 확인한 다음, 비식별 테스트 입력으로 실제 동작을 별도로 확인합니다.

문제가 생겼을 때​

스니펫이 보이지 않으면 다음 순서로 확인합니다.

  1. 대상 에이전트가 현재 계정이나 공유 범위에 포함되는지 확인합니다.
  2. 스니펫 조회 권한이 있는지 확인합니다.
  3. 에이전트가 보관되었거나 사용 중지된 상태가 아닌지 확인합니다.
  4. 현재 화면에서 지원하는 호출 형식과 입력 조건을 확인합니다.

스니펫은 보이지만 호출이 거부되면 조회 권한과 실행 권한을 나눠 확인합니다. 호출은 되지만 결과가 다르면 이름이나 설명만 바꾸지 말고 지침, 모델, 연결 자원과 입력을 각각 비교합니다.

인증값이 공개된 상태로 복사됐다면 문서나 로그에서 문자열을 삭제하는 것만으로 끝내지 않습니다. 해당 비밀값을 교체해야 하는지 보안 담당자나 운영 절차에 따라 판단하고, 이후에는 승인된 비밀 관리 경로를 사용합니다.

캡처와 공개 범위​

현재 페이지는 실제 제품 화면의 메뉴명이나 성공 알림을 확인하지 않은 상태이므로 특정 버튼, 다운로드 동작이나 화면 경로를 단정하지 않습니다. 화면을 추가할 때는 비식별 데모 에이전트로 대상, 호출 형식과 조회 결과가 같은 대상을 가리키는지 확인해야 합니다. 토큰, 주소, 고객명, 이메일과 내부 식별자는 화면과 이미지 메타데이터에서 제거합니다.

실제 화면에서 이 관계를 안전하게 판별할 수 없다면 캡처를 넣지 않고 본문 절차만 유지합니다. 화면 촬영과 비식별 검토는 공개 본문과 분리된 편집 절차로 관리합니다.
