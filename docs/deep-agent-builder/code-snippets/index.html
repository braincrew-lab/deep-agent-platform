코드 스니펫과 외부 API

Deep Agent Builder에서 만든 에이전트는 채팅 화면 밖의 사내 시스템이나 자동화 도구에서도 부를 수 있습니다. 이 페이지는 브레인크루 AI혁신팀 김그루 사원이 시장 조사 리서처를 팀의 n8n 자동화에서 부르기 위해 API 키를 발급하고, 코드 스니펫 창에서 호출 예시를 복사하고, Webhook을 켜는 과정을 설명합니다. 개발 코드를 직접 다루지 않는 사용자 관점에서 각 화면이 무엇을 위한 것인지에 집중합니다.

이 페이지에서 할 수 있는 일

  • 외부에서 에이전트를 부르는 네 가지 방식(Invoke, 스트림 (SSE), 백그라운드 실행, Webhook)의 차이를 알고 업무에 맞게 고릅니다.
  • 에셋 화면의 API 키 탭에서 스코프와 만료일을 정해 API 키를 발급하고, 한 번만 보이는 키를 안전하게 보관합니다.
  • 에이전트 편집 화면의 코드 스니펫 창에서 방식과 언어(Python, JavaScript, cURL)를 골라 호출 예시를 복사합니다.
  • 설정 탭에서 Webhook 활성화를 켜고 Webhook URL을 복사해 외부 자동화 도구(예: n8n)에 넘깁니다.

외부에서 부르는 방식 고르기​

방식하는 일필요한 API 키 스코프이런 때 고르세요
Invoke질문을 보내고 답이 끝날 때까지 기다렸다가 한 번에 받습니다.invoke(에이전트를 동기 호출)짧은 요약이나 분류처럼 금방 끝나는 요청
스트림 (SSE)답이 만들어지는 대로 조금씩 받습니다.stream(에이전트 응답 스트리밍)사내 포털에 채팅 창을 붙여 글자가 바로바로 보여야 할 때
백그라운드 실행요청을 맡겨 두고, 나중에 결과를 확인합니다.background(에이전트를 백그라운드에서 실행)자료가 많아 오래 걸리는 보고서 작성
Webhook정해진 주소로 질문을 보내 답을 받습니다. 단순한 질의-응답에 맞고 외부 자동화 도구(예: n8n, Dify)와 연결하기 쉽습니다.invoke자동화 도구가 새 시장 자료를 받을 때마다 요약을 받아 오게 할 때

API 키는 스코프에 표시된 방식만 쓸 수 있습니다. 읽기 전용 접근이 필요한 경우를 위한 read 스코프도 있습니다.

API 키 발급하기​

외부에서 에이전트를 부르려면 API 키가 필요합니다. 사이드바의 에셋설정을 눌러 여는 에셋 화면에서 API 키 탭을 엽니다. 키가 없으면 "생성된 API 키가 없습니다."와 "API 키 추가를 눌러 첫 API 키를 생성하세요." 안내가 보입니다.

API 키 추가를 누르면 API 키 생성 창이 열립니다. 설명은 "외부 시스템에서 에이전트에 접근할 수 있도록 새 API 키를 생성합니다."입니다.

API 키 생성 창

번호메뉴기능이런 때 사용하세요
1이름 *키 이름입니다. 꼭 적어야 하며 100자까지 쓸 수 있습니다.쓰는 곳이 드러나는 이름을 붙일 때
2만료 (일)1일부터 365일까지 넣습니다. 비워 두면 만료되지 않습니다.일정 기간 뒤 자동으로 막히게 할 때
3스코프이 키로 허용할 방식을 invoke, stream, background, read 중에서 고릅니다. 창을 열면 invoke, stream, background가 체크되어 있습니다.꼭 필요한 방식만 허용할 때
4생성키를 만듭니다.입력을 마쳤을 때

이럴 때 쓰세요: 김그루 사원은 키를 쓰는 곳마다 따로 만듭니다. n8n 시장 조사 연동용 키는 invoke만 허용하고, 사내 포털 채팅 창을 시범 운영할 때 쓸 키는 stream만 허용해 시범 기간에 맞춰 만료일을 짧게 잡습니다. 한 키를 여러 곳에 함께 쓰지 않으면 한쪽 연동이 끝났을 때 그 키만 지워도 다른 연결은 그대로 동작합니다.

이름 아래 설명 칸에는 키 용도를 적습니다. 비워 둬도 되지만, 나중에 이 키를 왜 만들었는지 알아보기 쉽게 적어 두는 편이 좋습니다.

키를 만들면 "API 키가 생성되었습니다" 창이 열리고 키 값이 한 번만 표시됩니다.

API 키가 생성되었습니다 창

번호메뉴기능이런 때 사용하세요
1경고 문구"이 API 키는 한 번만 표시됩니다. 지금 복사하여 안전하게 보관하세요."가 보입니다.창을 닫기 전에 키를 옮겨 둬야 함을 확인할 때
2API 키새 키 값입니다. 이 창에서만 볼 수 있습니다.키 값을 확인할 때
3복사 버튼키 값을 클립보드에 복사합니다.키를 보관함에 옮길 때
4완료창을 닫습니다. 닫은 뒤에는 키 값을 다시 볼 수 없습니다.키를 안전한 곳에 옮긴 뒤

팁: 키를 잃어버리면 다시 볼 방법이 없습니다. 새 키를 만들고 예전 키는 지우세요. 키는 메신저나 메일 본문에 그대로 붙여 보내지 않습니다.

API 키 목록​

API 키 탭의 표에서 만든 키를 관리합니다. 위쪽 검색 칸에 이름 일부를 넣으면 목록이 걸러집니다.

API 키 목록

번호메뉴기능이런 때 사용하세요
1API 키 탭내가 만든 API 키 목록을 엽니다.키를 만들거나 정리할 때
2API 키 추가API 키 생성 창을 엽니다.새 키가 필요할 때
3이름키 이름과 그 아래 키 앞부분이 보입니다. 키 전체 값은 보이지 않습니다.어떤 키가 어디에 쓰이는지 확인할 때
4스코프이 키에 허용한 방식입니다.키로 부를 수 있는 방식을 확인할 때

API 키 목록의 사용 기록과 삭제

번호메뉴기능이런 때 사용하세요
1마지막 사용마지막으로 쓰인 때입니다. 한 번도 쓰지 않은 키는 "-"로 보입니다.연결이 실제로 동작하는지 확인할 때
2사용량호출 횟수입니다. 한 번도 쓰지 않은 키는 0입니다.호출이 얼마나 들어오는지 볼 때
3만료키가 만료되는 날짜입니다.키를 언제 바꿔야 하는지 확인할 때
4삭제 버튼행 끝 작업 열의 휴지통 아이콘입니다. 키를 영구 삭제하며, 이 키를 쓰는 모든 서비스가 즉시 멈춥니다.더 쓰지 않거나 노출된 키를 없앨 때

코드 스니펫 창​

에이전트 편집 화면 위쪽 헤더의 코드 스니펫 아이콘을 누르면 이 에이전트를 부르는 예시 코드가 담긴 창이 열립니다. 개발 담당자에게 넘길 호출 예시를 여기서 복사합니다.

코드 스니펫 창

번호메뉴기능이런 때 사용하세요
1코드 스니펫 아이콘헤더에서 코드 스니펫 창을 엽니다.호출 예시가 필요할 때
2방식 탭Invoke, 스트림 (SSE), 백그라운드 실행, Webhook 중 고릅니다. Webhook은 Webhook을 켜지 않았으면 코드 위에 "Webhook 활성화가 OFF입니다"가 보입니다.외부에서 부를 방식을 정할 때
3언어 탭Python, JavaScript, cURL 중 고릅니다.개발 담당자가 쓰는 언어로 예시를 볼 때
4복사지금 보이는 예시를 복사하고 "클립보드에 복사되었습니다" 알림을 띄웁니다.예시를 넘길 때

탭 아래 코드 영역에는 고른 방식과 언어의 호출 예시가 보입니다. 요청 모양을 확인할 때 이 영역을 봅니다. 창 맨 위에는 요청에 넣을 인증 헤더 모양과 "API Key는 별도 메뉴에서 발급/관리하세요" 안내가 보입니다. 예시 코드에는 실제 API 키가 들어 있지 않고, 환경 변수에서 키를 읽는 자리만 있습니다. 개발 담당자에게 예시를 넘길 때 키를 함께 붙여 보내지 말고, 키는 사내 보관함 같은 안전한 경로로 따로 전달하세요.

Webhook 켜기​

Webhook은 에이전트 편집 화면 오른쪽 설정 탭의 Webhook 묶음에서 켭니다. 안내 문구는 외부 시스템(n8n, Dify 등)에서 REST API로 에이전트를 호출할 수 있고 API Key 인증이 필요하다는 내용입니다.

Webhook 묶음

번호메뉴기능이런 때 사용하세요
1Webhook 활성화켜면 이 에이전트의 Webhook URL이 만들어집니다. 바꾸는 즉시 저장되고 "에이전트 설정이 저장되었습니다" 알림이 뜹니다.외부에서 부르기 시작하거나 멈출 때
2Webhook URL외부 도구가 요청을 보낼 주소입니다. 스위치를 켰을 때만 보입니다.자동화 도구에 주소를 넣을 때
3복사 버튼Webhook URL을 복사합니다.주소를 넘길 때
4API 키 안내호출할 때 invoke 스코프를 포함한 API 키를 인증 헤더에 넣어야 한다는 안내입니다.어떤 키가 필요한지 확인할 때

이럴 때 쓰세요: 영업팀이 매주 받는 업계 소식 메일을 n8n이 받아 시장 조사 리서처의 Webhook URL로 보내면, 요약이 돌아와 팀 메신저 채널에 올라가게 할 수 있습니다. 김그루 사원은 Webhook URL과 함께 요청에 넣을 질문 문장(예: 메일 내용을 다섯 줄로 요약하고 출처를 적어 주세요)을 정해 이서준 선임에게 넘겨, 매번 같은 형식의 요약이 오게 합니다. 쌓인 요약 가운데 눈에 띄는 소식은 주간 업무 보고의 시장 동향 항목으로 옮깁니다.

스위치를 켜면 헤더 저장 옆에 "저장되지 않은 변경이 있습니다"가 보입니다. 계속 쓸 설정이면 헤더 저장을 눌러 현재 버전에도 기록해 둡니다.

따라 해 보기: n8n에서 시장 조사 리서처 부르기 준비​

김그루 사원이 팀 n8n 담당 이서준 선임에게 연결 정보를 넘기는 순서입니다. n8n 쪽 설정 화면은 n8n 안내를 따르며 이 매뉴얼에서는 다루지 않습니다.

  1. 사이드바의 에셋설정을 눌러 여는 에셋 화면의 API 키 탭에서 API 키 추가를 누릅니다.
  2. 이름에 "AI혁신팀 n8n 시장 조사", 설명에 "시장 조사 리서처 Webhook 연동", **만료 (일)**에 90을 넣고, 스코프는 stream과 background 체크를 풀어 invoke만 남긴 뒤 생성을 누릅니다.
  3. 한 번만 보이는 키를 복사해 팀 비밀번호 보관함에 저장하고 완료를 누릅니다.
  4. 사이드바에서 시장 조사 리서처를 누르고 에이전트 설정 > 오른쪽 설정 탭으로 갑니다.
  5. Webhook 묶음의 Webhook 활성화를 켜고, Webhook URL을 복사합니다.
  6. 헤더의 코드 스니펫에서 Webhook 탭과 cURL을 골라 복사합니다.
  7. 이서준 선임에게 Webhook URL과 cURL 예시를 보내고, API 키는 보관함 공유로 따로 전달합니다.
  8. 연결이 끝나면 API 키 탭에서 그 키의 마지막 사용이 바뀌었는지 확인합니다.

팁: 결과가 이상하면 먼저 채팅 화면에서 같은 자료로 시험해 보고, 지침을 고친 뒤 다시 연결을 확인하세요. 시장 조사 흐름은 사례: 시장 조사 보고서에 있습니다.

넘긴 뒤 관리할 것​

  • 키를 쓰는 곳이 바뀌거나 담당자가 바뀌면 새 키를 만들고 예전 키를 삭제합니다.
  • 에이전트를 더 이상 외부에서 부르지 않으면 Webhook 활성화를 끕니다.
  • 에이전트를 MCP 호환 클라이언트에서 쓰고 싶다면 Webhook 대신 MCP 서버로 여는 방법도 있습니다. MCP와 에이전트의 MCP화를 참고하세요.
