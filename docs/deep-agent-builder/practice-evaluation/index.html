Deep Agent Builder 실습 6: 평가 데이터셋으로 에이전트를 채점하고 고친 뒤 다시 비교하기

이 실습은 실습 1에서 만든 "고객 문의 답장 도우미"를 고객 문의 질문 묶음으로 채점하고, 떨어진 이유를 읽어 지침을 고친 뒤, 같은 조건으로 다시 채점해 두 결과를 비교합니다. 평가 화면 각 탭의 설명은 에이전트 평가 개요부터 이어지는 평가 장에 있으므로, 이 페이지는 처음부터 끝까지 한 번에 돌리는 손동작과 결과를 읽는 법에 집중합니다.

이 페이지에서 할 수 있는 일

  • CSV 파일 하나로 평가 데이터셋을 만들고, 문항을 고치거나 더합니다.
  • 기본 평가기를 복사해 우리 회사 응대 기준을 채점하는 평가기 "응대 기준 준수"를 만듭니다.
  • 평가를 실행하고 요약 카드, 결과 표, 결과 상세에서 떨어진 이유를 찾습니다.
  • 지침을 고쳐 새 버전으로 저장한 뒤 같은 조건으로 다시 실행하고, 실행 비교와 대시보드로 전후를 확인합니다.

목표​

항목내용
만들 것데이터셋 "고객 문의 답장 기본 문항"(9문항), 사용자 평가기 "응대 기준 준수", 고친 지침 버전(V2 "평가 반영 수정")
결과물고치기 전 실행과 고친 뒤 실행 두 개, 그리고 두 실행의 비교 결과
걸리는 시간준비 15분, 실행 한 번에 1~2분, 결과 읽기와 수정 15분
난이도★★★★☆

준비물​

파일내용형식
고객문의_평가문항_8건.csv브레인크루로 들어온 고객 문의 8개(question 열)와, 각 문의를 어떻게 응대해야 하는지 적은 기대 응대(answer 열)csv
브레인크루_고객문의_응대기준.md평가기 프롬프트에 옮겨 적을 응대 원칙(첫 문장 되짚기와 감사 인사, 결론→근거→다음 안내, [담당자 확인 필요] 표시, 해요체, 마무리 문장). 파일은 올리지 않고 내용만 참고합니다.md
고객 문의 답장 도우미실습 1에서 만든 에이전트. 김그루 사원의 사이드바 내 에이전트에 있습니다.에이전트

데이터셋을 파일로 만들 때 올릴 수 있는 확장자는 .csv 하나입니다. 엑셀에서 작성했다면 "CSV UTF-8(쉼표로 분리)"로 저장해 올립니다. 첫 줄의 열 이름은 영문 question, answer로 적습니다.

CSV의 첫 두 행은 다음과 같습니다.

questionanswer
보고서 자동 작성 기능이 엑셀 파일도 지원하나요?제품 기능 문의로 분류하고, 결론-근거-다음 안내 순서로 엑셀 지원 여부를 안내하며, 확인되지 않은 세부 사항은 [담당자 확인 필요]로 표시한다.
연간 계약하면 할인율이 얼마인가요?계약·견적 문의로 분류하고, 할인율을 확정하지 않고 [담당자 확인 필요]로 표시하며 영업팀 안내로 마무리한다.

1단계. 평가 화면 열기​

더 보기 &gt; 평가

번호메뉴입력하거나 고를 값
1더 보기사이드바에서 누릅니다. 오른쪽에 유틸리티, 작업, 평가 메뉴가 펼쳐집니다.
2평가"평가 데이터셋, 실행, 평가기를 관리합니다." 항목을 누릅니다.
  1. 사이드바의 더 보기를 누릅니다.
  2. 펼쳐진 메뉴에서 평가를 누릅니다. 평가 화면이 열리고 데이터셋 탭이 먼저 보입니다.

2단계. 템플릿과 작성 가이드 확인하기​

템플릿 내려받기

번호메뉴기능이런 때 사용하세요
1작성 가이드"평가 데이터셋 작성 가이드" 창을 엽니다.CSV를 쓰기 전에 열마다 무엇을 적을지 확인할 때
2템플릿빈 CSV 양식을 내려받는 메뉴를 펼칩니다.열 이름을 직접 타이핑하지 않고 양식에서 시작할 때
3템플릿 (영문 열)question, answer와 근거 열이 영문 이름으로 들어 있는 CSV 양식을 내려받습니다. 옆에 **템플릿 (한글 열)**도 있습니다.이 실습처럼 영문 열 이름으로 맞출 때
4데이터셋 생성3단계에서 쓸 데이터셋 생성 창을 엽니다.파일이 준비되었을 때

평가 데이터셋 작성 가이드

번호메뉴기능이런 때 사용하세요
1템플릿 (영문 열)가이드 창 안에서도 같은 양식을 내려받을 수 있습니다.가이드를 읽다가 바로 양식을 받을 때
2질문 행"실제 사용자 말투로 쓰고, 답이 하나로 정해지게 합니다."고객이 실제로 보낸 문장을 그대로 question에 적을 때
3답변 행"확인 가능한 사실(수치, 명칭, 예/아니오와 조건)을 간결하게 적습니다."기대 응대를 한두 문장으로 줄여 answer에 적을 때
  1. 템플릿을 누르고 **템플릿 (영문 열)**을 골라 양식을 내려받습니다. 이 실습은 준비물의 CSV를 그대로 쓰므로 양식은 열 이름을 확인하는 용도입니다.
  2. 작성 가이드를 눌러 한 장 요약의 질문 행과 답변 행을 읽습니다. 근거문서, 청크, 답변가능 열은 지식을 찾아 답하는 에이전트용이라 이 실습에서는 비워 둡니다. 가이드 전체 설명은 평가 데이터셋 만들기에 있습니다.
  3. 오른쪽 위 X로 가이드 창을 닫습니다.

3단계. CSV 파일로 데이터셋 만들기​

데이터셋 생성 창 위쪽

번호메뉴입력하거나 고를 값
1이름고객 문의 답장 기본 문항
2설명고객 문의 답장 도우미의 분류·응대 기준 준수를 점검하는 기본 문항
3CSV 파일시작 방법에서 고른 채로 둡니다(처음 값).
4파일고객문의_평가문항_8건.csv. 올리면 파일 이름과 1.7 KB가 보입니다.

CSV 미리보기

번호메뉴확인할 것
1미리보기question, answer 두 열로 나뉘어 앞 다섯 행이 보이는지, 한글이 깨지지 않았는지
2남은 행 안내"그 외 3행이 더 있습니다."로 모두 8행인지
3생성확인을 마치면 누릅니다.
  1. 데이터셋 생성을 누릅니다.

  4. 창을 아래로 내려 미리보기를 확인하고 생성을 누릅니다. 목록에 "고객 문의 답장 기본 문항"이 문항 8로 나타납니다.

4단계. 문항 확인하고 하나 고치기, 하나 더하기​

데이터셋 상세

2평가 설정이 데이터셋의 채점 설정을 펼칩니다(5단계). 옆의 "없음 · 자동"은 지금 문서 버전과 언어 값입니다.주 지표를 정할 때
3문항 6 편집(연필)그 문항의 "문항 수정" 창을 엽니다. 옆 휴지통은 문항을 지웁니다.기대 응대를 더 분명하게 고칠 때
4문항 추가빈 "문항 추가" 창을 엽니다.빠진 유형의 문의를 더할 때

문항 수정 창

번호메뉴입력하거나 고를 값
1질문회의록 요약 기능을 시험해 볼 수 있는 방법이 있나요?(그대로 둡니다)
2참조 답변교육·도입 문의로 분류하고, 체험 방법을 안내하며 체험 기간 같은 조건은 확정하지 않고 [담당자 확인 필요]로 표시한 뒤 AI혁신팀 안내로 마무리한다.
3사용 안 함재질의 평가는 쓰지 않으므로 처음 값 그대로 둡니다.

  3. 참조 답변을 위 표대로 고치고 저장을 누릅니다.
  4. 문항 추가를 누르고 아래 값을 넣어 저장합니다. 문항 수가 "총 9개"로 바뀝니다.
    • 질문: 제안서 PPT 작성기를 우리 회사 서식으로 바꿀 수 있나요? 비용이 따로 드나요?
    • 참조 답변: 제품 기능 문의와 계약·견적 문의가 섞인 것으로 분류하고, 서식 변경 가능 여부를 결론-근거-다음 안내 순서로 안내하되 추가 비용은 확정하지 않고 [담당자 확인 필요]로 표시하며 영업팀 안내로 마무리한다.

6단계. 사용자 평가기 "응대 기준 준수" 만들기​

평가기 탭

번호메뉴기능이런 때 사용하세요
1정확성 (Accuracy) 카드기본 평가기입니다. 카드를 누르면 이 평가기를 복사하는 창이 열립니다.통과/실패 평가기를 바탕으로 우리 기준을 만들 때
2응대 기준 준수 카드저장하면 사용자 평가기에 생기는 카드입니다. 통과/실패 배지가 붙습니다.만든 평가기를 확인하거나 고칠 때

복사해서 새 평가기 만들기

번호메뉴입력하거나 고를 값
1이름응대 기준 준수("정확성 (Accuracy) (복사본)"을 지우고 입력)
2평가 유형통과/실패 그대로 둡니다. 통과/실패에서는 점수 범위 칸이 나오지 않고 통과(1)와 실패(0)로 채점합니다.
3프롬프트 템플릿아래 프롬프트로 바꿉니다.
4저장누르면 "평가기를 만들었습니다."가 뜹니다.

  1. 평가기 탭을 엽니다.

  2. 기본 평가기의 정확성 (Accuracy) 카드를 누릅니다. "복사해서 새 평가기 만들기" 창이 열립니다.

  3. 이름을 "응대 기준 준수"로, 설명을 "첫 문장 되짚기·감사, 유형 분류, 확정 금지 표시, 해요체, 마무리 문장 다섯 가지를 모두 지켰는지 봅니다."로 바꿉니다.

  4. 프롬프트 템플릿의 영어 프롬프트를 지우고 아래 내용을 넣습니다. {question}에는 데이터셋의 질문, {reference_answer}에는 참조 답변, {agent_answer}에는 에이전트 답변이 들어갑니다. {agent_answer}는 꼭 있어야 합니다.

    프롬프트: 너는 브레인크루 고객 문의 답장 초안을 검토하는 채점자다.

    고객 문의: {question}

    기대 응대: {reference_answer}

    에이전트 답장: {agent_answer}

    아래 다섯 가지를 모두 지키면 1, 하나라도 어기면 0을 준다.

    1. 첫 문장에서 문의 내용을 되짚고 감사 인사를 한다.
    2. 기대 응대에 적힌 문의 유형에 맞게 답한다.
    3. 가격, 할인율, 계약 조건, 일정은 확정하지 않고 [담당자 확인 필요]로 표시한다(해당하는 문의일 때만).

  3. 데이터셋별 성적과 전체 실행 표에서 두 실행의 정답률과 평가기를 확인하고, "#5 0.0% → #6 88.9%"처럼 보고서에 옮깁니다.

대시보드의 다른 칸은 에이전트 평가 요약에 있습니다.

이럴 때 쓰세요: 김그루 사원은 고객 문의 답장 도우미를 팀에 공유하기 전에 "응대 기준을 정말 지키는지" 숫자로 보여 달라는 요청을 받았습니다. 지난주 실제로 들어온 문의 여덟 개를 CSV로 정리해 데이터셋을 만들고, 응대 기준 문서를 그대로 옮긴 평가기로 채점했더니 0%가 나왔습니다. 채점 사유를 읽어 보니 내용은 맞는데 감사 인사, 해요체, 마무리 문장이 빠져 있었습니다. 지침 세 줄을 더해 다시 돌린 결과 88.9%가 되었고, 남은 한 문항(요금 계산을 단정한 답)은 다음 수정 거리로 팀장에게 함께 보고했습니다.

흔한 실수와 해결​

증상원인해결
CSV를 골랐는데 "CSV 헤더에 question, answer 열이 있어야 합니다."가 뜹니다.첫 줄 열 이름을 "질문", "답변"처럼 적었거나 다른 이름을 썼습니다.첫 줄을 영문 question, answer로 고치거나 **템플릿 (영문 열)**에서 시작합니다.
정답률이 0%인데 이유를 모르겠습니다.평가기 프롬프트가 어긴 항목을 적게 하지 않았습니다.프롬프트에 "reasoning에는 어긴 항목 번호와 이유를 적는다"를 넣어, 채점 사유에서 번호를 모아 볼 수 있게 합니다.
Fix 에이전트가 "이미 반영되어 있다"고 답했는데 다시 돌려도 점수가 같습니다.Fix 에이전트가 지침을 실제로 바꾸지 않았습니다. 예시의 첫 요청에서 이런 일이 있었습니다.가운데 지침에서 바뀐 줄을 직접 확인하고, 없으면 "어느 섹션 맨 아래에 다음 줄을 그대로 추가해 주세요"처럼 위치와 문장을 정확히 적어 다시 요청합니다.
두 실행의 점수 차이를 믿기 어렵습니다.다시 실행할 때 평가기, 데이터셋 문항, 채점 모델 가운데 하나가 바뀌었습니다.비교가 끝날 때까지 평가기와 문항을 고치지 않고, 실행 생성 창의 세 칸을 같은 값으로 둡니다.
실행 유효성이 주의로 나옵니다.실행 중 사내 지식 검색 도구가 시간 초과되었습니다.무효가 아니면 비교에 쓸 수 있습니다. 검색 결과가 중요한 에이전트라면 같은 조건으로 다시 실행해 확인합니다.
평가 설정을 바꾸려는데 저장이 안 됩니다.이 데이터셋으로 진행 중인 평가 실행이 있습니다.실행이 끝난 뒤 바꿉니다. 주 지표는 첫 실행 전에 정해 둡니다.

응용 과제​

  1. 10단계에서 남은 실패 문항을 고치도록 "요금 문의에는 1인당 금액이나 총액을 계산해 단정하지 말고 [담당자 확인 필요]로 표시한다"를 지침에 더한 뒤, 같은 조건으로 세 번째 실행을 돌려 #6과 비교해 보세요.
  2. 같은 데이터셋을 기본 평가기 **전문성 (Professional)**으로도 실행해, 형식 기준과 어조 점수가 함께 나아졌는지 대시보드의 평가기 성능에서 비교해 보세요.
  3. 반복 횟수를 3으로 두고 다시 실행해, 같은 지침에서도 문항별 결과가 흔들리는지 실행 비교의 문항별 다수결로 확인해 보세요.
