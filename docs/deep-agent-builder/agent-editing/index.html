에이전트 수정

에이전트를 쓰다 보면 지침에 규칙을 더하거나, 모델과 연결 항목을 바꾸거나, 답이 달라진 원인을 찾아 이전 상태로 돌아가야 할 때가 있습니다. 이 페이지는 에이전트 편집 화면의 메뉴를 헤더, 가운데 편집 영역, 오른쪽 탭 순서로 설명하고, 김그루 사원이 주간 업무 보고서 도우미의 지침에 규칙을 더해 새 버전으로 저장하고 되돌리는 과정을 따라 합니다.

이 페이지에서 할 수 있는 일

  • 에이전트 편집 화면의 헤더, 폼·비주얼 편집 영역, 오른쪽 탭에 있는 메뉴가 각각 무엇을 바꾸는지 확인합니다.
  • 헤더의 저장을 눌러야 저장되는 항목, 바꾸는 즉시 반영되는 항목, 설정 탭 카드의 버튼으로 저장하는 항목을 구분합니다.
  • 모델과 파라미터를 바꾸고 변경 사항 확인 창에서 바뀌는 값을 확인한 뒤 저장합니다.
  • 설정 탭에서 에이전트 모드, Recursion Limit, MCP 서버, Webhook, Context Compaction을 조정합니다.
  • 지침을 고친 뒤 새 버전으로 저장하고, 버전 목록에서 이전 버전으로 되돌립니다.
  • 에이전트를 복제하거나 삭제하고, 워크스페이스에 등록을 요청합니다.

에이전트 편집 화면 열기와 전체 구성​

에이전트 대화 화면에서 왼쪽 사이드바의 에이전트 설정을 누르면 에이전트 편집 화면이 열립니다. 사이드바에는 대화 화면으로 돌아가는 뒤로, 이 에이전트와 새 대화를 여는 이 에이전트와 새 대화, 지금 화면인 에이전트 설정이 그대로 보입니다. 작업 영역은 위쪽 헤더, 가운데 편집 영역, 오른쪽 탭으로 나뉩니다. 헤더에는 이름, 설명과 저장·버전 버튼이 있고, 가운데 편집 영역에서는 폼 / 비주얼 전환으로 지침, 서브에이전트, 모델 설정, 도구함, 지식함, 미들웨어를 고칩니다. 오른쪽에는 Fix 에이전트, 테스트, 오프너, 파일, 스킬, 스케줄, 설정 탭이 있어, 가운데에서 바꾼 구성을 바로 시험하거나 실행 설정을 조정합니다.

저장되는 방식​

에이전트 편집 화면의 항목은 저장되는 방식이 세 가지입니다. 헤더의 버전 안내를 누르면 저장과 버전에 대한 안내를 화면에서도 볼 수 있습니다.

첫째, 이름, 설명, 지침은 헤더의 저장을 눌러야 현재 버전에 저장됩니다. 고치면 저장 옆에 "저장되지 않은 변경이 있습니다"가 보이고 저장이 눌리는 상태로 바뀝니다. 저장하기 전의 지침은 대화와 테스트 탭에 쓰이지 않으므로, 지침을 고쳤으면 먼저 저장한 뒤 시험합니다.

둘째, 도구, 모델, 오프너, 스킬 스위치, 지식, 미들웨어, 서브에이전트 추가와 제거, 설정 탭의 에이전트 모드와 Webhook 활성화 스위치, Fix 에이전트가 적용한 변경은 바꾸는 즉시 반영됩니다. 헤더의 저장을 누르지 않아도 대화와 테스트 탭에서 곧바로 바뀐 구성으로 답합니다. 모델은 변경 사항 확인 창에서 확인하고 저장을 누른 순간 반영됩니다. 다만 이 변경들은 아직 현재 버전의 저장본에 기록되지 않았기 때문에, 헤더에 "저장되지 않은 변경이 있습니다"가 보이고 저장이 눌리는 상태가 됩니다. 이때 저장을 누르면 현재 버전에 기록됩니다. 워크스페이스 등록은 저장된 버전으로 하므로, 등록을 요청하기 전에는 꼭 저장을 누릅니다.

셋째, 설정 탭의 Recursion Limit, MCP 서버, Context Compaction은 헤더의 저장이 아니라 각자의 버튼으로 저장합니다. Recursion Limit은 설정 탭 위쪽의 저장, MCP 서버는 MCP 서버 활성화 버튼(활성화한 뒤에는 MCP 설정 업데이트와 MCP 서버 비활성화), Context Compaction은 그 카드 안의 저장을 누릅니다.

방식해당 항목저장하는 방법
헤더의 저장으로 저장이름, 설명, 지침헤더의 저장을 누릅니다. 누르기 전의 지침은 대화와 테스트에 쓰이지 않습니다.
바꾸는 즉시 반영도구, 모델, 오프너, 스킬 스위치, 지식, 미들웨어, 서브에이전트 추가와 제거, 설정 탭의 에이전트 모드와 Webhook 활성화, Fix 에이전트의 변경바꾸는 즉시 대화와 테스트에 반영됩니다. 현재 버전에 기록하려면 "저장되지 않은 변경이 있습니다"가 보일 때 헤더의 저장을 누릅니다.
설정 탭 카드의 버튼으로 저장Recursion Limit, MCP 서버, Context Compaction설정 탭 위쪽 저장, MCP 서버 활성화 버튼, Context Compaction 카드 안 저장을 각각 누릅니다.

Fix 에이전트 탭 위쪽에는 "Fix Agent가 적용한 변경 사항은 즉시 반영되며 버전 초안에는 포함되지 않습니다."라는 안내가 있습니다. Fix 에이전트가 고친 내용도 바로 대화와 테스트에 쓰이고, 헤더의 저장을 눌러야 현재 버전에 기록됩니다. 자세한 내용은 Fix 에이전트를 참고하세요.

헤더: 이름, 버전, 저장​

헤더에는 눌러서 바로 고치는 에이전트 이름(최대 50자)과 설명(최대 255자), 그리고 워크스페이스 등록, 코드 스니펫, 버전 안내, 에이전트 복제, 에이전트 삭제, 현재 버전, 저장, 저장 옵션 더 보기가 있습니다. 현재 버전은 지금 쓰는 버전(예: V1)을 보여 주고, 누르면 버전 목록이 열립니다. 저장은 저장할 변경이 없으면 눌리지 않습니다. 저장 옵션 더 보기는 저장 오른쪽의 화살표입니다. 나머지 버튼은 이어지는 절과 이 페이지 아래쪽의 "에이전트 복제와 삭제" 절에서 설명합니다.

저장 옵션 메뉴​

저장 옵션 더 보기를 누르면 새 버전으로 저장과 에이전트 내보내기 두 항목이 보입니다. 새 버전으로 저장은 현재 설정을 복사해 새 버전(V2, V3 …)을 만들며, 버전 설명은 30자까지 적을 수 있고 비워 둬도 됩니다. 에이전트 내보내기는 에이전트를 ZIP 파일로 내려받고, 끝나면 "에이전트가 성공적으로 내보내졌습니다"가 나옵니다. 내보낸 파일을 주고받는 방법은 에이전트 가져오기와 내보내기에 있습니다.

버전 안내​

버전 안내를 누르면 저장 방식을 설명하는 창이 열립니다. 창은 세 부분입니다. 즉시 저장되는 설정에는 "도구, 모델, 오프너 등 고급 설정은 변경하는 즉시 저장됩니다. 아래 버전 초안에는 포함되지 않습니다."라고 적혀 있습니다. 이 항목들은 바꾸는 즉시 반영되고, 현재 버전에 기록하려면 헤더의 저장을 누른다는 뜻입니다. 저장과 새 버전으로 저장의 차이에는 저장은 현재 활성 버전을 업데이트하고 새 버전으로 저장은 현재 설정을 복사해 새 버전을 만들며, 새 버전에는 파일과 대화 기록이 이어지지 않는다고 적혀 있습니다. 버전 개수에는 에이전트당 버전을 20개 이하로 두기를 권장하며 강제 제한은 아니라고 적혀 있습니다.

워크스페이스 등록​

워크스페이스 등록을 누르면 "워크스페이스에 에이전트 등록" 창이 열립니다. 등록할 워크스페이스를 고르고 등록할 버전을 정한 뒤 등록 요청을 보냅니다. 등록은 저장된 버전으로 하므로, 헤더에 "저장되지 않은 변경이 있습니다"가 보이면 먼저 저장을 누릅니다. 저장하지 않은 채 등록하려 하면 "저장되지 않은 변경이 있습니다. 에이전트를 먼저 저장한 뒤 등록하세요."가, 저장하지 않은 서브에이전트가 있으면 "저장되지 않은 서브에이전트가 있습니다. 저장한 뒤 다시 시도하세요."가 나옵니다. 워크스페이스마다 확인을 거쳐 각각 요청되며, 관리자 심사가 필요한 워크스페이스는 "심사를 요청했습니다", 바로 게시되는 워크스페이스는 "게시되었습니다"로 결과가 나옵니다. 게시된 에이전트는 동료의 사이드바 워크스페이스 에이전트 탭과 에이전트 템플릿 화면에 나타납니다. 서브에이전트를 쓰는 에이전트는 서브에이전트가 먼저 배포되어 있어야 합니다. 배포와 관리 과정은 커뮤니티에서 설명합니다.

코드 스니펫​

코드 스니펫을 누르면 이 에이전트를 호출하는 예시 코드 창이 열립니다. Invoke, 스트림 (SSE), 백그라운드 실행, Webhook 방식별로, Python, JavaScript, cURL, OpenAI SDK, LangChain 예시를 볼 수 있습니다. 자세한 내용은 코드 스니펫과 외부 API를 참고하세요.

폼 보기: 지침, 서브에이전트, 모델, 연결 항목​

가운데 편집 영역의 폼 보기에서는 에이전트 구성을 항목별 입력란으로 고칩니다. 위쪽에 지침, 서브에이전트, 모델 설정이 있고, 아래쪽에 도구함, 지식함, 미들웨어가 나란히 있습니다. 지침 제목을 누르면 지침 영역이 접히거나 펼쳐지고, 에디터 확장을 누르면 지침 입력란이 큰 창으로 열립니다. 지침 입력란에는 에이전트가 모든 대화에서 따르는 역할, 작업 순서, 답변 형식을 적습니다.

서브에이전트 오른쪽 버튼은 서브에이전트 관리 창을, 모델 설정은 모델 설정 창을 엽니다. 도구함의 도구 버튼은 "도구 추가" 창을, 지식함의 지식 버튼은 지식을 검색해 고르는 "지식 추가" 창을, 미들웨어의 추가 버튼은 "미들웨어 추가" 창을 엽니다. 연결된 도구가 없으면 도구함에 "추가된 도구가 없습니다"가 보입니다.

도구함에 붙인 도구는 항목을 눌러 "도구 설정" 창에서 표시 이름, 활성화, 파라미터를 바꿀 수 있습니다. 미들웨어는 항목의 설정 버튼으로 "미들웨어 설정" 창을 엽니다. 지식함에 고를 수 있는 지식은 Deep Connector에서 만든 컬렉션이며, 이 화면에서 새 지식을 올리지는 않습니다.

모델 설정 창​

모델 설정을 누르면 모델 설정 창이 열립니다. 모델 선택에서 사용할 모델을 고르면 모델 정보에 그 모델의 설명과 입력·출력 컨텍스트가 보입니다. API 키가 등록되지 않은 모델에는 "[API 키 미등록]"이 붙고, 원하는 모델이 목록에 없으면 모델 관리로 모델 설정 페이지에 가서 추가합니다(모델 구성 참고).

파라미터에는 모델이 지원하는 값만 보입니다. temperature(0 이상 2 이하), top_p(0 이상 1 이하), top_k(1 이상), max_tokens(1 이상)을 바꿔 답변을 더 일정하게 하거나 길이를 제한합니다. 사고 기능을 지원하는 모델에서는 **사고 깊이 (Effort)**에서 낮음, 보통, 높음을 고르고, 모델에 따라 사고 토큰 예산 (Budget Tokens)(1024 이상)도 정합니다. 취소는 바꾼 내용을 버리고 창을 닫으며, 저장은 다음 확인 창으로 넘어갑니다.

저장을 누르면 바로 저장되지 않고 변경 사항 확인 창이 먼저 열립니다. 이 창은 바뀌는 항목마다 현재 값과 변경 값을 나란히 보여 주며, 원래 없던 값은 "(없음)"으로 보입니다. 값을 다시 고치려면 돌아가기를, 맞으면 확인하고 저장을 누릅니다. "모델 설정이 저장되었습니다"가 나오면 끝입니다.

모델은 확인하고 저장을 누르는 즉시 대화와 테스트에 반영됩니다. 헤더에 "저장되지 않은 변경이 있습니다"가 보이면, 바꾼 모델을 현재 버전에 기록하기 위해 헤더의 저장도 누릅니다.

서브에이전트 관리 창​

서브에이전트의 관리 버튼을 누르면 "서브에이전트 관리" 창이 열립니다. 이 에이전트가 작업을 위임할 수 있는 서브에이전트를 추가하거나 제거합니다. 창 위쪽 현재 서브에이전트에는 연결된 에이전트가 보이고 괄호 안 숫자가 개수입니다. 그 아래 "에이전트 검색..." 칸과 내 에이전트 / 워크스페이스 에이전트 탭에서 붙일 에이전트를 찾아 이름과 설명을 확인한 뒤 추가 버튼을 누릅니다. 추가하면 "서브에이전트가 추가되었습니다"가 나오고 바로 반영됩니다. 현재 버전에 기록하려면 헤더의 저장을 누릅니다.

서브에이전트를 어떻게 나눠 쓰는지는 서브에이전트 할당하기에서 설명합니다.

비주얼 보기​

비주얼을 누르면 에이전트를 가운데 두고 모델, 도구, 스킬, 지식, 서브 에이전트, 미들웨어가 선으로 이어진 그림이 나옵니다. 무엇이 연결되어 있고 무엇이 비어 있는지 한눈에 볼 때 씁니다. 에이전트 상자에는 이름, 설명, 지침 앞부분이 보이고, 도구, 스킬, 지식, 서브 에이전트, 미들웨어 상자의 도구 추가, 스킬 추가, 지식 추가, 서브에이전트 추가, 미들웨어 추가 버튼으로 이 자리에서 바로 연결을 더합니다. 서브 에이전트 상자의 에이전트를 누르면 그 에이전트의 에이전트 편집 화면으로 이동할지 묻습니다. 상자를 끌어 옮기다 배치가 흐트러지면 기본 레이아웃으로 처음 배치로 되돌립니다.

오른쪽 탭​

오른쪽 탭은 일곱 개입니다. 구성을 고치고 시험하는 탭(Fix 에이전트, 테스트)과 에이전트에 딸린 설정을 다루는 탭(오프너, 파일, 스킬, 스케줄, 설정)으로 나뉩니다.

테스트​

테스트 탭에서는 에이전트 편집 화면을 떠나지 않고 에이전트에게 질문해 봅니다. 지침을 고친 뒤 같은 질문을 다시 보내 답이 바뀌었는지 확인할 때 씁니다. 테스트 탭은 저장된 지침으로 답하므로, 지침을 고쳤으면 헤더의 저장을 누른 뒤 보냅니다. 도구, 모델처럼 바꾸는 즉시 반영되는 항목은 저장하지 않아도 바로 시험에 쓰입니다.

처음에는 "주간 업무 보고서 도우미 테스트"처럼 에이전트 이름이 들어간 제목이 보입니다. "에이전트를 테스트해 보세요..." 입력란에 질문을 적고 전송을 누릅니다. Enter로 보내고 Shift + Enter로 줄을 바꾸며, 파일 업로드로 파일을 함께 첨부할 수 있습니다. 새 대화(마우스를 올리면 "새 테스트 스레드")는 시험 대화를 새로 시작합니다.

파일​

파일 탭에는 에이전트가 모든 대화에서 참고할 파일을 올려 둡니다. 채팅에 매번 첨부하지 않아도 되는 고정 자료(예: 보고서 양식, 용어집)를 둘 때 씁니다. "파일을 드래그하거나 클릭하여 업로드" 영역에 파일을 끌어다 놓거나 파일 선택을 눌러 고르면, 올린 파일 목록과 개수("2개 파일")가 보입니다. 올린 파일이 없으면 "업로드된 파일이 없습니다"가 보입니다.

파일 탭에 올리는 파일은 에이전트 하나에 50개까지, 파일 하나에 50MB까지입니다. 화면 안내 문구에는 일부 형식만 적혀 있지만, 실제로 올릴 수 있는 확장자는 채팅 첨부와 같은 .pdf, .jpg, .jpeg, .png, .gif, .webp, .md, .markdown, .txt, .xlsx, .xls, .xlsb, .xlsm, .csv, .docx, .pptx, .ppt, .hwp, .hwpx, .html, .htm입니다. 형식별 한도와 거절 사유는 파일 첨부 정책과 가드레일에서 설명합니다. 파일 탭의 파일은 새 버전으로 저장할 때 이어지지 않고, 에이전트를 내보낼 때도 ZIP에 들어가지 않습니다.

스킬​

스킬 탭에서는 에이전트가 쓸 스킬을 스위치로 켜고 끕니다. 위쪽에 문서 작성 스킬과 일반 스킬 두 하위 탭이 있습니다. 문서 작성 스킬은 문서작성 에이전트가 문서를 만들 때 쓰는 스킬이며, ZIP 업로드로 .zip 파일을 올려 이 자리에서 추가할 수 있습니다. 일반 스킬은 사이드바의 에셋설정을 눌러 여는 에셋 화면의 스킬 탭에 올려 둔 스킬입니다. 스위치는 바꾸는 즉시 반영됩니다.

스킬을 만들고 올리는 방법은 스킬 만들기와 업로드를 참고하세요.

스케줄​

스케줄 탭에서는 "에이전트 자동 실행 스케줄을 관리합니다"라는 안내 아래 스케줄 추가로 자동 실행을 예약합니다. 실행 시각은 폼에서 고르거나 스케줄 표현식으로 직접 적고, 타임존과 실행 메시지를 정합니다. 스케줄 실행은 매번 새 대화로 시작되며 파일을 첨부할 수 없습니다. 주간 업무 보고서 도우미를 매주 금요일 오후에 실행하는 예시는 스케줄링과 백그라운드 모드에서 설명합니다.

설정 탭​

설정 탭은 에이전트가 답을 만드는 방식을 정합니다. 위쪽에 "에이전트 실행 설정을 관리합니다"라는 안내와 저장 버튼이 있고, 그 아래로 에이전트 모드, Recursion Limit, MCP 서버, Webhook, Context Compaction이 차례로 이어집니다. 항목마다 저장하는 방법이 다르니 아래 설명을 확인하세요.

에이전트 모드에서는 일반 에이전트와 문서작성 에이전트 가운데 고릅니다. 문서작성 에이전트는 모든 대화를 문서 작성 모드로 실행해, PPT·문서·표를 만들고 대화 화면의 문서 캔버스에서 결과를 보여 줍니다. 고르는 즉시 반영되며 "에이전트 모드가 저장되었습니다"가 나옵니다.

Recursion Limit의 최대 처리 단계 수는 한 번 답하는 동안 에이전트가 거칠 수 있는 내부 처리 단계(예: 모델 호출, 도구 실행)의 상한입니다. 1부터 1000까지 넣을 수 있고 기본값은 500입니다. 값을 올리면 자료 수집이나 스케줄 실행처럼 단계가 많은 작업이 멈추지 않고 더 많은 단계를 진행할 수 있지만, 그만큼 처리 시간과 비용이 늘 수 있습니다. 값을 내리면 끝없이 반복되는 실행을 더 일찍 멈춥니다. 답변이 "작업 한계에 도달했습니다"라는 안내와 함께 중단되면 값을 올려 봅니다. 바꾼 값은 탭 위쪽 저장을 눌러야 저장되며, 기본값으로 초기화를 누르면 입력값이 500으로 돌아갑니다(이때도 저장을 눌러야 저장됩니다).

MCP 서버는 이 에이전트를 MCP 호환 클라이언트(예: Claude Desktop, Cursor)에서 도구처럼 부를 수 있게 엽니다. MCP 서버 활성화 스위치를 켜고 서버 이름(영문, 숫자, _, -, . 만 사용)과 설명을 적은 뒤 MCP 서버 활성화 버튼을 누릅니다. 활성화되면 연결 JSON을 복사해 클라이언트에 넣을 수 있고, 이름이나 설명을 바꾼 뒤에는 MCP 설정 업데이트, 끌 때는 MCP 서버 비활성화를 누릅니다. 자세한 내용은 MCP와 에이전트의 MCP화에 있습니다.

Webhook은 외부 시스템(예: n8n, Dify)이 REST API로 이 에이전트를 호출할 수 있게 합니다. Webhook 활성화 스위치는 켜고 끄는 즉시 반영되고, 켜면 Webhook URL과 복사 버튼이 보입니다. 호출할 때는 사이드바의 에셋설정을 눌러 여는 에셋 화면의 API 키 탭에서 만든 invoke 권한 API 키를 함께 보내야 합니다. 호출 방법은 코드 스니펫과 외부 API에 있습니다.

Context Compaction은 대화가 길어지면 최근 메시지를 뺀 앞부분을 자동으로 요약해 모델이 읽을 분량을 줄입니다. Context Compaction 활성화 스위치로 켜고, **압축 시작 비율 (모델 컨텍스트 대비 %)**에는 대화 분량이 모델 컨텍스트 길이의 몇 %를 넘으면 요약을 시작할지 10부터 95까지 넣습니다(기본값 80, 기본값으로 초기화로 되돌림). 최근 유지 메시지 수에는 요약하지 않고 원문 그대로 남길 최근 메시지 개수를 2부터 100까지 넣습니다(기본값 10). 스위치와 두 값은 이 카드 안의 저장을 눌러야 저장됩니다. 한 대화에서 여러 주의 보고서를 이어 쓰다가 "대화가 컨텍스트 한계를 초과했습니다"가 나오면 켜 둡니다.

설정 항목을 업무에 맞게 고르는 방법은 세부 설정과 메모리에서 설명합니다. 문서작성 에이전트와 캔버스는 캔버스로 문서·PPT·표 만들기를 참고하세요.

사례: 지침에 규칙을 더하고 새 버전으로 저장하기​

김그루 사원은 주간 업무 보고서 도우미에 "지난주 대비" 비교를 넣기로 했습니다. 원래 지침은 V1에 그대로 두고, 규칙을 더한 지침을 V2로 저장한 뒤 결과를 비교합니다.

1단계: 바꾸기 전 결과 확인​

오른쪽 테스트 탭에서 새 대화를 누르고 김그루_주간업무메모_1106.md를 첨부해 아래 질문을 보냅니다. 업무별 진행 표의 열 구성을 기록해 둡니다.

프롬프트: 이번 주 주간 업무 보고서 초안을 작성해 주세요.

2단계: 새 버전 만들기​

헤더의 저장 옵션 더 보기를 누르고 새 버전으로 저장을 고르면 "새 버전 생성" 창이 열립니다. 창에는 "현재 버전의 설정을 복사하여 새 버전을 만듭니다."라는 안내와 30자 이내로 적는 버전 설명 (선택사항) 칸, 취소, 저장이 있습니다.

버전 설명에 "지난주 대비 열 추가"를 적고 저장을 누릅니다. "새 버전이 생성되었습니다"가 나오고 헤더의 현재 버전이 V2로 바뀝니다.

3단계: 지침에 규칙 추가하고 저장​

현재 버전이 V2인지 확인하고, 지침 입력란 끝에 아래 문장을 붙인 뒤 헤더의 저장을 누릅니다.

프롬프트: 사용자가 지난주 보고서를 함께 주면 업무별 진행 표에 "지난주 대비" 열을 추가해 늘어남, 줄어듦, 같음, 신규 가운데 하나로 표시합니다. 지난주 보고서가 없으면 이 열을 만들지 않습니다.

4단계: 같은 질문으로 비교​

테스트 탭에서 새 대화를 누르고, 1단계와 같은 메모에 지난주 보고서 내용을 함께 붙여 같은 질문을 보냅니다. 업무별 진행 표에 "지난주 대비" 열이 생겼는지 1단계 결과와 비교합니다.

팁: 지침을 저장했다고 해서 답이 원하는 대로 바뀌는 것은 아닙니다. 바꾸기 전과 같은 질문을 새 대화에서 보내 결과를 나란히 비교하세요.

버전 목록과 되돌리기​

헤더의 현재 버전을 누르면 지금까지 저장한 버전 목록이 열립니다. 목록에는 V1, V2처럼 저장한 버전과 저장할 때 적은 설명이 함께 보입니다. 버전을 고르면 그 버전의 지침과 구성으로 바뀝니다. 버전마다 있는 버전 설명 수정은 "버전 설명 수정" 창을 열어 설명을 고치고, 버전 삭제는 그 버전을 목록에서 지웁니다. 지금 쓰고 있는 활성 버전은 삭제할 수 없습니다.

편집 중인 변경을 저장하지 않은 채 다른 버전을 고르면 "저장하지 않은 변경사항" 창이 열립니다. 저장 후 이동을 누르면 지금 내용을 저장하고 이동하고, 저장 없이 이동을 누르면 변경을 버리고 이동합니다.

버전 삭제를 누르면 "버전을 삭제할까요?" 창이 열리고, "이 버전은 목록에서 제거됩니다. 현재 활성 버전과 편집 중인 내용은 유지됩니다."라는 안내가 나옵니다. 삭제를 누르면 지워집니다. 다른 곳에서 참조 중인 버전은 삭제할 수 없습니다.

따라 해 보기​

  1. 헤더의 현재 버전을 누릅니다.
  2. 목록에서 V1을 누릅니다.
  3. 헤더가 V1로 바뀌고 지침 입력란에서 "지난주 대비" 문장이 사라졌는지 확인합니다.
  4. 다시 V2를 쓰려면 같은 방법으로 V2를 고릅니다.

에이전트 복제와 삭제​

헤더의 에이전트 복제를 누르면 같은 구성의 새 에이전트가 만들어지고 그 에이전트 편집 화면으로 이동합니다. 원본은 바뀌지 않으므로, 원본과 다르게 시험해 보고 싶을 때 씁니다. 복제한 뒤에는 이름부터 원본과 구분되게 바꿉니다.

에이전트 삭제를 누르면 삭제 확인 창이 열립니다. 창에는 지우려는 에이전트 이름과 함께 "에이전트를 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다."가 보입니다. 이름이 맞는지 확인하고 삭제를 누르면 에이전트가 지워지고 새 에이전트 화면으로 이동합니다. 지우지 않으려면 취소를 누릅니다.

다른 에이전트의 서브에이전트로 연결된 에이전트를 지우면, 삭제할 때 그 연결도 함께 제거된다는 안내가 먼저 나옵니다. 워크스페이스에 배포 중인 에이전트는 삭제할 수 없습니다.

수정이 예상대로 되지 않을 때​

  • 헤더의 저장이 눌리지 않으면 저장할 변경이 없는 상태입니다. 이름, 설명, 지침을 실제로 바꿨는지 봅니다.
  • 설정 탭의 Recursion Limit, MCP 서버, Context Compaction 값이 반영되지 않으면 그 항목의 버튼(탭 위쪽 저장, MCP 서버 활성화 또는 MCP 설정 업데이트, Context Compaction 카드 안 저장)을 눌렀는지 확인합니다.
  • 지침을 바꿨는데 답이 그대로이면 헤더의 저장을 눌렀는지 먼저 확인합니다. 저장하지 않은 지침은 대화와 테스트에 쓰이지 않습니다. 저장했다면 테스트 탭에서 새 대화를 눌러 다시 물어봅니다. 앞 대화의 내용이 답에 영향을 줄 수 있습니다.
  • 워크스페이스 등록 때 "저장되지 않은 변경이 있습니다. 에이전트를 먼저 저장한 뒤 등록하세요."가 나오면 헤더의 저장을 누른 뒤 다시 등록합니다.
  • 바꾼 뒤 답이 오히려 나빠졌다면 버전 목록에서 이전 버전으로 돌아가 같은 질문을 보내 비교합니다.
