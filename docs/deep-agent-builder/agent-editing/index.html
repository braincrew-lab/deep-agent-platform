에이전트 수정

에이전트를 만든 뒤에는 이름과 설명을 정리하고, 지침과 연결된 자원을 업무에 맞게 조정할 수 있습니다. 수정 화면에서 바꾼 항목은 저장한 뒤 실제 대화로 확인합니다. 이름을 바꾼 것만으로 답변 방식이 달라지지는 않습니다.

수정 화면 열기​

에이전트 목록에서 수정할 에이전트를 선택한 뒤 수정 화면으로 이동합니다. 수정 권한이 없으면 일부 항목을 바꾸거나 저장할 수 없습니다. 저장할 수 있는 권한과 에이전트를 실행할 수 있는 권한은 별개일 수 있으므로, 저장이 되지 않을 때 실행 권한부터 의심하지 않습니다.

수정 화면에 들어가면 먼저 현재 이름, 설명, 지침, 모델과 연결된 자원을 확인합니다. 한 번에 여러 항목을 바꾸기보다 원인을 확인하려는 항목부터 하나씩 수정하는 편이 결과를 비교하기 쉽습니다.

이름과 설명 바꾸기​

이름과 설명은 목록에서 에이전트를 구분하고 용도를 파악하는 데 쓰입니다. 이름이나 설명을 바꿔도 에이전트의 답변 규칙이 자동으로 바뀌지는 않습니다.

다음 기준으로 내용을 정리합니다.

  • 이름만 읽어도 담당 업무를 구분할 수 있는지 확인합니다.
  • 설명에는 언제 사용하는 에이전트인지 적습니다.
  • 비슷한 에이전트가 있다면 이름의 기준을 맞춥니다.
  • 저장한 뒤 목록과 수정 화면에 새 내용이 표시되는지 확인합니다.

지침 수정하기​

지침은 에이전트가 여러 대화에서 반복해서 따라야 하는 기준입니다. 역할, 답변 형식, 반드시 유지할 정보, 정보가 부족할 때의 처리 방법을 적습니다. 이번 요청에만 필요한 자료나 조건은 대화 메시지에 넣는 편이 적절합니다.

지침을 바꾼 뒤에는 정상 입력과 정보가 부족한 입력을 각각 보내 봅니다. 지침이 저장됐다는 안내만으로 답변 품질이 확인되는 것은 아니므로, 변경 전후의 결과를 같은 기준으로 비교합니다.

모델과 연결 자원 조정하기​

에이전트에는 활성 모델을 연결할 수 있습니다. 모델을 바꾸면 같은 지침과 입력에서도 답변의 표현이나 길이가 달라질 수 있으므로, 변경 후에는 업무와 가까운 질문으로 결과를 확인합니다.

도구, 미들웨어, 스킬, 서브에이전트는 에이전트가 사용할 수 있는 범위를 정합니다. 필요한 자원만 연결하고, 연결을 바꾼 뒤에는 해당 자원이 필요한 요청을 보내 동작을 확인합니다. 서브에이전트를 연결할 때는 부모 에이전트와 하위 에이전트가 서로를 순환해서 부르지 않는지 확인합니다.

자원을 제거하기 전에는 다른 설정이나 에이전트가 이를 참조하는지 확인합니다. 참조 관계를 정리하지 않고 제거하면 기존 업무의 실행 결과가 달라질 수 있습니다.

실행 설정 조정하기​

실행 설정에는 맥락 압축, 재귀 한계, MCP와 Webhook 사용 여부 등이 포함될 수 있습니다. 설정 이름과 현재 값을 확인한 뒤 필요한 항목만 바꿉니다.

맥락 압축을 사용하는 경우에는 사용 여부, 압축을 시작할 토큰 기준, 최근 메시지 보존 개수를 함께 확인합니다. 숫자 설정은 허용 범위 안의 정수만 저장할 수 있습니다. 설정을 끈 뒤에도 저장된 숫자 값이 즉시 사라진다고 보지 말고, 다음 실행에서 실제로 어떤 맥락이 유지되는지 확인합니다.

설정 카드에서 저장하는 항목과 이름, 설명, 지침을 저장하는 동작이 분리되어 있을 수 있습니다. 한쪽을 저장했다고 다른 쪽 변경까지 저장됐다고 판단하지 않습니다.

파일, 일정과 기타 자산​

에이전트에 파일, 일정, MCP 설정 또는 코드 조각이 연결된 경우에는 각 항목의 사용 목적과 저장 상태를 따로 확인합니다. 화면에 함께 표시된다고 해서 같은 저장 동작을 공유하는 것은 아닙니다.

파일이나 일정처럼 외부 자원과 실행 시점에 영향을 주는 항목은 수정 후 실제 사용 결과까지 확인합니다. 연결이 목록에 보이는 것과 실행에 사용할 수 있는 상태인 것은 다를 수 있습니다.

에이전트 복사하기​

복사는 기존 에이전트의 구성을 바탕으로 새 에이전트를 만드는 기능입니다. 복사본을 만들면 원본과 구분되는 이름을 먼저 정하고, 지침과 연결 자원을 새 업무에 맞게 다시 확인합니다.

복사본을 실험용으로 사용할 때는 원본을 바로 바꾸지 않고 같은 입력을 보내 결과를 비교합니다. 복사 후에도 모델, 자원, 파일과 설정이 새 용도에 맞는지 확인해야 합니다.

보관하기​

더 이상 사용하지 않는 에이전트는 삭제 대신 보관 상태로 전환될 수 있습니다. 보관하기 전에 다른 에이전트가 해당 에이전트를 하위 에이전트로 참조하는지 확인합니다. 참조가 남아 있으면 보관이 거부되거나 참조 정리가 먼저 필요할 수 있습니다.

보관 후에는 목록에서 보이는 상태와 기존 참조의 변화를 확인합니다. 보관은 모든 기록이 즉시 사라지는 작업으로 보지 않습니다.

수정 후 확인 순서​

  1. 바꾸려던 항목만 변경됐는지 확인합니다.
  2. 저장이 완료됐는지 확인하고 수정 화면을 다시 엽니다.
  3. 모델과 연결 자원의 현재 상태를 확인합니다.
  4. 정상 입력과 정보가 부족한 입력으로 에이전트를 실행합니다.
  5. 답변이 달라졌다면 이름과 설명, 지침, 모델, 자원 중 무엇을 바꿨는지 결과와 함께 비교합니다.

저장 성공은 의도한 동작 변화나 답변 품질을 보장하지 않습니다. 수정 목적과 실제 실행 결과가 일치하는지 확인해야 합니다.

수정이 예상대로 되지 않을 때​

먼저 저장 자체가 실패했는지, 저장은 됐지만 다른 항목을 바꿨는지 나눠서 확인합니다. 그다음 수정 권한, 입력값의 허용 범위, 연결된 자원의 상태, 서브에이전트 참조를 차례로 봅니다.

같은 문제가 반복되면 여러 항목을 동시에 바꾸지 말고 마지막으로 바꾼 항목부터 되돌려 봅니다. 실행 결과와 설정 화면을 함께 비교하면 어떤 변경이 영향을 줬는지 좁히기 쉽습니다.
