에이전트 수정

에이전트를 만든 뒤에는 이름과 설명을 정리하고, 지침과 연결된 자원을 업무에 맞게 조정할 수 있습니다. 무엇을 바꿨을 때 저장 버튼을 눌러야 하는지, 무엇이 바꾸는 즉시 저장되는지가 서로 다르므로 이 페이지는 두 저장 방식을 구분해서 설명합니다. 수정이 끝나면 버전 기록을 활용해 이전 상태로 돌아가거나, 변경 전후의 실행 결과를 비교할 수 있습니다.

수정 화면 열기​

에이전트 목록에서 수정할 에이전트를 선택한 뒤 수정 화면으로 이동합니다. 수정 화면에서 바꾼 항목은 저장한 뒤 실제 대화로 확인합니다. 이름을 바꾼 것만으로 답변 방식이 달라지지는 않습니다.

수정 권한이 없으면 항목을 바꾸거나 저장할 수 없습니다. 저장할 수 있는 권한과 에이전트를 실행할 수 있는 권한은 별개이므로, 저장이 되지 않을 때 실행 권한부터 의심하지 않습니다.

수정 화면에 들어가면 먼저 현재 이름, 설명, 지침, 모델과 연결된 자원을 확인합니다. 한 번에 여러 항목을 바꾸기보다 원인을 확인하려는 항목부터 하나씩 수정하는 편이 결과를 비교하기 쉽습니다.

저장 방식이 둘로 나뉩니다​

수정 화면의 저장 동작은 항목에 따라 둘로 나뉩니다.

  • 이름, 설명, 지침은 우상단 저장 버튼을 눌렀을 때 저장됩니다. 이 세 항목을 고치면 저장 버튼이 활성화되고, 저장에 성공하면 버튼이 다시 비활성화됩니다.
  • 도구, 미들웨어, 모델, 서브에이전트, 오프너, 파일, 스킬, 일정처럼 대부분의 항목은 바꾸는 즉시 저장됩니다. 별도의 저장 버튼을 누르지 않습니다. 실행 설정은 예외로, 우측 설정 탭에서 각 항목의 저장을 눌러야 반영됩니다.

Fix 에이전트 대화로 바꾼 내용도 즉시 반영되며, 버전 초안에는 포함되지 않는다는 안내가 화면에 표시됩니다. 한쪽을 저장했다고 다른 쪽 변경까지 저장됐다고 판단하지 않도록 주의합니다.

이름과 설명 바꾸기​

이름과 설명은 목록에서 에이전트를 구분하고 용도를 파악하는 데 쓰입니다. 이름이나 설명을 바꿔도 에이전트의 답변 규칙이 자동으로 바뀌지는 않습니다.

  1. 수정 화면에서 이름과 설명을 고칩니다. 저장 버튼이 활성화됩니다.
  2. 저장을 누르고 저장되었다는 안내를 확인합니다.
  3. 좌측 목록과 수정 화면에 새 내용이 표시되는지 확인합니다.

다음 기준으로 내용을 정리하면 목록 관리가 쉬워집니다.

  • 이름만 읽어도 담당 업무를 구분할 수 있게 씁니다.
  • 설명에는 언제 사용하는 에이전트인지 적습니다.
  • 비슷한 에이전트가 있다면 이름의 기준을 맞춥니다.

지침 수정하기​

지침은 에이전트가 여러 대화에서 반복해서 따라야 하는 기준입니다. 역할, 답변 형식, 반드시 유지할 정보, 정보가 부족할 때의 처리 방법을 적습니다. 이번 요청에만 필요한 자료나 조건은 대화 메시지에 넣는 편이 적절합니다.

지침을 고치면 저장 버튼이 활성화됩니다. 저장을 눌러 반영한 뒤, 정상 입력과 정보가 부족한 입력을 각각 보내 봅니다. 지침이 저장됐다는 안내만으로 답변 품질이 확인되는 것은 아니므로, 변경 전후의 결과를 같은 기준으로 비교합니다.

버전으로 기록하고 되돌아가기​

수정 화면 상단의 버전 메뉴에는 현재 버전이 표시됩니다. 활성 버전이 없으면 그 상태가 그대로 표시됩니다. 버전은 에이전트 설정의 기록 지점이며, 다음 작업에 사용합니다.

  • 버전 전환: 목록에서 다른 버전을 선택해 그 시점의 설정으로 되돌아갑니다.
  • 새 버전으로 저장: 지금까지의 수정 내용을 새 버전으로 남기고 싶을 때 저장 버튼 옆의 새 버전으로 저장을 사용합니다. 버전 이름과 설명을 입력하며, 이름은 25자 이하, 설명은 100자 이하로 씁니다. 새 버전에는 파일, 메모리, 대화 기록이 이어지지 않습니다.
  • 버전 이름 변경: 버전 목록의 연필 아이콘으로 각 버전의 이름과 설명을 나중에 고칠 수 있습니다. 다른 버전이 이미 쓰고 있는 이름을 넣으면 중복 안내가 표시됩니다.
  • 버전 삭제: 버전 목록의 휴지통 아이콘으로 필요 없는 버전을 지웁니다.

버전을 전환할 때 저장하지 않은 변경사항이 있으면 안내 대화상자가 열립니다. 저장 없이 이동을 누르면 바꾼 내용이 사라지고, 저장 후 이동을 누르면 저장을 마친 뒤 이동합니다. 바꾼 내용을 남기고 싶다면 저장 후 이동을 선택합니다.

한 사람만 수정하는 것도 아니기 때문에, 편집하는 동안 다른 곳에서 같은 버전이 바뀌었다는 안내가 나올 수 있습니다. 이때는 내 편집 내용 버리기 또는 최신 버전 위에서 계속 편집 중에서 선택합니다. 어느 쪽이 최신 상태인지 모르겠으면 안내를 닫은 뒤 화면의 내용을 다시 확인하고 결정합니다.

버전 삭제는 되돌리기 어려운 작업이므로 화면이 몇 가지를 제한합니다. 현재 사용 중인 활성 버전은 삭제할 수 없고, 다른 곳에서 참조 중인 버전도 삭제할 수 없습니다. 다른 버전 작업이 진행 중일 때에는 작업이 끝난 후에 삭제할 수 있습니다. 삭제를 확인하면 목록에서 버전이 사라지고 삭제되었다는 안내가 표시됩니다. 삭제 결과를 확인하지 못했거나 버전이 목록에 남아 있으면 결과 확인 또는 목록 새로고침을 눌러 최신 상태를 확인합니다.

버전 개수는 에이전트당 20개 이하로 관리하면 목록을 읽기 쉽습니다. 이 값은 권장 기준이며 강제 제한은 아닙니다.

모델과 연결 자원 조정하기​

에이전트에는 활성 모델을 연결할 수 있습니다. 모델과 연결 자원의 변경은 즉시 저장됩니다. 모델을 바꾸면 같은 지침과 입력에서도 답변의 표현이나 길이가 달라질 수 있으므로, 변경 후에는 업무와 가까운 질문으로 결과를 확인합니다.

도구, 미들웨어, 스킬, 서브에이전트는 에이전트가 사용할 수 있는 범위를 정합니다. 필요한 자원만 연결하고, 연결을 바꾼 뒤에는 해당 자원이 필요한 요청을 보내 동작을 확인합니다. 서브에이전트를 연결할 때는 부모 에이전트와 하위 에이전트가 서로를 순환해서 부르지 않는지 확인합니다.

자원을 제거하기 전에는 다른 설정이나 에이전트가 이를 참조하는지 확인합니다. 참조 관계를 정리하지 않고 제거하면 기존 업무의 실행 결과가 달라질 수 있습니다.

실행 설정 조정하기​

우측 설정 탭에는 에이전트 실행과 관련된 항목이 모여 있습니다. 이 탭의 변경은 저장 버튼을 눌러야 저장됩니다.

  • 최대 처리 단계 수: 한 번의 응답을 만드는 동안 허용되는 내부 처리 단계의 최대 개수입니다. 기본값은 500이고, 자료 수집이나 일정 실행처럼 단계가 많은 작업은 500 이상을 권장합니다. 값을 올려도 실행 횟수나 비용이 늘어나지 않습니다.
  • Context Compaction: 대화가 길어지면 이전 메시지를 요약해 문맥 관리에 쓰이는 공간을 아낍니다. 활성화하면 요약을 시작하는 임계값(토큰)과 최근 유지 메시지 수를 함께 지정합니다. 임계값은 1,000에서 2,000,000 사이, 최근 유지 메시지 수는 2에서 100 사이의 값만 저장할 수 있습니다. 활성화를 끄면 두 입력은 비활성화되지만, 저장해 둔 숫자 값이 곧바로 사라지지는 않습니다.

설정 탭에서 값을 허용 범위 밖으로 입력하면 저장 시 범위 안내가 표시되고 저장되지 않습니다. 안내에 따라 값을 고친 뒤 다시 저장합니다. 설정을 끈 뒤에도 저장된 숫자가 화면에 남아 있을 수 있으므로, 다음 실행에서 실제로 어떤 맥락이 유지되는지 확인합니다.

파일, 일정과 기타 자산​

에이전트에 파일, 일정, MCP 설정 또는 코드 조각이 연결된 경우에는 각 항목의 사용 목적과 저장 상태를 따로 확인합니다. 화면에 함께 표시된다고 해서 같은 저장 동작을 공유하는 것은 아닙니다.

파일이나 일정처럼 외부 자원과 실행 시점에 영향을 주는 항목은 수정 후 실제 사용 결과까지 확인합니다. 연결이 목록에 보이는 것과 실행에 사용할 수 있는 상태인 것은 다를 수 있습니다.

에이전트 삭제하기​

더 이상 사용하지 않는 에이전트는 수정 화면 상단의 휴지통 아이콘으로 삭제합니다. 삭제를 누르면 되돌릴 수 없다는 확인 대화상자가 열립니다. 에이전트 이름을 다시 확인한 뒤 삭제를 눌러 진행합니다.

삭제하려는 에이전트가 다른 에이전트의 서브에이전트로 등록되어 있으면, 삭제 시 해당 참조가 자동으로 제거된다는 경고가 함께 표시됩니다. 참조를 정리할 생각이 없다면 여기서 중단하고, 삭제하겠다는 선택을 확실히 하려면 그래도 삭제를 누릅니다.

삭제 권한이 없으면 휴지통 아이콘을 사용할 수 없고 권한 안내가 표시됩니다. 이 경우 관리자에게 삭제 대상과 사유를 전달해 요청합니다.

에이전트 복사하기​

복사는 기존 에이전트의 구성을 바탕으로 새 에이전트를 만드는 기능입니다. 복사본을 만들면 원본과 구분되는 이름을 먼저 정하고, 지침과 연결 자원을 새 업무에 맞게 다시 확인합니다.

복사본을 실험용으로 사용할 때는 원본을 바로 바꾸지 않고 같은 입력을 보내 결과를 비교합니다. 복사 후에도 모델, 자원, 파일과 설정이 새 용도에 맞는지 확인해야 합니다.

수정 후 확인 순서​

  1. 바꾸려던 항목만 변경됐는지 확인합니다.
  2. 저장 방식이 둘로 나뉘는 규칙에 맞춰 저장을 완료했는지 확인하고, 수정 화면을 다시 엽니다.
  3. 모델과 연결 자원의 현재 상태를 확인합니다.
  4. 정상 입력과 정보가 부족한 입력으로 에이전트를 실행합니다.
  5. 답변이 달라졌다면 이름과 설명, 지침, 모델, 자원 중 무엇을 바꿨는지 결과와 함께 비교합니다. 필요하면 버전 전환으로 이전 설정으로 되돌려 같은 입력을 다시 보냅니다.

저장 성공은 의도한 동작 변화나 답변 품질을 보장하지 않습니다. 수정 목적과 실제 실행 결과가 일치하는지 확인해야 합니다.

수정이 예상대로 되지 않을 때​

먼저 저장 자체가 실패했는지, 저장은 됐지만 다른 항목을 바꿨는지 나눠서 확인합니다. 저장에 실패하면 화면에 실패 안내가 표시되고 저장은 반영되지 않으므로, 안내를 닫은 뒤 다시 시도합니다. 편집하는 동안 다른 곳에서 같은 버전이 바뀌었다는 안내가 나오면 내 편집 내용 버리기 또는 최신 버전 위에서 계속 편집 중에서 선택해 상태를 정리한 뒤 저장합니다.

저장 실패가 반복되면 수정 권한, 입력값의 허용 범위, 연결된 자원의 상태, 서브에이전트 참조를 차례로 봅니다. 같은 문제가 계속되면 여러 항목을 동시에 바꾸지 말고 마지막으로 바꾼 항목부터 되돌려 봅니다. 실행 결과와 설정 화면을 함께 비교하면 어떤 변경이 영향을 줬는지 좁히기 쉽습니다.
