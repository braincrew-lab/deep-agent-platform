에이전트 수정

에이전트를 쓰다 보면 지침에 규칙을 더하거나, 모델과 연결 항목을 바꾸거나, 답이 달라진 원인을 찾아 이전 상태로 돌아가야 할 때가 있습니다. 이 페이지는 에이전트 편집 화면의 메뉴를 헤더, 가운데 편집 영역, 오른쪽 탭 순서로 설명하고, 김그루 사원이 주간 업무 보고서 도우미의 지침에 규칙을 더해 새 버전으로 저장하고 되돌리는 과정을 따라 합니다.

이 페이지에서 할 수 있는 일

  • 에이전트 편집 화면의 헤더, 폼·비주얼 편집 영역, 오른쪽 탭에 있는 메뉴가 각각 무엇을 바꾸는지 확인합니다.
  • 헤더의 저장을 눌러야 저장되는 항목, 바꾸는 즉시 반영되는 항목, 설정 탭 카드의 버튼으로 저장하는 항목을 구분합니다.
  • 모델 설정 창에서 모델과 파라미터를 확인하고, 변경 사항 확인 창에서 바뀌는 값을 확인한 뒤 저장합니다.
  • 설정 탭에서 에이전트 모드, Recursion Limit, MCP 서버, Webhook, Context Compaction을 조정합니다.
  • 지침을 고친 뒤 새 버전으로 저장하고, 버전 목록에서 이전 버전으로 되돌립니다.
  • 에이전트를 복제하거나 삭제하고, 워크스페이스에 등록을 요청합니다.

에이전트 편집 화면 열기와 전체 구성​

에이전트 대화 화면에서 왼쪽 사이드바의 에이전트 설정을 누르면 에이전트 편집 화면이 열립니다. 사이드바에는 대화 화면으로 돌아가는 뒤로, 이 에이전트와 새 대화를 여는 이 에이전트와 새 대화, 지금 화면인 에이전트 설정이 그대로 보입니다. 작업 영역은 위쪽 헤더, 가운데 편집 영역, 오른쪽 탭으로 나뉩니다. 헤더에는 이름, 설명과 저장·버전 버튼이 있고, 가운데 편집 영역에서는 폼 / 비주얼 전환으로 지침, 서브에이전트, 모델 설정, 도구함, 지식함, 미들웨어를 고칩니다. 오른쪽에는 Fix 에이전트, 테스트, 오프너, 파일, 스킬, 스케줄, 설정 탭이 있어, 가운데에서 바꾼 구성을 바로 시험하거나 실행 설정을 조정합니다.

에이전트 편집 화면 전체 구성

번호메뉴기능이런 때 사용하세요
1뒤로이전 화면으로 돌아갑니다.수정을 마치고 대화 화면으로 돌아갈 때
2이 에이전트와 새 대화이 에이전트와 새 대화를 엽니다.지침을 바꾼 뒤 이전 대화와 섞이지 않게 처음부터 물어볼 때
3에이전트 설정지금 보고 있는 에이전트 편집 화면입니다.대화 중 답이 마음에 들지 않아 지침을 바로 고치려 할 때
4오른쪽 탭Fix 에이전트, 테스트, 오프너, 파일, 스킬, 스케줄, 설정 탭입니다.바꾼 구성을 시험하거나 실행 설정을 조정할 때

위쪽 헤더(이름, 설명, 저장·버전 버튼), 가운데 편집 영역 위의 폼 / 비주얼 전환, 그 아래 편집 영역(지침, 서브에이전트, 모델, 도구함, 지식함, 미들웨어)은 이어지는 절에서 하나씩 설명합니다.

저장되는 방식​

에이전트 편집 화면의 항목은 저장되는 방식이 세 가지입니다. 헤더의 버전 안내를 누르면 저장과 버전에 대한 안내를 화면에서도 볼 수 있습니다.

첫째, 이름, 설명, 지침은 헤더의 저장을 눌러야 현재 버전에 저장됩니다. 저장할 변경이 없으면 저장은 눌리지 않고, 이름·설명·지침을 고치면 저장이 눌리는 상태로 바뀝니다. 저장하면 "저장되었습니다"가 나옵니다. 저장하기 전의 지침은 대화와 테스트 탭에 쓰이지 않으므로, 지침을 고쳤으면 먼저 저장한 뒤 시험합니다.

둘째, 도구, 모델, 오프너, 스킬 스위치, 지식, 미들웨어, 서브에이전트 추가와 제거, 설정 탭의 에이전트 모드와 Webhook 활성화 스위치, Fix 에이전트가 적용한 변경은 바꾸는 즉시 반영됩니다. 헤더의 저장을 누르지 않아도 대화와 테스트 탭에서 곧바로 바뀐 구성으로 답합니다. 모델은 변경 사항 확인 창에서 확인하고 저장을 누른 순간 반영됩니다. 다만 이 변경들은 아직 현재 버전의 저장본에 기록되지 않았기 때문에, 헤더의 저장이 눌리는 상태가 됩니다. 이때 저장을 누르면 현재 버전에 기록됩니다. 워크스페이스 등록은 저장된 버전으로 하므로, 등록을 요청하기 전에는 꼭 저장을 누릅니다.

셋째, 설정 탭의 Recursion Limit, MCP 서버, Context Compaction은 헤더의 저장이 아니라 각자의 버튼으로 저장합니다. Recursion Limit은 설정 탭 위쪽의 저장, MCP 서버는 MCP 서버 활성화 버튼(활성화한 뒤에는 MCP 설정 업데이트와 MCP 서버 비활성화), Context Compaction은 그 카드 안의 저장을 누릅니다.

방식해당 항목저장하는 방법
헤더의 저장으로 저장이름, 설명, 지침헤더의 저장을 누릅니다. 누르기 전의 지침은 대화와 테스트에 쓰이지 않습니다.
바꾸는 즉시 반영도구, 모델, 오프너, 스킬 스위치, 지식, 미들웨어, 서브에이전트 추가와 제거, 설정 탭의 에이전트 모드와 Webhook 활성화, Fix 에이전트의 변경바꾸는 즉시 대화와 테스트에 반영됩니다. 현재 버전에 기록하려면 헤더의 저장이 눌리는 상태일 때 저장을 누릅니다.
설정 탭 카드의 버튼으로 저장Recursion Limit, MCP 서버, Context Compaction설정 탭 위쪽 저장, MCP 서버 활성화 버튼, Context Compaction 카드 안 저장을 각각 누릅니다.

Fix 에이전트 탭 위쪽에는 "Fix Agent가 적용한 변경 사항은 즉시 반영되며 버전 초안에는 포함되지 않습니다."라는 안내가 있습니다. Fix 에이전트가 고친 내용도 바로 대화와 테스트에 쓰이고, 헤더의 저장을 눌러야 현재 버전에 기록됩니다. 자세한 내용은 Fix 에이전트를 참고하세요.

헤더: 이름, 버전, 저장​

헤더 왼쪽에는 에이전트 이름과 설명이, 오른쪽에는 워크스페이스 등록, 코드 스니펫, 버전 안내, 에이전트 복제, 에이전트 삭제, 현재 버전, 저장, 저장 옵션 더 보기가 있습니다. 현재 버전은 지금 쓰는 버전(예: V1)을 보여 주고, 누르면 버전 목록이 열립니다. 저장은 저장할 변경이 없으면 눌리지 않습니다. 저장 옵션 더 보기는 저장 오른쪽의 화살표입니다. 나머지 버튼은 이어지는 절과 이 페이지 아래쪽의 "에이전트 복제와 삭제" 절에서 설명합니다.

헤더 왼쪽의 에이전트 이름은 눌러서 바로 고치며 최대 50자이고, 비어 있으면 "에이전트 이름..."이 흐리게 보입니다. 이름 아래 설명도 같은 방법으로 고치며 최대 255자이고, 비어 있으면 "에이전트 설명..."이 보입니다. 목록에서 다른 에이전트와 구분되지 않거나 동료가 목록만 보고 용도를 알게 하려면 이 두 칸을 다듬습니다. 헤더 오른쪽 버튼은 두 그림으로 나눠 설명합니다.

에이전트 편집 화면 헤더 1

번호메뉴기능이런 때 사용하세요
1워크스페이스 등록이 에이전트를 워크스페이스에 등록하는 창을 엽니다.팀 전체가 쓰도록 공유하려 할 때
2코드 스니펫이 에이전트를 다른 시스템에서 호출하는 예시 코드 창을 엽니다.연동 담당자에게 호출 방법을 전달할 때
3버전 안내저장 방식과 버전에 대한 안내 창을 엽니다.저장과 새 버전으로 저장의 차이가 헷갈릴 때
4에이전트 복제이 에이전트를 복사해 새 에이전트를 만들고, 복사본의 에이전트 편집 화면으로 이동합니다.원본은 그대로 두고 변형을 시험할 때

2현재 버전지금 쓰는 버전(예: V1)을 표시합니다. 누르면 버전 목록이 열립니다.이전 버전으로 되돌리거나 버전 설명을 고칠 때
3저장고친 이름, 설명, 지침과, 바로 반영된 다른 변경을 현재 버전에 저장합니다. 저장할 변경이 없으면 눌리지 않습니다. 저장하면 "저장되었습니다"가 나옵니다.지침 문장을 다듬은 뒤, 또는 저장이 눌리는 상태로 바뀌었을 때

저장 옵션 메뉴​

저장 옵션 더 보기를 누르면 새 버전으로 저장과 에이전트 내보내기 두 항목이 보입니다. 새 버전으로 저장은 현재 설정을 복사해 새 버전(V2, V3 …)을 만들며, 버전 설명은 30자까지 적을 수 있고 비워 둬도 됩니다. 에이전트 내보내기는 에이전트를 ZIP 파일로 내려받고, 끝나면 "에이전트가 성공적으로 내보내졌습니다"가 나옵니다. 내보낸 파일을 주고받는 방법은 에이전트 가져오기와 내보내기에 있습니다.

버전 안내​

버전 안내를 누르면 저장 방식을 설명하는 창이 열립니다. 창은 세 부분입니다. 즉시 저장되는 설정에는 "도구, 모델, 오프너 등 고급 설정은 변경하는 즉시 저장됩니다. 아래 버전 초안에는 포함되지 않습니다."라고 적혀 있습니다. 이 항목들은 바꾸는 즉시 반영되고, 현재 버전에 기록하려면 헤더의 저장을 누른다는 뜻입니다. 저장과 새 버전으로 저장의 차이에는 저장은 현재 활성 버전을 업데이트하고 새 버전으로 저장은 현재 설정을 복사해 새 버전을 만들며, 새 버전에는 파일과 대화 기록이 이어지지 않는다고 적혀 있습니다. 버전 개수에는 에이전트당 버전을 20개 이하로 두기를 권장하며 강제 제한은 아니라고 적혀 있습니다.

2저장과 새 버전으로 저장의 차이저장은 현재 활성 버전의 이름, 설명, 지침을 업데이트하고, 새 버전으로 저장은 현재 설정을 복사해 새 버전을 만든다고 안내합니다. 새 버전에는 파일과 대화 기록이 이어지지 않습니다.어느 쪽으로 저장할지 정할 때

워크스페이스 등록​

테스트​

테스트 탭에서는 에이전트 편집 화면을 떠나지 않고 에이전트에게 질문해 봅니다. 지침을 고친 뒤 같은 질문을 다시 보내 답이 바뀌었는지 확인할 때 씁니다. 테스트 탭은 저장된 지침으로 답하므로, 지침을 고쳤으면 헤더의 저장을 누른 뒤 보냅니다. 도구, 모델처럼 바꾸는 즉시 반영되는 항목은 저장하지 않아도 바로 시험에 쓰입니다.

처음에는 "주간 업무 보고서 도우미 테스트"처럼 에이전트 이름이 들어간 제목과 "에이전트와 테스트 대화를 시작하세요"가 보이고, 오프너 탭에 넣은 예시 질문(예: "이번 주 핵심 성과를 알려줘.", "업무별 진행 상황 표를 보여줘.", "다음 주 계획은 어떻게 돼?")이 버튼으로 나옵니다. 예시 질문을 누르거나 "에이전트를 테스트해 보세요..." 입력란에 질문을 적고 전송을 누릅니다. Enter로 보내고 Shift + Enter로 줄을 바꾸며, 파일 업로드로 파일을 함께 첨부할 수 있습니다. 오른쪽 위 새 대화(마우스를 올리면 "새 테스트 스레드")는 시험 대화를 새로 시작합니다.

설정 탭​

설정 탭은 에이전트가 답을 만드는 방식을 정합니다. 위쪽에 "에이전트 실행 설정을 관리합니다"라는 안내와 저장 버튼이 있고, 그 아래로 에이전트 모드, Recursion Limit, MCP 서버, Webhook, Context Compaction이 차례로 이어집니다. 항목마다 저장하는 방법이 다르니 아래 설명을 확인하세요.

에이전트 모드에서는 일반 에이전트와 문서작성 에이전트 가운데 고릅니다. 문서작성 에이전트는 모든 대화를 문서 작성 모드로 실행해, PPT·문서·표를 만들고 대화 화면의 문서 캔버스에서 결과를 보여 줍니다. 고르는 즉시 반영되며 "에이전트 모드가 저장되었습니다"가 나옵니다.

Recursion Limit의 최대 처리 단계 수는 한 번 답하는 동안 에이전트가 거칠 수 있는 내부 처리 단계(예: 모델 호출, 도구 실행)의 상한입니다. 1부터 1000까지 넣을 수 있고 기본값은 500입니다. 화면 안내대로 이 값은 복잡한 작업이 중간에 중단되지 않도록 여유를 두는 안전 한도이며, 값을 올린다고 실행 횟수나 비용이 늘어나지는 않습니다. 자료 수집이나 스케줄 실행처럼 단계가 많은 작업은 500 이상을 권장합니다. 답변이 "작업 한계에 도달했습니다"라는 안내와 함께 중단되면 값을 올려 봅니다. 바꾼 값은 탭 위쪽 저장을 눌러야 저장되며, 입력란 옆 기본값으로 초기화를 누르면 입력값이 500으로 돌아갑니다(이때도 저장을 눌러야 저장됩니다).

MCP 서버는 이 에이전트를 MCP 호환 클라이언트(예: Claude Desktop, Cursor)에서 도구처럼 부를 수 있게 엽니다. MCP 서버 활성화 스위치를 켜고 서버 이름(영문, 숫자, _, -, . 만 사용)과 설명을 적은 뒤 MCP 서버 활성화 버튼을 누릅니다. 활성화되면 연결 JSON을 복사해 클라이언트에 넣을 수 있고, 이름이나 설명을 바꾼 뒤에는 MCP 설정 업데이트, 끌 때는 MCP 서버 비활성화를 누릅니다. 자세한 내용은 MCP와 에이전트의 MCP화에 있습니다.

Webhook은 외부 시스템(예: n8n, Dify)이 REST API로 이 에이전트를 호출할 수 있게 합니다. 화면 안내대로 호출할 때는 API 키 인증이 필요합니다. Webhook 활성화 스위치는 켜고 끄는 즉시 반영되고, 켜면 Webhook URL과 복사 버튼이 보입니다. 호출할 때는 사이드바의 에셋설정을 눌러 여는 에셋 화면의 API 키 탭에서 만든 invoke 권한 API 키를 함께 보내야 합니다. 호출 방법은 코드 스니펫과 외부 API에 있습니다.

Context Compaction은 대화가 길어지면 최근 메시지를 뺀 앞부분을 자동으로 요약해 모델이 읽을 분량을 줄입니다. 수정이 예상대로 되지 않을 때​

  • 헤더의 저장이 눌리지 않으면 저장할 변경이 없는 상태입니다. 이름, 설명, 지침을 실제로 바꿨는지 봅니다.
  • 설정 탭의 Recursion Limit, MCP 서버, Context Compaction 값이 반영되지 않으면 그 항목의 버튼(탭 위쪽 저장, MCP 서버 활성화 또는 MCP 설정 업데이트, Context Compaction 카드 안 저장)을 눌렀는지 확인합니다.
  • 지침을 바꿨는데 답이 그대로이면 헤더의 저장을 눌렀는지 먼저 확인합니다. 저장하지 않은 지침은 대화와 테스트에 쓰이지 않습니다. 저장했다면 테스트 탭에서 새 대화를 눌러 다시 물어봅니다. 앞 대화의 내용이 답에 영향을 줄 수 있습니다.
  • 워크스페이스 등록 때 "저장되지 않은 변경이 있습니다. 에이전트를 먼저 저장한 뒤 등록하세요."가 나오면 헤더의 저장을 누른 뒤 다시 등록합니다.
  • 바꾼 뒤 답이 오히려 나빠졌다면 버전 목록에서 이전 버전으로 돌아가 같은 질문을 보내 비교합니다.
