Deep Agent Builder 실습 2: 직접 만들고 다듬기

이 실습은 빌더 대화 없이 이름과 설명만으로 빈 에이전트를 만든 뒤, 지침을 직접 쓰고, 모델 설정을 확인하고, 챗 오프너를 넣고, 테스트 탭에서 회의록 파일로 시험합니다. 예시는 브레인크루 AI혁신팀 김그루 사원이 회의록에서 일정과 할 일을 뽑아 요일별 표로 정리하는 주간 일정 정리 도우미를 만드는 과정입니다. 편집 화면 전체 구성은 에이전트 수정에 있습니다.

이 페이지에서 할 수 있는 일

  • 에이전트 직접 만들기로 빈 에이전트를 만듭니다.
  • 지침 입력란에 역할, 입력, 출력 형식, 금지 사항을 나눠 적고 저장합니다.
  • 모델 설정 창에서 모델과 입력 길이를 확인하고, 오프너 탭에 예시 질문을 넣습니다.
  • 테스트 탭에 파일을 붙여 저장 전에 결과를 확인합니다.

목표​

항목내용
만들 것주간 일정 정리 도우미(직접 만든 에이전트)
결과물요일 · 시간 · 일정·할 일 · 담당 · 출처 열의 주간 일정표, 날짜 미정 목록, 중요한 일 3가지
걸리는 시간만들기 1분, 지침 5분, 오프너 2분, 테스트 1분
난이도★★☆☆☆

준비물​

파일내용형식
회의록_AI업무혁신_20261110.txt브레인크루 4분기 AI 업무 혁신 주간 회의록(가상). 결정 사항 3건, 액션 아이템 4건과 기한, 다음 회의 일시txt

테스트 탭과 대화 화면에는 .pdf, .jpg, .jpeg, .png, .gif, .webp, .md, .markdown, .txt, .xlsx, .xls, .xlsb, .xlsm, .csv, .docx, .pptx, .ppt, .hwp, .hwpx, .html, .htm 파일을 붙일 수 있습니다. 같은 회의록의 html 판(회의록_AI업무혁신_20261110.html)으로 해도 결과가 같아야 합니다.

1단계. 이름과 설명만으로 만들기​

새 에이전트 만들기 창

번호메뉴입력하거나 고를 값
1에이전트 이름주간 일정 정리 도우미 (50자까지)
2에이전트 설명 (선택)회의록과 메모에서 일정과 할 일을 뽑아 요일별 주간 계획표로 정리합니다. (255자까지)
3확인빈 에이전트를 만들고 에이전트 편집 화면으로 이동합니다.
  1. 사이드바 새 에이전트를 누르고 입력란 아래 에이전트 직접 만들기를 누릅니다.
  2. 이름과 설명을 적고 확인을 누릅니다.

2단계. 지침 쓰고 저장하기​

지침 입력과 저장

번호메뉴입력하거나 고를 값
1지침 입력란아래 다섯 줄의 지침. 입력란 오른쪽 아래에 글자 수(이 예시는 240자)가 보입니다.
2저장헤더의 저장 버튼입니다. 누르면 이름·설명·지침이 현재 버전(V1)에 저장됩니다.

입력한 지침은 다음과 같습니다.

너는 브레인크루 AI혁신팀의 주간 일정 정리 도우미다. 첨부한 회의록, 업무 메모에서 날짜, 시간, 담당자, 할 일을 찾아 월요일부터 금요일까지 요일별 표(요일 | 시간 | 일정·할 일 | 담당 | 출처)로 정리한다. 날짜가 없는 할 일은 표 아래 '날짜 미정' 목록에 따로 적는다. 원문에 없는 일정은 만들지 않고, 불확실하면 [확인 필요]를 붙인다. 마지막에 이번 주 가장 중요한 일 3가지를 한 줄씩 요약한다.

지침은 "역할 → 입력 → 출력 형식 → 금지 사항 → 마무리" 순서로 한 줄에 하나씩 쓰면 나중에 고칠 곳을 찾기 쉽습니다. 저장하기 전에는 헤더에 "한 번도 저장되지 않았습니다" 또는 "저장되지 않은 변경이 있습니다"가 보입니다.

3단계. 모델 설정 확인하기​

모델 설정 창

번호메뉴기능이런 때 사용하세요
1모델 선택이 에이전트가 쓸 모델입니다. 새 에이전트는 기본 모델(이 환경은 GPT-4.1)로 시작합니다.긴 회의록이 많으면 입력 길이가 긴 모델로 바꿀 때
2입력고른 모델이 한 번에 읽을 수 있는 입력 토큰 길이입니다. GPT-4.1은 1,047,576 토큰, 출력은 32,768 토큰입니다.한 주치 회의록을 한꺼번에 넣어도 되는지 볼 때
3취소바꾸지 않고 닫습니다.기본값 그대로 쓸 때
  1. 폼 보기의 모델 줄 오른쪽 모델 설정(톱니)을 누릅니다.
  2. 모델과 입력 길이를 확인하고, 바꿀 것이 없으면 취소를 누릅니다.

오른쪽 파라미터에는 고른 모델이 받는 항목만 카드로 나옵니다. GPT-4.1은 temperature(기본값 1, 02), max_tokens(032768, 0이면 보내지 않음), top_p(기본값 1, 0~1), seed, stop, tool_choice(auto, none, required), response_format 등 10개입니다. 값을 바꾸고 저장을 누르면 "변경 사항 확인" 표가 먼저 나오고, 확인하고 저장을 눌러야 저장됩니다. 일정표처럼 형식이 정해진 결과는 기본값으로도 충분하므로 이 실습에서는 바꾸지 않습니다. 항목별 뜻은 모델 구성에 있습니다.

4단계. 챗 오프너 넣기​

Chat Opener 추가 창

번호메뉴입력하거나 고를 값
1예시 질문 입력란첨부한 회의록에서 이번 주 일정을 요일별 표로 정리해 줘.
2추가오프너를 목록에 넣습니다. 바로 저장됩니다.
  1. 오른쪽 탭 줄의 오프너를 누르고 추가를 누릅니다.
  2. 첫 오프너를 적고 추가를 누릅니다.
  3. 같은 방법으로 두 번째 오프너 "날짜가 정해지지 않은 할 일만 따로 모아 줘."를 넣습니다.

오프너는 에이전트당 12개까지 넣을 수 있고, 대화 화면과 테스트 탭의 빈 화면에 버튼으로 보입니다. 자세한 설명은 챗 오프너에 있습니다.

5단계. 테스트 탭에서 시험하기​

테스트 탭에서 시험하기

번호메뉴입력하거나 고를 값
1테스트오른쪽 탭 줄에서 누릅니다. 저장하지 않은 지침도 바로 반영해 시험합니다.
2오프너 버튼"첨부한 회의록에서 이번 주 일정을 요일별 표로 정리해 줘."를 누르면 입력란에 들어갑니다.
3테스트 입력란파일 업로드(클립)로 회의록_AI업무혁신_20261110.txt를 붙인 뒤 Enter로 보냅니다.

결과​

주간 일정표 결과

번호항목확인할 것
1표 머리글지침대로 요일, 시간, 일정·할 일, 담당, 출처 다섯 열인지
2할 일 칸회의록의 기한(예: 윤지원 과장의 복리후생 규정 개정본 전달, 11/12 마감)이 해당 요일에 들어갔는지
3날짜 미정결정 사항처럼 날짜가 없는 일이 따로 모였는지

이 실습에서는 "AI혁신팀 주간 일정 (2026-11-11~11-15)" 표에 화요일 주간 회의, 화요일 복리후생 규정 개정본 전달(마감 11/12), 목요일 판매 리포트 에이전트 개선(마감 11/14), 금요일 설문 분석 에이전트 초안 준비(마감 11/17)가 들어가고, 지역별 실적표 추가·설문 분석 에이전트 공유·규정 최신본 등록은 "날짜 미정"에 [확인 필요]와 함께 모였습니다. 마지막에는 "이번 주 가장 중요한 일 3가지"가 붙었습니다.

결과에는 고칠 점도 보입니다. 11/12(목) 마감인 일이 화요일 칸에, 11/14(토) 마감인 일이 목요일 칸에 들어갔고, 다음 주 화요일인 11/17 마감인 일이 금요일에 들어갔습니다. 모델이 붙인 요일과 기간을 그대로 믿지 말고 회의록 원문의 날짜와 하나씩 대조하세요. 이런 날짜 배치 오류는 지침에 "할 일은 기한 날짜의 요일 칸에 넣는다. 이번 주를 넘는 기한은 '다음 주 이후' 목록에 적는다."를 더하면 줄어듭니다. 고친 뒤에는 테스트 탭의 새 대화로 같은 질문을 다시 보내 비교합니다. 모델의 답은 실행마다 조금씩 다를 수 있습니다.

설정값 표​

설정위치이 실습의 값기본값과 의미
에이전트 이름·설명헤더주간 일정 정리 도우미 / 회의록과 메모에서…이름 50자, 설명 255자까지. 사이드바와 대화 화면 제목에 보입니다.
지침폼 보기다섯 줄 지침(240자)처음에는 비어 있습니다. 헤더 저장으로 현재 버전에 저장됩니다.
모델폼 보기 모델 설정GPT-4.1계정 기본 모델로 시작합니다. 파라미터를 비워 두면 모델 기본값을 씁니다.
챗 오프너오프너 탭2개처음에는 없습니다. 최대 12개, 추가하면 바로 저장됩니다.
에이전트 모드설정 탭일반 에이전트기본값은 일반 에이전트입니다. 문서 파일을 받으려면 실습 4처럼 문서작성 에이전트로 바꿉니다.

이럴 때 쓰세요: 김그루 사원은 월요일 아침마다 지난주 회의록 서너 개를 훑어 이번 주 할 일을 정리합니다. 주간 일정 정리 도우미에 회의록을 한꺼번에 붙이면 요일별 표와 날짜 미정 목록이 나오므로, 팀 메신저에 표를 붙이고 날짜 미정 항목만 담당자에게 물어보면 됩니다. 지침을 직접 쓰는 방식은 형식이 분명한 업무에서 빌더 대화보다 빠릅니다.

흔한 실수와 해결​

증상원인해결
대화 화면에서 바꾼 지침이 반영되지 않습니다.지침을 고친 뒤 헤더 저장을 누르지 않았습니다.헤더에 "저장되지 않은 변경이 있습니다"가 보이면 저장을 누릅니다. 테스트 탭은 저장 전 내용으로도 시험됩니다.
편집 화면을 떠나려는데 확인 창이 뜹니다.저장하지 않은 변경이 있습니다.남길 내용이면 먼저 저장합니다.
모델 설정에서 저장을 눌렀는데 창이 닫히지 않습니다."변경 사항 확인" 단계입니다.표를 확인하고 확인하고 저장을 누릅니다.
표 대신 줄글로 답합니다.지침에 출력 형식이 모호합니다.열 이름을 지침에 그대로 적습니다(예: 요일 | 시간 | 일정·할 일 | 담당 | 출처).

응용 과제​

  1. 위 "결과"에서 말한 날짜 배치 규칙을 지침에 더하고 저장 옵션 더 보기의 새 버전으로 저장으로 V2를 만든 뒤, 같은 질문으로 V1과 결과를 비교해 보세요. 버전 다루는 법은 에이전트 수정에 있습니다.
  2. 회의록 html 판과 txt 판을 함께 붙여 같은 일정이 두 번 나오지 않는지 확인해 보세요.
  3. 스케줄 탭에 매주 월요일 9시 실행을 걸어 두는 방법을 스케줄링과 백그라운드 모드에서 읽어 보세요.
