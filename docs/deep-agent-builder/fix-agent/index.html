Deep Agent Builder Fix 에이전트

Fix 에이전트는 이미 만든 에이전트의 동작을 자연어로 점검하고 수정하는 대화형 경로입니다. 이 페이지에서는 수정 요청을 보내기 전에 확인할 권한과 대상, 대화 중 확인할 결과, 자동 반영과 보류된 기능의 경계를 설명합니다.

시작 전에 확인할 것​

Fix 에이전트를 사용하려면 다음 조건을 확인합니다.

  1. 수정하려는 에이전트가 현재 사용자 소유인지 확인합니다.
  2. 에이전트 편집 권한이 있는지 확인합니다.
  3. 수정 요청이 어떤 동작을 바꿔야 하는지 한 문장으로 정리합니다.
  4. 실제 고객 정보, 토큰, 호스트와 내부 식별자를 요청 내용에 넣지 않습니다.

Fix 대화 조회에는 에이전트 조회 권한이 필요하고, 수정 요청과 대화 초기화에는 에이전트 편집 권한이 필요합니다. 실행을 다시 이어가는 별도 경로는 실행 권한을 추가로 확인합니다. 화면에서 버튼이 보인다는 사실만으로 실행 권한까지 있다고 판단하지 않습니다.

수정 요청 보내기​

에이전트 편집 화면에서 현재 동작과 바꾸려는 결과를 함께 적습니다. 예를 들어 답변 형식, 누락된 확인 절차, 특정 조건에서의 질문 순서를 구체적으로 설명합니다. 한 번에 여러 동작을 바꾸기보다 하나의 변경을 먼저 요청하면 결과를 확인하기 쉽습니다.

요청을 보내면 Fix 대화가 새로 만들어지거나, 같은 대화 식별자를 사용해 기존 대화를 다시 시작합니다. 새 대화는 대기 상태로 등록된 뒤 처리 큐로 전달됩니다. 같은 대화를 재사용하는 경우 이전 이벤트가 정리되고 대화가 대기 상태로 돌아간 뒤 새 요청이 처리됩니다.

대화 중 확인할 결과​

결과는 별도 결과 화면이 아니라 현재 대화 스트림으로 전달됩니다. 처음에는 대화 식별자를 확인할 수 있는 메타 정보가 오고, 이후 다음 종류의 결과가 순서대로 나타날 수 있습니다.

  • 메시지 일부가 도착하는 진행 결과
  • 에이전트 설정에 적용될 변경 초안
  • 추가 정보가 필요한 경우의 명확화 질문
  • 처리가 끝났음을 나타내는 완료 결과
  • 처리를 끝내지 못한 경우의 오류 결과

명확화 질문이 나오면 요청의 대상, 조건 또는 원하는 출력 형식을 보충합니다. 완료 결과가 보이기 전에는 변경이 끝났다고 판단하지 않습니다. 오류 결과가 나오면 같은 요청을 무조건 반복하지 말고, 권한과 대상 에이전트의 상태를 먼저 확인합니다.

변경이 반영되는 범위​

현재 Fix 대화는 그래프가 만든 변경 초안을 에이전트에 자동 저장하는 경로입니다. 따라서 완료 결과를 확인한 뒤 에이전트 설정을 다시 열어 이름, 설명, 지침과 관련 자원이 의도대로 바뀌었는지 확인합니다. 변경 내용을 확인하지 않은 채 대화가 끝났다는 사실만으로 성공을 기록하지 않습니다.

Fix 대화는 저장 권한과 실행 권한을 같은 것으로 취급하지 않습니다. 도구, 미들웨어, 스킬과 같은 자원을 연결한 뒤 실제 실행이 가능한지는 해당 자원의 사용 권한을 실행 시점에 다시 판단합니다. 수정이 저장되었지만 실행할 수 없는 경우에는 에이전트 설정과 자원 사용 권한을 나누어 점검합니다.

지원하지 않는 흐름으로 오해하기 쉬운 항목​

현재 확인된 Fix 대화에는 별도의 수정안 승인·거부 단계, 버전별 파일 저장, 현재 버전 포인터 교체, 에이전트 버전 비교를 수행하는 별도 수명주기가 포함되어 있지 않습니다. 이런 기능을 화면에 있다고 가정하거나, 수정 요청 뒤 승인 단계가 반드시 나온다고 안내해서는 안 됩니다.

화면의 Fix 패널, 입력 폼과 시각 상태의 동기화, 저장 표시, 재시도 버튼은 서버 계약만으로 확정할 수 없습니다. 제품 버전에서 실제 화면을 확인하기 전에는 메뉴 이름과 성공 문구를 단정하지 않습니다.

대표적인 실패와 다음 판단​

요청을 보낼 수 없습니다​

편집 권한과 대상 에이전트의 소유 범위를 확인합니다. 요청 내용이 허용된 길이와 형식인지도 확인합니다. 권한이 없으면 관리자에게 권한 범위를 요청하고, 대상이 잘못되었다면 현재 사용자에게 속한 에이전트를 다시 선택합니다.

대화는 시작됐지만 결과가 오지 않습니다​

대화 식별자와 연결 상태를 확인합니다. 연결이 끊기면 서버는 취소 신호를 best-effort로 전달할 수 있으므로, 동일 요청을 반복하기 전에 기존 대화가 완료 또는 오류 상태로 수렴했는지 확인합니다. 재시도 경로가 제공되는 경우에도 실행 권한이 별도로 필요한지 확인합니다.

원하는 변경이 반영되지 않았습니다​

먼저 완료 결과와 에이전트 설정의 현재 값을 다시 조회합니다. 설정이 바뀌지 않았다면 요청이 실제로 완료됐는지와 오류 결과를 확인합니다. 설정은 바뀌었지만 실행 결과가 그대로라면 지침, 연결된 자원, 자원 사용 권한과 입력 조건을 각각 점검합니다.

오류가 반복됩니다​

같은 요청을 바로 반복하지 말고 에이전트 소유권, 편집 권한, 자원 사용 권한과 현재 대화 상태를 확인합니다. 필요한 정보가 부족하면 명확화 질문에 맞춰 요청을 다시 작성합니다. 원인을 확인할 수 없는 상태에서 성공으로 기록하거나 기능이 지원된다고 추정하지 않습니다.
