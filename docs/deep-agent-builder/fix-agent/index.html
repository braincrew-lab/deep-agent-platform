Fix 에이전트

Fix 에이전트는 에이전트 편집 화면 오른쪽에 있는 수정 도우미입니다. 지침 문장을 직접 고치지 않아도 "이렇게 바꿔 주세요"라고 적으면 Fix 에이전트가 지침과 구성을 대신 고칩니다. 이 페이지는 김그루 사원이 에이전트 만들기에서 직접 만든 "이메일 초안 도우미"에 서명 규칙을 더하고 지침을 압축하는 과정을 따라 합니다. 이 페이지의 그림은 원래 에이전트를 그대로 두려고 복제로 만든 사본에서 찍었기 때문에, 화면의 에이전트 이름이 "이메일 초안 도우미 사본"으로 보입니다.

이 페이지에서 할 수 있는 일

  • 테스트 탭에서 고칠 답변을 찾고, 무엇을 바꿀지 한 문장으로 정리합니다.
  • Fix 에이전트에 요청을 보내기 전에 새 버전을 저장해 되돌릴 지점을 남깁니다.
  • 자연어로 수정 요청을 보내고, 바뀐 지침을 직접 확인합니다.
  • Fix 에이전트가 확인 질문을 보내면 보기를 골라 승인하거나 직접 답합니다.
  • 테스트 탭에서 같은 질문을 다시 보내 수정 전후를 비교하고, 필요하면 이전 버전으로 돌아갑니다.

시작하기 전에 알아 둘 점​

  • Fix 에이전트는 지금 열어 둔 에이전트를 고치며, 고친 내용은 곧바로 대화와 테스트 탭에 반영됩니다. 탭 위쪽에 "Fix Agent가 적용한 변경 사항은 즉시 반영되며 버전 초안에는 포함되지 않습니다."라는 안내가 있습니다.
  • 바로 반영된 변경은 아직 현재 버전에 기록되지 않은 상태라서, 헤더에 "저장되지 않은 변경이 있습니다"가 보입니다. 결과를 확인한 뒤 헤더의 저장을 눌러야 현재 버전에 기록되고, 워크스페이스 등록도 저장된 버전으로 할 수 있습니다.
  • 고친 결과가 마음에 들지 않을 때 돌아갈 곳이 필요하면, 요청을 보내기 전에 새 버전으로 저장으로 지금 상태를 남겨 둡니다.
  • 다른 버전 작업이 진행 중이면 "버전 작업이 진행 중입니다. 완료된 뒤 다시 시도하세요."가 나옵니다. 잠시 기다렸다가 다시 보냅니다.

1단계: 고칠 답변 찾기​

Fix 에이전트를 열기 전에 어떤 답이 문제인지 먼저 확인합니다. 이메일 초안 도우미의 에이전트 편집 화면에서 오른쪽 테스트 탭을 열고 아래 질문을 보냅니다.

프롬프트: 영업1팀 최하늘 책임에게 다음 주 화요일 회의록 요약 도우미 시연 일정을 잡자는 메일을 써 주세요.

이메일 초안 도우미는 제목과 본문을 지침대로 씁니다. 그런데 AI혁신팀은 메일 끝에 늘 "브레인크루 AI혁신팀 김그루 드림" 서명을 붙이는데, 지침에 그 규칙이 없어 서명이 빠져 있습니다.

고칠 답변 찾기

번호메뉴기능이런 때 사용하세요
1테스트에이전트 편집 화면을 떠나지 않고 에이전트에게 질문해 보는 탭입니다.자주 쓰는 요청을 실제로 보내 결과를 점검할 때
2보낸 질문시험용으로 보낸 요청입니다.수정 뒤 같은 질문으로 다시 비교할 때
3메일 끝부분맺음말 뒤에 서명이 없습니다.팀 규칙과 다른 부분을 찾을 때

문제가 된 부분을 찾았으면 무엇을 바꿀지 한 문장으로 정리합니다. 이 사례에서는 "메일 끝에 항상 정해진 서명을 붙인다"가 고칠 내용입니다.

2단계: 되돌릴 지점 만들기​

헤더의 저장 옵션 더 보기를 누르고 새 버전으로 저장을 고르면 "새 버전 생성" 창이 열립니다.

새 버전 생성 창

번호메뉴기능이런 때 사용하세요
1버전 설명 (선택사항)새 버전에 붙일 설명을 30자까지 적습니다. 비워 둬도 됩니다."서명 규칙 추가"처럼 이번 수정의 목적을 남길 때
2취소창을 닫고 버전을 만들지 않습니다.버전을 나눌 필요가 없는 작은 수정이라고 판단했을 때
3저장지금 설정을 새 버전으로 저장합니다. 헤더의 현재 버전이 다음 번호(예: V2)로 바뀝니다.Fix 에이전트에 요청하기 직전, 원래 지침을 V1로 남길 때

창의 버전 설명 (선택사항) 칸(30자까지, 비워 둬도 됨)에 "서명 규칙 추가"를 적고 저장을 누릅니다. 헤더의 현재 버전이 V2로 바뀝니다. 이제 V2에서 Fix 에이전트를 쓰고, 원래 지침은 V1에 그대로 남습니다. 버전 관리는 에이전트 수정에서 자세히 설명합니다.

3단계: Fix 에이전트 탭 열기​

에이전트 편집 화면을 열면 오른쪽에 Fix 에이전트 탭이 먼저 선택되어 있습니다. 처음에는 대화가 비어 있고, "이메일 초안 도우미 수정"처럼 에이전트 이름 뒤에 "수정"이 붙은 제목과 "자연어로 에이전트를 수정하세요" 안내 아래에 요청 예시 세 문장이 보입니다.

  • "tavily 검색 도구 추가해줘"
  • "todo로 작업 관리할 수 있는 기능 추가해줘"
  • "시스템 프롬프트를 구조화된 프롬프트로 압축해 개선해줘"

예시는 눌러서 쓰는 버튼이 아니므로, 참고해서 입력란에 직접 적습니다. 요청은 "에이전트를 어떻게 수정할지 설명하세요..." 입력란에 적고 Enter나 전송으로 보내며, Shift + Enter로 줄을 바꿉니다. 입력란이 비어 있으면 전송을 누를 수 없습니다. 앞선 요청과 관계없는 다른 수정을 시작할 때는 새 대화(마우스를 올리면 "새 수정 스레드")를 누릅니다.

Fix 에이전트 탭 시작 화면 위쪽

번호메뉴기능이런 때 사용하세요
1Fix 에이전트자연어 수정 탭을 엽니다. 에이전트 편집 화면을 처음 열면 이 탭이 선택되어 있습니다.테스트 탭에서 문제를 확인한 뒤 수정하러 돌아올 때
2새 대화Fix 에이전트와의 수정 대화를 새로 시작합니다. 마우스를 올리면 "새 수정 스레드"로 표시됩니다.앞선 요청과 관계없는 다른 수정을 시작할 때
3즉시 반영 안내"Fix Agent가 적용한 변경 사항은 즉시 반영되며 버전 초안에는 포함되지 않습니다."라는 안내입니다.요청 전에 새 버전 저장이 필요한지 판단할 때
4제목지금 고치는 에이전트 이름 뒤에 "수정"이 붙은 제목과 "자연어로 에이전트를 수정하세요" 안내가 보입니다.맞는 에이전트를 고치는지 확인할 때

같은 화면 아래쪽에는 예시 요청과 입력란, 전송이 있습니다.

Fix 에이전트 탭 시작 화면 아래쪽

번호메뉴기능이런 때 사용하세요
1예시 요청"tavily 검색 도구 추가해줘", "todo로 작업 관리할 수 있는 기능 추가해줘", "시스템 프롬프트를 구조화된 프롬프트로 압축해 개선해줘" 세 문장입니다. 눌러서 쓰는 버튼은 아니므로 참고해 직접 적습니다.요청 문장의 형태를 참고할 때
2수정 요청 입력란"에이전트를 어떻게 수정할지 설명하세요..." 자리에 요청을 적습니다. Enter로 보내고 Shift + Enter로 줄을 바꿉니다.고칠 내용과 바뀐 뒤 기대하는 결과를 함께 적을 때
3전송요청을 보냅니다. 입력란이 비어 있으면 누를 수 없습니다.요청을 다 적었을 때

첫 번째와 두 번째 예시("tavily 검색 도구 추가해줘", "todo로 작업 관리할 수 있는 기능 추가해줘")에서 보듯 Fix 에이전트는 지침 문장뿐 아니라 도구 추가 같은 구성 변경도 요청받을 수 있습니다.

4단계: 서명 규칙 추가 요청하기​

요청에는 무엇이 문제였는지와 바뀐 뒤 어떻게 동작해야 하는지를 함께 씁니다. "메일을 더 좋게"처럼 막연하게 쓰면 Fix 에이전트가 무엇을 바꿔야 할지 알기 어렵습니다.

프롬프트: 이메일 본문 끝에 항상 "브레인크루 AI혁신팀 김그루 드림" 서명을 붙이도록 지침에 규칙을 추가해 주세요. 사용자가 보내는 사람을 따로 알려 주면 그 이름과 소속으로 바꿔 주세요.

서명 규칙 추가 결과

번호메뉴기능이런 때 사용하세요
1보낸 요청내가 보낸 요청이 대화에 남습니다.나중에 어떤 요청으로 지침이 바뀌었는지 되짚을 때
2Fix 에이전트의 답현재 지침에서 확인한 내용, 바꿀 내용, 바꾼 결과를 설명합니다.요청을 잘못 이해하지 않았는지 확인할 때
3지침가운데 폼 보기의 지침에 서명 규칙이 들어갔는지 직접 봅니다.요청한 내용이 어느 문장에 들어갔는지 확인할 때
4헤더 저장 상태헤더에 "저장되지 않은 변경이 있습니다"가 보이면 저장을 눌러 현재 버전에 기록할 수 있습니다.고친 결과를 현재 버전에 남길 때

Fix 에이전트는 먼저 현재 지침에 서명 관련 규칙이 없는지 살펴본 뒤, 무엇을 추가할지 설명하고 지침을 고칩니다. 김그루 사원의 요청에서는 확인 질문 없이 바로 반영되었고, 지침 끝에 "이메일 본문 끝에는 항상 서명을 붙입니다. 기본 서명은 "브레인크루 AI혁신팀 김그루 드림"입니다."와 "사용자가 보내는 사람 이름과 소속을 알려주면, 해당 정보로 서명을 변경하여 사용합니다." 두 문장이 더해졌습니다. 답만 보고 끝내지 말고, 가운데 폼 보기의 지침에 서명 규칙이 실제로 들어갔는지 직접 확인합니다. 바뀐 지침은 이미 대화와 테스트에 반영된 상태이며, 헤더의 저장 왼쪽에 "저장되지 않은 변경이 있습니다"가 보입니다. 저장은 7단계에서 결과를 비교한 뒤 8단계에서 해도 됩니다.

5단계: 확인 질문에 답하기​

요청이 모호하거나 고치는 방법이 여러 가지면 Fix 에이전트가 바로 고치지 않고 먼저 확인 질문을 보냅니다. 질문은 보기 카드로 나오며, 입력란에는 "먼저 위의 질문에 답변해 주세요"가 보입니다. 요청이 충분히 분명하다고 판단하면 질문 없이 바로 고치기도 합니다. 예를 들어 "메일을 좀 더 짧게 써 주게 해 줘."는 질문 없이 곧바로 지침에 문장이 더해졌고, 아래처럼 바꿀 방향을 정하지 않은 요청에서는 확인 질문이 나왔습니다.

프롬프트: 말투 좀 바꿔 줘.

Fix 에이전트는 "어떤 말투로 바꿔 드릴까요?"라고 묻고, "격식 있고 정중한 말투", "친근하고 편안한 말투", "간결하고 명확한 말투" 세 보기와 "직접 입력 (원하는 내용을 자유롭게 작성)"을 보여 줍니다. 보기는 요청할 때마다 조금씩 달라질 수 있습니다. 보기 가운데 하나를 고르거나, 직접 입력을 골라 "받는 사람 직급에 맞춰 정중하게"처럼 원하는 답을 적은 뒤 제출을 누릅니다. 보기를 고르면 그 방향으로 진행하도록 승인하는 셈입니다.

Fix 에이전트의 확인 질문

번호메뉴기능이런 때 사용하세요
1질문Fix 에이전트가 무엇을 확인하려는지 보여 줍니다. 질문 내용은 요청에 따라 달라집니다.요청이 어떻게 해석되는지 확인할 때
2보기Fix 에이전트가 제안한 답입니다. 하나를 고르면 그 방향으로 진행하도록 승인하는 셈입니다.제안이 내 의도와 맞을 때
3직접 입력보기 대신 원하는 답을 적습니다."받는 사람 직급에 맞춰 정중하게"처럼 기준을 직접 정할 때
4제출고르거나 적은 답을 보냅니다.답을 정했을 때

긴 설명으로 답하고 싶으면 질문 카드 오른쪽 위의 선택지 닫기를 누릅니다. 그러면 보기 카드가 닫히고 입력란 안내가 "선택지 대신 직접 답을 입력하세요..."로 바뀌어, 입력란에 직접 답을 적을 수 있습니다.

선택지 닫기와 입력란

번호메뉴기능이런 때 사용하세요
1선택지 닫기보기 카드를 닫고 입력란에 직접 답을 쓰게 합니다. 입력란 안내가 "선택지 대신 직접 답을 입력하세요..."로 바뀝니다.긴 설명으로 답하고 싶을 때
2입력란질문에 답하기 전에는 "먼저 위의 질문에 답변해 주세요"가 보입니다.질문에 먼저 답해야 한다는 것을 확인할 때

질문이 여러 개면 "2개의 확인이 필요합니다"처럼 묶음으로 나오고, 이전 질문, 다음 질문으로 옮겨 다니며 답한 뒤 전체 제출을 누릅니다. 답을 받으면 Fix 에이전트가 수정을 이어 갑니다. 김그루 사원이 "격식 있고 정중한 말투"를 고르자, 지침의 "존댓말을 씁니다"가 "격식 있고 정중한 존댓말을 씁니다"로 바뀌었습니다.

팁: 질문 없이 바로 고쳐진 결과가 의도와 다르면, 가운데 지침에서 더해진 문장을 직접 지우거나 고친 뒤 저장합니다.

6단계: 지침을 압축해 다듬기​

규칙을 여러 번 덧붙이다 보면 지침이 길어지고 문장이 겹칩니다. 이때는 Fix 에이전트 탭의 세 번째 예시 "시스템 프롬프트를 구조화된 프롬프트로 압축해 개선해줘"처럼 지침 전체를 정리해 달라고 요청합니다.

프롬프트: 시스템 프롬프트를 구조화된 프롬프트로 압축해 개선해줘. 역할, 입력, 작성 순서, 서명 규칙, 금지 사항을 소제목으로 나누고, 지금 들어 있는 규칙은 하나도 빼지 말아 줘.

Fix 에이전트는 지침 전체를 바꾸는 요청에는 바로 고치지 않고, 어떻게 정리할지 먼저 제안한 뒤 그대로 반영할지 확인을 구하기도 합니다. 김그루 사원의 요청에서도 정리한 지침을 먼저 보여 주고 "이렇게 구조화된 프롬프트로 시스템 프롬프트를 업데이트해 드릴까요?"라고 물었습니다. 이때는 제안을 읽어 보고 아래처럼 답을 보내면 지침이 바뀝니다.

프롬프트: 네, 그대로 지침에 반영해 주세요.

김그루 사원의 지침은 "# 이메일 초안 도우미" 아래 역할, 입력, 작성 순서, 서명 규칙, 금지 사항 다섯 소제목으로 나뉘었습니다. Fix 에이전트가 무엇을 합치고 어떻게 나눴는지 설명하면, 소제목으로 나뉜 새 지침을 읽으며 서명 규칙과 [확인 필요] 규칙이 그대로 남았는지 설명과 대조합니다. 이 사례에서는 서명 규칙 소제목 아래 기본 서명과 보내는 사람을 바꾸는 규칙이, 작성 순서 아래 [확인 필요] 규칙과 "격식 있고 정중한 존댓말로 작성"이 그대로 남았고, 금지 사항 아래에도 알려 주지 않은 날짜, 금액, 약속은 [확인 필요]로 표시한다는 규칙이 다시 정리되었습니다.

지침 압축 결과

번호메뉴기능이런 때 사용하세요
1보낸 요청압축을 요청한 문장입니다.어떤 기준으로 정리를 요청했는지 되짚을 때
2Fix 에이전트의 답기존 규칙을 유지하면서 어떻게 나눴는지 설명하고, 정리한 지침을 보여 줍니다.빠진 규칙이 없는지 설명과 대조할 때
3지침소제목으로 나뉜 새 지침입니다.서명 규칙과 [확인 필요] 규칙이 그대로 남았는지 확인할 때

팁: 압축을 요청할 때는 "지금 들어 있는 규칙은 하나도 빼지 말아 줘"처럼 지켜야 할 조건을 함께 적으세요. 정리 과정에서 규칙이 사라지면 결과가 달라집니다.

7단계: 테스트 탭에서 전후 비교하기​

지침이 바뀌었으면 테스트 탭에서 새 대화를 누르고 1단계와 같은 질문을 다시 보냅니다. 새 대화에서 물어야 앞 대화가 섞이지 않아 비교하기 쉽습니다. Fix 에이전트가 고친 지침은 저장하지 않아도 이미 테스트에 반영되어 있습니다. 답변의 메일 끝에 "브레인크루 AI혁신팀 김그루 드림" 서명이 붙었는지, 제목 한 줄 뒤에 인사, 용건, 세부 내용, 요청 사항, 맺음말 순서가 압축 뒤에도 그대로인지, 알려 주지 않은 시간이나 장소를 지어내지 않았는지 봅니다.

수정 뒤 다시 시험한 답변

번호메뉴기능이런 때 사용하세요
1테스트고친 지침으로 같은 질문을 다시 보내는 탭입니다.수정 전후 답을 비교할 때
2새 대화앞 대화와 섞이지 않는 새 시험 대화를 엽니다.1단계와 같은 조건으로 시험할 때
3제목답변 첫 줄의 제목입니다. 그 아래로 인사, 용건, 세부 내용, 요청 사항, 맺음말 순서가 그대로인지 봅니다.압축 뒤에도 기존 규칙이 지켜지는지 확인할 때
4메일 끝부분"브레인크루 AI혁신팀 김그루 드림" 서명이 붙었는지 봅니다.서명 규칙이 지켜졌는지 확인할 때

김그루 사원이 다시 받은 답은 "제목: [확인 필요] 회의록 요약 도우미 시연 일정 제안의 건"으로 시작해 "최하늘 책임님께,", "안녕하세요."부터 "감사합니다."까지 정해진 순서로 이어졌고, 맨 끝에 "브레인크루 AI혁신팀 김그루 드림" 서명이 붙었습니다. 시간은 정하지 않고 "가능하신 시간대를 회신 주시면 일정을 확정하도록 하겠습니다."처럼 상대에게 묻는 문장으로 남겼습니다. 제목 앞에 [확인 필요]가 붙은 것처럼 압축 뒤에 표시 방식이 달라질 수도 있으니, 마음에 들지 않으면 Fix 에이전트에 다시 요청합니다.

같은 질문을 두세 번 보내 봐도 문제가 다시 나오지 않는지 확인합니다. 보내는 사람을 바꾼 요청("보내는 사람은 박지원 팀장으로 해 주세요")도 함께 시험하면 서명 규칙의 예외까지 확인할 수 있습니다.

8단계: 저장하거나 되돌리기​

결과가 마음에 들면 헤더의 저장을 눌러 Fix 에이전트가 바꾼 내용을 현재 버전(V2)에 기록합니다. 변경은 이미 대화에 반영되어 있지만, 저장해야 현재 버전에 남고 워크스페이스 등록도 이 내용으로 할 수 있습니다. 저장하면 "저장되었습니다" 알림이 잠시 나오고, 헤더의 "저장되지 않은 변경이 있습니다"가 사라지며 저장 버튼이 흐리게 바뀝니다.

결과가 마음에 들지 않으면 헤더의 현재 버전을 눌러 버전 목록을 열고 V1을 고릅니다. 목록에는 Fix 에이전트를 쓰기 전에 남겨 둔 원래 버전 V1과, 저장할 때 적은 "서명 규칙 추가" 설명이 붙은 V2가 보이고, 지금 쓰는 V2 앞에는 별 표시가 붙습니다. 저장하지 않은 변경이 있는 채로 V1을 고르면 "저장하지 않은 변경사항" 창이 열리며, 고친 결과를 버리려면 저장 없이 이동을 누릅니다.

따라 해 보기​

  1. 사이드바에서 이메일 초안 도우미를 열고 에이전트 설정을 누릅니다.
  2. 오른쪽 테스트 탭에서 1단계의 질문을 보내고, 메일 끝에 서명이 없는지 확인합니다.
  3. 헤더의 저장 옵션 더 보기에서 새 버전으로 저장을 고르고, 버전 설명에 "서명 규칙 추가"를 적어 저장합니다.
  4. Fix 에이전트 탭으로 돌아가 4단계의 요청을 보냅니다.
  5. 가운데 지침에 서명 규칙이 들어갔는지 확인합니다. 이어서 "말투 좀 바꿔 줘."를 보내고, 확인 질문이 오면 보기를 고르거나 직접 입력으로 답하고 제출합니다.
  6. 6단계의 압축 요청을 보내고, 확인을 구하면 반영해 달라고 답한 뒤 기존 규칙이 빠지지 않았는지 지침을 읽어 봅니다.
  7. 테스트 탭에서 새 대화를 누르고 2번에서 보낸 질문을 다시 보내 결과를 비교합니다.
  8. 원하는 대로 바뀌었으면 헤더의 저장을 눌러 현재 버전에 기록하고, 아니면 현재 버전에서 V1을 고릅니다.
