모델 구성

모델은 에이전트의 응답을 생성하는 구성 요소입니다. 같은 지침과 입력을 사용해도 모델에 따라 응답의 표현, 길이, 판단 방식이 달라질 수 있으므로 모델 선택은 에이전트 설정과 실행 결과를 함께 확인하는 작업으로 봐야 합니다.

모델 목록 확인​

에이전트를 만들거나 수정하기 전에 현재 작업 공간에서 선택할 수 있는 모델을 확인합니다. 목록에서 다음을 구분해 보세요.

  • 사용자 모델로 표시되는 항목
  • 기본 제공 모델 또는 외부 공급 모델에서 들어온 항목
  • 현재 실행 환경에서 사용할 수 있는 항목

목록이 비어 있거나 예상한 모델이 보이지 않으면 에이전트 설정을 계속하기보다 모델 공급 상태와 사용 권한을 먼저 확인합니다. 목록에 보인다는 사실만으로 실제 실행 가능성이 확인되는 것은 아닙니다.

이름으로 모델을 찾을 수 있고, 공급자와 하위 공급자를 기준으로 범위를 좁힐 수 있습니다. 페이지 단위로 목록을 읽는 환경에서는 다음 페이지가 있는지도 확인합니다. 이름 검사 기능을 사용하면 이름 형식과 현재 사용자 범위에서의 사용 가능 여부를 미리 확인할 수 있습니다.

기본 모델 선택​

기본 모델은 에이전트 제작이나 실행에서 별도 모델을 지정하지 않았을 때 기준으로 삼는 모델입니다. 다음 기준으로 선택합니다.

  • 반복해서 사용할 업무와 맞는가
  • 에이전트 지침과 업무 난이도에 맞는가
  • 해당 모델로 실행했을 때 결과가 업무 기준을 충족하는가

기본 모델 변경과 에이전트별 모델 변경은 별개입니다. 기본 모델을 바꿨다고 해서 이미 만들어진 에이전트의 개별 설정이 모두 바뀐다고 보지 마세요. 변경 후에는 기본값과 각 에이전트의 선택값을 따로 확인해야 합니다.

모델을 추가하는 방법​

사용자 모델을 언제나 직접 추가할 수 있는 것은 아닙니다. 현재 계약에서는 사용자 모델 추가 요청이 허용되지 않으며, 모델은 미리 정해진 공급 경로를 통해 들어옵니다. 따라서 새 모델이 필요할 때는 직접 생성부터 시도하기보다 조직에서 사용하는 모델 공급 또는 에이전트 설치 절차를 확인합니다.

이 제약은 모델 목록에 보이는 항목과 사용자가 직접 만든 항목을 구분하기 위해 필요합니다. 모델이 보이지 않는다면 이름을 바꿔 다시 만들기보다 해당 모델이 현재 작업 공간에 공급됐는지, 사용 권한이 있는지, 실행 환경에 연결됐는지를 확인합니다.

모델 수정과 동기화​

이미 등록된 사용자 모델은 변경 가능한 메타데이터를 수정할 수 있습니다. 수정 결과에는 버전 변화가 따를 수 있으므로 저장 후 모델 이름과 버전, 변경 내용이 의도와 일치하는지 확인합니다. 모든 항목을 수정할 수 있는 것은 아닙니다.

분기된 모델을 동기화할 때는 어떤 기준 모델에 맞춰지는지 먼저 확인합니다. 작업 공간에서 파생된 모델은 작업 공간의 주 버전 기준으로 동기화될 수 있으며, 동기화 후 버전과 모델 상태를 다시 확인해야 합니다.

모델 삭제​

모델을 삭제하기 전에는 다음을 확인합니다.

  • 삭제할 모델이 기본 모델인지
  • 어떤 에이전트가 해당 모델을 참조하는지
  • 한 모델만 삭제하는지, 여러 모델을 함께 삭제하는지
  • 삭제 후 남은 모델과 기본값이 어떻게 처리되는지

삭제 대상에 기본 모델이 포함되면 남은 모델 중 먼저 생성된 모델이 새 기본값으로 선택될 수 있습니다. 남은 모델이 없으면 기본값이 비워질 수 있습니다. 모델을 참조하던 에이전트의 설정도 함께 정리될 수 있으므로 삭제 후에는 에이전트의 모델 선택을 확인합니다.

여러 모델을 한 번에 삭제할 때는 삭제할 목록을 먼저 확정합니다. 일부만 정리됐다고 가정하지 말고, 작업 결과와 남은 모델 목록을 확인한 뒤 다음 작업을 진행합니다.

공급자별 설정 확인​

모델 연결에 자격 증명이 필요한 경우에는 환경에서 정한 자격 증명 키와 공급자 설정을 사용합니다. 자격 증명 키는 대문자, 숫자, 밑줄로 구성하며 첫 글자는 대문자 또는 밑줄이어야 하고 최대 길이는 255자입니다.

지원되는 공급자 유형은 Anthropic, OpenAI, Google, Azure, AWS Bedrock, OpenAI 호환 공급자입니다. Azure는 배포 이름과 엔드포인트, API 키 환경 이름과 값을 사용합니다. AWS Bedrock은 액세스 키와 시크릿 키 환경 이름과 값, 리전을 사용합니다. OpenAI 호환 공급자는 하위 공급자, 기본 URL, API 키 환경 이름을 사용합니다.

자격 증명 값은 일반 문서나 문의 내용에 그대로 남기지 않습니다. 모델이 목록에 나타나더라도 자격 증명과 실행 권한이 준비되지 않으면 실행되지 않을 수 있습니다.

변경 후 확인 순서​

  1. 의도한 모델이 선택됐는지 확인합니다.
  2. 기본 모델이 있다면 기본값이 기대한 모델과 일치하는지 확인합니다.
  3. 수정 또는 동기화 후 이름, 버전, 상태를 확인합니다.
  4. 삭제 후 기본값과 에이전트의 모델 참조가 예상 범위에서 정리됐는지 확인합니다.
  5. 실제 업무와 비슷한 입력으로 실행해 결과를 확인합니다.

모델 선택은 설정 화면에서 끝나지 않습니다. 모델의 사용 가능 상태와 에이전트 지침, 도구 설정을 함께 확인하고 실제 실행 결과로 판단해야 합니다.
