모델 구성

모델은 에이전트가 생각하고 답을 만드는 데 쓰는 AI 언어 모델입니다. 이 페이지는 에셋 화면의 모델 탭에서 내가 쓸 수 있는 모델과 기본 모델을 확인하고, 에이전트 편집 화면의 모델 설정 창에서 에이전트마다 모델과 파라미터를 바꾸는 방법을 설명합니다. 예시는 브레인크루 AI혁신팀 김그루 사원의 시장 조사 리서처입니다.

이 페이지에서 할 수 있는 일

  • 에셋 화면의 모델 탭에서 모델 목록과 상세 정보를 보고, 새 에이전트에 쓸 기본 모델을 정합니다.
  • 모델에 필요한 API 키가 등록됐는지 확인하고, 없으면 시크릿으로 등록합니다.
  • 에이전트 편집 화면의 모델 설정 창에서 모델을 바꾸고 temperature, top_p, top_k, max_tokens 같은 파라미터를 정합니다.
  • 저장하기 전 변경 사항 확인에서 바뀌는 값을 비교합니다.
  • [API 키 미등록] 표시와 모델이 없을 때의 안내를 읽고 해결합니다.

에셋 화면의 모델 탭​

사이드바의 에셋설정을 눌러 여는 에셋 화면에서 모델 탭을 엽니다. 위쪽에 기본 모델 선택, 왼쪽에 모델 목록, 오른쪽에 고른 모델의 상세가 보입니다.

에셋 화면의 모델 탭

번호메뉴기능이런 때 사용하세요
1기본 모델과 적용에이전트를 새로 만들 때 기본으로 쓸 모델을 고르고 적용합니다. 바뀌면 "기본 모델이 변경되었습니다" 알림이 뜹니다.팀이 표준으로 정한 모델로 새 에이전트를 시작하고 싶을 때
2모델 검색...이름으로 모델을 찾습니다.모델이 많을 때
3프로바이더 필터전체, Anthropic, OpenAI, Google, Azure, AWS Bedrock, OpenRouter, BizRouter, Custom 중 하나로 목록을 거릅니다.특정 제공사 모델만 볼 때

이럴 때 쓰세요: AI혁신팀이 사내 표준 모델을 GPT-4.1로 정하면, 김그루 사원은 내 기본 모델을 GPT-4.1로 적용해 두고 신규 입사자 교육 첫 시간에도 교육생들이 같은 모델을 기본 모델로 적용하게 안내합니다. 모두 같은 모델로 에이전트를 만들기 시작하므로 실습 결과가 사람마다 크게 달라지는 일이 줄어듭니다. 교육 자료의 화면 설명도 그 모델 이름으로 맞춰 둡니다.

필터 아래 모델 목록에는 모델 이름과 제공사, 설명이 보이고, 목록 위 선택으로 여러 모델을 골라 한꺼번에 지울 수 있습니다. 목록에서 모델을 누르면 오른쪽 상세에 설명, 컨텍스트 정보, 파라미터와 함께 필수 환경변수(모델이 쓰는 키 이름과 등록됨 또는 미등록 상태)가 보입니다. 아무 모델도 고르지 않으면 "선택된 모델이 없습니다"가 보입니다.

모델 상세의 필수 환경변수 옆에 미등록이 보이면 그 모델을 부를 API 키가 아직 없다는 뜻입니다. 옆의 등록을 누르면 시크릿 입력 창이 열리고, 키를 넣으면 등록됨으로 바뀝니다. 시크릿 생성 권한이 없으면 "시크릿 생성 권한이 없습니다"가 보이므로 관리자에게 요청하세요.

목록에 원하는 모델이 없으면 사이드바 더 보기 > 유틸리티에서 **유형:**을 모델로 바꾸고 설치합니다. 워크스페이스에 새 버전이 나온 모델은 상세에 "새 버전 사용 가능"과 최신 버전으로 동기화가 보입니다.

따라 해 보기: 기본 모델 정하기​

  1. 사이드바의 에셋설정을 눌러 에셋 화면을 열고 모델 탭을 누릅니다.
  2. 목록에서 팀이 쓰기로 한 모델을 누르고, 상세의 필수 환경변수가 등록됨인지 확인합니다. 미등록이면 등록으로 키를 넣습니다.
  3. 위쪽 기본 모델에서 그 모델을 고르고 적용을 누릅니다.
  4. 사이드바 새 에이전트로 에이전트를 만들 때 이 모델이 기본으로 쓰이는지 확인합니다.

모델이 없을 때의 안내​

쓸 수 있는 모델이 하나도 없으면 대화로 에이전트를 만드는 화면 위에 "사용 가능한 모델이 없어 이 에이전트를 실행할 수 없습니다. 모델을 등록하면 바로 사용할 수 있습니다." 안내가 보입니다. 안내의 모델 등록을 누르면 에셋 화면의 모델 탭으로 이동합니다. 위 방법대로 모델을 설치하고 API 키를 등록하면 안내가 사라집니다. 경고 닫기로 안내를 잠시 닫을 수도 있지만, 모델이 없으면 에이전트는 실행되지 않습니다.

에이전트 편집 화면의 모델 설정​

에이전트마다 다른 모델을 쓸 수 있습니다. 에이전트 편집 화면 가운데 편집 영역의 폼 보기에서 모델 칸에 지금 쓰는 모델 이름이 보이고, 오른쪽 톱니바퀴(모델 설정)를 누르면 모델 설정 창이 열립니다.

에이전트 편집 화면의 모델 칸

번호메뉴기능이런 때 사용하세요
1모델이 에이전트가 쓰는 모델 이름입니다. 정해지지 않았으면 "설정되지 않음"이 보입니다.어떤 모델로 답하는지 확인할 때
2모델 설정(톱니바퀴)모델 설정 창을 엽니다.모델이나 파라미터를 바꿀 때

모델 이름 옆에 노란 [API 키 미등록] 표시가 붙으면 이 모델을 부를 API 키가 내 시크릿에 없다는 뜻입니다. 위 그림처럼 키가 등록된 모델에는 이 표시가 없습니다. 워크스페이스에서 키를 제공하는 환경에서는 이 표시가 보여도 답이 정상으로 올 수 있습니다. 답이 오지 않으면 이 표시부터 확인합니다.

API 키가 없는 모델이 지정되어 있으면 키가 있는 다른 모델로 자동으로 바뀌고 "모델이 (이전 모델)에서 (새 모델)(으)로 변경되었습니다 (API 키 미등록)" 알림이 뜰 수 있습니다. 원래 모델을 쓰려면 그 모델의 키를 등록한 뒤 다시 고릅니다.

모델 설정 창​

모델 설정 창은 위에 모델 선택이 있고, 그 아래 왼쪽에 모델 정보와 모델 관리, 오른쪽에 파라미터가 있으며, 맨 아래에 취소와 저장이 있습니다.

모델 설정 창

번호메뉴기능이런 때 사용하세요
1모델 선택이 에이전트가 쓸 모델을 목록에서 고릅니다.다른 모델로 바꿀 때
2모델 정보의 입력고른 모델이 한 번에 받을 수 있는 입력 토큰 길이입니다. 바로 아래 출력에 출력 토큰 길이, 위 설명에 모델 설명이 보입니다.긴 자료를 한 번에 넣을 수 있는지 확인할 때
3파라미터 카드고른 모델이 지원하는 항목만 카드로 나옵니다. 그림은 temperature 카드이고, 카드마다 선택 또는 필수 표시와 설명, 슬라이더와 입력 칸, 입력 범위가 있습니다. 파라미터 오른쪽 위 숫자는 항목 수입니다.답의 다양성이나 길이를 조절할 때
4저장바로 저장하지 않고 변경 사항 확인 화면으로 넘어갑니다.값을 다 고른 뒤

이럴 때 쓰세요: 긴 회의록을 통째로 넣어야 하는 회의록 요약 도우미는 모델을 고를 때 모델 정보의 입력 토큰 길이부터 비교하고, 고객 문의 답장 도우미처럼 매번 같은 말투가 중요한 에이전트는 모델은 그대로 두고 temperature만 낮춥니다. 김그루 사원은 바꾼 뒤 테스트 탭에서 지난주에 쓴 회의록이나 문의 메일을 그대로 보내 바꾸기 전 답과 비교합니다. 결과가 나아졌을 때만 헤더의 저장으로 현재 버전에 기록합니다.

모델 정보 아래의 모델 관리를 누르면 에셋 화면의 모델 탭이 열립니다. "모델 설정 페이지에서 모델 정의를 추가하거나 편집하세요" 안내가 함께 보이며, 원하는 모델이 목록에 없을 때 씁니다. 취소를 누르면 바꾼 값을 버리고 창을 닫습니다.

모델마다 파라미터 항목과 범위가 다릅니다. 예를 들어 이 환경의 GPT-4.1은 temperature, max_tokens, top_p, seed, stop, tool_choice, response_format, presence_penalty, frequency_penalty, parallel_tool_calls 10개 항목이 있고, "모델에 reasoning 설정 없음, 기존 방식으로 전달" 안내가 보입니다. Claude Sonnet 4.6은 temperature, max_tokens, top_p, top_k, stop_sequences 5개이고 max_tokens가 필수입니다. 자주 쓰는 항목은 다음과 같습니다.

항목하는 일입력 범위
temperature샘플링 온도입니다. 낮을수록 같은 질문에 비슷한 답을, 높을수록 다양한 답을 냅니다.모델에 따라 02 또는 01
top_p누적 확률 기준으로 후보 단어를 제한합니다. 낮을수록 가능성이 높은 단어로 범위가 좁아집니다.0~1
top_k후보를 확률 상위 K개 단어로 제한합니다. 지원하는 모델에서만 보입니다.1 이상
max_tokens한 번에 생성할 출력 토큰의 최대 개수입니다. 0이면 값을 보내지 않습니다.0부터 모델 출력 한도까지

변경 사항 확인​

저장을 누르면 같은 창이 변경 사항 확인 화면으로 바뀝니다.

변경 사항 확인

번호메뉴기능이런 때 사용하세요
1변경 값 열저장하면 들어갈 새 값입니다. 표에는 바뀌는 항목만 항목, 현재 값, 변경 값 열로 나오고, 값이 없던 항목의 현재 값은 "(없음)"으로 보입니다.저장 전에 바뀌는 값을 확인할 때
2돌아가기앞 화면으로 돌아가 값을 고칩니다.잘못 바꾼 값이 있을 때
3확인하고 저장바뀐 값을 저장합니다.표의 값이 맞을 때

temperature 하나만 바꿔도 표에는 그동안 값이 없던 다른 항목(예: frequency_penalty, parallel_tool_calls, presence_penalty)이 창에 처음 채워져 있던 값으로 함께 나올 수 있습니다. 저장되면 "모델 설정이 저장되었습니다" 알림이 뜹니다.

모델 설정은 확인하고 저장을 누르는 즉시 에이전트에 반영되어, 대화와 테스트 탭에서 곧바로 새 모델로 답합니다. 헤더의 저장을 누르지 않아도 됩니다. 다만 현재 버전의 저장본에는 아직 기록되지 않아 헤더 저장 옆에 "저장되지 않은 변경이 있습니다"가 보입니다. 워크스페이스 등록을 요청하기 전에는 헤더 저장을 눌러 현재 버전에 기록합니다.

따라 해 보기: 시장 조사 리서처의 답을 일정하게 만들기​

비교표처럼 숫자를 다루는 에이전트는 같은 질문에 매번 비슷한 형식으로 답하는 편이 좋습니다.

  1. 사이드바에서 시장 조사 리서처를 누르고 에이전트 설정을 누릅니다.

  2. 가운데 편집 영역 폼 보기의 모델 칸에서 톱니바퀴(모델 설정)를 누릅니다.

  3. 모델 선택에서 쓸 모델을 고르고 모델 정보의 입력 토큰 길이를 확인합니다.

  4. 파라미터의 temperature 칸에 0.2를 넣습니다.

  5. 저장을 누르고 변경 사항 확인에서 temperature의 현재 값과 변경 값을 확인한 뒤 확인하고 저장을 누릅니다.

  6. 이 에이전트와 새 대화에서 브레인크루_AI업무도구_시장메모.md를 첨부하고 아래 프롬프트를 보냅니다. 대화를 새로 열어 한 번 더 보낸 뒤 두 답의 형식이 비슷한지 비교합니다.

    프롬프트: 첨부한 시장 메모로 경쟁 도구 A, B, C, D 비교표를 만들어 주세요. 열은 제품, 유형, 가격, 강점, 약점·제약, 도입 조건, 출처로 하고, 메모에 없는 값은 "자료에 없음"으로 적어 주세요.

팁: 모델이나 파라미터를 바꾸기 전에 헤더 저장 메뉴의 새 버전으로 저장으로 되돌릴 지점을 만들어 두면, 결과가 나빠졌을 때 이전 버전과 비교하기 쉽습니다. 버전은 에이전트 수정에서 설명합니다.

정리​

  • 쓸 수 있는 모델과 기본 모델은 에셋 화면의 모델 탭에서 보고 정합니다. 모델이 없으면 유틸리티에서 설치하고 API 키를 시크릿으로 등록합니다.
  • 에이전트마다 모델 설정 창에서 모델과 파라미터를 바꾸고, 변경 사항 확인을 거쳐 저장합니다.
