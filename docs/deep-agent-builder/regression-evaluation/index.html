회귀 평가와 개선

지침을 고쳐 한 문항이 나아져도, 다른 문항이 오히려 나빠질 수 있습니다. 회귀 평가는 지침을 고치기 전과 뒤에 같은 데이터셋과 같은 평가기로 실행해, 나아진 문항과 나빠진 문항을 함께 확인하는 방법입니다. 이 페이지는 이메일 초안 도우미의 첫 평가에서 찾은 문제를 Fix 에이전트로 고치고, 같은 조건으로 다시 실행해 두 실행을 비교하는 순서를 설명합니다.

이 페이지에서 할 수 있는 일

  • 고치기 전 실행의 실패 문항에서 지침의 고칠 점을 정합니다.
  • 새 버전으로 저장으로 고칠 새 버전을 만들어 원래 지침을 이전 버전에 남긴 뒤, Fix 에이전트에 수정을 요청합니다.
  • 같은 데이터셋, 같은 평가기, 같은 채점 모델로 다시 실행합니다.
  • 실행 비교로 두 실행의 지표와 문항별 상승·하락을 확인하고, 나빠졌으면 이전 버전으로 돌아갑니다.

회귀 평가의 순서​

단계하는 일화면
1고치기 전 실행을 끝내고 실패 문항의 채점 사유를 읽습니다.평가 > 평가 실행
2새 버전으로 저장으로 고칠 새 버전("평가 반영 수정")을 만듭니다. 원래 지침은 그 전 버전에 그대로 남습니다.에이전트 편집 화면 헤더
3Fix 에이전트 탭에서 고칠 점을 요청하고, 바뀐 지침을 확인한 뒤 헤더의 저장으로 현재 버전에 기록합니다.에이전트 편집 화면 오른쪽
41단계와 같은 데이터셋, 평가기, 채점 모델로 다시 실행합니다.평가 > 평가 실행
5실행 비교로 고치기 전과 뒤를 나란히 봅니다.실행 상세의 진단 요약

비교가 의미 있으려면 4단계에서 데이터셋의 문항, 평가기, 채점 모델을 1단계와 똑같이 둡니다. 이 셋 가운데 하나라도 바뀌면 점수 차이가 지침 때문인지 가릴 수 없습니다.

고칠 점 정하기​

평가 결과 읽기와 비교의 순서대로 고치기 전 실행에서 실패한 문항만 남기고 채점 사유를 읽습니다. 여러 문항에서 같은 항목이 빠졌다고 지적되면 그것을 한 문장으로 정리합니다. 예를 들어 회신 기한이나 문의처가 빠지거나, 요청에 분명히 적힌 날짜를 [확인 필요]로 남긴 문항이 여럿이면 "요청에 나온 날짜, 기한, 담당자를 빠짐없이 그대로 적는다"가 고칠 점입니다.

Fix 에이전트로 지침 고치기​

에이전트 편집 화면 오른쪽의 Fix 에이전트 탭에서 자연어로 지침 수정을 요청합니다. 탭 위쪽에는 "Fix Agent가 적용한 변경 사항은 즉시 반영되며 버전 초안에는 포함되지 않습니다."라는 안내가 있습니다. Fix 에이전트가 고친 내용은 그 즉시 대화와 테스트 탭에 쓰이므로, 원래 지침으로 돌아갈 지점이 필요하면 요청하기 전에 헤더의 저장 옵션 더 보기에서 새 버전으로 저장을 고릅니다. 그러면 지금 설정을 복사한 새 버전이 만들어져 현재 버전이 되고, 이후 Fix 에이전트의 변경과 헤더 저장은 모두 이 새 버전에 쌓입니다. 원래 지침은 새 버전으로 저장을 누르기 전에 쓰던 버전에 그대로 남아 있어, 결과가 나쁘면 그 버전으로 돌아갑니다.

즉시 반영된 변경은 아직 현재 버전에 기록되지 않은 상태여서, 헤더에 "저장되지 않은 변경이 있습니다"가 보입니다. 그래서 결과를 확인한 뒤 헤더의 저장을 누릅니다. 저장해야 고친 지침이 현재 버전에 기록되고, 워크스페이스 등록은 저장된 버전으로 하므로 나중에 이 버전을 동료와 함께 쓰도록 등록할 수 있습니다. 버전을 남기고 되돌리는 방법은 Fix 에이전트와 에이전트 수정에 있습니다.

Fix 에이전트로 지침 고치기

번호메뉴기능이런 때 사용하세요
1현재 버전지금 고치고 있는 버전입니다(그림에서는 새로 만든 V3). 누르면 버전 목록이 열립니다. 옆의 "저장되지 않은 변경이 있습니다"는 Fix 에이전트의 변경이 아직 버전에 기록되지 않았다는 뜻입니다.요청 전에 새로 만든 "평가 반영 수정" 버전에 있는지 확인할 때, 결과가 나쁘면 그 전 버전(V2)으로 돌아갈 때
2보낸 요청내가 보낸 수정 요청입니다. 그 아래에 Fix 에이전트가 무엇을 바꿨는지 설명한 답이 이어집니다. 탭 위쪽에는 즉시 반영 안내가 있습니다.요청이 제대로 이해되었는지 확인할 때
3지침Fix 에이전트가 고친 지침이 바로 보입니다. 그림에서는 작성 순서 4번이 "요청에 나온 날짜, 시간, 장소, 인원, 회신 기한, 담당자, 문의처 등 숫자 정보를 하나도 빠뜨리지 말고 본문에 그대로 적습니다"로 바뀌었습니다.요청한 규칙이 어느 문장에 들어갔는지 확인할 때
4저장바로 반영된 변경을 현재 버전에 기록합니다.테스트까지 마치고 결과를 남길 때

따라 해 보기​

  1. 사이드바에서 "이메일 초안 도우미"를 누르고 에이전트 설정을 누릅니다.

  2. 헤더의 저장 옵션 더 보기에서 새 버전으로 저장을 고르고, 새 버전 생성 창의 "버전 설명 (선택사항)" 칸에 "평가 반영 수정"을 적어 저장을 누릅니다. 이 새 버전이 현재 버전이 되고, 원래 지침은 바로 전 버전에 남습니다. 버전 목록에서 그 전 버전이 어느 것인지 기억해 둡니다.

  3. 오른쪽 Fix 에이전트 탭에서 아래 요청을 보냅니다.

    프롬프트: 메일 초안을 쓸 때 요청에 나온 날짜, 시간, 장소, 회신 기한, 담당자와 문의처를 하나도 빠뜨리지 말고 본문에 그대로 적도록 지침을 고쳐 주세요. [확인 필요]는 요청에 정말 없는 정보에만 쓰고, 요청에 적힌 정보는 [확인 필요]로 바꾸지 말아 주세요. 받는 사람의 이름과 직함은 요청에 적힌 그대로 쓰게 해 주세요.

  4. 화면 가운데 지침에 요청한 규칙이 들어갔는지 확인합니다.

  5. 테스트 탭에서 고치기 전에 실패했던 질문 하나를 그대로 보내 답이 바뀌었는지 봅니다.

  6. 답이 원하는 대로 바뀌었으면 헤더의 저장을 눌러 고친 지침을 현재 버전에 기록합니다.

같은 조건으로 다시 실행하기​

평가 화면의 평가 실행 탭으로 돌아가 이메일 초안 도우미를 고르고 평가 시작을 누릅니다. 데이터셋은 "이메일 초안 기본 10문항", 평가기는 완전성 (Completeness), **모델 (선택 사항)**은 고치기 전 실행과 같은 값으로 두고 실행 시작을 누릅니다. 실행 방법은 평가 실행에 있습니다.

실행이 끝나면 목록에 고치기 전 실행과 고친 뒤 실행이 함께 나옵니다. 두 실행의 번호를 적어 둡니다. 그림의 예에서는 #1이 고치기 전 실행(완전성 90.0%, 9/10), #3이 고친 뒤 실행(100.0%, 10/10)입니다. 그 사이의 #2는 실행 중 서버 연결이 끊겨 5문항이 오류로 끝났고(50.0%), 실행 이름 앞에 "무효 (환경)"을 뜻하는 빨간 점이 붙었습니다. 이런 실행은 지침 때문이 아니라 실행 환경 때문에 점수가 떨어진 것이므로 비교에 쓰지 않고, 같은 조건으로 다시 실행합니다.

두 실행 비교하기​

목록에서 고치기 전 실행(#1)을 누르고, 실행 상세의 진단 요약 오른쪽 실행 비교를 누릅니다. 아래에 "실행 비교" 창이 펼쳐지고, 지금 보고 있는 실행이 기준에 미리 체크되어 있습니다. 창의 목록에는 같은 데이터셋으로 돌린 실행의 실행(번호), 전체 정답률, 시작(시각)이 보이므로, 이를 보고 고친 뒤 실행(#3)의 비교 칸을 체크합니다. 실행 비교를 다시 누르면 창이 접힙니다.

비교할 실행 고르기

번호메뉴기능이런 때 사용하세요
1실행 비교실행 비교 창을 펼치거나 접습니다.두 실행을 나란히 보고 싶을 때
2기준비교의 기준이 될 실행을 체크합니다. 처음 열면 지금 보고 있는 실행(그림에서는 #1)이 체크되어 있습니다.고치기 전 실행을 기준으로 둘 때
3비교기준과 견줄 실행을 체크합니다. 그림에서는 고친 뒤 실행 #3을 골랐습니다.고친 뒤 실행을 고를 때
4무효 표시실행 이름 앞의 빨간 점은 환경 문제로 무효인 실행입니다. 마우스를 올리면 "무효 (환경)"이 보입니다. 그림의 #2가 그런 실행입니다.비교에서 뺄 실행을 가려낼 때

창 위쪽 안내대로 같은 데이터셋의 실행을 기준과 비교에 한쪽당 최대 10개씩 고를 수 있습니다. 여러 개를 고르면 반복 실행으로 보고 문항별 다수결로 맞춥니다. 무효 표시가 붙은 실행을 고르면 비교 결과 대신 "환경 문제로 무효인 실행은 비교할 수 없습니다: #2"처럼 안내가 나옵니다. 그 실행의 체크를 풀면 비교 결과가 다시 나옵니다.

기준과 비교를 하나씩 고르면 아래에 비교 결과가 나옵니다. 대표 지표 표에는 **기준 (실행 1개)**와 비교 (실행 1개) 열이 근거 확정 문항 기준과 전체 문항 기준으로 나뉘어 나옵니다. 근거 문서를 쓰지 않는 이메일 초안 도우미에서는 근거 지표가 모두 "—"이고, 맨 아래 전체 정답 행을 봅니다. 그 아래 진단 지표 표에는 채점 통과율, 결과 분류, 문항 토큰, 소요 시간 같은 진단 지표가 두 열로 나옵니다.

실행 비교 결과: 지표

번호메뉴기능이런 때 사용하세요
1전체 정답대표 지표 표에서 기준과 비교의 정답률을 나란히 보여 줍니다. 그림에서는 90.0% (9/10)에서 100.0% (10/10)로 올랐습니다.정답률이 얼마나 바뀌었는지 볼 때
2채점 통과율진단 지표 표에서 오류를 실패로 센 통과율입니다. 그림에서는 90.0% (9/10)에서 100.0% (10/10)입니다. 같은 표의 문항 토큰과 소요 시간도 함께 봅니다.정답률은 올랐는데 답변이 길어지거나 느려지지 않았는지 볼 때

그림의 예에서 문항 토큰 p50은 14,018에서 14,074로 거의 그대로였고, 소요 시간 p50은 4.4초에서 9.3초로 늘었습니다. 고친 지침으로 답이 나아져도 이렇게 느려질 수 있으므로 진단 지표 표도 함께 확인합니다.

진단 지표 표 아래 문항별 과반 정답 전이 표는 양쪽 모두 결과가 있는 문항을 기준과 비교에서 과반 정답이었는지 과반 정답 아님이었는지로 나눠 셉니다. 오류는 오답으로 셉니다. 상승한 문항에는 기준에서 틀리고 비교에서 맞은 문항이, 하락한 문항에는 기준에서 맞고 비교에서 틀린 문항이 번호, 질문, "기준 0/1 → 비교 1/1" 같은 기록과 함께 나옵니다.

실행 비교 결과: 문항별 변화

번호메뉴기능이런 때 사용하세요
1문항별 과반 정답 전이기준과 비교에서 각각 맞았는지로 문항을 나눠 센 표입니다. 그림에서는 9문항이 양쪽 모두 정답이고, 1문항이 기준에서 틀렸다가 비교에서 맞았습니다.몇 문항이 새로 맞고 몇 문항이 새로 틀렸는지 셀 때
2상승한 문항기준에서는 틀리고 비교에서는 맞은 문항입니다. 그림에서는 직원 120명에게 감사 메일을 쓰는 #6이 "기준 0/1 → 비교 1/1"로 나왔습니다.고친 지침이 노린 문항을 바로잡았는지 볼 때
3하락한 문항기준에서는 맞고 비교에서는 틀린 문항입니다. 그림에서는 0개라 "—"만 보입니다.지침 수정이 다른 문항을 망가뜨렸는지 볼 때

따라 해 보기​

  1. 평가 실행 목록에서 고치기 전 실행(예: #1)을 누릅니다.
  2. 진단 요약 오른쪽 실행 비교를 누릅니다.
  3. 기준에 고치기 전 실행이 체크되어 있는지 확인하고, 고친 뒤 실행(예: #3)의 비교 칸을 체크합니다. 이름 앞에 빨간 점이 있는 무효 실행(예: #2)은 고르지 않습니다.
  4. 대표 지표 표에서 전체 정답이 올랐는지 봅니다.
  5. 상승한 문항에 고칠 점으로 정했던 문항이 들어 있는지 확인합니다.
  6. 하락한 문항이 있으면 고친 뒤 실행을 열고, 결과 표에서 같은 질문의 행을 눌러 채점 사유를 읽습니다.
  7. 하락한 문항의 문제가 더 크면 에이전트 편집 화면의 현재 버전을 눌러 버전 목록에서 "평가 반영 수정" 대신 새 버전으로 저장을 누르기 전에 쓰던 버전을 고릅니다. 이 버전에는 Fix 에이전트로 고치기 전의 원래 지침이 그대로 있으므로, 여기서 다른 방식으로 다시 고칩니다. 상승만 있으면 "평가 반영 수정" 버전을 그대로 씁니다.

팁: 같은 설정으로 다시 실행해도 에이전트 답변과 채점 결과는 조금씩 달라질 수 있습니다. 문항 수가 적은 데이터셋에서 한두 문항 차이는 흔들림일 수 있으므로, 중요한 판단 전에는 평가 실행 생성 창의 반복 횟수를 3 이상으로 두고 비교합니다. 기준과 비교에 반복 실행을 여러 개 고르면 문항별 다수결로 비교합니다.

정리​

  • 회귀 평가는 데이터셋, 평가기, 채점 모델을 그대로 두고 지침만 바꿔 다시 실행하는 것입니다.
  • Fix 에이전트의 변경은 바로 반영되므로, 요청하기 전에 새 버전으로 저장으로 고칠 새 버전("평가 반영 수정")을 만들어 원래 지침을 그 전 버전에 남기고, 결과를 확인한 뒤 헤더의 저장으로 새 버전에 기록합니다. 결과가 나쁘면 새 버전으로 저장하기 전의 버전으로 돌아갑니다.
  • 실행 비교에서는 정답률보다 하락한 문항을 먼저 확인합니다.
