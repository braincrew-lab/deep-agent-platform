Deep Agent Builder 실행 상태 확인

이 페이지는 실행이 끝났는지, 일부 결과만 나온 상태인지, 운영자 확인이 필요한지를 구분할 때 사용합니다. 에이전트 실행과 평가 실행을 한 번에 성공으로 판단하지 않고, 대상과 처리 범위를 확인한 뒤 다음 조치를 정하는 방법을 설명합니다.

먼저 확인할 준비 상태​

실행 내역을 보려면 관리자 화면에 접근할 수 있어야 하며, 확인하려는 Workspace의 권한도 필요합니다. 인프라 상태를 함께 점검하는 작업은 별도의 운영 권한이 필요합니다. 권한이 없으면 상태를 추정하지 말고 Workspace 관리자에게 조회 범위를 요청하세요.

실제 제품 화면의 메뉴와 버튼 이름은 배포 버전에 따라 달라질 수 있습니다. 화면에서 실행 내역이나 평가 실행을 찾을 수 없다면, 화면 이름을 임의로 바꾸어 찾지 말고 관리자에게 현재 버전의 진입 경로를 확인하세요.

에이전트 실행 상태 확인​

다음 순서로 한 실행의 범위를 확인합니다.

  1. 실행 대상 에이전트와 Workspace를 확인합니다.
  2. 시작 시각, 종료 시각, 현재 상태를 함께 봅니다.
  3. 실행이 끝났다면 오류 내용과 실행 시간을 확인합니다.
  4. 오류나 중단이 있으면 실행 상세 정보와 관련 로그를 확인합니다.
  5. 로그를 공유하기 전 이메일, 고객 정보, 인증 정보가 포함되지 않았는지 확인합니다.

처리 중인 실행은 완료로 기록하지 않습니다. 성공으로 표시돼도 확인하려는 작업 범위와 실제 결과가 맞는지 대조하세요. 중단된 실행은 중단 사유와 종료 시각을 함께 기록해야 원인을 구분할 수 있습니다.

평가 실행 결과 확인​

평가 실행은 요청이 등록된 뒤 실제 처리가 시작되기까지 시간이 걸릴 수 있습니다. 등록됐다는 사실만으로 모든 Case가 처리됐다고 판단하지 마세요.

  1. 실행이 대기 중인지, 처리 중인지, 종료됐는지 확인합니다.
  2. 종료됐다면 전체 Case 중 몇 개가 처리됐는지 확인합니다.
  3. 각 Case의 점수, 판단 근거, 오류 여부를 확인합니다.
  4. 일부 Case만 처리됐거나 오류로 끝났다면 처리된 결과만으로 전체 품질을 판단하지 않습니다.
  5. 취소한 실행은 최종 상태와 처리된 Case 수를 다시 조회합니다.

동시에 실행할 수 있는 평가 수를 초과하면 새 요청을 반복하지 말고, 같은 사용자가 이미 대기 중이거나 처리 중인 평가가 있는지 먼저 확인하세요. 취소를 눌렀더라도 남은 Case 처리가 즉시 멈췄다고 단정하지 말고 최종 상태를 다시 확인합니다.

인프라 상태가 함께 표시될 때​

관리자 화면에 대기열이나 저장소 상태가 표시되면 다음 정보를 함께 기록합니다.

  • 어떤 작업의 대기열인지
  • 대기 중인 작업 또는 지연 정보
  • 상태를 수집한 시각
  • 정상 상태인지, 일부 정보를 읽지 못한 상태인지

일부 정보가 비어 있거나 지연 상태로 표시된다고 해서 곧바로 전체 인프라 장애로 결론 내리지 마세요. 연결 목록이나 실시간 수집이 일시적으로 실패했을 수도 있습니다. 같은 화면을 다시 조회하고, 반복되면 운영 담당자에게 확인을 요청합니다.

화면에 표시되지 않는 지표를 있다고 가정해 운영 판단을 넓히지 마세요. 특히 작업자별 상세 현황이나 실패 작업 순위가 보이지 않는다면, 현재 화면이 제공하는 범위까지만 판단합니다.

운영 조치 뒤에 다시 확인할 것​

연결 정리나 집계 보정처럼 관리자 조치를 실행했다면 요청이 받아들여진 것과 실제 상태가 바뀐 것은 구분해야 합니다.

  1. 조치 대상과 실행 시각을 기록합니다.
  2. 요청 결과에서 실패한 대상이 따로 표시됐는지 확인합니다.
  3. 잠시 후 연결 또는 집계 상태를 다시 조회합니다.
  4. 실행 상태나 저장된 결과가 예상하지 않게 바뀌지 않았는지 확인합니다.
  5. 감사 기록에 조치 내역이 남았는지 확인합니다.

상태를 다시 읽지 못했다면 조치가 완료됐다고 보고하지 않습니다. 오류가 발생한 뒤에도 일부 변경이 남을 수 있으므로, 같은 요청을 반복하기 전에 현재 상태부터 확인하세요.

완료 판단과 문제 해결​

다음 항목을 모두 확인했을 때 실행 상태를 기록합니다.

  • 대상 에이전트, Workspace 또는 평가 실행을 식별했습니다.
  • 화면의 상태와 상세 정보의 상태를 대조했습니다.
  • 종료된 실행이라면 종료 시각과 오류를 확인했습니다.
  • 평가라면 처리된 Case 수와 Case별 결과를 확인했습니다.
  • 대기열 또는 인프라 정보가 정상인지 일부 누락인지 구분했습니다.
  • 취소나 관리자 조치 뒤에 상태를 다시 조회했습니다.

실행이 오래 대기하거나 처리 중인 상태에 머물면 새 요청을 반복하지 말고 권한, 동시 실행 수, 대기열 상태를 차례로 확인하세요. 결과가 비어 있으면 실행이 아직 끝나지 않았거나 처리 범위가 제한됐을 수 있습니다. 원인을 확인하지 않은 채 실패 Case를 삭제하거나 판단 기준을 낮추지 마세요.
