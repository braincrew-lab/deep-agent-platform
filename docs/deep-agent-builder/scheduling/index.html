Deep Agent Builder 스케줄링

에이전트를 정해진 시각에 반복 실행하려면 스케줄을 등록합니다. 이 문서에서는 스케줄을 만들고 바꾼 뒤 다음 실행 시각과 실제 실행 결과를 확인하는 순서를 설명합니다. 제품 화면의 메뉴와 버튼 이름은 배포 환경에 따라 다를 수 있으므로, 화면에서 보이는 문구를 기준으로 진행하세요.

시작하기 전에​

다음 조건을 먼저 확인합니다.

  • 스케줄을 적용할 에이전트가 있어야 합니다.
  • 스케줄을 만들거나 수정할 권한이 있어야 합니다.
  • 실행할 메시지는 고객 자료나 인증정보가 없는 테스트 문구로 준비합니다.
  • 반복 실행이 업무에 영향을 줄 수 있다면 활성화 전에 대상 에이전트와 다음 실행 시각을 다시 확인합니다.

스케줄을 관리할 수 있어도 에이전트가 실제 업무를 수행할 권한까지 자동으로 생기는 것은 아닙니다. 실행이 되지 않으면 스케줄 설정과 에이전트의 실행 권한을 나누어 확인하세요.

스케줄에서 확인할 값​

스케줄 목록이나 상세 화면에서 다음 값을 확인합니다.

값확인할 내용
반복 일정몇 분, 몇 시, 어떤 요일에 실행할지 나타내는 5개 항목 일정 형식
시간대반복 일정을 해석할 기준 시간대. 기본값은 UTC일 수 있으므로 화면에서 확인
실행 메시지실행할 때 에이전트에 전달할 문구. 앞뒤 공백을 제외하고 1자 이상 10,000자 이하
활성화 상태반복 실행 여부
다음 실행 시각다음 실행 예정 시각. 비활성 상태에서는 비어 있을 수 있음
최근 실행 정보최근 실행 시각, 실행 결과, 연결된 실행 기록
실행 횟수지금까지 반복 실행된 횟수

스케줄이 목록에 보인다는 사실만으로 에이전트 실행이 끝났다고 판단하지 마세요. 예정 시각이 지난 뒤 최근 실행 정보와 연결된 실행 기록을 따로 확인해야 합니다.

스케줄 만들기​

  1. 대상 에이전트의 스케줄 관리 화면으로 이동합니다. 실제 화면에서 스케줄을 추가하는 메뉴나 버튼을 확인합니다.
  2. 반복 일정, 시간대, 실행 메시지를 입력합니다. 처음에는 짧은 비식별 테스트 문구를 사용합니다.
  3. 반복 일정은 5개 항목 형식으로 입력합니다. 새 스케줄을 만들거나 반복 일정의 분 항목을 바꿀 때는 분 항목에 숫자 하나만 입력합니다. 매분, 간격, 범위, 목록을 나타내는 형식은 검증 오류로 거부되므로, 화면의 안내를 확인한 뒤 지원되는 실행 주기를 선택합니다. 이미 저장된 오래된 일정은 같은 반복 일정을 그대로 다시 저장할 수 있습니다. 저장 후에는 목록이나 상세 화면에서 처리 결과를 확인합니다.
  4. 저장한 뒤 목록이나 상세 화면에서 대상 에이전트, 활성화 상태, 다음 실행 시각을 확인합니다.
  5. 예정 시각이 지난 뒤 최근 실행 시각, 결과, 연결된 실행 기록을 다시 확인합니다.

시간대는 표준 IANA 시간대 이름이어야 합니다. 시간대 형식이 올바르지 않거나 기존 일정이 잘못된 값이면 다음 실행 시각이 비어 있을 수 있습니다. 이 경우 시간을 임의로 계산하지 말고 시간대와 반복 일정을 다시 입력합니다.

기존 스케줄 바꾸기​

  1. 대상 스케줄을 엽니다.
  2. 반복 일정, 시간대, 실행 메시지 또는 활성화 상태 중 바꿀 항목만 수정합니다.
  3. 저장한 뒤 다음 실행 시각이 의도대로 바뀌었는지 확인합니다.
  4. 실행 메시지만 바꾼 경우에도 저장된 메시지가 맞는지 확인하되, 다음 실행 시각이 불필요하게 바뀌지 않았는지 함께 살펴봅니다.
  5. 다음 실행 뒤 실제 실행 기록과 결과를 확인합니다.

활성화 상태를 켜거나 끄는 작업은 일반 수정과 별도 권한이 필요할 수 있습니다. 저장이 거부되면 입력값을 반복해서 제출하지 말고, 변경하려는 항목에 필요한 권한을 관리자에게 확인하세요.

일시 중지와 삭제​

잠시 실행을 멈추려면 스케줄을 비활성화한 뒤 활성화 상태와 다음 실행 시각이 바뀌었는지 확인합니다. 삭제는 비활성화와 달리 스케줄 정의를 없애는 작업일 수 있으므로, 삭제 전에 반복 일정과 마지막 실행 정보를 기록하세요. 삭제 후 복원할 수 있다고 가정하지 마세요.

보관된 에이전트의 스케줄은 조회·수정·삭제가 가능할 수 있지만 다시 활성화하거나 새 일정을 추가할 수 없는 경우가 있습니다. 에이전트를 삭제한 뒤에도 스케줄 항목이 보이면 비활성화 상태, 다음 실행 시각, 최근 결과를 확인하세요. 과거 실행 기록의 보존 여부는 스케줄 항목과 별도로 판단합니다.

실행 결과 확인​

스케줄이 저장되면 다음 순서로 실제 실행을 확인합니다.

  1. 스케줄 목록에서 다음 실행 시각을 확인합니다.
  2. 예정 시각이 지난 뒤 최근 실행 시각, 최근 결과, 실행 횟수를 다시 확인합니다.
  3. 연결된 실행 기록에서 현재 상태와 결과 또는 오류를 확인합니다.
  4. 실행이 끝나지 않은 상태라면 완료로 기록하지 않습니다.
  5. 스케줄이 계속 활성 상태인지, 다음 실행 시각이 다시 계산됐는지 확인합니다.

스케줄 저장 결과는 반복 실행을 예약했다는 뜻이지, 에이전트가 실제로 실행됐다는 뜻은 아닙니다. 실행 기록이 없으면 스케줄 설정, 실행 권한, 실행을 담당하는 환경의 상태를 순서대로 점검합니다. 같은 요청을 바로 다시 저장하거나 새 스케줄을 만들지 말고, 먼저 기존 항목의 활성화 상태와 다음 실행 시각을 확인하세요.

저장, 예정, 실행을 구분하는 기준​

화면에서 확인한 상태확인된 사실아직 확인되지 않은 것
설정이 저장됨반복 일정과 실행 메시지가 저장됨다음 실행이 실제로 시작됐는지
다음 실행 시각이 표시됨실행 예정 시각이 계산됨해당 시각에 실행이 끝났는지
최근 실행 정보와 실행 기록이 있음실제 실행의 상태와 결과를 확인할 수 있음이후 반복 실행이 계속되는지

이 세 상태를 한 단계로 묶어 기록하지 마세요. 특히 저장 직후의 화면만 보고 실행 성공으로 판단하지 말고, 예정 시각 이후 실행 기록과 결과를 확인한 뒤 완료로 기록합니다.

대표적인 문제와 다음 조치​

화면에서 보이는 증상확인할 것다음 조치
저장이 거부됨반복 일정 형식, 시간대, 실행 메시지, 변경 권한입력값을 하나씩 확인하고 권한 문제인지 형식 문제인지 구분합니다.
다음 실행 시각이 비어 있음비활성화 상태, 시간대, 기존 일정 형식올바른 시간대와 반복 일정을 다시 저장합니다.
메시지만 바꿨는데 다음 실행 시각도 달라짐저장할 때 다른 항목도 함께 바뀌었는지변경 내용을 다시 확인하고 의도하지 않은 일정 변경이면 관리자에게 문의합니다.
예정 시각이 지났지만 실행 기록이 없음활성화 상태, 다음 실행 시각, 실행 권한, 실행 환경 상태예약 저장과 실제 실행을 나누어 확인하고 중복 일정을 만들지 않습니다.
보관된 에이전트의 일정을 다시 켤 수 없음에이전트가 보관 상태인지, 활성화 권한이 있는지에이전트 상태를 확인한 뒤 활성화 요청을 반복하지 않습니다.
에이전트를 삭제했는데 일정이 남아 보임활성화 상태, 다음 실행 시각, 최근 결과정리된 일정과 과거 실행 기록을 구분해 확인합니다.

완료 기준​

다음 항목을 모두 확인하면 스케줄 작업을 완료로 기록합니다.

  1. 대상 에이전트와 필요한 권한을 확인했습니다.
  2. 반복 일정, 시간대, 실행 메시지를 검증했습니다.
  3. 목록에서 활성화 상태와 다음 실행 시각을 확인했습니다.
  4. 예정 시각 이후 최근 실행 정보와 연결된 실행 기록을 대조했습니다.
  5. 오류가 났다면 입력 형식, 권한, 실제 실행 문제를 구분했습니다.
