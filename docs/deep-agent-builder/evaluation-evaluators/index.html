평가기 구성

평가기는 에이전트 답변을 채점하는 기준입니다. 평가기마다 채점 모델에 보내는 프롬프트와 채점 방식(통과/실패 또는 점수)이 정해져 있습니다. 이 페이지는 평가기 탭의 기본 평가기가 각각 무엇을 보는지, 그리고 이메일 초안 도우미에 맞춘 사용자 평가기 "이메일 형식 점검"을 만드는 방법을 설명합니다.

이 페이지에서 할 수 있는 일

  • 기본 평가기 여섯 가지가 보는 것을 비교하고, 점검 목적에 맞는 평가기를 고릅니다.
  • 기본 평가기를 복사해 내 기준으로 고친 평가기를 만듭니다.
  • 프롬프트 템플릿을 직접 써서 사용자 평가기를 만들고, 고치고, 지웁니다.

평가기 탭​

평가 화면의 평가기 탭을 엽니다. 위쪽에 기본 평가기, 아래쪽에 사용자 평가기가 카드로 나옵니다. 카드 아래 배지는 채점 방식입니다. 통과/실패는 통과(1)와 실패(0)로, 0-5처럼 숫자 범위가 적힌 것은 그 범위의 점수로 채점합니다. 평가기 생성 왼쪽의 데이터 새로고침(둥근 화살표)은 다른 탭에서 만든 평가기가 아직 보이지 않을 때 목록을 다시 불러옵니다.

기본 평가기는 처음부터 제공되는 평가기입니다. 카드를 누르면 그 평가기를 복사해 새 평가기를 만드는 창이 열립니다. 기본 평가기 자체는 고치거나 지울 수 없습니다.

평가기 탭

번호메뉴기능이런 때 사용하세요
1평가기 생성새 사용자 평가기를 만드는 창을 엽니다.업무에 맞는 채점 기준을 직접 정할 때
2채점 방식 배지통과/실패, 또는 0-5처럼 적힌 점수 범위입니다.결과가 통과율로 나올지 점수로 나올지 미리 볼 때
3사용자 평가기 카드내가 만든 평가기입니다. 카드를 누르면 고치는 창이 열립니다. 하나도 없으면 "사용 가능한 평가기가 없습니다."와 평가기 생성 버튼이 보입니다.만든 평가기를 고칠 때
4삭제(휴지통)카드에 마우스를 올리면 오른쪽 위에 나타납니다. 누르면 삭제 확인 창이 열립니다.더 쓰지 않는 평가기를 지울 때

워크스페이스에 참여하지 않은 계정은 평가기 생성 자리에 "평가기를 생성하거나 저장하려면 워크스페이스에 참여하세요."가 보이고, 기본 평가기 카드를 누르면 읽기 전용 "평가기 상세" 창이 열립니다.

기본 평가기가 보는 것​

기본 평가기는 여섯 가지입니다. 채점 모델은 채점 사유를 질문과 같은 언어로 적으므로, 한국어 질문이면 결과 화면의 채점 사유도 한국어로 나옵니다.

평가기채점 방식보는 것이메일 초안 도우미에 쓸 때
정확성 (Accuracy)통과/실패에이전트 답변이 참조 답변과 맞는지 봅니다.날짜나 금액이 참조 답변과 어긋나지 않았는지 볼 때
충실도 (Faithfulness)통과/실패에이전트의 답변이 참조 자료에 충실한지 봅니다.지식을 찾아 답하는 에이전트에 씁니다. 메일 초안 점검에는 잘 맞지 않습니다.
관련성 (Relevance)통과/실패에이전트의 답변이 질문과 관련이 있는지, 질문에 직접 답하는지 봅니다.요청과 다른 종류의 메일을 쓰지 않았는지 대략 볼 때
완전성 (Completeness)통과/실패에이전트의 답변이 참조 답변의 주요 내용을 모두 포함하는지 봅니다. 곁가지 세부 사항이 빠진 것은 실패로 보지 않습니다.요청에 나온 일시, 장소, 기한, 담당자가 빠짐없이 들어갔는지 볼 때(이 장의 예시에서 쓰는 평가기)
자연스러움 (Humanizer)0~5점문장 흐름, 구체성, 일관된 어조, 상황에 맞는 감정 표현, 읽기 쉬움 다섯 기준을 하나씩 따져 맞는 개수만큼 점수를 줍니다. 참조 답변과는 비교하지 않습니다.메일이 틀에 박힌 기계적인 문장으로 쓰였는지 볼 때
전문성 (Professional)0~5점명확한 구성, 간결함, 정중한 어조, 알맞은 격식, 정확한 용어 다섯 기준을 하나씩 따져 점수를 줍니다. 참조 답변과는 비교하지 않습니다.사과·거절 메일의 어조가 업무에 맞는지 볼 때

평가기 생성 창의 빠른 삽입에는 위 여섯 가지와 함께 충실도: 검색 문맥 (Faithfulness) 프롬프트가 있습니다. 이 프롬프트는 참조 답변 대신 에이전트가 도구로 찾아 본 결과(검색 문맥)를 근거로, 답변의 사실이 그 결과에서 뒷받침되는지 채점합니다. 지식을 찾아 답하는 에이전트용 사용자 평가기를 만들 때 바탕으로 씁니다.

기본 평가기 복사하기​

기본 평가기 카드를 누르면 "복사해서 새 평가기 만들기" 창이 열립니다. 창 설명은 "이 기본 평가기를 복사하여 수정합니다."이고, 이름에는 "(복사본)"이 붙어 있습니다. 기본 평가기의 프롬프트는 영어로 되어 있어, 프롬프트 칸 위에 "채점 모델에 보내는 영어 프롬프트입니다. 번역하면 채점 결과가 달라질 수 있어 원문을 유지합니다."라는 안내가 보입니다.

기본 평가기 복사

번호메뉴기능이런 때 사용하세요
1이름새 평가기 이름입니다. 처음에는 "전문성 (Professional) (복사본)"처럼 채워져 있고 255자까지 고칠 수 있습니다.원래 평가기와 구분되는 이름을 붙일 때
2평가 유형원래 평가기의 채점 방식이 그대로 들어 있습니다. 바로 아래 점수 범위(그림에서는 0과 5)도 원래 값입니다.0~5점 대신 다른 범위를 쓰고 싶을 때
3영어 프롬프트 안내프롬프트가 영어로 되어 있는 이유입니다. 그 아래 프롬프트 템플릿 칸에 원래 평가기의 프롬프트가 들어 있고, 고친 뒤 저장하면 사용자 평가기로 만들어집니다.프롬프트를 번역할지 판단할 때
4저장사용자 평가기로 저장합니다.고친 기준을 쓰기로 했을 때

사용자 평가기 만들기​

평가기 생성을 누르면 "평가기 생성" 창이 열립니다. 창 설명은 "사용자 정의 프롬프트 템플릿으로 새 평가기를 생성합니다."입니다. 왼쪽에서 이름과 채점 방식을, 오른쪽에서 프롬프트를 정합니다. 칸이 많아 같은 창을 두 장으로 나눠 보여 줍니다.

평가기 생성 창: 이름과 평가 유형

번호메뉴기능이런 때 사용하세요
1이름평가기 이름입니다. 꼭 입력해야 하고 255자까지 넣을 수 있습니다. 같은 이름의 평가기가 이미 있으면 "같은 이름의 평가기가 이미 존재합니다."가 나옵니다.무엇을 채점하는지 이름만 보고 알 수 있게 할 때
2설명 (선택)카드에 보일 설명입니다.다른 사람이 언제 쓰면 되는지 남길 때
3평가 유형통과/실패 또는 **점수 (범위)**를 고릅니다. **점수 (범위)**를 고르면 아래에 점수 범위(최소, 최대)가 나타납니다. 최소는 0 이상, 최대는 100 이하, 폭은 2 이상이어야 하고, 어기면 "점수 범위는 0 이상에서 시작하고 폭이 2 이상이며 100 이하로 끝나야 합니다."가 나옵니다.기준을 모두 지켰는지만 볼지(통과/실패), 사내 점검표처럼 1~5점으로 정도를 볼지(점수) 정할 때
4템플릿 변수 가이드누르면 프롬프트에 쓸 수 있는 변수가 펼쳐집니다. {question}은 평가 질문, {reference_answer}는 참조 답변, {agent_answer}는 에이전트의 생성 답변입니다.질문과 답변이 들어갈 자리를 표시할 때

평가기 생성 창: 프롬프트

번호메뉴기능이런 때 사용하세요
1빠른 삽입기본 평가기 프롬프트를 프롬프트 칸에 채워 넣습니다. 누르면 평가 유형과 점수 범위도 그 평가기 값으로 바뀝니다.기본 프롬프트를 바탕으로 조금만 고칠 때
2프롬프트 템플릿채점 모델에 보내는 프롬프트입니다. 꼭 입력해야 하고 {agent_answer}가 들어가야 합니다. 빠지면 "프롬프트 템플릿에 {agent_answer}가 포함되어야 합니다."가 나옵니다.채점 기준을 우리 업무 말로 적을 때
3저장평가기를 만듭니다. "평가기를 만들었습니다." 안내가 뜨고 사용자 평가기에 카드가 생깁니다.입력을 마쳤을 때

저장 왼쪽의 취소는 저장하지 않고 창을 닫습니다.

프롬프트 끝에는 채점 결과를 JSON으로만 답하게 하는 줄을 넣습니다. 프롬프트 칸이 비어 있을 때 보이는 예시처럼 score와 reasoning 두 값을 받으면, score는 채점 결과로, reasoning은 결과 화면의 채점 사유로 나옵니다.

따라 해 보기​

이메일 초안 도우미가 쓴 메일이 "제목 줄, 인사와 맺음말, 요청한 사실" 세 가지를 모두 갖췄는지 통과/실패로 보는 평가기를 만듭니다.

  1. 평가기 탭에서 평가기 생성을 누릅니다.

  2. 이름에 "이메일 형식 점검", 설명에 "제목 줄, 인사와 맺음말, 요청한 일시·기한·담당자를 모두 갖췄는지 봅니다"를 입력합니다.

  3. 평가 유형은 통과/실패 그대로 둡니다.

  4. 프롬프트 템플릿에 아래 내용을 넣습니다.

    프롬프트: 너는 업무 이메일 초안을 검토하는 채점자다.

    요청: {question}

    꼭 들어가야 할 내용: {reference_answer}

    에이전트가 쓴 메일: {agent_answer}

    아래 세 가지를 모두 지키면 1, 하나라도 어기면 0을 준다.

    1. 메일 첫 줄이 "제목:"으로 시작한다.
    2. 받는 사람에 맞는 인사로 시작하고 정중한 맺음말로 끝난다.
    3. 꼭 들어가야 할 내용에 적힌 날짜, 시간, 장소, 기한, 담당자가 바뀌지 않고 모두 들어 있다.

    reasoning에는 어긴 항목 번호와 이유를 한국어로 적는다. JSON으로만 응답: {"score": 0 또는 1, "reasoning": "설명"}

  5. 저장을 누릅니다. 사용자 평가기에 "이메일 형식 점검" 카드가 통과/실패 배지와 함께 나타납니다.

팁: 한 평가기에 기준을 너무 많이 넣으면 무엇 때문에 실패했는지 가리기 어렵습니다. 내용이 빠졌는지는 완전성, 어조는 전문성, 형식은 사용자 평가기처럼 나눠 두고 필요한 것만 골라 실행합니다.

사용자 평가기 고치기와 지우기​

사용자 평가기 카드를 누르면 "평가기 수정" 창이 열립니다. 생성 창과 같은 칸을 고친 뒤 저장을 누르면 "평가기를 저장했습니다." 안내가 뜹니다. 카드에 마우스를 올려 나타나는 휴지통을 누르면 "평가기 삭제" 확인 창이 열리고, 삭제를 누르면 "이 평가기가 영구적으로 삭제됩니다." 안내대로 지워집니다.

평가기 프롬프트를 고치면 이름이 같아도 채점 기준이 달라집니다. 지침 수정 전후를 같은 기준으로 비교하려면 비교가 끝날 때까지 평가기를 고치지 않고, 새 기준이 필요하면 새 평가기로 만듭니다.
