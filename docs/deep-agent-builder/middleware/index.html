Deep Agent Builder 미들웨어와 실행 전 처리

미들웨어는 에이전트 실행에 공통 처리를 덧붙이는 구성입니다. 도구처럼 외부 작업을 직접 수행하는 자원도 아니고, 스킬처럼 작업 절차를 설명하는 자료도 아닙니다. 이 페이지에서는 미들웨어의 역할, 에이전트에 연결할 때의 판단 기준, 실행 권한과 설정을 확인하는 순서를 설명합니다.

미들웨어가 담당하는 일​

미들웨어는 에이전트 실행 흐름의 특정 지점에서 요청이나 결과를 처리합니다. 따라서 같은 에이전트라도 연결한 미들웨어의 종류와 설정에 따라 실행 전 확인, 호출 전 변환, 실행 후 정리 같은 동작이 달라질 수 있습니다. 개별 미들웨어가 어느 시점에 무엇을 처리하는지는 해당 항목의 설명과 설정을 기준으로 판단해야 합니다.

미들웨어와 다른 구성의 경계는 다음과 같습니다.

구성담당하는 일실행 때 확인할 것
도구에이전트가 외부 작업을 호출하는 연결점외부 호출 대상과 사용 권한
미들웨어실행 흐름에 적용하는 처리 구성적용 조건과 설정값
스킬업무 절차와 전문 지식을 제공하는 자료참고 시점과 업무 적합성
모델응답을 생성하는 엔진선택된 모델과 사용 권한

미들웨어를 추가했다고 에이전트가 새로운 외부 시스템에 접근한다고 판단하지 않습니다. 외부 호출 여부는 연결된 도구와 실행 권한을 함께 확인해 판단합니다. 미들웨어는 그 실행 흐름에 별도의 처리를 적용하는 구성으로 이해하면 됩니다.

카탈로그에서 확인할 항목​

현재 미들웨어는 전역 카탈로그에서 조회하는 읽기 전용 자원으로 다뤄집니다. 목록에서 확인할 수 있는 항목과 실제 사용할 수 있는 권한은 같은 뜻이 아닙니다. 다음 정보를 차례로 확인합니다.

  1. 이름과 설명이 맡기려는 업무와 맞는지 확인합니다.
  2. 유형과 버전을 확인합니다. 유형은 사전 제공, 직접 정의, 공급자 제공처럼 서로 다른 관리 범위를 구분하는 데 사용됩니다.
  3. 사용에 필요한 환경 설정 항목이 있는지 확인합니다. 필요한 값이 없을 때 실행에 어떤 영향이 있는지 제품 설정과 실행 결과로 확인합니다.
  4. 사용 가능 여부를 확인합니다. 권한 그룹을 해석할 수 없거나 사용 권한이 없을 때 어떤 상태로 표시되는지 확인합니다.
  5. 상세 정보에서 설정 가능한 항목, 기본 설정, 변경 가능한 범위를 확인합니다.

목록에 항목이 없거나 상세 정보를 열 수 없다면 먼저 로그인 상태와 미들웨어 조회 권한을 확인합니다. 목록 조회 권한이 있다고 해서 모든 미들웨어를 에이전트에 연결하거나 실행할 수 있다고 판단하지 않습니다.

에이전트에 연결할 때의 판단​

에이전트에 미들웨어를 연결하기 전에는 이 처리가 모든 실행에 필요한지 판단합니다. 한 업무에만 필요한 처리를 모든 에이전트에 넣으면 실행 흐름을 이해하기 어려워지고, 설정 오류가 발생했을 때 원인을 좁히기도 어렵습니다.

다음 질문에 답할 수 있을 때 연결합니다.

  • 이 미들웨어가 처리해야 하는 실행 조건은 무엇인가?
  • 기본 설정으로 충분한가, 에이전트별 설정이 필요한가?
  • 실행에 필요한 환경 설정과 사용 권한이 준비됐는가?
  • 연결 뒤 에이전트의 응답이나 도구 실행 결과에서 무엇을 확인할 것인가?
  • 이 처리가 없어도 되는 요청에 같은 미들웨어가 적용되지 않는가?

연결 가능한 항목으로 보여도 실행 전 사용 권한을 별도로 확인합니다. 편집 화면에서 연결이 저장된 사실만으로 실행 성공을 예상하지 않습니다. 저장 권한, 미들웨어 조회 권한, 실제 사용 권한을 나누어 확인해야 합니다.

설정을 바꾸는 순서​

미들웨어 설정은 에이전트에 연결된 인스턴스 설정과 카탈로그의 기본 설정을 구분해서 봅니다. 카탈로그의 기본값을 확인하지 않고 에이전트 설정만 바꾸면 어떤 값이 실제 실행에 적용되는지 판단하기 어렵습니다.

  1. 미들웨어 상세에서 기본 설정과 변경 가능한 항목을 확인합니다.
  2. 에이전트 편집 화면에서 해당 미들웨어의 인스턴스 설정을 엽니다.
  3. 업무에 필요한 값만 바꿉니다. 지원하지 않는 항목을 임의로 추가하지 않습니다.
  4. 설정을 저장한 뒤 변경된 값이 다시 조회되는지 확인합니다.
  5. 테스트 실행에서 미들웨어가 필요한 조건으로 적용되는지 확인합니다.
  6. 결과가 달라졌다면 지침, 입력, 도구 설정과 미들웨어 설정을 나누어 비교합니다.

설정 화면의 구체적인 저장 방식이나 표시 이름은 배포된 화면에서 확인해야 합니다. 현재 근거는 에이전트별 미들웨어 설정 조회·변경·검증 범위를 확인하지만, 모든 화면의 저장 알림이나 버튼 문구까지 확정하지는 않습니다.

권한을 분리해서 확인하기​

미들웨어를 조회하는 권한과 에이전트를 수정하는 권한은 별개입니다. 에이전트 상세를 열 수 있어도 미들웨어 설정을 읽지 못할 수 있고, 설정을 읽을 수 있어도 변경 권한이 없을 수 있습니다. 실행할 때는 연결된 미들웨어를 사용할 수 있는지도 다시 확인합니다.

권한 문제를 확인할 때는 다음 순서를 따릅니다.

  1. 에이전트 상세와 편집 권한이 있는지 확인합니다.
  2. 미들웨어 목록과 상세를 읽을 권한이 있는지 확인합니다.
  3. 해당 미들웨어의 사용 가능 상태와 필요한 환경 설정을 확인합니다.
  4. 에이전트에 연결하거나 설정을 바꿀 권한이 있는지 확인합니다.
  5. 테스트 실행에서 에이전트와 연결 자원 모두의 실행 권한이 있는지 확인합니다.

사용 불가 상태를 숨기지 않고 표시하는 것은 권한 문제를 연결 실패와 구분하기 위해서입니다. 사용 가능 여부가 false라면 미들웨어 자체가 고장 났다고 단정하지 말고, 권한 그룹과 필요한 환경 설정이 영향을 주는지 먼저 확인합니다.

현재 지원 범위와 제한​

현재 확인된 미들웨어 카탈로그의 사용자 표면은 목록과 상세 조회입니다. 이름, 설명, 태그를 카탈로그 화면에서 직접 편집하거나 개인 미들웨어를 별도로 만들고 동기화하는 기능은 이 근거 범위에서 지원 계약으로 확정하지 않습니다.

따라서 다음 행동은 구분해야 합니다.

가능한 판단이 페이지에서 확정할 수 있는 내용
목록 확인미들웨어의 유형, 버전, 사용 가능 여부와 요약 정보 확인
상세 확인설정 스키마, 기본 설정과 변경 가능 항목 확인
에이전트 구성에이전트에 연결된 미들웨어와 인스턴스 설정 확인
실행 확인필요한 권한과 환경 설정을 갖춘 테스트 실행으로 결과 비교
카탈로그 편집현재 근거만으로는 지원한다고 확정하지 않음

지원하지 않는 편집 흐름을 찾았다면 다른 화면에서 임의로 반복하지 않습니다. 제품 버전과 권한을 확인한 뒤, 실제 화면에 제공되는 에이전트별 설정 경로를 사용합니다.

결과가 기대와 다를 때​

실행 결과가 바뀌었을 때는 미들웨어를 원인으로 바로 단정하지 않습니다. 다음 순서로 한 항목씩 비교합니다.

  1. 같은 입력과 같은 스레드 조건으로 다시 확인합니다.
  2. 에이전트에 연결된 미들웨어 목록과 저장된 설정을 확인합니다.
  3. 미들웨어의 사용 가능 상태와 필요한 환경 설정을 확인합니다.
  4. 연결된 도구의 실행 권한과 외부 호출 결과를 확인합니다.
  5. 미들웨어를 제외한 조건에서 비교 테스트를 수행할 수 있는지 검토합니다.

조회는 성공했지만 실행이 실패한다면 조회 권한과 사용 권한이 다른지 확인합니다. 설정 저장 뒤 값이 사라진다면 지원되는 설정 항목인지, 저장 후 다시 읽은 값이 최신 값인지 확인합니다. 목록에서 항목이 보이지 않는다면 검색어와 유형 필터를 지우기 전에 권한과 카탈로그 범위를 먼저 확인합니다.

다음 문서​

  • 에이전트 수정에서 에이전트 구성과 연결 자원을 조정하는 방법을 확인합니다.
  • 핵심 개념에서 실행과 리소스 권한의 관계를 확인합니다.
