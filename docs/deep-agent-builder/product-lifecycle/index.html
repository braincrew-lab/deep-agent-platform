Deep Agent Builder 제품 수명주기

Deep Agent Builder에서 에이전트는 생성한 뒤 바로 끝나는 대상이 아닙니다. 구성하고 저장한 뒤 실행으로 확인하고, 필요하면 다시 수정하거나 보관합니다. 이 페이지는 각 단계에서 무엇이 바뀌는지와 다음 단계로 넘어가기 전에 무엇을 확인할지 설명합니다.

수명주기에서 구분할 대상​

에이전트는 재사용할 업무 구성입니다. 이름, 설명, 지침, 모델, 도구, 미들웨어, 스킬과 서브에이전트가 에이전트의 동작 범위를 정합니다. 스레드는 한 대화의 맥락이고, 실행은 스레드에서 요청을 처리하는 한 번의 작업입니다.

따라서 다음 상태를 섞어 판단하지 마세요.

구분바뀌는 것확인할 기준
구성에이전트의 이름, 지침, 모델, 연결 자원과 실행 설정수정 화면에 의도한 값이 저장됐는가
대화현재 스레드의 입력과 맥락이전 업무의 지시와 자료가 섞이지 않았는가
실행요청 처리의 진행 상태와 종료 결과성공, 오류, 취소, 중단, 시간 초과 중 무엇인가
보관에이전트를 다시 사용하는 상태와 참조 관계다른 에이전트가 하위 구성으로 참조하지 않는가

구성을 저장했다고 실행 결과가 바뀌었다고 단정할 수는 없습니다. 반대로 실행이 성공했다고 설정이 저장됐다고 볼 수도 없습니다.

생성하고 실행 가능한 상태 확인하기​

에이전트는 업무 설명으로 초안을 만들거나 이름과 설명을 직접 입력해 시작할 수 있습니다. 생성 방식과 관계없이 다음 항목을 확인해야 실제 실행을 판단할 수 있습니다.

  1. 에이전트 목록과 수정 화면에서 이름과 설명이 맡길 업무를 정확히 나타내는지 확인합니다.
  2. 지침에 역할, 답변 형식, 제한 조건과 정보가 부족할 때의 처리 방법이 들어 있는지 확인합니다.
  3. 현재 활성 모델이 업무에 맞고 워크스페이스에서 사용 가능한지 확인합니다.
  4. 도구, 미들웨어, 스킬과 서브에이전트가 필요한 범위만 연결됐는지 확인합니다.
  5. 테스트 실행에서 정상 입력과 정보가 부족한 입력을 각각 보내 결과를 비교합니다.

초안이 만들어졌다는 사실과 실행 권한이 있다는 사실은 별개입니다. 수정 권한, 모델 사용 권한, 연결된 리소스의 실행 권한이 각각 필요할 수 있습니다. 생성 세션에서 추가 질문이나 승인 요청이 나타나면 값을 확인한 뒤 같은 세션에서 이어서 작업합니다.

수정하고 다시 확인하기​

반복해서 같은 방식으로 어긋나는 답변이 나오면 개별 요청을 반복하기보다 지침과 연결 자원을 먼저 점검합니다. 수정 화면에서 한 번에 여러 항목을 바꾸지 말고, 원인을 확인하려는 항목부터 하나씩 변경하세요.

수정 후에는 다음 순서로 확인합니다.

  1. 바꾸려던 항목만 변경됐는지 확인합니다.
  2. 저장이 완료됐는지 확인하고 수정 화면을 다시 엽니다.
  3. 모델, 연결 자원과 실행 설정의 현재 값을 확인합니다.
  4. 같은 기준의 정상 입력과 정보가 부족한 입력으로 다시 실행합니다.
  5. 결과가 달라졌다면 이름과 설명, 지침, 모델, 자원 중 어떤 변경이 영향을 줬는지 비교합니다.

이름과 설명은 목록에서 대상을 구분하는 정보입니다. 이름만 바꿔도 답변 규칙이 자동으로 바뀌지는 않습니다. 지침, 모델, 도구와 같은 구성 변경은 저장 정책이 항목마다 다를 수 있으므로 각 항목의 저장 상태를 따로 확인합니다.

복사본과 서브에이전트 관리하기​

복사는 기존 구성을 바탕으로 새 에이전트를 만드는 방법입니다. 복사본을 실험용으로 사용할 때는 원본과 구분되는 이름을 정하고, 지침, 모델, 연결 자원, 파일과 실행 설정을 새 업무에 맞게 다시 확인합니다. 같은 입력을 보내 원본과 결과를 비교하면 원본을 바로 변경하지 않고 영향 범위를 좁힐 수 있습니다.

서브에이전트는 다른 에이전트가 일부 업무를 맡길 수 있는 하위 구성입니다. 연결하기 전에 부모 에이전트와 하위 업무가 분명한지 확인하고, 화면에 표시되는 소유 범위와 상태를 점검합니다. 보관 상태, 슈퍼 에이전트 연결, 자기 참조와 순환 호출의 허용 여부는 현재 제품 화면과 권한에서 확인해야 합니다.

보관하기 전에 확인하기​

더 이상 사용하지 않는 에이전트는 삭제 대신 보관 상태로 전환할 수 있습니다. 보관은 모든 기록이 즉시 사라지는 작업으로 보지 마세요. 먼저 다른 에이전트가 해당 에이전트를 하위 에이전트로 참조하는지 확인합니다. 보관 방식과 기존 참조에 미치는 영향은 제품 화면에서 확인한 뒤 진행합니다.

보관한 뒤에는 목록에 표시되는 상태와 기존 참조의 변화를 확인합니다. 다시 사용할 수 있는지, 연결된 업무가 다른 에이전트로 안전하게 이동했는지는 화면과 실행 결과로 따로 판단해야 합니다.

문제가 생겼을 때 좁혀 가는 순서​

문제가 발생하면 수명주기의 어느 단계에서 어긋났는지 먼저 나눕니다.

관측한 문제먼저 확인할 것다음 판단
생성이 진행되지 않음입력값, 생성 세션 상태, 모델과 리소스 권한추가 질문이나 승인 요청이면 값을 입력하고 같은 세션을 이어 갑니다.
저장되지 않음수정 권한, 입력값 허용 범위, 항목별 저장 동작저장 실패와 실행 실패를 분리해 확인합니다.
저장했지만 답변이 달라지지 않음실제로 바뀐 지침, 모델, 자원과 실행 입력이름과 설명만 바꾼 것은 아닌지 확인합니다.
실행 중 오류나 시간 초과입력 자료, 대화 맥락, 연결 자원과 종료 상태같은 요청을 즉시 반복하지 말고 결과와 원인을 나눠 확인합니다.
보관할 수 없음하위 에이전트 참조, 상태와 소유 범위참조를 정리할 수 있는 권한과 영향 범위를 확인합니다.

실행 결과가 불명확한 상태에서 성공이나 실패를 추정하지 마세요. 상태를 확인할 방법이 없으면 실행을 반복하기 전에 관리자나 승인된 지원 경로에 확인할 정보를 준비합니다.

다음 문서​

  • 실행 상태와 스레드의 관계는 핵심 개념에서 확인합니다.
  • 실행 결과를 반복해서 점검하려면 반복 업무를 읽습니다.
