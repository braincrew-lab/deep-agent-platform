에이전트 수명주기

에이전트는 한 번 만들고 끝나는 도구가 아닙니다. 맡길 일을 정하고, 만들고, 시험하고, 고치고, 점수로 확인한 뒤 동료와 나눠 쓰고, 정해진 시간에 돌리며 지켜보는 일을 되풀이합니다. 이 페이지는 김그루 사원의 주간 업무 보고서 도우미를 예로 들어 에이전트 하나가 거치는 일곱 단계를 정리하고, 단계마다 쓰는 화면과 읽을 매뉴얼 페이지를 연결합니다.

이 페이지에서 할 수 있는 일

  • 기획부터 운영까지 에이전트가 거치는 일곱 단계를 한눈에 봅니다.
  • 단계마다 Deep Agent Builder의 어느 화면을 쓰는지 확인합니다.
  • 지금 내 에이전트가 어느 단계에 있고, 다음에 무엇을 할지 정합니다.
  • 단계마다 필요한 매뉴얼 페이지로 바로 이동합니다.

한눈에 보는 일곱 단계​

기획 → 만들기 → 테스트 → 개선 → 평가 → 공유 → 운영 순서로 진행합니다. 운영하면서 새 문제가 보이면 개선 단계로 돌아가 고치고, 다시 평가한 뒤 새 버전을 공유합니다.

단계하는 일쓰는 화면마치는 기준읽을 페이지
1 기획맡길 업무, 넣을 자료, 받고 싶은 결과, 하지 말아야 할 일을 정합니다.화면 밖(메모)만들기 요청 문장과 시험 질문 3개에서 5개가 준비됨첫 에이전트 설계하기, 핵심 개념 이해하기
2 만들기대화로 만들거나 직접 만들고, 지침·모델·도구·지식·미들웨어·스킬을 연결합니다.홈 화면, 에이전트 편집 화면의 구성 칸에이전트 편집 화면에서 지침과 연결 항목을 확인하고 저장함에이전트 만들기, 에이전트 수정, 도구와 스킬 구성, 지식으로 근거 있는 답변 받기, 모델 구성, 미들웨어와 개인정보 보호
3 테스트준비한 시험 질문을 보내 답의 형식과 내용을 확인합니다.에이전트 편집 화면 테스트 탭, 대화 화면시험 질문마다 기대한 형식으로 답함에이전트 수정, 대화 화면과 채팅 목록
4 개선어긋난 점을 말로 설명해 고치거나 지침을 직접 고치고, 큰 변경은 새 버전으로 남깁니다.에이전트 편집 화면 Fix 에이전트 탭, 헤더의 저장과 새 버전으로 저장같은 시험 질문에서 문제가 사라짐Fix 에이전트, 에이전트 수정
5 평가질문과 기대 답을 묶은 데이터셋으로 평가를 실행해 점수로 확인합니다.더 보기 > 평가기준 점수가 기록되고, 고친 버전의 점수가 이전보다 낮지 않음에이전트 평가 개요, 평가 데이터셋 만들기, 평가 실행, 평가 결과 읽기와 비교, 회귀 평가와 개선
6 공유워크스페이스 등록을 요청해 동료가 쓰게 하고, 바뀐 버전은 재배포를 요청합니다.에이전트 편집 화면 헤더 워크스페이스 등록, 에이전트 템플릿 > 커뮤니티 에이전트 관리등록 상태가 게시됨으로 바뀜즐겨찾기·워크스페이스·다운로드, 커뮤니티, 시크릿과 권한
7 운영정해진 시간에 자동 실행하고, 실행 결과와 사용량을 지켜봅니다.에이전트 편집 화면 스케줄 탭, 더 보기 > 작업실패한 실행을 확인하는 주기가 정해짐스케줄링과 백그라운드 모드, 모니터링과 실행 상태 확인

1단계: 기획​

만들기 전에 에이전트에게 맡길 일을 좁힙니다. 김그루 사원은 주간 업무 보고서 도우미를 이렇게 정했습니다.

정할 것주간 업무 보고서 도우미의 예
맡길 업무한 주 업무 메모를 받아 팀장에게 올릴 주간 업무 보고서로 정리
쓸 사람AI혁신팀 김그루 사원(나중에 팀원 전체)
넣을 자료요일별 업무 메모, 이슈, 다음 주 계획
받고 싶은 결과제목, 이번 주 핵심 성과 3줄, 업무별 진행 표, 이슈와 조치, 다음 주 계획, 확인 필요 여섯 부분으로 나뉜 보고서
하지 말아야 할 일메모에 없는 업무나 숫자를 지어내지 않음, 숫자는 메모 그대로 옮김, 빠진 정보는 [확인 필요]로 표시
시험 질문정상 요청, 자료가 부족한 요청, 형식을 바꾸는 요청, 범위 밖 요청 네 가지

질문 하나에 답 하나로 끝나는 업무는 에이전트 하나로 충분합니다. 보고서 작성과 메일 발송처럼 단계가 나뉘는 업무라면 멀티에이전트 개념도 함께 봅니다.

2단계: 만들기​

홈 화면 입력란에 기획한 내용을 한두 문장으로 적고 보내면 대화로 에이전트 만들기가 시작됩니다. 확인 질문에 답하면서 도구, 미들웨어, 스킬, 서브에이전트 추천과 모델, 시스템 프롬프트(지침)가 정리되고, 에이전트가 완성되면 바로 이용하기가 나타납니다. 이름과 설명만 정해 빈 에이전트로 시작하고 싶다면 에이전트 직접 만들기를 누릅니다. 동료가 게시한 비슷한 에이전트가 있다면 에이전트 템플릿에서 본떠 만들 수도 있습니다.

만든 뒤에는 사이드바의 에이전트 설정으로 에이전트 편집 화면을 열어 지침, 모델, 도구함, 지식함, 미들웨어를 확인합니다. 이름, 설명, 지침을 고쳤다면 헤더의 저장을 누릅니다. 저장하기 전의 지침은 대화와 테스트 탭에 쓰이지 않습니다. 도구, 모델, 오프너, 스킬, 지식, 미들웨어는 바꾸는 즉시 반영되며, 이런 변경도 현재 버전에 기록하려면 헤더에 "저장되지 않은 변경이 있습니다"가 보일 때 저장을 누릅니다.

3단계: 테스트​

기획 단계에서 준비한 시험 질문을 그대로 보냅니다. 에이전트 편집 화면 오른쪽 테스트 탭에서 바로 보내도 되고, 대화 화면에서 이 에이전트와 새 대화로 새 채팅을 열어 보내도 됩니다. 답변마다 다음을 봅니다.

  • 지침에서 정한 순서와 형식대로 답했는지
  • 메모의 숫자가 바뀌지 않았는지
  • 메모에 없는 업무를 지어내지 않았는지

시험 질문마다 새 채팅을 여는 편이 좋습니다. 앞 질문의 자료가 다음 답변에 섞이지 않습니다. 오류 문구나 끊긴 답이 나오면 문제 해결을 봅니다.

4단계: 개선​

결과가 어긋나면 에이전트 편집 화면 오른쪽 Fix 에이전트 탭에서 고치고 싶은 점을 말로 설명합니다. 예를 들어 "숫자는 메모에 적힌 그대로 쓰고, 메모에 없는 업무는 넣지 말라는 규칙을 지침에 추가해 줘"라고 보내면 Fix 에이전트가 구성을 고쳐 줍니다. Fix 에이전트가 고친 내용은 바로 대화와 테스트에 반영되고, 결과가 좋으면 헤더의 저장으로 현재 버전에 기록합니다. 지침을 직접 고쳤다면 저장을 눌러야 시험에 쓰입니다.

고친 뒤에는 3단계의 시험 질문을 다시 보냅니다. 형식을 크게 바꾸는 것처럼 변경이 클 때는 고치기 전에 헤더 저장 옵션 더 보기의 새 버전으로 저장으로 새 버전을 만들어 두면, 헤더의 현재 버전을 눌러 이전 버전과 오가며 비교할 수 있습니다.

5단계: 평가​

시험 질문이 몇 개를 넘어가면 손으로 하나씩 보내기 어렵습니다. 더 보기의 평가에서 질문과 기대 답을 묶은 데이터셋을 만들고, 평가기를 골라 평가를 실행하면 답변 품질이 점수로 나옵니다. 첫 평가 점수는 이후 개선을 비교할 기준이 됩니다. 4단계에서 고친 뒤 같은 데이터셋으로 다시 평가해 점수가 떨어지지 않았는지 확인합니다.

평가 화면과 결과 읽는 법은 에이전트 평가 개요부터 차례로 읽고, 고치기 전후를 비교하는 방법은 회귀 평가와 개선에서 봅니다.

6단계: 공유​

내가 만든 에이전트는 처음에는 나만 봅니다. 팀원도 쓰게 하려면 에이전트 편집 화면 헤더의 워크스페이스 등록을 눌러 워크스페이스에 등록을 요청합니다. 등록은 저장된 버전으로 하므로, 헤더에 "저장되지 않은 변경이 있습니다"가 보이면 먼저 저장을 누릅니다. 창에서는 워크스페이스마다 지금 상태(미등록, 심사 대기, 게시됨, 반려됨)를 확인하고, 등록할 버전을 고른 뒤 등록 요청 버튼("1개 등록 요청"처럼 고른 워크스페이스 수가 표시됨)을 누릅니다. 관리자 심사가 필요한 워크스페이스라면 "관리자 심사 후 게시됩니다."가 보이고 심사를 거쳐 게시되며, 그렇지 않은 워크스페이스라면 "등록 요청이 바로 게시됩니다."가 보이고 바로 게시됩니다. 결과는 "심사를 요청했습니다", "게시되었습니다", "실패했습니다" 중 하나로 나옵니다. 게시된 에이전트는 에이전트 템플릿 화면에 나타나고, 동료가 한 번 대화하면 그 동료의 사이드바 워크스페이스 에이전트 탭에도 나타납니다.

공유하기 전에 다음을 점검합니다.

  • 개인정보가 들어올 수 있는 업무라면 개인정보 보호 미들웨어가 연결돼 있는지
  • 지침에 비공개 정보나 비밀 값이 들어 있지 않은지
  • 서브에이전트가 있다면 서브에이전트도 먼저 배포되어 있는지. 배포되지 않은 서브에이전트가 있으면 그 워크스페이스는 요청에서 제외됩니다.
  • 연결한 스킬이 배포되어 있는지. 배포되지 않은 스킬이 있으면 배포 요청을 보낼 수 없습니다.

공유한 뒤 에이전트를 고쳤다면 에이전트 템플릿 화면의 커뮤니티 에이전트 관리에서 재배포를 요청합니다. 승인 전까지는 지금 배포된 버전이 그대로 유지됩니다. 워크스페이스 에이전트는 동료가 대화와 즐겨찾기만 할 수 있고 설정은 바꿀 수 없습니다. 자세한 내용은 즐겨찾기·워크스페이스·다운로드와 커뮤니티에 있습니다.

7단계: 운영​

주간 업무 보고서처럼 정해진 때마다 하는 일은 에이전트 편집 화면 오른쪽 스케줄 탭에서 스케줄 추가를 눌러 자동 실행을 걸어 둡니다. 실행 시각은 폼 또는 스케줄 표현식으로 정하고, 타임존과 실행 메시지를 적습니다. 스케줄은 실행할 때마다 새 대화를 시작하고 파일을 첨부할 수 없으므로, 실행 메시지만으로 할 일이 분명하도록 씁니다. 오래 걸리는 요청은 대화 화면 입력란 아래 오른쪽의 백그라운드 모드를 켜고 보내면 기다리지 않고 다른 일을 할 수 있습니다.

실행 결과는 더 보기의 작업에서 지켜봅니다. 작업 기록 탭에서 백그라운드로 실행한 작업의 상태를, 스케줄 작업 탭에서 스케줄별 다음 실행과 실행 횟수, 상태를 봅니다. 대화 화면 오른쪽 위의 사용량 표시를 누르면 채팅 하나에서 쓴 토큰 수를 확인할 수 있습니다.

운영 중 같은 질문에서 답이 자꾸 어긋나거나 동료가 문제를 알려 오면 그 질문을 평가 데이터셋에 더하고 4단계로 돌아갑니다. 자세한 내용은 스케줄링과 백그라운드 모드와 모니터링과 실행 상태 확인에 있습니다.
