Deep Agent Builder 환경 구성과 세부 옵션

이 페이지는 워크스페이스의 기본 모델과 메모리 설정을 확인하고 바꿀 때 필요한 판단 기준을 설명합니다. 모델 선택, 메모리 사용 여부, 메모리에 허용할 모델 목록은 서로 다른 설정이므로 한 항목을 바꿨다고 나머지 설정까지 바뀐 것으로 판단하지 마세요.

먼저 구분할 설정​

워크스페이스 설정은 다음 세 범위로 나눠 확인합니다.

설정확인할 내용바뀌는 범위
기본 모델현재 워크스페이스의 기본 모델과 변경 권한워크스페이스의 기본 모델 값
메모리 기본값새 실행에서 메모리를 기본으로 사용할지메모리 기본 사용 여부
메모리 모델기본 모델과 허용 목록메모리에 사용할 모델과 선택 가능한 모델 범위

워크스페이스의 기본 모델 변경은 구성원별 모델 데이터를 갱신하는 작업이 아닙니다. 기본값을 바꾼 뒤에도 구성원이나 에이전트가 실제로 어떤 모델을 사용하는지는 해당 대상의 설정과 실행 권한을 따로 확인해야 합니다.

기본 모델 확인하기​

기본 모델을 바꾸기 전에 다음 순서로 확인합니다.

  1. 워크스페이스 상세 정보에서 현재 기본 모델이 있는지 확인합니다. 값이 없으면 기본 모델은 설정되지 않은 상태입니다.
  2. 변경하려는 모델이 현재 워크스페이스에서 사용할 수 있는지 확인합니다. 전역 모델 목록에 존재하는 것만 기본 모델로 지정할 수 있습니다.
  3. 기본 모델을 바꾼 뒤 변경 응답의 기본 모델 식별자를 확인하고, 상세 정보를 다시 조회해 모델 이름까지 기대한 값인지 확인합니다.
  4. 에이전트나 구성원 한 명을 대상으로 비식별 테스트 입력을 보내 실제 실행 모델이 기대한 값과 일치하는지 확인합니다.

기본 모델을 삭제하려면 값을 null로 설정하거나 빈 변경 요청을 사용할 수 있지만, 두 방식이 같은 결과를 내는 현재 계약에 의존하기보다 화면이나 응답에서 기본 모델이 비어 있는지 다시 확인하세요.

메모리 기본값과 허용 목록 설정하기​

메모리 설정에는 세 값이 있습니다.

  • 메모리 기본값: 새 실행에서 메모리를 기본으로 켤지 결정합니다.
  • 메모리 기본 모델: 메모리가 사용할 모델을 지정합니다.
  • 메모리 허용 모델 목록: 메모리에 지정할 수 있는 모델을 제한합니다.

설정은 다음 순서로 바꿉니다.

  1. 현재 메모리 기본값, 기본 모델, 허용 모델 목록을 먼저 조회합니다.
  2. 메모리를 기본으로 사용할지 결정합니다. 이 값을 바꿔도 이미 실행 중인 작업의 상태가 자동으로 바뀐다고 가정하지 마세요.
  3. 메모리 기본 모델을 지정할 때 전역 모델 후보와 허용 목록을 함께 대조합니다.
  4. 허용 목록이 비어 있지 않다면 기본 모델이 그 목록에 포함되는지 확인합니다.
  5. 저장 후 설정을 다시 조회해 세 값이 함께 기대한 상태가 되었는지 확인합니다.

허용 목록이 비어 있으면 제한 없이 허용하는 방향으로 동작합니다. 따라서 빈 목록을 차단 설정으로 해석하면 안 됩니다. 제한을 사용하려면 허용할 모델을 명시적으로 남겨야 합니다.

권한과 실패를 해석하는 법​

워크스페이스 설정 조회와 변경에는 관리자 애플리케이션 접근 권한과 워크스페이스 읽기 또는 기본 모델 편집 권한이 관여합니다. 권한 오류가 나면 값을 다시 보내기 전에 현재 계정의 역할과 대상 워크스페이스를 확인하세요.

메모리 모델이 허용 목록 밖에 있으면 요청은 거부됩니다. 이때는 모델 값을 반복해서 저장하지 말고, 허용 목록에 모델을 추가할 수 있는 권한과 모델 후보 자체의 존재를 순서대로 확인합니다. 모델 후보가 없거나 유효하지 않으면 설정 변경이 아니라 모델 공급 경로를 먼저 점검해야 합니다.

워크스페이스를 찾지 못했거나 요청 형식이 맞지 않는 경우도 설정 값의 문제와 구분해야 합니다. 권한 거부, 대상 없음, 입력 검증 실패, 허용되지 않은 메모리 모델은 서로 다른 다음 조치를 가집니다.

저장 후 완료 확인​

설정 저장이 끝났다고 판단하려면 다음 항목을 모두 확인합니다.

  1. 응답에 요청한 워크스페이스와 설정 대상이 맞는지 확인합니다.
  2. 기본 모델과 메모리 세 값이 다시 조회한 결과에 반영됐는지 비교합니다.
  3. 허용 목록이 비어 있는지, 아니면 실제 허용 범위를 담고 있는지 확인합니다.
  4. 구성원별 모델 변경이나 에이전트 실행 권한까지 자동으로 바뀌었다고 추정하지 않습니다.
  5. 비식별 테스트 입력으로 실제 실행 결과를 확인합니다.

동시에 여러 설정을 바꾸면 어느 값에서 실패했는지 좁히기 어렵습니다. 기본 모델, 메모리 기본값, 메모리 모델을 나눠 저장하고 각 저장 뒤에 다시 조회하는 편이 원인을 추적하기 쉽습니다.
