세부 설정과 메모리

에이전트 하나하나의 실행 방식은 에이전트 편집 화면의 설정 탭에서, 모든 대화에 걸쳐 나를 기억하는 방식은 에셋 화면의 메모리 탭에서, 화면 모양과 언어는 환경설정에서 정합니다. 이 페이지는 브레인크루 AI혁신팀 김그루 사원이 주간 업무 보고서 도우미의 실행 설정을 다듬고, 메모리에 보고서 작성 선호를 남기고, 화면을 자기에게 맞게 바꾸는 과정을 설명합니다.

이 페이지에서 할 수 있는 일

  • 에이전트 편집 화면 설정 탭의 구성(에이전트 모드, Recursion Limit, MCP 서버, Webhook, Context Compaction)과 묶음마다 값을 저장하는 버튼을 압니다.
  • Recursion Limit의 최대 처리 단계 수를 1부터 1000 사이로 정합니다(기본 500).
  • Context Compaction으로 긴 대화를 자동 요약하는 시점(10부터 95%까지)과 남길 최근 메시지 수(2개부터 100개까지)를 정합니다.
  • 에셋 화면의 메모리 탭에서 메모리를 켜고 추출 모델을 고르고, 메모리 편집 창에서 기억된 내용을 고칩니다.
  • 환경설정에서 컬러 테마, 서체, 글자 크기, 표시 언어, 푸시 알림을 바꿉니다.
  • 프로필에서 계정 정보와 기본 워크스페이스를 확인하고, 닉네임과 비밀번호를 바꿉니다.

에이전트 편집 화면의 설정 탭​

에이전트 편집 화면 오른쪽 탭 줄 끝의 설정을 누르면 "에이전트 실행 설정을 관리합니다" 화면이 열립니다.

설정 탭

번호메뉴기능이런 때 사용하세요
1설정 탭이 에이전트의 실행 설정 화면을 엽니다.실행 방식을 바꿀 때
2에이전트 모드일반 에이전트와 문서작성 에이전트 중 고릅니다. "전환하는 즉시 저장됩니다" 안내대로 고르는 즉시 저장됩니다.문서 작성용 에이전트로 바꿀 때
3최대 처리 단계 수Recursion Limit 값을 넣습니다. 옆에 "(범위: 1 - 1000)"이 보입니다.긴 작업이 중간에 멈출 때
4저장탭 맨 위 오른쪽 버튼입니다. 값을 바꾸기 전에는 흐리고, 바꾸면 누를 수 있게 됩니다.최대 처리 단계 수를 저장할 때

이럴 때 쓰세요: 김그루 사원은 월말이면 주간 업무 보고서 도우미에게 네 주치 업무 메모와 회의록을 한꺼번에 첨부해 월간 보고 초안을 맡깁니다. 파일을 여러 번 읽느라 답이 표 중간에서 멈추고 "작업 한계에 도달했습니다" 알림이 뜨면, 지침을 고치기 전에 최대 처리 단계 수부터 올리고 테스트 탭에서 같은 파일로 다시 보내 끝까지 나오는지 확인합니다. 확인이 끝나면 헤더 저장까지 눌러 두어야 워크스페이스에 등록할 버전에도 같은 값이 들어갑니다.

최대 처리 단계 수 칸 아래에는 "기본값: 500. 자료 수집·스케줄 실행 등 단계가 많은 작업은 500 이상을 권장합니다." 안내가 보입니다. 칸 옆의 되돌리기 아이콘(기본값으로 초기화)을 누르면 값이 500으로 돌아갑니다.

위에서부터 다음 묶음이 차례로 있습니다. 묶음마다 값을 저장하는 방법이 다르므로 마지막 열을 함께 봅니다.

묶음하는 일값을 저장하는 방법자세한 설명
에이전트 모드일반 에이전트와 문서작성 에이전트 중 고릅니다. 문서작성 에이전트는 모든 대화를 문서 작성 모드로 실행합니다.고르는 즉시 저장됩니다.PPT·문서 만들기
Recursion Limit한 번 답하는 동안 허용할 내부 처리 단계 수를 정합니다.값을 바꾼 뒤 이 탭 맨 위 오른쪽의 저장을 누릅니다.아래 설명
MCP 서버이 에이전트를 MCP 호환 클라이언트에서 쓰게 엽니다.MCP 서버 활성화 스위치를 켜고 MCP 서버 활성화 버튼을 누릅니다. 켠 뒤에는 MCP 설정 업데이트로 바꾼 내용을 반영하고 MCP 서버 비활성화로 끕니다.MCP와 에이전트의 MCP화
Webhook외부 시스템이 정해진 주소로 이 에이전트를 부르게 합니다.Webhook 활성화 스위치를 켜거나 끄는 즉시 저장되고 "에이전트 설정이 저장되었습니다" 알림이 뜹니다.코드 스니펫과 외부 API
Context Compaction대화가 길어지면 앞부분을 자동으로 요약합니다.이 묶음 안의 저장을 누릅니다. 탭 맨 위 저장과는 따로 동작합니다.아래 설명

이 탭에서 저장한 값은 헤더의 저장을 누르지 않아도 그 자리에서 대화와 테스트 탭에 반영됩니다. 다만 현재 버전의 저장본에는 아직 기록되지 않아, 헤더 저장 옆에 "저장되지 않은 변경이 있습니다"가 보이고 저장을 누를 수 있게 됩니다. 이때 헤더 저장을 누르면 바꾼 값이 현재 버전에 기록됩니다. 워크스페이스 등록은 저장된 버전을 쓰므로, 등록을 요청하기 전에 헤더 저장을 눌러 둡니다. 저장과 버전은 에이전트 수정에서 설명합니다.

Recursion Limit은 한 번의 응답을 만드는 동안 모델 호출과 도구 실행을 합친 내부 처리 단계를 몇 번까지 허용할지 정하는 상한입니다. 처리 단계가 이 값에 닿으면 답변이 중간에 멈추고 "작업 한계에 도달했습니다" 알림이 뜹니다. 화면 설명대로 값을 올려도 실행 횟수나 비용이 그 자체로 늘지는 않으며, 복잡한 작업이 중간에 멈추지 않도록 여유를 두는 안전 한도입니다. 값을 낮추면 끝나지 않고 계속 도는 실행을 더 일찍 멈춥니다. 처음에는 기본값 500으로 두고, 자료를 여러 번 찾아 정리하는 작업이 자주 멈출 때 올립니다. 범위를 벗어난 값(예: 1001)을 넣고 저장을 누르면 "유효하지 않은 값입니다" 알림이 뜨고 저장되지 않습니다.

Context Compaction​

대화가 길어지면 이전 메시지를 요약해 모델이 한 번에 읽는 양(컨텍스트 창)을 아낍니다. 예상 토큰 수가 실행 모델 컨텍스트 길이의 정한 비율을 넘으면, 최근 메시지를 뺀 앞부분을 자동으로 요약합니다.

Context Compaction 묶음에는 스위치 하나, 입력 칸 두 개와 버튼 두 개가 있습니다.

Context Compaction 묶음

번호메뉴기능이런 때 사용하세요
1Context Compaction 활성화자동 요약을 켜고 끕니다. 처음에는 켜져 있습니다.긴 대화를 요약 없이 그대로 두고 싶을 때 끕니다
2압축 시작 비율 (모델 컨텍스트 대비 %)요약을 시작할 시점입니다. 10부터 95까지, 처음 값은 80입니다. 낮추면 더 일찍 요약합니다.긴 자료를 자주 다뤄 답이 느려질 때
3최근 유지 메시지 수요약하지 않고 원문 그대로 둘 최근 메시지 수입니다. 2부터 100까지, 처음 값은 10입니다.최근 대화를 더 많이 그대로 남기고 싶을 때
4저장이 묶음의 값을 저장합니다. 값을 바꾸기 전에는 흐립니다. 탭 맨 위 저장으로는 이 값이 저장되지 않습니다.비율이나 메시지 수를 바꾼 뒤

비율 칸 옆의 되돌리기 아이콘(기본값으로 초기화)을 누르면 처음 값으로 돌아갑니다.

범위를 벗어나면 "비율은 10에서 95 사이여야 합니다", "최근 유지 메시지 수는 2에서 100 사이여야 합니다"가 보입니다.

따라 해 보기: 주간 업무 보고서 도우미 실행 설정 다듬기​

주간 업무 보고서 도우미는 스케줄로 매주 자동 실행되고, 메모와 회의록을 여러 번 읽어 보고서를 만듭니다.

  1. 사이드바에서 주간 업무 보고서 도우미를 누르고 에이전트 설정을 누릅니다.

  2. 오른쪽 설정 탭을 누릅니다.

  3. 에이전트 모드가 일반 에이전트인지 확인합니다.

  4. 최대 처리 단계 수가 500보다 작으면 500으로 바꾸고 탭 맨 위 오른쪽의 저장을 누릅니다.

  5. Context Compaction에서 압축 시작 비율을 70으로, 최근 유지 메시지 수를 12로 바꾸고 그 묶음 안의 저장을 누릅니다.

  6. 테스트 탭에서 김그루_주간업무메모_1106.md(11월 2일~6일 업무 메모)와 브레인크루_AI혁신팀_주간회의록_1110.txt(11월 10일 화요일 회의록)를 첨부하고 아래 프롬프트를 보내, 중간에 멈추지 않고 끝까지 답하는지 봅니다.

    프롬프트: 첨부한 11월 2일6일 업무 메모와 11월 10일 회의록을 합쳐 AI혁신팀 업무 보고서를 써 주세요. 11월 2일6일에 완료한 일, 진행 중인 일, 11월 10일 회의 결정 사항, 앞으로의 계획 순으로 정리해 주세요.

팁: 답이 길어지다가 갑자기 멈추면 먼저 최대 처리 단계 수를 확인합니다. 단계가 많은 작업은 화면 안내대로 500 이상을 권장합니다. 스케줄 실행은 스케줄링과 백그라운드 모드에서 설명합니다.

에셋 화면의 메모리 탭​

메모리는 대화 전반에서 내 어투, 언어, 선호를 자동으로 기억해 다음 대화에 반영하는 기능입니다. 에이전트마다가 아니라 내 계정 기준으로 동작합니다. 사이드바의 에셋설정을 눌러 여는 에셋 화면에서 메모리 탭을 엽니다.

메모리 탭

번호메뉴기능이런 때 사용하세요
1메모리 스위치"대화 전반의 어투, 언어, 선호도를 자동으로 기억합니다" 기능을 켜고 끕니다. 처음에는 꺼져 있습니다.대화마다 같은 선호를 반복해 말하기 싫을 때
2추출 모델대화에서 기억할 내용을 뽑아낼 모델을 고릅니다.메모리를 처음 켤 때
3메모리 내용지금 기억된 내용입니다. 비어 있으면 "아직 메모리 내용이 없습니다"가 보입니다.무엇이 기억됐는지 확인할 때
4수정메모리 편집 창을 엽니다.기억된 내용을 고치거나 덧붙일 때

이럴 때 쓰세요: 김그루 사원은 이메일 초안 도우미, 회의록 요약 도우미, 보고서 초안 도우미를 번갈아 쓰는데, 대화마다 "존댓말로, 결론 먼저"를 다시 적는 일이 번거로웠습니다. 메모리를 켜 두면 내 계정 기준으로 선호가 쌓여 어느 에이전트와 대화해도 같은 형식으로 답이 시작됩니다. 한 달에 한 번쯤 메모리 내용을 열어 지난 작업 때 잠깐 부탁한 요청(예: 금액을 달러로 적기)이 남아 있지 않은지 보고, 수정으로 지웁니다.

고를 수 있는 추출 모델이 없으면 "선택할 수 있는 추출 모델이 없습니다. 모델 탭에서 모델을 설치하거나 필요한 API 키를 등록하세요."가 보입니다. 이때는 추출 모델을 고를 수 없어 메모리 스위치를 켜도 켜지지 않습니다. 모델 준비는 모델 구성을 참고하세요. 스위치와 추출 모델은 바꾸는 즉시 저장됩니다.

메모리 편집 창​

메모리 내용 칸의 수정을 누르면 메모리 편집 창이 열립니다.

메모리 편집 창

번호메뉴기능이런 때 사용하세요
1내용 입력란지금까지 기억된 내용이 그대로 들어 있습니다. 문장을 지우거나 고치고 새 선호를 덧붙입니다. 아래 오른쪽에 "85/2000"처럼 글자 수가 보입니다.잘못 기억된 내용을 고칠 때
2저장고친 내용을 저장하고 창을 닫습니다. 탭의 메모리 내용에 바로 반영됩니다.고치기를 마쳤을 때

메모리 내용은 2000자까지 적을 수 있고, 2000자에 닿으면 "최대 2000자까지 입력할 수 있습니다."가 빨간 글씨로 나옵니다. 취소를 누르거나 창을 닫으면 고친 내용은 버려집니다.

따라 해 보기: 보고서 작성 선호 남기기​

  1. 사이드바의 에셋설정을 눌러 에셋 화면을 열고 메모리 탭을 누릅니다.

  2. 메모리 스위치를 켜고 추출 모델을 고릅니다.

  3. 수정을 누르고 메모리 편집 창에 아래 내용을 적은 뒤 저장을 누릅니다.

    프롬프트: 김그루는 브레인크루 AI혁신팀 사원이다. 답변은 한국어 존댓말로 쓰고, 결론을 먼저 적은 뒤 표로 정리하는 형식을 좋아한다. 금액은 만원 단위로 적는다.

  4. 아무 에이전트와 새 대화를 열어 "이번 주 업무를 정리해 주세요"처럼 형식을 지정하지 않은 요청을 보내고, 결론을 먼저 쓰는지 봅니다. 메모리는 다음 대화부터 반영될 수 있습니다.

팁: 메모리에는 개인 연락처나 고객 정보처럼 기억되면 곤란한 내용을 적지 않습니다. 팀 전체가 따라야 할 형식은 메모리보다 스킬에 두는 편이 낫습니다. 스킬 만들기와 업로드를 참고하세요.

환경설정​

사이드바 아래쪽 환경설정을 누르면 "앱 환경설정 관리" 설정 화면이 열립니다. 화면은 외관, 언어 및 지역, 알림, 정보 네 영역으로 나뉩니다.

외관에는 세 가지가 있습니다. 컬러 테마는 화면 강조 색을 Default, Blue, Green, Rose, Orange, Red 중에서 고릅니다. 서체는 Pretendard, Noto Sans KR, 시스템 기본, Noto Serif KR 중에서 고르며, 바로 아래 서체 미리보기에 서체마다 "내게 맞는 화면으로 더 편안하게" 문장이 보여 비교할 수 있습니다. 글자 크기는 화면 전체 글자 크기를 작게, 보통, 크게 중에서 고릅니다. 외관 항목은 고르는 즉시 저장됩니다.

언어 및 지역의 표시 언어는 메뉴와 안내 문구 언어를 한국어 또는 영어로 바꿉니다. 알림의 푸시 알림은 "에이전트 업데이트에 대한 알림을 받습니다" 스위치로, 처음에는 켜져 있습니다. 정보에는 Deep Agent Builder 이름 아래 지금 쓰는 제품 버전이 보이고, 릴리스 노트 주소가 등록되어 있으면 릴리스 노트 링크가 함께 보입니다. 문제를 문의할 때 이 버전을 함께 알려 주면 확인이 빠릅니다.

프로필​

사이드바 맨 아래 내 이름을 누르고 프로필을 고르면 "계정 정보" 화면이 열립니다. 같은 메뉴의 로그아웃으로 로그아웃합니다.

프로필 화면은 위에서부터 계정 정보, 워크스페이스, 개인 정보, 보안, 활동 다섯 영역입니다. 계정 정보에는 이메일, 레벨, 닉네임, 사용자 ID가 차례로 보입니다. 이 가운데 바꿀 수 있는 것은 닉네임뿐입니다. 닉네임 줄 오른쪽의 연필 버튼을 누르면 닉네임 설정 창이 열리고, "닉네임 입력" 칸에 새 닉네임을 적어 저장을 누르면 "닉네임이 저장되었습니다" 알림이 뜹니다. 닉네임은 라운지에서 실명 대신 표시되며 2자부터 50자까지 영문, 숫자, 한글, 하이픈(-), 언더스코어(_)만 쓸 수 있습니다. 다른 사람이 쓰는 닉네임이면 "이미 사용 중인 닉네임입니다"가 보입니다.

워크스페이스 영역의 기본 워크스페이스에는 지금 내 기본 워크스페이스 이름이 보입니다. 이 칸은 흐리게 잠겨 있어 프로필 화면에서는 바꿀 수 없고, 기본 워크스페이스가 없으면 "없음"으로 보입니다. 바꿔야 하면 관리자에게 요청합니다. 개인 정보에는 이름, 연락처, 회사/기관, 부서, 직책이, 활동에는 가입일과 마지막 로그인이 보이며 둘 다 보기만 할 수 있습니다.

비밀번호는 보안 영역에서 바꿉니다. 비밀번호 변경 줄 오른쪽의 변경을 누르면 비밀번호 변경 창이 열립니다.

프로필 화면

번호메뉴기능이런 때 사용하세요
1닉네임 연필 버튼닉네임 설정 창을 엽니다. 닉네임은 라운지에서 실명 대신 표시되며 2자부터 50자까지 영문, 숫자, 한글, 하이픈(-), 언더스코어(_)만 쓸 수 있습니다.라운지에 글을 쓰기 전에

맨 위 계정 정보에는 이메일, 레벨, 닉네임, 사용자 ID가 보입니다.

그 아래 보안의 비밀번호 변경 줄 오른쪽 변경을 누르면 비밀번호 변경 창이 열리고, 맨 아래 활동에는 마지막 로그인과 가입일이 보입니다.

비밀번호 변경 창은 "현재 비밀번호를 확인한 후 새 비밀번호를 설정합니다." 안내와 함께 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 칸이 있습니다. 세 칸을 채우고 창 아래 비밀번호 변경을 누릅니다. 새 비밀번호가 현재 비밀번호와 같으면 "새 비밀번호가 현재 비밀번호와 동일합니다."가 보입니다. 바뀌면 "비밀번호가 성공적으로 변경되었습니다." 알림이 뜹니다. 회사가 통합 로그인(SSO)을 쓰는 환경에서는 이 영역이 보이지 않거나, 변경을 눌렀을 때 회사 비밀번호 변경 화면이 새 창으로 열릴 수 있습니다.

정리​

  • 에이전트별 실행 방식은 에이전트 편집 화면 설정 탭에서 정합니다. Recursion Limit은 1부터 1000까지(기본 500)이고 탭 맨 위 저장으로, Context Compaction은 비율 10부터 95%까지와 최근 메시지 2개부터 100개까지(처음 값 80%, 10개)이고 묶음 안의 저장으로 저장합니다. Recursion Limit은 작업이 중간에 멈추지 않게 하는 안전 한도입니다.
  • 내 계정 기준의 기억은 에셋 화면의 메모리 탭에서 켜고 메모리 편집 창에서 고칩니다.
  • 화면 모양과 언어는 환경설정에서 바꿉니다. 프로필에서는 계정 정보를 확인하고 닉네임과 비밀번호를 바꾸며, 기본 워크스페이스는 보기만 할 수 있습니다.
