Deep Agent Builder MCP와 에이전트의 MCP화

이 페이지는 에이전트에 MCP를 연결한 뒤 설정 저장, 도구 목록 확인, 실제 실행을 구분하는 방법을 설명합니다. 연결 정보가 저장됐거나 도구 이름이 보인다는 사실만으로 업무 실행이 끝난 것은 아닙니다. 권한, 외부 서버 연결, 실행 결과를 순서대로 확인해야 합니다.

MCP를 연결하면 무엇이 달라지는가​

MCP는 에이전트가 외부 도구를 사용할 수 있게 하는 연결 방식입니다. MCP 설정은 에이전트 이름과 지침과 별도로 관리되므로, 에이전트가 정상적으로 보이더라도 MCP가 꺼져 있거나 연결 정보가 비어 있으면 도구를 사용할 수 없습니다.

연결 정보에는 이름, 설명, 연결 대상과 인증 참조가 포함될 수 있습니다. 인증이 필요한 경우 실제 비밀값을 일반 설정이나 문서에 붙여 넣지 말고 제품이 안내하는 안전한 참조 방식을 사용하세요. 저장된 연결 정보와 이번 연결 확인에 필요한 인증 정보는 같은 것으로 취급하지 않습니다.

MCP를 연결한 뒤에는 다음 세 단계를 따로 확인합니다.

확인 대상확인할 내용여기까지 확인된 상태
설정 저장MCP가 켜져 있고 연결 정보가 저장됐는지에이전트 설정이 저장됨
도구 확인외부 서버에서 사용할 도구와 세부 도구를 찾았는지연결 가능한 도구 목록이 표시됨
실제 실행현재 에이전트가 입력을 받아 도구를 호출했는지입력에 대한 호출 결과 또는 오류가 표시됨

설정 저장이나 도구 목록 확인만으로 업무 실행이 성공했다고 판단하지 마세요.

연결 전에 확인할 것​

먼저 에이전트를 볼 수 있는 권한과 MCP 설정을 바꿀 수 있는 권한을 구분합니다. MCP 설정을 수정하려면 편집 권한이 필요하고, 도구를 실제로 사용하려면 에이전트의 실행 권한과 연결된 자원의 사용 권한도 필요합니다.

다음 순서로 연결 준비 상태를 확인합니다.

  1. 사용할 MCP 서버의 연결 방식과 연결 주소를 확인합니다.
  2. 필요한 헤더, 실행 환경 설정, 인증 참조를 준비합니다.
  3. 저장할 설정에 실제 비밀값이 남지 않는지 확인합니다.
  4. MCP 서버가 제공하는 도구와 세부 도구의 이름, 입력 형식을 확인합니다.
  5. 비식별 테스트 입력으로 도구 목록 확인과 실제 실행을 각각 시험합니다.

MCP-over-HTTP 개인 도구를 새로 등록한다면 도구 유형을 MCP HTTP로 지정하고 variant도 함께 확인해야 합니다. variant를 생략하면 등록 검증이 실패할 수 있습니다. 일반 HTTP 도구의 설정을 MCP 설정에 그대로 적용하지 마세요.

설정과 도구 목록을 확인하는 순서​

제품의 에이전트 설정 화면에서 MCP 활성화 상태와 연결 정보를 확인합니다. 실제 화면의 메뉴와 버튼을 확인하기 전에는 화면 라벨이나 성공 메시지를 문서만 보고 단정하지 마세요.

설정을 저장한 뒤 에이전트에 표시되는 도구 목록을 다시 확인합니다. 목록에 도구가 보이지 않으면 다음 순서로 원인을 좁힙니다.

  1. MCP 설정이 켜져 있는지 확인합니다.
  2. 연결 주소와 인증 참조가 현재 환경에서 유효한지 확인합니다.
  3. 도구 목록을 읽는 데 필요한 인증 정보가 준비됐는지 확인합니다.
  4. 외부 서버가 도구 목록을 반환하는지 확인합니다.
  5. 세부 도구 이름과 입력 형식이 에이전트에 전달됐는지 확인합니다.
  6. 에이전트에 해당 도구를 사용할 권한이 있는지 확인합니다.

도구 목록 확인에 실패하면 저장된 연결 정보와 이번 확인에 사용한 인증 정보를 혼동하지 마세요. 필요한 인증 정보가 없으면 외부 서버에 연결하기 전에 확인이 중단될 수 있습니다.

MCP 도구를 실행할 때의 경계​

실행에는 도구 입력뿐 아니라 현재 사용자, 실행 중인 에이전트와 대화의 문맥이 함께 필요합니다. 문맥이 맞지 않거나 실행 권한이 없으면 도구 호출이 시작되지 않을 수 있습니다. 도구 목록이 보이는지와 실제 실행이 가능한지는 별도로 확인하세요.

도구 응답이 오래 걸리면 정해진 시간 뒤 시간 초과로 끝날 수 있습니다. 연결 단계의 일시적인 오류는 다시 시도할 수 있지만, 이미 외부 서버에 도달했을 수 있는 요청이나 서버 오류를 무조건 다시 보내면 같은 작업이 중복될 수 있습니다. 재시도 전에 외부 작업이 실행됐는지 확인하세요.

실행 결과에는 에이전트가 읽을 수 있는 도구 결과가 포함될 수 있습니다. 외부 서버가 오류를 반환하거나 세부 도구를 찾지 못하거나 연결이 끊기면 실행 결과에 도구 오류가 표시될 수 있습니다. 도구 오류 하나만으로 전체 실행이 항상 즉시 끝났다고 판단하지 말고, 화면의 실행 상태와 결과 범위를 함께 확인하세요.

실패 원인별 다음 판단​

화면에서 본 상태먼저 확인할 것다음 판단
MCP 설정을 저장할 수 없음편집 권한, 연결 주소 형식, variant, 필수 인증 참조설정 검증을 통과시킨 뒤 도구 목록 확인을 다시 시도
설정은 저장됐지만 도구가 보이지 않음목록 확인에 필요한 인증 정보, 외부 서버의 도구 목록, 도구 유형설정 저장과 도구 목록 확인을 별도로 기록
도구는 보이지만 호출이 실패함도구 사용 권한, 세부 도구 이름, 입력 형식연결이 아니라 실행 입력과 권한을 점검
실행이 오래 걸리거나 시간 초과외부 서버 응답, 입력 범위, 현재 실행 상태같은 요청을 반복하기 전에 외부 작업의 중복 여부 확인
MCP 연결 또는 서비스 오류외부 서버 상태, 연결 정책, 실행 상태새 요청 전에 실패 범위와 재시도 가능성을 확인

오류 메시지에 연결 주소, 인증값, 고객 데이터가 포함돼 있다면 공개 문서나 캡처에 복사하지 않습니다. 로그와 화면을 공유할 때도 실제 값 대신 승인된 비식별 자료를 사용합니다.

완료 확인​

MCP 연결 작업은 다음 네 가지를 모두 확인했을 때 완료로 봅니다.

  1. MCP 설정이 의도한 에이전트에 저장돼 있습니다.
  2. 에이전트에 필요한 도구와 세부 도구가 표시됩니다.
  3. 테스트 입력으로 실제 호출 결과 또는 재현 가능한 오류가 확인됩니다.
  4. 설정 권한, 도구 사용 권한, 외부 서버 상태를 구분해 기록했습니다.

도구 목록이 보인다는 사실만으로 실제 업무 입력이 처리된 것은 아닙니다. 반대로 테스트 실행이 실패했다고 해서 설정 저장까지 실패했다고 단정하지 말고, 어느 단계에서 멈췄는지 분리해 확인하세요.
