MCP와 에이전트의 MCP화

MCP(Model Context Protocol)는 AI 도구와 에이전트가 서로를 부를 때 쓰는 공통 연결 방식입니다. Deep Agent Builder에서는 MCP를 두 방향으로 씁니다. 바깥의 MCP 서버를 도구로 등록해 에이전트가 쓰게 하는 방향과, 내가 만든 에이전트를 MCP 서버로 열어 MCP 호환 클라이언트에서 부르게 하는 방향입니다. 이 페이지는 브레인크루 AI혁신팀 김그루 사원의 사내 규정 Q&A 비서를 예로 두 방향을 모두 설명합니다.

이 페이지에서 할 수 있는 일

  • MCP가 쓰이는 두 방향을 구분합니다.
  • 에셋 화면 도구 탭의 도구 추가 메뉴에서 Dify, n8n, Connect MCP 서버를 도구로 등록하고 연결 테스트로 확인합니다.
  • 등록한 MCP 도구의 하위 도구(세부 도구)를 테스트로 시험하고, 에이전트 도구함에 붙입니다.
  • 에이전트 편집 화면 설정 탭에서 MCP 서버 활성화를 켜고 서버 이름과 설명을 정합니다.
  • 연결 JSON을 복사해 MCP 호환 클라이언트에 넣고, 필요 없으면 MCP 서버 비활성화로 닫습니다.

MCP가 쓰이는 두 방향​

방향하는 일설정하는 곳브레인크루 예
MCP 서버를 도구로 쓰기바깥 MCP 서버가 제공하는 기능을 에이전트가 도구처럼 부릅니다.에셋 화면의 도구 탭에서 도구 추가사내 규정 Q&A 비서가 사내 지식 검색 MCP(deep_connector_kb)로 규정 문서를 찾음, 팀이 n8n에 만든 일정 등록 워크플로우를 도구로 등록
에이전트를 MCP 서버로 열기내 에이전트를 다른 MCP 호환 클라이언트에서 부를 수 있게 엽니다.에이전트 편집 화면 설정 탭의 MCP 서버김그루 사원이 쓰는 MCP 호환 데스크톱 앱에서 사내 규정 Q&A 비서에게 바로 질문

MCP 서버를 도구로 등록하기​

사이드바의 에셋설정을 눌러 여는 에셋 화면의 도구 탭에서 도구 추가를 누르면 MCP 서버 종류별 항목이 보입니다.

메뉴넣는 값알아 둘 점
Dify MCP ServerDify MCP 서버 URLDify 워크플로우를 MCP로 연결합니다. URL은 /mcp로 끝나야 합니다.
n8n MCP Servern8n MCP 서버 URL, 인증 토큰n8n 워크플로우를 MCP로 연결합니다. 토큰은 환경변수로 추가(환경변수 이름만 적으면 서버에서 값을 불러옴) 또는 직접 입력 중에서 고릅니다.
Connect MCP ServerURL, TokenConnect MCP 서버를 연결합니다. Token에는 발급받은 토큰 값만 그대로 넣습니다. 앞에 다른 글자를 붙이지 않습니다.

종류를 고르면 새 도구 추가 창이 열립니다. 안내 문구는 "새 도구 설정을 생성합니다. 도구 유형에 따라 필요한 필드를 입력하세요."이고, 그 아래에 고른 종류(예: n8n MCP Server)가 보입니다. 아래 그림은 김그루 사원이 팀의 n8n 일정 등록 워크플로우를 braincrew_n8n_calendar라는 이름으로 등록하려고 값을 넣은 화면입니다.

도구 이름, 표시 이름, 설명을 넣은 새 도구 추가 창

번호메뉴기능이런 때 사용하세요
1도구 이름영문 소문자로 시작하고 소문자, 숫자, 밑줄(_)만 씁니다. 만든 뒤에는 바꿀 수 없습니다.에이전트가 부를 도구 이름을 정할 때
2표시 이름목록과 상세에 보일 이름입니다. 한글과 공백을 쓸 수 있고, 비우면 도구 이름이 보입니다(선택).사람이 읽기 쉬운 이름을 붙일 때
3설명이 도구가 하는 일을 적습니다.에이전트와 팀원이 도구 쓰임을 알게 할 때

같은 창 아래쪽에서 연결 값을 넣고 확인합니다. 그림의 서버 주소는 가렸습니다.

URL과 인증 토큰을 넣고 연결 테스트를 누른 새 도구 추가 창

번호메뉴기능이런 때 사용하세요
1URLn8n MCP 서버 URL을 넣습니다.연결할 서버 주소를 넣을 때
2인증 토큰오른쪽 위 글자를 눌러 환경변수로 추가와 직접 입력을 오갑니다. 환경변수로 넣을 때는 환경변수 이름만 적고, 직접 넣을 때는 토큰 값을 적습니다.토큰을 화면에 남기지 않고 관리할 때
3연결 테스트넣은 값으로 서버에 연결해 봅니다. 결과는 창 안에 보입니다.생성 전에 주소와 토큰이 맞는지 확인할 때
4생성도구를 만듭니다.연결을 확인했을 때

이럴 때 쓰세요: 팀 동료가 n8n에 일정 등록 워크플로우를 만들었다고 알려 오면, 김그루 사원은 URL을 받아 n8n MCP Server로 등록하고 토큰은 환경변수로 추가를 골라 이름만 적습니다. 생성 전에 연결 테스트로 주소와 토큰을 확인해 두면, 나중에 회의록 요약 도우미에 붙였을 때 일정이 안 들어가는 원인이 연결인지 지침인지 가리기 쉬워집니다. 연결이 확인된 도구는 회의록의 액션 아이템 기한을 팀 일정으로 옮기는 데 씁니다.

연결 테스트에 실패하면 버튼 위에 빨간 상자로 오류와 걸린 시간이 보입니다. 위 그림처럼 서버 주소에 닿지 못하면 "fetch failed"가 보입니다. 이때는 URL과 인증 값을 다시 확인합니다.

하위 도구 확인과 테스트​

MCP 서버 하나에는 여러 기능(하위 도구)이 들어 있습니다. 도구 탭 목록에서 MCP 도구를 누르면 오른쪽 상세에 설명과 세부 도구 (sub-tools) 표(이름, 설명)가 보이고, 위쪽에 테스트, 기본값 설정, 수정, 삭제 버튼이 있습니다. 하위 도구 정보가 아직 없는 MCP 도구는 테스트 창에서 서브 도구 조회를 눌러 하위 도구를 먼저 가져옵니다.

테스트를 누르면 "도구 테스트 - 도구 이름" 창이 열립니다. 위쪽 **타임아웃 (초)**에서 요청 제한 시간(1~60초, 기본값 10초)을 정합니다. 아래 그림은 사내 규정 Q&A 비서가 쓰는 deep_connector_kb 도구의 테스트 창입니다.

세부 도구 선택, 파라미터 칸, 자동채우기, 테스트 실행

번호메뉴기능이런 때 사용하세요
1세부 도구 (sub-tool)시험할 하위 도구를 고릅니다. 고르면 아래에 그 하위 도구의 설명이 보입니다.여러 하위 도구 중 하나를 시험할 때
2파라미터 칸고른 하위 도구가 받는 값이 이름과 형식([string], [integer] 등)과 함께 나옵니다. 넘길 값을 적습니다. 받는 값이 없으면 "이 도구는 파라미터가 없습니다"가 보입니다.시험할 값을 직접 넣을 때
3자동채우기AI 자동채우기에서 모델을 고르고 누르면 파라미터 값을 채웁니다. 아래 다른 값으로 채우기로 다른 값을 받습니다.어떤 값을 넣을지 모를 때
4테스트 실행고른 하위 도구를 실제로 부릅니다. 결과는 버튼 아래에 보입니다.도구가 실제로 동작하는지 확인할 때

이럴 때 쓰세요: 사내 규정 Q&A 비서가 규정 문서를 못 찾는다는 문의가 오면, 김그루 사원은 지침을 고치기 전에 deep_connector_kb 테스트 창에서 search_documents를 골라 같은 검색어로 테스트 실행을 해 봅니다. 여기서 문서가 나오면 도구는 정상이므로 지침의 검색 원칙을 손보고, 여기서도 실패하면 토큰이나 컬렉션 문제로 보고 Deep Connector 담당자에게 문의합니다. 원인이 도구와 지침 중 어디인지 먼저 가르면 같은 질문으로 대화를 여러 번 다시 돌리지 않아도 됩니다.

테스트 실행에 실패하면 버튼 아래에 실패, 걸린 시간, 오류 내용(예: "오류: fetch failed")이 보입니다. 하위 도구 정보가 보인다고 실제 호출이 성공하는 것은 아니므로, 하나라도 테스트 실행까지 해 봅니다.

등록한 MCP 도구는 일반 도구와 같이 에이전트 편집 화면 도구함의 + 도구로 붙입니다. 붙인 뒤 도구 설정 창의 서브 도구에서 하위 도구별 값을 에이전트마다 다르게 정할 수 있습니다. 자세한 과정은 도구와 스킬 구성에 있습니다.

에이전트를 MCP 서버로 열기​

에이전트 편집 화면 오른쪽 설정 탭에서 Recursion Limit 아래에 MCP 서버 묶음이 있습니다. 안내 문구는 "MCP 서버를 활성화하면 Claude Desktop, Cursor 등 MCP 호환 클라이언트에서 이 에이전트를 사용할 수 있습니다."입니다.

설정 탭 MCP 서버 묶음에서 스위치를 켜고 서버 이름과 설명을 넣은 모습

번호메뉴기능이런 때 사용하세요
1MCP 서버 활성화 스위치켜면 서버 이름과 설명 칸이 나타납니다. 스위치만 켜서는 열리지 않습니다.MCP 서버로 열 준비를 할 때
2서버 이름클라이언트에 보일 이름입니다. 영문, 숫자, _, -, . 만 쓸 수 있고 128자까지 적습니다.클라이언트에서 알아보기 쉬운 이름을 정할 때
3설명이 서버가 무엇을 하는지 적습니다.클라이언트 사용자에게 쓰임을 알릴 때
4MCP 서버 활성화 버튼눌러야 실제로 열립니다. 이미 열려 있으면 MCP 설정 업데이트로 바뀝니다.입력을 마치고 서버를 열 때

MCP 서버 묶음은 설정 탭에서 Recursion Limit 아래에 있습니다. 스위치를 켜면 서버 이름에 에이전트 이름이 먼저 들어갑니다. 사내 규정 Q&A 비서처럼 이름에 한글이나 공백이 있으면 "MCP 이름은 영문, 숫자, _, -, . 만 사용할 수 있고, 점(.)만으로는 만들 수 없습니다. 저장하려면 바꿔주세요."가 보이므로 braincrew-policy-qa처럼 바꿉니다. 이 묶음의 설정은 헤더 저장이 아니라 이 버튼으로 반영되고, 누르면 "MCP 설정이 저장되었습니다" 알림이 뜹니다.

연결 JSON 복사​

MCP 서버가 열리면 같은 묶음 아래에 연결 JSON이 나타납니다. MCP 호환 클라이언트의 MCP 서버 설정에 이 JSON을 넣으면 클라이언트가 이 에이전트를 부를 수 있습니다.

MCP 서버를 연 뒤 나타난 연결 JSON, 서버 주소는 가림

번호메뉴기능이런 때 사용하세요
1연결 JSON클라이언트에 넣을 설정입니다. MCP 서버가 열린 뒤에만 보입니다.클라이언트 설정을 준비할 때
2복사누르면 버튼이 잠시 **복사됨!**으로 바뀌고 "연결 JSON이 클립보드에 복사되었습니다" 알림이 뜹니다.JSON을 클라이언트에 붙여 넣을 때
3JSON 내용mcpServers 아래에 서버 이름(braincrew-policy-qa), 서버 주소(url), 연결 방식(transport)이 들어 있습니다.어떤 서버로 연결되는지 확인할 때
4API 키 안내API 키 자리 표시(YOUR_API_KEY)를 토큰 페이지의 API 키로 교체하라는 안내가 보입니다.클라이언트에 인증 값을 넣을 때

이럴 때 쓰세요: 김그루 사원은 하루 대부분을 MCP 호환 데스크톱 앱에서 문서 작업을 하므로, 사내 규정 Q&A 비서를 MCP 서버로 열어 두고 그 앱에서 바로 출장비나 취업규칙을 묻습니다. 연결 JSON을 붙여 넣은 뒤 API 키 자리를 내 키로 바꾸고, 출장비 질문 하나로 답이 오는지 확인합니다. 팀원이 같은 방식으로 쓰고 싶어 하면 JSON만 넘기고 키는 각자 발급받게 해, 키를 넣은 설정이 돌아다니지 않게 합니다.

클라이언트에서 이 에이전트를 부를 때는 API 키가 필요합니다. 키는 에셋 화면의 API 키 탭에서 발급하며, 발급 방법은 코드 스니펫과 외부 API에서 설명합니다. 키를 넣는 자리와 방법은 클라이언트 제품의 안내를 따릅니다. 키를 넣은 설정은 다른 사람에게 그대로 보내지 마세요.

MCP 서버 닫기​

더 이상 외부 클라이언트에서 쓰지 않으면 MCP 서버 활성화 스위치를 끕니다. 그러면 빨간 MCP 서버 비활성화 버튼이 나타나고, 눌러야 실제로 닫힙니다. 닫히면 "MCP 서버가 비활성화되었습니다" 알림이 뜨고 연결 JSON이 사라집니다.

따라 해 보기: 사내 규정 Q&A 비서를 MCP 서버로 열기​

  1. 사이드바에서 사내 규정 Q&A 비서를 누르고 에이전트 설정을 누릅니다.

  2. 오른쪽 설정 탭을 누르고 MCP 서버 묶음으로 스크롤합니다.

  3. MCP 서버 활성화 스위치를 켭니다.

  4. 서버 이름을 braincrew-policy-qa로 바꾸고, 설명에 "브레인크루 사내 규정 Q&A"를 입력합니다.

  5. MCP 서버 활성화 버튼을 누르고 "MCP 설정이 저장되었습니다" 알림을 확인합니다.

  6. 연결 JSON의 복사를 눌러 MCP 호환 클라이언트의 MCP 서버 설정에 붙여 넣고, 클라이언트 안내에 따라 내 API 키를 넣습니다.

  7. 클라이언트에서 아래 프롬프트로 질문해 답이 오는지 확인합니다.

    프롬프트: 브레인크루 출장비 규정에서 국내 출장 일비는 하루 얼마인가요?

열기 전에 확인할 것​

  • MCP 서버로 연 에이전트는 키를 가진 사람이면 클라이언트에서 부를 수 있습니다. 키는 필요한 사람에게만 발급하고, 쓰지 않는 키는 API 키 탭에서 지웁니다.
  • 에이전트가 쓰는 지식과 도구가 그대로 쓰이므로, 바깥에 알려도 되는 범위의 에이전트인지 먼저 확인합니다.
  • 서버 이름을 바꾼 뒤에는 MCP 설정 업데이트를 누르고, 클라이언트 쪽 설정도 새 JSON으로 바꿉니다.
  • 클라이언트 쪽 설정 방법은 각 클라이언트 제품의 안내를 따릅니다. 이 매뉴얼에서는 다루지 않습니다.
