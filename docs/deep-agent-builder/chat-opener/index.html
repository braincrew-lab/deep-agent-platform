Deep Agent Builder 챗 오프너

챗 오프너는 에이전트 대화를 시작할 때 사용자가 무엇을 요청할지 판단하도록 돕는 시작 문구입니다. 에이전트의 지침이나 모델을 대신하지 않으므로, 오프너를 바꾼 뒤에는 실제 요청을 보내 에이전트의 동작도 따로 확인해야 합니다.

챗 오프너의 역할​

챗 오프너는 에이전트 설정에 포함되는 시작 메시지 목록입니다. 에이전트 정의에는 이름, 설명, 지침, 모델과 연결 자원뿐 아니라 챗 오프너도 함께 보관될 수 있습니다. 에이전트를 내보내기 전에 오프너 메시지는 미리보기에서 확인할 수 있고, 정의 파일에는 선택 항목으로 기록됩니다.

오프너와 지침의 역할은 다릅니다.

구성담당하는 일바꾼 뒤 확인할 것
챗 오프너사용자가 시작할 요청의 방향을 고르는 데 도움문구가 실제 업무를 정확히 안내하는지
지침여러 대화에서 반복 적용할 역할과 응답 기준 정의실제 응답이 기준을 지키는지
개별 요청현재 스레드에서 처리할 구체적인 업무 전달요청의 범위와 결과

오프너 문구만 바꿔도 에이전트의 역할, 연결 자원, 모델이 자동으로 바뀌지는 않습니다. 반대로 지침이나 연결 자원을 바꿨다면 오프너가 여전히 그 구성을 정확히 안내하는지 다시 확인해야 합니다.

오프너를 설계하는 기준​

오프너는 에이전트의 실제 업무를 짧게 드러내야 합니다. 다음 기준을 적용합니다.

  • 한 문구에서 요청할 수 있는 결과가 무엇인지 알 수 있어야 합니다.
  • 에이전트가 처리할 수 없는 범위를 약속하지 않아야 합니다.
  • 입력 자료, 출력 형식 또는 필요한 조건이 있다면 문구에 드러냅니다.
  • 비슷한 오프너는 합치고, 서로 다른 업무는 나눕니다.
  • 연결된 도구나 스킬이 필요한 요청은 해당 자원이 없을 때도 실행된다고 표현하지 않습니다.

오프너에 긴 업무 지침을 넣지 마세요. 반복 규칙과 제한 조건은 지침에 두고, 오프너에는 사용자가 선택할 작업과 기대 결과를 남깁니다. 고객 자료, 비밀값, 실제 계정 정보와 같은 데이터를 예시 문구에 넣지 않고 비식별 테스트 입력을 사용합니다.

오프너를 바꾸기 전 확인할 것​

먼저 에이전트의 수정 권한과 현재 설정을 확인합니다. 챗 오프너는 에이전트 수정 대상에 포함되며, 저장 권한과 에이전트를 실행할 권한은 별개일 수 있습니다. 수정 화면에 들어갈 수 있다는 사실만으로 오프너 저장과 실행까지 모두 허용된다고 판단하지 않습니다.

다음도 함께 확인합니다.

  • 어떤 에이전트의 오프너를 바꾸는지
  • 현재 오프너와 지침이 서로 모순되지 않는지
  • 오프너가 안내하는 모델, 도구, 스킬과 서브에이전트가 실제 연결되어 있는지
  • 변경을 시험할 비식별 입력과 결과 판정 기준이 준비됐는지

오프너를 수정하고 확인하는 순서​

  1. 제품에서 제공하는 에이전트 수정 경로로 대상 에이전트를 엽니다. 실제 화면의 메뉴와 버튼 이름은 제품 버전에 따라 다를 수 있으므로 표시된 문구를 확인합니다.
  2. 현재 오프너와 이름, 설명, 지침, 모델, 연결 자원을 함께 읽습니다. 오프너만 보고 현재 실행 구성을 추정하지 않습니다.
  3. 바꿀 오프너 문구만 수정합니다. 다른 설정을 함께 바꿨다면 어떤 변경이 결과에 영향을 줬는지 구분할 수 있도록 기록합니다.
  4. 오프너 변경을 저장합니다. 이름, 지침 또는 설정 카드의 저장 동작이 분리되어 있을 수 있으므로 한 항목을 저장했다고 모든 변경이 저장됐다고 보지 않습니다.
  5. 수정 경로를 다시 열어 문구가 유지되는지 확인합니다. 목록에 새 문구가 보이는 것만으로 저장된 내용을 모두 확인했다고 판단하지 않습니다.
  6. 오프너가 제안한 요청을 하나 선택해 실제 실행합니다. 실행 권한과 요청에 필요한 리소스 사용 권한이 있는지 확인합니다.
  7. 답변의 내용과 상태를 오프너가 약속한 범위와 비교합니다. 지침, 모델, 연결 자원 중 무엇이 결과에 영향을 줬는지도 함께 기록합니다.

오프너가 제공되지 않거나 실행이 시작되지 않으면 문구를 계속 바꾸지 말고 수정 권한, 에이전트의 상태, 실행 권한과 연결 자원의 사용 가능 여부를 차례로 확인합니다.

오프너와 내보내기·가져오기​

에이전트 정의에는 챗 오프너 파일이 선택 항목으로 포함될 수 있습니다. 내보내기 미리보기에서는 오프너 메시지와 함께 첨부파일, 비밀 키, 차단 사유를 확인할 수 있습니다. 미리보기가 가능하다고 해서 실제 내보내기까지 가능한 것은 아닙니다. 내보내기 시 차단 사유를 다시 검사하며, 순환 참조나 정의 파일 누락이 남아 있으면 내보내기가 거부될 수 있습니다.

가져온 에이전트는 원본과 다른 식별자로 새로 만들어집니다. 오프너가 포함된 파일을 가져왔다고 해서 원본 에이전트의 오프너가 바뀌거나, 가져온 에이전트의 연결 자원과 권한이 원본과 같아지는 것은 아닙니다. 가져온 뒤에는 새 에이전트의 오프너, 지침, 모델, 연결 자원을 별도로 확인합니다.

첨부파일의 실제 내용이나 비밀값은 에이전트 정의와 같은 방식으로 이동하지 않을 수 있습니다. 오프너 문구에 첨부가 있다고 적혀 있어도 첨부가 내보내기·가져오기 결과에 포함됐다고 추정하지 말고, 미리보기와 결과 요약에서 제외 여부를 확인합니다.

대표적인 문제와 다음 판단​

증상먼저 확인할 것다음 행동
오프너를 저장할 수 없음에이전트 수정 권한과 변경 대상실행 권한을 확대하기보다 수정 권한과 입력 조건을 확인
저장했지만 문구가 돌아감다시 연 수정 화면의 오프너와 실제 저장 범위오프너 저장과 다른 설정 저장이 분리됐는지 확인
오프너와 실제 답변이 다름지침, 모델, 연결 자원, 개별 요청오프너 문구보다 실제 구성을 먼저 비교
오프너가 안내한 작업이 실행되지 않음실행 권한과 필요한 리소스의 사용 가능 여부연결 목록 표시와 실행 가능 상태를 분리해 확인
내보내기에서 차단됨미리보기의 차단 코드와 정의 파일 상태순환 참조나 누락된 정의를 해결한 뒤 다시 미리보기
가져온 뒤 결과가 달라짐새 에이전트의 식별자, 모델, 지침, 연결 자원원본과 가져온 에이전트를 각각 조회하고 권한을 비교

오프너를 수정한 뒤 결과가 달라졌다면 먼저 오프너 자체가 아니라 실제로 저장된 지침, 모델, 연결 자원과 현재 스레드의 입력을 비교합니다. 한 번의 실행 결과만으로 오프너가 모든 업무 결과를 보장한다고 판단하지 않습니다.

완료 기준​

다음 조건을 확인하면 오프너 변경을 완료한 것으로 기록합니다.

  • 대상 에이전트와 수정 권한을 확인했습니다.
  • 수정 경로를 다시 열었을 때 오프너 변경이 유지됩니다.
  • 오프너가 안내하는 요청을 비식별 입력으로 실행했습니다.
  • 실제 답변과 실행 상태를 지침, 모델, 연결 자원과 함께 비교했습니다.
  • 내보내기 또는 가져오기를 했다면 새 에이전트의 오프너와 권한을 원본과 따로 확인했습니다.
