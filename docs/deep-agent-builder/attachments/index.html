Deep Agent Builder 첨부파일 지원

첨부파일은 에이전트 생성, Thread 대화, 커뮤니티 게시물에서 각각 다른 방식으로 사용됩니다. 이 페이지는 파일을 어디에 추가할 수 있는지와 저장·실행·삭제 결과를 화면에서 어떻게 구분할지 설명합니다. 파일이 목록에 보인다는 사실만으로 에이전트가 파일을 읽었거나 답변에 반영했다고 판단하지 마세요.

시작하기 전에 확인할 것​

다음 조건을 먼저 확인합니다.

  • 에이전트와 Thread 또는 게시물을 조회하고 수정할 권한이 있습니다.
  • 고객 자료가 아닌 승인된 비식별 테스트 파일을 사용합니다.
  • 파일 형식과 크기를 확인할 수 있습니다.
  • 파일을 삭제하거나 다시 올리기 전에 원본과 실행 결과를 보존해야 하는지 확인했습니다.

파일을 올리는 권한과 파일을 실행 입력으로 사용하는 권한은 다를 수 있습니다. 화면에 파일이 표시되더라도 실행 입력과 결과에서 실제 사용 여부를 따로 확인합니다.

첨부파일이 사용되는 세 가지 경로​

경로파일의 역할완료 전에 확인할 결과
에이전트 생성생성 요청 또는 후속 입력에 참고 자료로 추가생성 화면이나 세션 상세에 파일이 연결되고, 실행 결과와의 관계가 확인됨
Thread와 메시지현재 대화의 실행 입력파일이 메시지에 연결되고, 실행 결과에서 입력으로 사용됐는지 확인됨
커뮤니티 게시물게시물에 연결된 이미지 또는 파일게시물 연결, 조회 권한, 삭제 결과가 확인됨

에이전트 생성에 추가하는 파일은 PNG, JPEG, GIF, WebP 이미지여야 하며 한 번에 최대 10개까지 올릴 수 있습니다. 파일 하나의 크기와 전체 합산 크기는 운영 환경의 설정을 따르므로 고정된 숫자로 판단하지 마세요.

커뮤니티 첨부는 한 번에 하나를 올리는 경우와 여러 개를 묶어 올리는 경우의 결과를 구분합니다. 여러 파일을 올릴 때 일부가 실패하면 같은 요청에서 이미 만들어진 항목도 정리될 수 있습니다.

생성 화면에 이미지 첨부하기​

1. 테스트 입력과 파일을 준비합니다​

이미지에서 확인할 질문을 하나 정합니다. 파일 이름, 파일 형식, 실제 내용이 서로 맞는 비식별 테스트 이미지를 사용합니다. 이미지가 아닌 파일을 생성 화면의 이미지 첨부에 보내지 마세요.

2. 생성 요청 또는 후속 입력에 파일을 추가합니다​

생성 화면에서 이미지를 추가한 뒤 파일 이름과 형식이 표시되는지 확인합니다. 후속 입력에 파일을 다시 추가하는 경우에는 질문이나 지시도 함께 입력합니다. 이미지만 보내고 필요한 응답 내용을 빠뜨리면 요청이 거절될 수 있습니다.

요청이 성공하면 세션 상세에서 첨부된 파일의 이름, 형식, 크기와 조회 권한 상태를 확인합니다. 파일을 열 수 있는 주소가 표시되더라도 공개 링크처럼 공유하지 마세요.

3. 저장 결과와 실행 결과를 따로 확인합니다​

먼저 세션 상세에 파일이 남아 있는지 확인합니다. 그다음 이미지가 실제 생성 흐름의 입력으로 사용됐는지 실행 상태와 결과를 대조합니다. 파일이 저장됐다는 응답만으로 이미지 해석이 성공했다고 기록하지 마세요.

파일을 열 수 없으면 현재 사용자와 생성 세션이 파일의 소유 범위에 포함되는지 확인합니다. 세션이 아직 처리 중이거나 파일이 삭제·폐기·만료된 상태라면 조회되지 않을 수 있습니다. 다른 사용자의 파일로 바꾸지 말고 권한과 세션 상태를 다시 확인합니다.

Thread 입력과 결과를 구분합니다​

Thread에 넣은 파일은 해당 메시지의 입력 첨부입니다. 실행 결과로 만들어진 파일이나 답변에 다시 표시된 파일과 같은 자원으로 취급하지 마세요.

  1. Thread의 메시지에 파일이 연결돼 있는지 확인합니다.
  2. 파일 상태와 실행 입력 목록을 확인합니다.
  3. 실행 기록에서 그 파일이 사용됐는지 대조합니다.
  4. 답변, 결과 파일, 원본 첨부를 각각 구분해 기록합니다.
  5. 보존하거나 삭제할 범위를 결정합니다.

파일이 메시지에 붙어 있다는 표시만 있고 실행 입력에 나타나지 않으면 사용됐다고 단정하지 않습니다. 자세한 Thread 상태, 실행 결과, 삭제 범위는 Thread와 첨부파일 보관에서 확인합니다.

커뮤니티 게시물의 첨부를 관리합니다​

게시물 작성 화면에서 파일을 올린 뒤 업로드 결과에 파일 이름, 크기, 형식과 상태가 표시되는지 확인합니다. 게시물에 연결된 첨부인지도 함께 확인합니다.

예약 게시물이나 아직 공개되지 않은 게시물의 첨부는 작성자 또는 게시물 관리 권한이 있는 사용자만 조회할 수 있습니다. 파일을 볼 수 없다면 로그인 상태, 게시물의 공개 상태, 현재 계정의 관리 권한을 확인합니다.

파일을 내려받는 동작과 게시물 안에서 이미지를 바로 보는 동작은 결과가 다를 수 있습니다. 화면이 제공하는 동작 이름을 확인하고, 하나의 동작이 다른 동작까지 보장한다고 해석하지 마세요.

삭제하기 전에는 원본과 게시물 연결을 보존해야 하는지 확인합니다. 삭제 뒤에도 파일이 잠시 보이면 삭제 상태, 게시물에 남은 연결, 캐시를 나눠 확인합니다. 삭제 표시가 보인다는 사실만으로 모든 저장소와 게시물 본문에서 즉시 사라졌다고 단정하지 마세요.

결과를 판정하는 기준​

첨부파일 작업은 다음 항목을 모두 확인했을 때 완료로 기록합니다.

  • 파일을 추가한 경로가 생성, Thread, 커뮤니티 게시물 중 어디인지 확인했습니다.
  • 업로드 결과에서 파일 이름, 크기, 형식과 상태를 확인했습니다.
  • 생성에서는 파일 연결 상태와 실제 실행 입력 사용 여부를 구분했습니다.
  • Thread에서는 원본 첨부, 실행 입력, 답변과 결과 파일을 구분했습니다.
  • 커뮤니티에서는 게시물 연결, 조회 방식, 삭제 주체와 삭제 상태를 확인했습니다.
  • 비식별 테스트 파일만 사용했고 파일 조회 주소, 고객 자료와 비밀값을 공개하지 않았습니다.

대표적인 실패와 다음 판단​

이미지 첨부가 거절됨​

파일 형식, 실제 파일 내용, 첨부 개수와 운영 환경의 크기 제한을 먼저 확인합니다. 지원 형식과 크기 조건을 확인한 뒤 테스트 파일을 줄여 다시 준비합니다.

이미지 없이 질문만 처리됨​

세션의 첨부 목록, 메시지 입력과 실행 입력을 대조합니다. 파일 저장과 실제 사용을 분리해 기록하고 실행 근거를 다시 조회합니다.

파일을 열 수 없음​

현재 사용자, 세션 또는 게시물의 소유 범위와 상태를 확인합니다. 권한이 없는 파일로 바꾸지 말고 관리자에게 조회 권한과 공개 상태를 확인해 달라고 요청합니다.

여러 파일을 올리던 중 일부가 실패함​

오류 결과와 같은 요청에서 만들어진 항목의 정리 결과를 함께 확인합니다. 일부 성공으로 기록하지 말고 해당 요청의 전체 상태를 다시 조회합니다.

삭제 뒤 파일이 계속 보임​

삭제 상태, 게시물 본문 연결, 캐시 또는 별도 저장 위치를 나눠 확인합니다. 삭제 표시와 게시물 연결을 대조하고 전체 삭제를 단정하지 않습니다.

가져온 에이전트에 첨부가 없음​

내보내기 미리보기와 가져오기 결과에서 첨부 제외 상태를 확인합니다. 첨부파일 자체는 에이전트 정의와 함께 옮겨지지 않을 수 있으므로 원본 파일을 별도로 준비합니다.

파일 형식이나 권한 오류를 피하려고 관리자 권한을 임의로 부여하지 마세요. 오류 내용, 파일 상태와 사용한 비식별 입력을 승인된 지원 경로에 전달합니다.
