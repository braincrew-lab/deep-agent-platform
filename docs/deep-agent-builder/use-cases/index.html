Deep Agent Builder 활용 사례

사례의 목표​

이 사례는 정보가 빠진 요청을 받았을 때 질문으로 되돌아가는 안내 도우미를 만드는 연습입니다. 실제 고객의 사용 사례나 성과를 설명하지 않으며, 제작 화면과 대화 화면을 익히는 데 목적이 있습니다.

평가 기준은 세 가지입니다.

  • 입력에 포함된 사실을 유지하는가
  • 요청한 형식을 지키는가
  • 정보가 없을 때 추측하지 않고 확인하는가

시작하기에서 만든 도우미를 그대로 사용합니다. 지침을 확인하거나 수정하려면 대화 화면에서 수정 화면으로 이동하세요.

도우미 지침 작성​

수정 화면의 지침에 다음 내용을 입력하고 저장합니다.

사용자가 제공한 모임 정보만으로 안내문 초안을 작성합니다. 시간, 장소, 준비물을 유지합니다. 제목 한 줄과 본문 세 문장을 사용합니다. 필요한 정보가 빠져 있으면 추측하지 말고 빠진 항목을 질문합니다.

이 지침은 고정할 업무 규칙과 매번 바뀌는 입력 자료를 나누는 예입니다. 시간과 장소처럼 요청마다 달라지는 값은 대화 입력에 넣고, 사실을 유지하고 누락 정보를 묻는 방식은 지침에 둡니다.

입력을 분리해 시험하기​

1. 정보가 모두 있는 요청​

다음 요청을 보냅니다.

가상의 독서 모임 안내를 작성해 주세요. 시간은 금요일 오후 3시입니다. 장소는 작은 회의실입니다. 각자 읽고 싶은 책 제목 하나를 준비합니다.

결과에 금요일 오후 3시, 작은 회의실, 책 제목 하나가 모두 들어가는지 확인합니다. 제목 한 줄과 본문 세 문장이라는 형식도 함께 확인합니다.

2. 정보가 빠진 요청​

첫 번째 모임의 정보를 이어서 사용하지 않도록, 별도의 가상 업무라는 점을 명시하고 다음 요청을 보냅니다.

앞의 모임과 다른 가상 모임입니다. 이번 안내에는 아래 정보만 사용해 주세요. 시간은 토요일 오전 10시입니다. 장소와 준비물은 아직 정하지 않았습니다. 안내문을 작성해 주세요.

결과가 토요일 오전 10시를 유지하는지 확인합니다. 장소로 작은 회의실을 다시 쓰거나 준비물을 임의로 정하지 않고, 필요한 정보를 묻거나 미정 상태를 분명히 밝혀야 합니다.

3. 누락 정보 보완​

도우미가 장소와 준비물을 물으면 다음과 같이 답합니다.

장소는 큰 회의실, 준비물은 필기도구입니다.

최종 초안에 토요일 오전 10시, 큰 회의실, 필기도구가 함께 남는지 확인합니다. 질문을 반복하거나 첫 번째 요청의 값을 되살리면 지침이나 입력 분리를 다시 점검합니다.

결과 판정​

상황기대하는 결과수정이 필요한 결과
정보가 모두 있음제공된 시간, 장소, 준비물을 안내문에 포함합니다.시간을 바꾸거나 장소 또는 준비물을 빠뜨립니다.
장소와 준비물이 미정필요한 정보를 묻거나 미정임을 명확히 드러냅니다.앞선 모임의 장소나 준비물을 그대로 넣습니다.
후속 정보를 제공함새로 받은 장소와 준비물을 사용합니다.질문만 반복하거나 이전 값을 유지합니다.

질문이나 답변의 정확한 문구는 모델에 따라 달라질 수 있습니다. 문구를 그대로 비교하기보다 사실 유지, 누락 정보 처리, 형식 준수 여부를 기준으로 판정합니다.

실패했을 때 수정하기​

답변이 지침과 다르면 지침을 한 번에 크게 바꾸지 말고, 어느 조건을 지키지 않았는지 먼저 기록합니다. 예를 들어 장소가 미정인데 임의의 장소를 넣었다면 “장소가 미정이면 먼저 질문합니다”처럼 검토할 수 있는 조건을 추가합니다.

수정한 뒤에는 같은 요청을 다시 보내고, 정보가 있는 요청과 빠진 요청을 모두 비교합니다. 지침을 저장한 뒤에도 변경이 반영되지 않으면 문제 해결에서 저장 상태와 답변 입력 경로를 확인합니다.

실제 업무에 적용하기​

실제 안내 업무에서는 독자가 행동하는 데 필요한 항목을 먼저 정합니다. 행사 안내라면 시간과 장소, 제출 안내라면 제출 대상과 기한이 기준이 될 수 있습니다.

조직 규정이나 최신 정보를 도우미가 자동으로 알고 있다고 가정하지 않습니다. 필요한 자료를 입력으로 제공하고, 확인된 범위 안에서 결과를 사용합니다. 같은 도우미로 다른 형식을 시험하려면 반복 업무의 복제 절차를 사용하세요.
