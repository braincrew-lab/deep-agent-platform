Deep Agent Builder 첫 에이전트 설계하기

첫 에이전트는 기능을 많이 붙이는 것보다 맡길 업무와 결과 기준을 먼저 고정하는 편이 안전합니다. 이 페이지에서는 외부 도구 없이 안내문을 작성하는 작은 업무를 기준으로 목적, 지침, 모델, 리소스를 정하고 첫 결과를 검토합니다.

시작 전에 정할 것​

에이전트를 만들기 전에 다음 네 가지를 한 문장씩 적습니다.

항목정할 내용예시
업무에이전트가 처리할 한 가지 업무모임 안내문 작성
입력사용자가 제공할 정보시간, 장소, 준비물
결과답변의 형식과 길이제목 한 줄과 본문 세 문장
제한추측하지 말아야 할 것빠진 정보는 확인 필요로 표시

처음에는 파일이나 외부 도구를 연결하지 않습니다. 입력과 결과를 눈으로 비교할 수 있어야 생성 성공과 답변 품질을 따로 판단할 수 있습니다. 에이전트 생성 권한과 사용할 모델이 준비되어 있는지도 확인합니다.

목적과 지침을 분리하기​

새 에이전트 화면에서 목적을 설명해 자연어 생성 세션을 시작할 수 있습니다. 목적 설명은 생성 세션의 초기 입력이며, 입력만으로 설정이 모두 끝나거나 다음 단계가 자동으로 생략되지는 않습니다.

다음처럼 업무 목적과 답변 규칙을 함께 적되, 두 내용을 구분해 씁니다.

가상 모임 안내문을 작성하는 도우미를 만들어 주세요. 사용자가 준 시간, 장소, 준비물을 유지하고 제목 한 줄과 본문 세 문장으로 작성해 주세요. 정보가 빠지면 추측하지 말고 확인이 필요하다고 알려 주세요. 외부 자료는 사용하지 않습니다.

목적을 보낸 뒤 생성 세션에서 이름, 설명, 지침과 모델을 확인합니다. 자연어 생성 세션에서 선택한 도구, 미들웨어, 스킬, 서브에이전트, 지침과 모델은 각각 설정 항목으로 저장되므로, 연결할 필요가 없는 리소스는 선택하지 않은 상태로 둡니다.

최소 구성으로 만들기​

  1. 에이전트 생성 화면에서 업무 목적을 입력하고 생성 세션을 시작합니다.
  2. 이름과 설명을 업무 범위에 맞게 정합니다. 이름은 목록에서 구별할 수 있게 쓰고, 설명에는 누구의 어떤 입력을 처리하는지 적습니다.
  3. 지침에 입력 보존 규칙, 출력 형식, 정보가 부족할 때의 처리 방법을 적습니다.
  4. 모델을 선택합니다. 명시한 모델이 없다면 사용자의 기본 모델이나 사용 가능한 첫 모델이 선택될 수 있으므로, 생성 전에 실제 선택값을 확인합니다.
  5. 도구, 미들웨어, 스킬과 서브에이전트는 업무에 필요한 경우에만 연결합니다. 선택한 리소스를 사용할 권한이 없으면 저장 또는 완료 단계에서 실패할 수 있습니다.
  6. 설정을 저장한 뒤 완료 동작을 선택합니다. 세션이 완료되고 사용 화면으로 전환되는지 확인합니다.

완료 전에는 선택한 도구, 미들웨어, 스킬, 서브에이전트, 모델과 지침을 다시 확인합니다. 설정 저장과 실제 에이전트 생성은 별도 단계이므로, 설정 화면에 값이 보인다는 이유만으로 사용 가능한 에이전트가 만들어졌다고 판단하지 않습니다.

첫 결과로 설계를 검증하기​

생성된 에이전트의 사용 화면에서 다음 입력을 보냅니다.

가상 모임 안내문을 작성해 주세요. 시간은 금요일 오후 3시, 장소는 작은 회의실입니다. 준비물은 읽고 싶은 책 제목 하나입니다.

응답이 도착하면 다음 순서로 비교합니다.

  1. 시간, 장소와 준비물이 입력과 같은지 확인합니다.
  2. 제목과 본문을 구별할 수 있는지 확인합니다.
  3. 본문이 요청한 세 문장 구성에 맞는지 확인합니다.
  4. 회비나 신청 마감일처럼 입력에 없는 조건을 추가하지 않았는지 확인합니다.

사실이 빠졌다면 누락된 항목을 지정해 수정 요청을 보냅니다. 같은 문제가 반복되면 대화 결과를 성공으로 간주하지 말고 지침을 수정한 뒤 다시 시험합니다. 첫 결과 하나만으로 모든 입력에서 품질이 같다고 결론 내리지 않습니다.

도구와 서브에이전트를 붙이는 시점​

최소 구성의 결과가 기준에 맞은 뒤에만 리소스를 하나씩 추가합니다. 도구를 붙였다면 도구가 필요한 입력과 도구 없이 처리할 입력을 각각 시험합니다. 서브에이전트를 붙일 때는 부모 에이전트와 하위 업무를 먼저 정하고, 대상이 호출 가능한 소유 범위에 있으며 보관 상태가 아닌지 확인합니다. 자기 자신을 연결하거나 순환 호출을 만들면 안 됩니다.

자연어 생성 세션에서 보이는 추천 또는 결정 화면이 현재 활성 생성 경로의 완료 조건이라고 단정하지 않습니다. 현재 활성 흐름은 설정 항목을 저장하고 완료 동작으로 finalize하는 경로이며, 화면에 등록돼 있지만 보류된 결정 단계와 구분해야 합니다.

생성이 멈출 때 판단하기​

  • 생성 세션이 시작되지 않으면 입력 길이와 생성 권한을 확인합니다. 자연어 초기 입력은 5자 이상 2,000자 이하인지 확인합니다.
  • 저장이 거부되면 선택한 모델과 리소스의 사용 권한, 리소스가 현재 사용 가능한 상태인지 확인합니다.
  • 세션이 완료되지 않으면 이름과 지침처럼 필수 설정이 채워졌는지 확인한 뒤 같은 세션에서 다시 시도합니다.
  • 사용 화면으로 전환됐지만 결과가 비어 있으면 생성 완료와 실행 결과를 분리해 확인하고, 입력이 실제 에이전트 대화에 전달됐는지부터 봅니다.
  • 생성 목적이 바뀌었다면 기존 세션을 계속 덧붙이지 말고 새 세션이나 새 에이전트로 기준을 분리합니다.

다음 단계​

에이전트 만들기에서 자연어 생성, 직접 생성과 서브에이전트의 차이를 비교합니다. 에이전트 수정에서 생성 후 지침과 리소스를 바꾸는 방법을 확인합니다. 반복 업무에서 여러 입력을 같은 기준으로 시험하는 방법을 읽습니다.
