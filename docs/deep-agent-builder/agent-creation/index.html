에이전트 만들기

Deep Agent Builder에서는 업무 설명으로 초안을 만들거나, 이름과 설명을 직접 입력해 에이전트를 시작할 수 있습니다. 다른 에이전트가 호출할 하위 구성이 필요하면 서브에이전트로 만듭니다. 어떤 경로를 선택해도 마지막에는 지침, 모델, 리소스를 확인한 뒤 실행 가능한 에이전트로 완성합니다.

생성 방식 선택​

방식적합한 경우시작할 때 필요한 정보
자연어 생성맡길 업무를 먼저 설명하고 초안을 만들 때업무 목적과 필요한 입력
직접 생성에이전트의 이름과 기본 틀이 이미 정해졌을 때이름과 설명
서브에이전트다른 에이전트가 일부 업무를 맡길 때호출할 부모 에이전트와 하위 업무

처음 만드는 에이전트라면 자연어 생성 또는 직접 생성을 선택합니다. 업무를 여러 역할로 나눌 계획이라면 서브에이전트의 호출 관계를 먼저 설계합니다.

자연어로 만들기​

  1. 생성 화면에서 에이전트가 맡을 업무를 설명합니다.
  2. 생성 세션이 시작되면 대화와 설정 화면에서 도구, 미들웨어, 스킬, 서브에이전트, 지침과 모델을 정합니다.
  3. 설정을 저장하면서 이름과 설명을 확인합니다.
  4. 필요한 항목이 준비되면 완료를 선택해 에이전트를 생성합니다.

업무 설명은 생성 세션의 초기 입력입니다. 입력만으로 설문이 끝나거나 설정 단계가 자동으로 건너뛰어지는 것은 아닙니다. 생성 중에 바꾼 도구, 미들웨어, 스킬, 서브에이전트, 지침과 모델은 각 설정 항목에 저장됩니다.

생성 세션이 완료되면 에이전트로 전환됩니다. 더 이상 진행하지 않는 세션은 폐기하거나 만료 상태로 정리할 수 있습니다. 생성 화면에 표시되는 기능과 현재 활성 생성 흐름이 다를 수 있으므로, 추천이나 승인 단계가 보인다는 이유만으로 해당 단계가 현재 생성 경로에서 실행된다고 판단하지 마세요.

직접 만들기​

직접 생성에서는 이름과 설명을 입력해 에이전트의 기본 틀을 만듭니다. 생성 직후에는 다음 항목을 확인합니다.

  • 에이전트 이름과 설명
  • 현재 선택된 모델
  • 연결된 도구, 미들웨어, 스킬과 서브에이전트
  • 지침과 응답 기준
  • 에이전트의 현재 상태

직접 생성으로 만든 초안은 이후 편집 화면에서 세부 설정을 추가합니다. 이름, 설명, 지침을 먼저 정한 뒤 업무에 필요한 리소스만 연결하면 됩니다. 초안을 만든 사실과 실제 실행 가능 여부는 별개이므로 모델과 리소스의 사용 권한도 확인해야 합니다.

서브에이전트 추가​

서브에이전트는 다른 에이전트가 일부 업무를 맡길 수 있는 하위 구성입니다. 생성하거나 연결할 때 다음 조건을 확인합니다.

  • 호출하는 부모 에이전트와 맡길 업무가 분명한지
  • 서브에이전트의 소유 범위가 호출 관계에 맞는지
  • 보관 처리된 에이전트를 연결하지 않는지
  • 슈퍼 에이전트를 서브에이전트로 연결하지 않는지
  • 자기 자신을 참조하거나 순환 호출을 만들지 않는지

서브에이전트 연결이 실패하면 이름이나 설명보다 소유권, 상태, 호출 관계를 먼저 확인합니다. 연결 목록에 표시되는 것만으로 실행 권한이 부여되는 것은 아닙니다.

생성 후 점검​

생성 직후에는 다음 순서로 확인합니다.

  1. 이름과 설명이 맡길 업무를 정확히 나타내는지 봅니다.
  2. 지침에 역할, 답변 형식, 제한 조건과 정보 부족 시 처리 방법이 들어 있는지 확인합니다.
  3. 모델이 업무에 맞고 현재 워크스페이스에서 사용할 수 있는지 확인합니다.
  4. 도구, 미들웨어, 스킬과 서브에이전트가 필요한 범위만 연결됐는지 확인합니다.
  5. 테스트 실행으로 결과를 확인합니다. 테스트 결과는 동작 검증에 사용하며, 테스트 대화가 설정을 자동으로 저장한다고 가정하지 않습니다.

생성 성공 여부와 원하는 에이전트가 만들어졌는지는 따로 확인해야 합니다. 생성이 성공했더라도 모델, 지침 또는 리소스가 목적과 다르면 편집 화면에서 수정합니다.

생성이 멈추거나 실패할 때​

먼저 입력, 권한, 세션 상태를 나누어 확인합니다. 이름과 설명의 값이 유효한지, 생성 세션이 활성 상태인지, 선택한 모델과 리소스를 사용할 권한이 있는지 차례로 봅니다. 서브에이전트라면 소유권, 보관 상태, 슈퍼 에이전트 여부와 순환 참조를 다시 확인합니다.

생성 세션에서 추가 질문이나 확인 요청이 나타나면 필요한 값을 입력한 뒤 같은 세션에서 작업을 이어 갑니다. 반대로 요청의 목적이 바뀌었다면 기존 세션을 계속 수정하기보다 새 에이전트나 새 세션으로 시작하는 편이 안전합니다.

다음 단계​

에이전트의 이름, 지침, 모델과 리소스를 바꾸려면 Deep Agent Builder 메뉴 안내를 읽습니다. 실제 요청을 보내고 스트리밍 결과를 확인하려면 Deep Agent Builder 반복 업무를 읽습니다. 모델 선택 기준이 필요하면 Deep Agent Builder 모델 구성을 확인합니다.
