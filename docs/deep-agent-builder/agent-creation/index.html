에이전트 만들기

새 에이전트는 새 에이전트 화면에서 만듭니다. 이 페이지는 화면에 있는 네 가지 시작 방법을 설명하고, 브레인크루 AI혁신팀 김그루 사원이 "주간 업무 보고서 도우미"를 빌더와 대화해 처음부터 끝까지 만드는 과정과, "이메일 초안 도우미"를 이름과 설명만으로 직접 만드는 과정을 따라 합니다.

이 페이지에서 할 수 있는 일

  • 업무 설명 한 단락과 참고 파일로 빌더와 대화하면서 에이전트를 만들고, 빌더의 확인 질문과 추천에 답하는 방법을 익힙니다.
  • 이름과 설명만 정해 둔 경우 에이전트 직접 만들기로 빈 에이전트를 만든 뒤 에이전트 편집 화면에서 채웁니다.
  • 동료가 워크스페이스에 등록해 둔 에이전트를 에이전트 템플릿에서 골라 템플릿으로 제작으로 내 에이전트를 만듭니다.
  • 받은 에이전트 ZIP 파일이 있으면 에이전트 가져오기로 들여옵니다.

새 에이전트 시작 화면​

왼쪽 사이드바 위쪽의 새 에이전트를 누르거나 왼쪽 위 로고를 누르면 열리는 화면입니다. 새 에이전트는 에이전트 생성 권한이 없으면 눌리지 않습니다. 가운데 입력란에 만들 에이전트를 설명하고 전송을 누르면 빌더와의 제작 대화가 시작됩니다. 입력란에는 "구축하려는 에이전트에 대해 설명해 주세요 (최소 5자)"가 보이며 5자 이상 적어야 보낼 수 있고, 파일 업로드로 참고 파일을 함께 붙입니다.

입력란 아래에는 다른 시작 방법이 있습니다. 에이전트 직접 만들기는 이름과 설명만 입력하는 창을, 에이전트 가져오기는 내보낸 에이전트 ZIP 파일을 올리는 창을 엽니다. 워크스페이스에 등록된 에이전트가 있으면 입력란 아래에 템플릿 카드로 보이며(세 개까지 보이고 10초마다 바뀝니다), 카드를 누르면 그 에이전트를 복사해 내 에이전트를 만든 뒤 에이전트 편집 화면으로 이동합니다. 아래 두 번째 그림은 워크스페이스에 등록된 주간 업무 보고서 도우미가 템플릿 카드 한 장으로 보이는 상태입니다. 사이드바의 에이전트 템플릿에서는 내 기본 워크스페이스나 직접 고른 워크스페이스에 등록된 템플릿을 볼 수 있습니다.

먼저 설명을 적어 보내는 부분입니다.

3에이전트 직접 만들기이름과 설명만 입력하는 창을 엽니다. 빌더 대화 없이 빈 에이전트가 만들어집니다.지침을 이미 직접 써 두었을 때
4에이전트 가져오기내보낸 에이전트 ZIP 파일을 올리는 창을 엽니다.동료에게서 에이전트 파일을 받았을 때

네 방법 가운데 무엇을 고를지는 지금 가진 정보로 정합니다.

방법맞는 경우만든 뒤 할 일
대화로 만들기할 일은 분명하지만 지침 문장, 연결할 도구·스킬은 아직 정하지 않았을 때빌더가 채운 설정을 확인하고 시험 질문을 보냅니다.
에이전트 직접 만들기이름·설명·지침을 직접 쓰고 싶을 때에이전트 편집 화면에서 지침을 쓰고 도구·지식·미들웨어를 직접 추가합니다.
템플릿으로 만들기워크스페이스에 비슷한 에이전트가 이미 등록되어 있을 때복사된 에이전트의 이름과 지침을 내 업무에 맞게 고칩니다.
에이전트 가져오기내보낸 ZIP 파일이 있을 때가져오기 요약에서 빠진 항목이 없는지 확인합니다.

이럴 때 쓰세요: 팀장님이 회의록 정리를 맡길 도우미가 있으면 좋겠다고 하면, 김그루 사원은 먼저 에이전트 템플릿 화면에서 "회의록"을 검색해 동료가 등록해 둔 것이 있는지 봅니다. 있으면 템플릿으로 만들어 이름과 지침만 고치고, 없으면 대화로 만들기로 시작합니다. 이메일 초안 도우미처럼 지침 문장을 이미 정리해 둔 경우에만 에이전트 직접 만들기를 고릅니다.

설계표를 먼저 쓰고 시작하면 어떤 방법이든 훨씬 빨리 끝납니다. 설계표 쓰는 법은 첫 에이전트 설계하기를 참고하세요.

대화로 만들기​

빌더는 업무 설명을 받아 확인 질문을 하고, 도구·미들웨어·스킬·서브에이전트를 추천하고, 쓸 수 있는 모델을 확인한 뒤 시스템 프롬프트(지침)를 써서 에이전트를 완성합니다. 사용자는 질문에 답하고 추천을 승인하거나 수정 요청합니다. 이 절에서는 김그루 사원이 주간 업무 보고서 도우미를 만듭니다.

1단계: 제작 요청 보내기​

입력란에 누가 무엇을 넣으면 어떤 결과를 받고 싶은지와 하지 말아야 할 일을 함께 적습니다. 입력 예시가 되는 파일이 있으면 파일 업로드로 함께 붙입니다. 이 예시에서는 김그루_주간업무메모_1106.md를 첨부하고 아래 프롬프트를 보냅니다.

프롬프트: AI혁신팀 구성원이 매주 금요일에 한 주 업무 메모를 넣으면 팀장에게 올릴 주간 업무 보고서 초안을 만들어 주는 에이전트를 만들어 주세요. 보고서는 제목, 이번 주 핵심 성과 3줄, 업무별 진행 표(업무, 진행 내용, 수치, 상태), 이슈와 조치, 다음 주 계획, 확인 필요 순서로 개조식으로 써 주세요. 메모에 없는 수치나 성과는 만들지 말고 [확인 필요]로 표시해 주세요. 첨부한 메모는 입력 예시입니다.

제작 요청 입력

번호메뉴기능이런 때 사용하세요
1첨부 파일입력란 위에 붙은 김그루_주간업무메모_1106.md입니다. 파일 이름 옆 X로 뺄 수 있습니다.빌더가 입력 형식을 이해하도록 실제 메모를 보여 줄 때
2설명 입력란제작 요청 문장을 적습니다. 여러 문장으로 길게 써도 됩니다.결과 형식과 금지 사항을 한 번에 알려 줄 때
3파일 업로드첨부할 파일을 고르는 창을 엽니다.파일을 더 붙일 때

이럴 때 쓰세요: 김그루 사원은 제작 요청을 보내기 전에 지난 몇 주 메모 가운데 업무 항목과 숫자가 가장 고르게 들어간 메모 하나를 골라 붙입니다. 메모가 들쭉날쭉하면 빌더가 그 형식을 기준으로 지침을 쓰기 때문입니다. 판매 실적 엑셀처럼 표 파일은 제작 요청에 붙지 않으므로, 에이전트를 만든 뒤 대화 화면에서 따로 올리기로 정해 둡니다.

제작 요청에 붙일 수 있는 파일

제작 요청에는 파일을 한 번에 10개까지 붙일 수 있고, 붙인 파일의 크기 합계는 50MB 이하여야 합니다. 붙일 수 있는 확장자는 .pdf, .jpg, .jpeg, .png, .gif, .webp, .md, .markdown, .txt, .docx, .pptx, .ppt, .hwp, .hwpx, .html, .htm입니다. 채팅 첨부와 달리 표 파일(.xlsx, .xls, .xlsb, .xlsm, .csv)은 제작 요청에 붙지 않으므로, 에이전트를 만든 뒤 대화 화면이나 에이전트 편집 화면의 파일 탭에 올립니다.

제작 대화 중 빌더의 확인 질문에 답할 때는 이미지(.jpg, .jpeg, .png, .gif, .webp)만 붙일 수 있습니다. 다른 파일을 붙여 보내면 "이미지 첨부만 지원합니다."가 나옵니다. 위치별 한도는 파일 첨부 정책과 가드레일에 모아 두었습니다.

2단계: 확인 질문에 답하기​

요청을 보내면 빌더가 화면에 "1단계: 에이전트 만들기 준비"부터 "9단계: 에이전트 생성 완료"까지의 진행 상황 목록을 띄우고, 요구사항을 정리하면서 필요한 내용을 확인 질문으로 묻습니다. 질문 내용과 개수는 요청에 따라 빌더가 정하므로 매번 다를 수 있습니다. 질문이 여러 개면 "3개의 확인이 필요합니다"처럼 한 묶음으로 나옵니다. 이 예시에서는 첫 묶음에서 보고서에 넣을 업무 범위, 참고할 자료, 꼭 지킬 조건을 물었고, 답을 보내자 두 번째 묶음에서 에이전트 이름, 하는 일을 설명하는 문장, 주요 업무를 물었습니다.

묶음 맨 위에는 "3개의 확인이 필요합니다"처럼 답해야 할 질문 수가 보입니다. 묶음 안에서는 질문 번호를 누르거나 이전 질문, 다음 질문으로 옮겨 다니며, 질문마다 빌더가 제안한 보기를 고르고 제출을 누릅니다. 두 화살표 사이에는 "1단계 / 3단계"처럼 지금 보는 질문 위치가 보입니다. 보기 대신 긴 설명으로 답하고 싶으면 선택지 닫기를 눌러 아래 입력란에 직접 쓰고, 닫은 카드는 선택지 다시 보기로 다시 엽니다. 전체 제출의 괄호 안 숫자(예: 0/3)는 답한 질문 수이며, 모두 답해야 보낼 수 있습니다. 요청을 처음부터 바꾸고 싶으면 처음부터 시작을 누릅니다.

확인 질문 묶음: 질문 고르기

번호메뉴기능이런 때 사용하세요
1처음부터 시작진행 중인 제작 대화를 버리고 처음부터 다시 시작합니다. 누르면 확인 창이 먼저 열립니다.요청 내용을 처음부터 바꿔 다시 만들고 싶을 때
2질문 번호해당 번호의 질문으로 바로 이동합니다.앞 질문의 답을 고치고 싶을 때
3보기빌더가 제안한 답입니다. 하나를 고르면 체크 표시가 붙습니다.제안이 내 의도와 맞을 때
4선택지 닫기보기 카드를 닫고 아래 입력란에 직접 답을 쓰게 합니다. 닫은 뒤에는 선택지 다시 보기로 다시 열 수 있습니다.보기 대신 긴 설명으로 답하고 싶을 때

3단계: 추천을 확인하기​

요구사항 정리가 끝나면 빌더가 도구 추천, 미들웨어 추천, 스킬 추천, 서브에이전트 추천을 차례로 보여 줍니다. 추천 카드에는 추천 항목 이름과 "사유:"가 함께 나옵니다. 요구사항에 맞는 항목이 없으면 "요구사항에 딱 맞는 추천 도구가 없어요."처럼 표시됩니다. 카드마다 승인 또는 수정 요청을 누릅니다.

추천 카드 확인

번호메뉴기능이런 때 사용하세요
1추천 카드 제목지금 어떤 종류의 추천인지 보여 줍니다(도구 추천, 미들웨어 추천, 스킬 추천, 서브에이전트 추천).어느 단계에 와 있는지 확인할 때

3수정 요청추천을 받아들이지 않고 바꿔 달라고 요청합니다. 누르면 "수정 의견을 입력하세요..." 칸이 열립니다.다른 도구가 필요하거나 추천이 업무와 맞지 않을 때

주간 업무 보고서 도우미는 첨부한 메모만 정리하면 되므로 도구가 없어도 됩니다. 이 예시에서 빌더는 사내 자료를 검색하는 도구를 추천했지만, 업무에 필요 없으므로 수정 요청을 누르고 "외부 도구 없이 첨부한 메모만 정리하게 해 주세요"라고 적어 보냈습니다. 그러자 카드가 "요구사항에 딱 맞는 추천 도구가 없어요."로 바뀌었고 승인을 눌렀습니다. 이어서 나온 미들웨어 추천에서 도구 재시도 미들웨어를 추천받았을 때도 수정 요청으로 "미들웨어 없이 진행해 주세요"라고 보낸 뒤 승인했습니다.

4단계: 지침 작성과 저장​

추천 확인이 끝나면 빌더가 "7단계: 에이전트 행동 지침 작성"으로 넘어가, 시스템 프롬프트 정리에서 지금까지의 답과 추천을 바탕으로 지침을 쓰고 시스템 프롬프트 저장으로 저장합니다. 이어서 에이전트 설정 저장, 에이전트 완성 단계가 진행됩니다. 각 단계는 대화 화면에 진행 표시로 나타나며, 눌러서 펼치면 처리 내용을 볼 수 있습니다. 모델은 따로 묻지 않고 워크스페이스의 기본 모델(이 예시에서는 GPT-4.1)로 정해집니다.

제작 진행 단계

번호메뉴기능이런 때 사용하세요
1시스템 프롬프트 정리빌더가 지침을 쓴 단계입니다.지침에 요청한 형식과 금지 사항이 들어갔는지 미리 볼 때
2시스템 프롬프트 저장빌더가 쓴 지침을 에이전트에 저장한 단계입니다.지침 작성이 끝났는지 확인할 때
3에이전트 설정 저장이름, 설명, 연결 항목을 저장한 단계입니다.제작이 끝나 가는지 확인할 때
4에이전트 완성마지막 단계입니다. 끝나면 완성 안내가 이어집니다.제작이 모두 끝났는지 확인할 때

쓸 수 있는 모델이 하나도 없으면 "사용 가능한 모델이 없어 이 에이전트를 실행할 수 없습니다. 모델을 등록하면 바로 사용할 수 있습니다."라는 안내와 모델 등록 버튼이 나옵니다. 모델 등록은 모델 구성을 참고하세요.

5단계: 완성하고 바로 이용하기​

모든 단계가 끝나면 빌더가 1단계부터 9단계까지 단계별 결과와 "9단계 완료: 에이전트가 완성됐어요" 안내를 정리하고, 화면 아래에 바로 이용하기 버튼이 나타납니다. 완성된 에이전트는 사이드바 내 에이전트 목록에도 바로 나타납니다.

처음부터 다시 시작하기​

제작 대화 도중 요청을 크게 바꾸고 싶으면 화면 위쪽 처음부터 시작을 누릅니다. 확인 창에 "지금까지 나눈 대화와 정한 설정이 모두 사라집니다."라는 안내가 보입니다. 창의 처음부터 시작을 누르면 제작 대화가 지워지고 새 에이전트 시작 화면으로 돌아가며, 취소를 누르면 제작 대화를 이어 갑니다.

  3. **에이전트 설명 (선택)**에 "받는 사람, 목적, 핵심 내용을 알려 주면 업무 이메일 초안을 씁니다."를 입력합니다.

  4. 확인을 누르면 에이전트 편집 화면이 열립니다. 지침과 도구함·지식함·미들웨어는 비어 있고, 모델은 기본 모델(GPT-4.1)로 정해져 있습니다.

  5. 지침 입력란에 아래 지침을 붙여 넣고 헤더의 저장을 누릅니다. 지침은 저장해야 대화와 테스트 탭에 쓰입니다.

    프롬프트: 당신은 브레인크루 직원의 업무 이메일 초안을 쓰는 도우미입니다. 사용자가 받는 사람, 목적, 핵심 내용을 알려 주면 제목 한 줄과 본문을 씁니다. 본문은 인사, 용건, 세부 내용, 요청 사항, 맺음말 순서로 쓰고 존댓말을 씁니다. 사용자가 알려 주지 않은 날짜, 금액, 약속은 만들지 않고 [확인 필요]로 표시합니다.

  6. 모델 칸에 모델 이름이 보이는지 확인합니다. 다른 모델을 쓰려면 모델 설정을 눌러 고르고 저장, 확인하고 저장을 차례로 누릅니다.

  7. 오른쪽 테스트 탭에서 아래 프롬프트로 시험합니다.

    프롬프트: 영업1팀 최하늘 책임에게 다음 주 화요일 회의록 요약 도우미 시연 일정을 잡자는 메일을 써 주세요.

  8. 답변에 제목 한 줄과 인사, 용건, 세부 내용, 요청 사항, 맺음말이 순서대로 있는지 봅니다. 이 예시에서는 "제목: [회의 일정 조율] 회의록 요약 도우미 시연 제안드립니다"로 시작해 "감사합니다."로 끝나는 메일이 나왔고, 끝에 보내는 사람 서명은 없었습니다.

만든 뒤 지침을 말로 고치는 방법은 Fix 에이전트에서 이 이메일 초안 도우미를 예로 설명합니다.

템플릿으로 만들기​

동료가 워크스페이스에 등록한 에이전트는 에이전트 템플릿 화면에 템플릿으로 나옵니다. 템플릿을 고르면 그 에이전트의 구성을 복사해 내 에이전트를 만듭니다. 원본은 바뀌지 않습니다. 화면 위쪽에는 두 탭이 있습니다. 첫 탭에는 내 기본 워크스페이스 이름(이 예시에서는 "브레인크루")이 붙어 있고 그 워크스페이스에 등록된 템플릿을 보여 줍니다. 그 워크스페이스의 에이전트를 볼 권한이 없으면 "접근 권한이 없습니다"가 보입니다. 옆의 워크스페이스 탭에서는 목록 상자에서 내가 속한 워크스페이스(예: AI혁신팀, 영업팀, 마케팅팀)를 하나 골라 그 워크스페이스의 템플릿을 봅니다. "템플릿 검색..." 칸에 이름이나 설명의 낱말을 넣어 찾고, 칸 오른쪽에 "총 1개"처럼 템플릿 수가 나옵니다. 템플릿 카드에는 에이전트 이름과 설명, 서브에이전트·지식·도구·스킬 수, 등록자, 최종 업데이트 날짜가 보입니다. 등록된 템플릿이 없으면 "등록된 템플릿이 없습니다"와 "워크스페이스에 템플릿을 등록해보세요."가 보입니다.

에이전트 템플릿 화면

번호메뉴기능이런 때 사용하세요
1에이전트 템플릿템플릿 화면을 엽니다. 화면 제목도 "에이전트 템플릿"입니다.동료가 등록한 에이전트를 둘러볼 때
2기본 워크스페이스 탭 / 워크스페이스첫 탭(내 기본 워크스페이스 이름)은 기본 워크스페이스의 템플릿을, 워크스페이스 탭은 목록 상자에서 고른 워크스페이스의 템플릿을 보여 줍니다.다른 팀 워크스페이스에 등록된 템플릿을 찾아볼 때
3템플릿 검색"템플릿 검색..." 칸에 이름이나 설명의 낱말을 넣어 찾습니다.템플릿이 많아 목록에서 찾기 어려울 때
4템플릿 카드등록된 템플릿입니다. 그림은 브레인크루 워크스페이스에 등록된 주간 업무 보고서 도우미입니다. 카드를 누르면 상세 창이 열립니다.구성과 등록자를 자세히 볼 때

이럴 때 쓰세요: 김그루 사원이 고객 문의 답장 도우미를 만들려다 영업팀 워크스페이스에 비슷한 템플릿이 있다는 말을 들으면, 워크스페이스 탭에서 영업팀을 고르고 "답장"으로 검색합니다. 카드 상세 창의 대화하기로 라마바유통 문의 메일 하나를 먼저 넣어 보고, 답장 형식이 맞으면 템플릿으로 제작으로 내 에이전트를 만든 뒤 지침의 서명과 말투만 AI혁신팀에 맞게 고칩니다.

템플릿 카드를 누르면 상세 창이 열립니다. 상세 창에는 에이전트 설명, 등록자, 연결된 도구·스킬·모델·서브에이전트(없으면 "연결된 리소스 없음")가 보입니다. 대화하기를 누르면 복사하지 않고 템플릿 에이전트와 바로 대화하고, 템플릿으로 제작을 누르면 구성을 복사한 내 에이전트가 만들어진 뒤 에이전트 편집 화면으로 이동합니다. 완료되면 "템플릿으로 에이전트를 만들었습니다"가 나옵니다.

템플릿이 쓰는 도구 가운데 내가 아직 갖고 있지 않은 도구가 있으면 "Tool이 자동으로 다운로드됩니다" 창이 먼저 열립니다. 다운로드 후 제작을 누르면 필요한 도구가 내 에셋에 추가된 뒤 에이전트가 만들어지고, 추가된 도구 이름이 알림에 표시됩니다.

내 에이전트를 워크스페이스에 등록하는 방법은 에이전트 수정의 워크스페이스 등록과 커뮤니티를 참고하세요.

에이전트 가져오기​

동료가 에이전트 내보내기로 내려받은 ZIP 파일이 있으면, 새 에이전트 시작 화면의 에이전트 가져오기를 눌러 그 파일을 올립니다. .zip 파일만 받으며, 창에는 "최대 200MB"라고 보이지만 실제로 올릴 수 있는 크기는 50MB까지입니다. 가져오기 요약을 읽는 방법과 내보내기 순서는 에이전트 가져오기와 내보내기에서 설명합니다.
