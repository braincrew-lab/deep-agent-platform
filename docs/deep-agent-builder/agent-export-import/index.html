Deep Agent Builder 에이전트 가져오기와 내보내기

에이전트를 다른 Workspace로 옮기려면 내보내기 파일을 만든 뒤 가져온 결과를 다시 확인해야 합니다. 미리보기, 파일 다운로드, 가져오기는 서로 다른 단계입니다. 파일이 업로드됐거나 새 에이전트가 만들어졌다는 사실만으로 설정과 연결된 자원이 모두 복원됐다고 판단하지 마세요.

이 작업을 시작하기 전에​

다음 조건을 확인합니다.

  1. 원본 에이전트를 열어 볼 수 있고 내보내기 권한이 있는지 확인합니다.
  2. 에이전트와 하위 에이전트가 서로를 반복해서 참조하지 않는지 확인합니다.
  3. 에이전트 정의에 필요한 설정 파일이 빠지지 않았는지 확인합니다.
  4. 첨부파일과 시크릿 값은 내보내기 파일에 포함되지 않는다는 점을 확인합니다.
  5. 대상 Workspace에서 필요한 모델, 도구, 스킬을 연결하거나 새로 만들 권한이 있는지 확인합니다.

세부 정보를 볼 권한이 없으면 미리보기 일부가 가려질 수 있습니다. 가려진 항목을 누락된 자원으로 단정하지 말고, 현재 계정에서 확인할 수 있는 범위를 기록합니다.

미리보기에서 내보내기 가능 여부 확인하기​

내보내기 화면에서 에이전트, 하위 에이전트, 연결된 모델과 도구, 스킬, 첨부파일 정보, 시크릿 참조, 차단 사유를 차례로 확인합니다.

차단 사유가 있으면 파일을 만들기 전에 해결해야 합니다.

  • 순환 참조가 있으면 에이전트 또는 하위 에이전트 연결을 끊습니다.
  • 필요한 설정 파일이 없으면 원본 에이전트의 정의를 복구합니다.

차단 사유가 남아 있으면 실제 내보내기가 거절됩니다. 미리보기를 다시 여는 것만으로는 해결되지 않습니다. 수정한 뒤 미리보기에서 차단 사유가 사라졌는지 다시 확인하세요.

첨부파일은 이름, 크기, 형식 같은 정보만 내보내기 대상에 포함될 수 있습니다. 파일 내용과 시크릿 값은 자동으로 따라가지 않습니다. 대상 Workspace에서 첨부파일을 다시 준비하고 시크릿을 별도로 등록해야 할 수 있습니다.

내보내기 파일 보관하기​

내보내기가 끝나면 ZIP 파일을 안전한 위치에 보관합니다. 파일 안에는 에이전트 구성 목록, 에이전트별 설정 파일, 선택적으로 시스템 지침과 대화 시작 문구가 들어갑니다. 내보내기 형식은 현재 지원되는 v2입니다.

다음 내용은 자동으로 포함되지 않습니다.

  • 시크릿의 실제 값
  • 첨부파일의 실제 내용
  • 원본 Workspace에만 있는 개인용 자원 정의
  • 원본 자원의 설치 정의

파일을 다른 사람에게 전달하기 전에 이름, 설명, 지침, 연결된 자원 목록에 고객 정보나 내부 주소가 들어 있지 않은지 확인합니다. 원본 에이전트의 파일이 내보내기 과정에서 수정되는 것은 아니지만, ZIP 파일 자체에는 민감한 정보가 남을 수 있으므로 접근 권한을 제한해 보관하세요.

다른 Workspace로 가져오기​

  1. 대상 Workspace의 에이전트 가져오기 화면을 엽니다.
  2. 내보낸 ZIP 파일을 선택합니다.
  3. 화면에 표시된 파일 형식과 검증 결과를 확인합니다.
  4. 가져오기를 실행합니다.
  5. 새로 만들어진 에이전트와 연결된 자원 요약을 확인합니다.

가져오기가 성공하면 원본과 별도의 새 에이전트가 만들어집니다. 하위 에이전트도 새 식별자를 받을 수 있으므로 원본 에이전트의 주소나 식별자가 그대로 유지된다고 가정하지 마세요.

원본 자원과 이름 또는 연결 정보가 맞으면 기존 자원을 연결할 수 있습니다. 대상 Workspace에 자원이 없거나 연결 권한이 맞지 않으면 일부 자원이 건너뛰어질 수 있습니다. 이 경우 가져오기 자체는 끝나도 원본과 같은 실행 결과가 나오지 않을 수 있습니다.

가져오기 결과에서 다음 항목을 확인합니다.

  • 새 에이전트가 만들어졌는지
  • 하위 에이전트 수와 새로 만들어진 자원 수가 예상과 맞는지
  • 연결되지 않아 건너뛴 자원이 있는지
  • 첨부파일이 제외됐는지
  • 원본과 다른 Workspace에서 가져온 작업인지

파일 검증 오류가 발생했을 때​

파일의 크기, 압축 해제 후 전체 크기, 파일 하나의 크기, 파일 수, 디렉터리 깊이에 제한이 있습니다. 제한과 같은 값은 허용될 수 있지만, 제한을 초과하면 거절됩니다.

검사 대상초과하면 거절되는 기준
압축 파일50 MiB 초과
압축 해제 후 전체 크기500 MiB 초과
파일 하나의 크기50 MiB 초과
파일 개수5,000개 초과
디렉터리 깊이10 초과

오류가 발생하면 먼저 증상을 기준으로 확인합니다.

  • ZIP이 손상됐거나 설정 형식이 잘못됐으면 원본에서 파일을 다시 내보냅니다.
  • 파일 크기 제한을 넘었으면 첨부파일과 불필요한 항목을 줄인 뒤 다시 만듭니다.
  • 지원하지 않는 형식이라고 나오면 현재 지원되는 v2 형식인지 확인합니다.
  • 파일을 읽는 중 오류가 발생하면 같은 파일을 반복해서 올리지 말고, 대상 Workspace에 에이전트가 일부 만들어졌는지 먼저 확인합니다.

파일을 올리는 형식 자체가 잘못된 경우에는 가져오기를 다시 시도하기 전에 파일 선택 단계와 지원 형식을 확인하세요.

재시도하기 전에 확인할 것​

가져오기에는 중복 실행을 줄이기 위한 요청 식별자가 사용될 수 있지만, 항상 중복 생성을 막는 것은 아닙니다. 저장된 재실행 정보가 만료되거나 일시적으로 사용할 수 없으면 같은 파일을 다시 올릴 때 새 에이전트가 만들어질 수 있습니다.

네트워크 오류나 응답 시간 초과가 발생하면 다음 순서로 확인합니다.

  1. 대상 Workspace의 에이전트 목록에서 새 에이전트가 생겼는지 확인합니다.
  2. 새 에이전트의 연결 자원과 설정 요약을 확인합니다.
  3. 생성 여부를 확인할 방법이 없으면 같은 ZIP을 반복해서 올리지 않습니다.
  4. 승인된 지원 절차에 따라 가져오기 상태를 확인한 뒤 다시 시도합니다.

가져오기 완료 확인하기​

다음 항목을 모두 확인해야 가져오기가 끝났다고 판단할 수 있습니다.

  1. 새 에이전트가 목록에 나타납니다.
  2. 하위 에이전트와 연결된 자원 수가 예상 범위와 맞습니다.
  3. 건너뛴 자원이나 제외된 첨부파일이 있는지 확인합니다.
  4. 필요한 모델, 도구, 스킬이 대상 Workspace에서 연결돼 있습니다.
  5. 가져온 에이전트를 열어 설정과 지침을 확인합니다.
  6. 비식별 테스트 입력으로 실제 실행 결과를 확인합니다.

ZIP이 정상적으로 접수됐거나 새 에이전트가 만들어졌다는 사실은 첨부파일, 시크릿, 원본 자원 연결, 실행 권한까지 복원됐다는 뜻이 아닙니다.
