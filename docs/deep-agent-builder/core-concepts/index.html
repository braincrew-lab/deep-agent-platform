핵심 개념

Deep Agent Builder의 작업 단위는 에이전트, 지침, 리소스, 스레드, 실행으로 나뉩니다. 에이전트는 재사용할 설정 묶음이고, 스레드는 대화 맥락을 담는 단위이며, 실행은 스레드에서 실제 요청을 처리하는 한 번의 작업입니다. 이 구분을 알면 생성 화면과 사용 화면의 역할이 섞이지 않습니다.

에이전트​

에이전트는 특정 업무를 반복해서 맡기는 구성입니다. 이름과 설명은 목록에서 대상을 구분하기 위한 정보이고, 지침은 에이전트가 어떤 역할로 답할지 정하는 내용입니다. 도구, 미들웨어, 스킬, 서브에이전트와 모델을 에이전트에 연결해 업무 범위를 정합니다.

에이전트 구성은 생성 뒤에도 수정할 수 있습니다. 직접 만든 초안에서는 이름, 설명, 지침을 입력한 뒤 저장해야 변경이 확정됩니다. 도구, 미들웨어, 모델, 서브에이전트와 같은 구성 변경은 화면의 저장 정책에 따라 즉시 반영됩니다.

지침​

지침은 에이전트의 역할과 응답 기준을 설명하는 시스템 프롬프트입니다. 다음 내용을 업무에 맞게 적습니다.

  • 맡길 업무와 답변 형식
  • 반드시 참고할 정보와 지켜야 할 제한
  • 정보가 부족할 때의 처리 방법
  • 도구나 스킬을 사용할 조건

지침과 개별 요청은 다릅니다. 지침은 여러 대화에서 반복 적용할 규칙이고, 개별 요청은 현재 스레드에서 처리할 업무입니다. 답변이 계속 같은 방식으로 어긋난다면 개별 요청을 반복하기보다 지침을 수정한 뒤 저장하고 다시 시험합니다.

리소스: 도구, 미들웨어, 스킬, 서브에이전트​

도구는 에이전트가 외부 작업을 실행할 때 호출하는 리소스입니다. 미들웨어는 실행 전후에 적용되는 처리 구성이고, 스킬은 업무 절차나 전문 지식을 담은 자료입니다. 서브에이전트는 다른 에이전트가 일부 업무를 맡길 수 있는 하위 구성입니다.

리소스의 목록과 사용 가능 여부는 권한에 따라 달라집니다. 추가 화면에 보이는 리소스라고 해서 실제 실행까지 허용된다는 뜻은 아닙니다. 실행할 때는 대상 리소스를 사용할 권한도 확인됩니다. 따라서 리소스를 추가할 때는 업무와의 관련성, 필요한 권한, 외부 호출 여부를 함께 확인해야 합니다.

모델​

에이전트는 한 번에 하나의 활성 모델을 사용합니다. 모델은 답변을 생성하는 데 사용되므로 에이전트의 업무에 맞춰 선택합니다. 모델을 바꿔도 에이전트의 이름이나 지침이 자동으로 바뀌지는 않습니다.

모델 목록은 사용자의 권한과 워크스페이스 설정에 따라 달라질 수 있습니다. 목록에 모델이 없거나 변경할 수 없다면 모델 자체의 문제로 단정하지 말고 모델 조회 권한과 워크스페이스 설정을 먼저 확인합니다.

스레드와 실행​

스레드는 한 대화의 맥락을 이어 가는 단위입니다. 같은 에이전트를 사용하더라도 업무가 다르면 스레드를 나누는 편이 안전합니다. 그러면 이전 업무의 지시와 자료가 새 업무에 섞일 가능성을 줄일 수 있습니다.

실행은 스레드에서 사용자가 보낸 요청을 에이전트가 처리하는 한 번의 작업입니다. 실행 중에는 답변이 스트리밍으로 표시될 수 있고, 도구 호출이나 추가 확인이 발생할 수 있습니다. 포그라운드 실행은 진행 결과를 바로 확인하는 데 적합하고, 백그라운드 실행은 완료 후 결과를 확인하는 작업에 적합합니다.

실행은 성공으로 끝날 수도 있고 오류, 취소, 중단 또는 시간 초과로 끝날 수도 있습니다. 실행 오류가 발생했을 때는 같은 요청을 무조건 반복하지 말고, 지침과 입력 자료, 사용한 리소스, 대화 맥락을 나누어 확인합니다.

승인과 명확화​

에이전트가 작업을 계속하려면 사람의 선택이나 추가 정보가 필요한 경우가 있습니다. 이 상태는 실행이 멈춘 것이 아니라 명확화나 승인을 기다리는 상태일 수 있습니다.

다음과 같은 상황에서 확인 요청이 나타날 수 있습니다.

  • 요청의 목적이나 범위를 더 좁혀야 할 때
  • 여러 리소스나 선택지 중 하나를 골라야 할 때
  • 실행에 필요한 값을 추가로 받아야 할 때

질문에 답하면 같은 실행의 맥락에서 작업을 이어 갑니다. 질문의 의도와 다른 값을 입력하면 결과가 달라질 수 있으므로, 선택지와 단위를 확인한 뒤 응답합니다.

저장과 실행 권한의 구분​

에이전트를 수정할 수 있는 권한과 에이전트가 리소스를 실행할 수 있는 권한은 별개입니다. 수정 화면에 들어갈 수 있어도 특정 도구나 모델을 실행하지 못할 수 있습니다. 반대로 실행 권한이 있어도 이름, 설명, 지침을 바꾸는 권한이 없을 수 있습니다.

테스트 탭에서 현재 초안을 시험할 때도 에이전트 실행 권한과 호출 대상 리소스의 실행 권한이 필요합니다. 테스트 결과는 초안의 동작을 확인하기 위한 것이며, 테스트 대화 자체가 에이전트 설정을 자동으로 저장하지는 않습니다.

개념 간 관계​

개념담당하는 일다음에 확인할 것
에이전트재사용할 업무 구성과 연결 리소스 보관이름, 지침, 모델, 연결 리소스
지침반복 적용할 역할과 응답 기준 정의적용 범위와 예외 조건
도구외부 작업 실행실행 권한과 외부 호출 대상
미들웨어실행 전후 처리 구성적용 조건과 저장 상태
스킬절차와 전문 지식 제공참고 시점과 업무 적합성
모델응답 생성 담당워크스페이스 목록과 활성 선택
스레드대화 맥락 보관현재 업무와 이전 지시의 혼합 여부
실행한 번의 요청 처리진행 상태, 승인, 종료 결과

에이전트는 지침과 리소스, 모델을 사용해 실행을 구성합니다. 실행은 스레드 안에서 이루어지고, 필요한 경우 승인이나 명확화 단계를 거칩니다. 어느 단계에서 문제가 생겼는지 구분하면 수정할 대상을 좁힐 수 있습니다.

다음 단계​

  • 에이전트를 처음 만들려면 Deep Agent Builder 시작하기를 읽습니다.
  • 기존 에이전트의 이름, 지침, 리소스를 바꾸려면 Deep Agent Builder 메뉴 안내를 읽습니다.
  • 실제 요청을 보내고 스트리밍 결과를 확인하려면 Deep Agent Builder 반복 업무를 읽습니다.
  • 모델 선택과 워크스페이스 모델 목록을 확인하려면 Deep Agent Builder 모델 구성을 읽습니다.
