Deep Agent Builder 시크릿과 권한

시크릿이 필요한 도구를 연결하거나 모델을 사용하려면 인증 정보와 사용 권한을 따로 확인해야 합니다. 이 페이지는 시크릿을 노출하지 않고, 권한이 부족할 때 무엇을 확인할지 안내합니다.

시크릿을 안전하게 다루기​

시크릿은 문서나 입력창에 직접 적지 않습니다. 다음 원칙을 지킵니다.

  • 시크릿 값, 토큰, 비밀번호를 문서·로그·테스트 입력에 남기지 않습니다.
  • 에이전트가 실제 업무에 필요한 도구와 모델만 연결합니다.
  • 권한이 없을 때 다른 사람의 리소스나 다른 인증 방식으로 우회하지 않습니다.
  • 실행 문제를 확인할 때도 시크릿 자체를 다시 입력하지 않습니다.

Code Sandbox를 사용하는 경우에도 실행 코드나 에이전트 지침에 Sandbox 인증 정보를 넣지 않습니다. 실행 환경에는 Sandbox 주소와 인증용 secret을 전달하지 않고, 토큰 발급과 세션 처리는 서비스가 담당합니다.

화면 확인이 필요한 항목​

아래 순서는 권한과 보안 경계를 확인하는 일반 기준입니다. 실제 메뉴 이름, 버튼, 권한 표시, 저장 완료 표시와 테스트 실행 화면은 제품 버전과 배포 환경에 따라 달라질 수 있습니다. 이 페이지의 UI 동선은 실제 화면에서 라벨과 결과를 확인한 뒤 확정해야 하며, 화면에 없는 항목은 찾으려고 임의로 만들지 않습니다.

권한 문제는 한 가지 기준으로만 판단하지 않습니다. 다음 세 범위를 각각 확인합니다.

확인 범위확인할 질문예시
작업 권한내가 이 작업을 할 수 있는가?에이전트 생성, 시크릿 관리, 모델 조회
공간 권한선택한 Workspace에서 작업할 수 있는가?Workspace 안의 에이전트와 리소스 조회·관리
리소스 권한이 도구나 모델을 실제 실행에 사용할 수 있는가?도구 연결, 모델 사용, 수정, 삭제

세 범위 중 하나라도 부족하면 저장이나 실행이 거부될 수 있습니다. 에이전트 화면을 열 수 있다는 사실만으로 연결한 도구와 모델까지 사용할 수 있다고 판단하지 않습니다.

권한 확인은 한 번에 끝나는 단일 검사가 아닙니다. 에이전트 화면을 열 수 있어도 Workspace 선택, 리소스 연결, 실행 단계에서 필요한 권한이 다를 수 있습니다. 연결을 저장한 뒤 같은 설정을 다시 열고, 비식별 입력으로 실행해 저장 결과와 실제 사용 가능 여부를 따로 확인합니다.

리소스를 연결하기 전 확인 순서​

  1. 로그인한 계정과 작업할 Workspace가 맞는지 확인합니다.
  2. 에이전트를 보고 수정할 수 있는지 확인합니다.
  3. 연결하려는 도구·모델·스킬을 조회할 수 있는지 확인합니다.
  4. 해당 도구와 모델을 실행에 사용할 수 있는지 확인합니다.
  5. 시크릿이 필요한 도구라면 시크릿을 만들거나 바꿀 권한과 도구 사용 권한을 각각 확인합니다.
  6. 저장한 뒤 에이전트 설정을 다시 열어 실제 화면에 표시되는 연결 상태와 권한 정보를 확인합니다.
  7. 비식별 입력으로 테스트 실행을 해 실제 사용 가능 여부를 확인합니다.

설정 화면에서 연결이 저장됐다고 해서 실행까지 성공하는 것은 아닙니다. 실행할 때 권한을 다시 확인하는 환경도 있으므로, 저장 후 테스트 실행을 완료 확인으로 사용합니다.

원격 권한 확인이 필요한 경우​

일부 환경은 권한을 별도 서비스에서 확인합니다. 이때는 조직에서 정한 하나의 권한 확인 방식을 사용하며, 한 방식이 실패했다고 다른 방식으로 자동 우회한다고 가정하지 않습니다.

운영자가 확인할 항목은 다음과 같습니다.

  • 원격 권한 서비스가 정상적으로 응답하는가
  • 도구와 모델의 사용 권한을 올바르게 읽어 오는가
  • 권한 서비스의 호환성 경고와 실제 연결 실패를 구분할 수 있는가
  • 일시적인 장애 때 사용할 수 있는 마지막 확인 결과의 유효 시간이 남아 있는가

원격 확인에 문제가 생겼을 때 권한을 임의로 허용하거나, 원인을 확인하지 않고 모든 요청을 거부하지 않습니다. 서비스 상태와 마지막 확인 시점을 관리자에게 전달해 판단을 요청합니다.

문제가 생겼을 때​

화면에서 보이는 상황먼저 확인할 것다음 행동
작업 자체가 거부됨현재 계정의 작업 권한과 Workspace 소속관리자에게 필요한 작업 권한을 요청
도구나 모델을 연결할 수 없음리소스 조회 권한과 사용 가능 상태리소스 소유자 또는 관리자에게 사용 권한을 요청
저장은 됐지만 실행이 거부됨실행 시점의 도구·모델 사용 권한같은 입력을 반복하기 전에 연결 상태와 권한을 다시 확인
원격 권한 확인이 실패함권한 서비스 상태와 설정된 확인 방식서비스 운영자에게 상태와 발생 시각을 전달
입력 형식 오류가 표시됨입력값과 허용된 항목권한 문제로 바꾸어 해석하지 말고 입력을 수정

지원 요청을 보낼 때는 시크릿과 토큰을 삭제합니다. 오류 문구, 발생 시각, 대상 Workspace와 에이전트 이름처럼 진단에 필요한 비밀이 아닌 정보만 남깁니다.

저장 후 완료 확인​

  1. 변경 대상이 올바른 계정, Workspace, 에이전트인지 확인합니다.
  2. 저장 결과만 보지 말고 설정을 다시 열어 실제 화면에 표시되는 연결 상태를 확인합니다.
  3. 비식별 입력으로 실제 실행을 시도합니다.
  4. 화면, 로그, 캡처에 시크릿이나 토큰이 노출되지 않았는지 확인합니다.
  5. 권한을 바꾼 범위를 넘어 다른 구성원의 설정이나 기존 실행까지 바뀌었다고 추정하지 않습니다.

시크릿 노출이 의심되면 값을 다시 확인하지 말고 조직의 자격 증명 교체 절차와 접근 로그 확인 절차를 따릅니다. 구체적인 교체 순서는 배포 환경의 운영 담당자에게 확인합니다.
