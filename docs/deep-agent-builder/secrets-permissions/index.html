시크릿과 권한

에이전트가 외부 도구나 모델을 쓰려면 API 키 같은 비밀 값이 필요하고, 사내 다른 시스템이 내 에이전트를 부르려면 그 시스템에 넘겨줄 열쇠가 필요합니다. 이 페이지는 사이드바의 에셋설정을 눌러 여는 에셋 화면의 시크릿 탭과 API 키 탭을 화면 순서대로 설명하고, 도구 기본값에서 시크릿을 참조하는 방법, 권한이 없을 때 화면에 나오는 문구와 그때 누구에게 무엇을 요청할지를 정리합니다.

이 페이지에서 할 수 있는 일

  • 시크릿 탭에서 내 시크릿을 등록·수정·삭제하고, 워크스페이스에 등록된 시크릿 목록을 확인합니다.
  • 미등록 탭에서 도구나 모델이 필요로 하는데 아직 등록하지 않은 시크릿을 찾아 바로 등록합니다.
  • 도구의 기본값 설정에서 값을 직접 적는 대신 시크릿 키 참조로 연결합니다.
  • API 키 탭에서 외부 시스템용 API 키를 만들고, 쓰지 않는 키는 지웁니다.
  • 권한이 없을 때 나오는 문구를 보고 어떤 권한이 빠졌는지 판단해 관리자에게 요청합니다.

비밀 값을 다루는 원칙​

API 키, 토큰, 비밀번호는 에이전트 지침, 대화 입력창, 사내 메신저, 게시글 어디에도 그대로 적지 않습니다. 이 페이지의 그림에 보이는 키 이름과 값은 모두 가상 값이며, 실제 키 값이 찍힌 부분은 가려 두었습니다.

  • 시크릿은 키 이름으로 참조합니다. 목록에서는 값의 앞부분 몇 글자만 보이고 나머지는 별표로 가려집니다.
  • 내가 만든 API 키는 만든 직후 한 번만 전체가 보입니다. 이후 목록에는 앞부분만 남습니다.
  • 키가 밖으로 새었다고 의심되면 그 키를 지우고 새로 만든 뒤, 키를 쓰던 시스템 담당자에게 알립니다.

시크릿 탭​

사이드바 아래쪽 에셋설정을 누르면 에셋 화면이 열립니다. 위쪽 탭은 도구, 모델, 스킬, 메모리, 시크릿, API 키, 커맨드 순서입니다. 시크릿 탭을 엽니다. 그림은 김그루 사원이 시장 조사 리서처의 검색 도구에 쓸 키를 등록해 둔 모습입니다.

삭제는 휴지통을 누르면 ""키 이름" 시크릿을 삭제하시겠습니까?"라는 브라우저 확인 창으로 묻습니다. 여러 개를 지우려면 줄 앞 체크 상자로 고른 뒤 위에 나오는 선택 항목 삭제를 누릅니다.

시크릿 추가 창​

시크릿 추가를 누르면 키 이름과 값을 넣는 창이 열립니다.

시크릿 추가 창

번호메뉴기능이런 때 사용하세요
1키시크릿 이름입니다. 예시 문구는 "OPENAI_API_KEY"입니다. 최대 255자입니다.도구 설명의 필수 환경변수와 같은 이름으로 등록할 때
2값실제 비밀 값입니다. 입력하면 가려져 보입니다.외부 서비스에서 발급받은 키를 붙여 넣을 때
3취소저장하지 않고 창을 닫습니다.키 이름을 다시 확인해야 할 때

미등록 탭​

미등록 탭에는 내 도구나 모델이 쓰는데 아직 등록되지 않은 키가 모입니다. 빠진 키가 있으면 키, 유형(도구인지 모델인지), 출처(그 키를 요구하는 도구나 모델 이름)와 등록 버튼이 줄마다 나옵니다. 등록을 누르면 키 이름이 채워진 시크릿 추가 창이 열리므로 값만 넣고 저장합니다. 그림은 필요한 키가 모두 등록되어 있을 때의 모습입니다.

미등록 탭

번호메뉴기능이런 때 사용하세요
1미등록도구나 모델이 필요로 하는데 아직 등록하지 않은 키 목록을 엽니다. 빠진 키가 없으면 탭 옆에 숫자가 붙지 않습니다.실행 중 시크릿이 없다는 알림을 받았을 때
2안내 문구빠진 키가 없으면 "필수 환경변수가 모두 등록되어 있습니다"와 "추가로 필요한 시크릿이 없습니다"가 보입니다.새 도구를 설치한 뒤 더 등록할 키가 없는지 확인할 때

이럴 때 쓰세요: 김그루 사원은 유틸리티에서 새 도구를 설치한 직후 바로 대화를 시작하지 않고 시크릿 탭의 미등록 숫자부터 봅니다. 숫자가 붙어 있으면 그 줄의 등록으로 키 이름이 채워진 창을 열어 값만 넣으므로, 도구 설명의 이름을 옮겨 적다 철자가 틀리는 일이 없습니다. 대화 중 "실행에 필요한 시크릿이 등록되어 있지 않습니다" 알림을 받았을 때도 같은 자리에서 등록한 뒤 같은 요청을 다시 보냅니다.

실행 중에 시크릿이 없어 멈추면 "실행에 필요한 시크릿이 등록되어 있지 않습니다. 시크릿 설정에서 등록한 뒤 다시 시도해 주세요." 알림이 뜹니다. 알림의 시크릿 설정을 눌러 이 탭으로 오면 됩니다. 도구 상세와 모델 상세의 필수 환경변수 옆에도 등록됨 또는 미등록이 표시됩니다.

따라 해 보기​

김그루 사원이 시장 조사 리서처의 검색 도구에 쓸 가상 키를 등록하는 순서입니다.

  1. 사이드바 에셋설정을 눌러 에셋 화면을 열고 시크릿 탭을 누릅니다.
  2. 미등록 탭에 검색 도구가 요구하는 키가 있으면 그 줄의 등록을 누릅니다. 없으면 등록됨 탭에서 시크릿 추가를 누르고 키에 "MARKET_SEARCH_API_KEY"를 적습니다.
  3. 값에 발급받은 키를 붙여 넣고 저장을 누릅니다.
  4. 등록됨 탭의 사용자 목록에 키가 생기고, 값은 앞부분만 보이는지 확인합니다.

도구 기본값에서 시크릿 참조하기​

도구 파라미터에 API 키 같은 값을 넣어야 할 때, 값을 직접 적는 대신 등록한 시크릿을 가리키게 할 수 있습니다. 에셋 화면의 도구 탭에서 도구를 고르고 상세 화면 위쪽의 기본값 설정(조절 막대 모양)을 누르면 "기본값 설정 · 도구 이름" 창이 열립니다. 창 위에는 "이 도구를 사용하는 내 에이전트 전체에 적용됩니다. 에이전트에 별도로 설정한 값이 우선하며, 저장 후 시작한 실행부터 반영됩니다."라는 안내가 있습니다. 기본값 설정 버튼은 기본값을 정할 수 있는 도구에만 보입니다. 하위 도구가 여러 개인 MCP 도구는 공통 설정과 하위 도구별 설정 탭으로 나뉘고, 공통 설정에는 "수정한 공통 설정만 저장합니다. 개별 설정이 있으면 개별 설정을 우선합니다."가 보입니다.

창에는 파라미터마다 칸이 하나씩 있고, 칸 위에는 파라미터 이름과 형식(string, integer 등), 필수·선택 여부, 적용 대상 하위 도구가 나옵니다. 칸 왼쪽의 설정 방식 목록에서 값을 넣는 방법을 고릅니다. 목록에는 기본값 해제 (상속), 직접 입력, 빈 값을 허용하는 파라미터에서만 보이는 빈 값 (null), 그리고 "고급 · 저장된 시크릿 연결" 묶음 아래의 시크릿 키 참조가 있습니다. 시크릿을 연결하려면 다음 순서로 합니다.

  1. 키를 넣을 파라미터 칸의 설정 방식 목록을 열고 시크릿 키 참조를 고릅니다. 시크릿 키 참조는 글자 값을 받는 파라미터에서, 시크릿을 볼 권한이 있을 때만 고를 수 있습니다.
  2. 오른쪽에 값 입력란 대신 "시크릿 키를 선택하세요"라고 적힌 시크릿 키 목록이 나타납니다. 목록을 열어 등록해 둔 키 이름(예: MARKET_SEARCH_API_KEY)을 고릅니다. 목록에는 키 이름만 보이고 값은 보이지 않습니다.
  3. 창 아래 오른쪽의 저장을 누릅니다. 키를 고르지 않고 저장하면 저장되지 않습니다.

저장한 뒤 창을 다시 열면 그 파라미터는 시크릿 키 참조로, 시크릿 키 목록에는 고른 키 이름이 선택된 채로 보입니다. 연결한 시크릿을 나중에 지웠다면 목록에 "키 이름 (사용할 수 없는 키)"로 보이므로 다른 키를 다시 고릅니다. 연결할 키가 아직 없으면 창 아래 왼쪽의 시크릿 등록을 눌러 창을 닫지 않고 새 시크릿을 등록한 뒤, 시크릿 키 목록에서 그 키를 고릅니다. 시크릿 등록은 시크릿 생성 권한이 있을 때만 보입니다.

도구 기본값 설정에서 시크릿 키 참조

번호메뉴기능이런 때 사용하세요
1설정 방식파라미터마다 기본값 해제 (상속), 직접 입력, 빈 값 (null), 시크릿 키 참조 중에서 고릅니다. 시크릿 키 참조는 "고급 · 저장된 시크릿 연결" 묶음 안에 있습니다.키를 화면에 적지 않고 시크릿으로 연결할 때
2시크릿 키시크릿 키 참조를 고르면 나오는 목록입니다. "시크릿 키를 선택하세요"에서 등록한 키 이름을 고릅니다. 지워진 키를 가리키고 있으면 "사용할 수 없는 키"가 붙습니다.앞에서 등록한 MARKET_SEARCH_API_KEY를 연결할 때
3시크릿 등록창을 닫지 않고 새 시크릿을 등록합니다. 시크릿 생성 권한이 있을 때만 보입니다.연결할 키가 아직 없을 때
4저장기본값을 저장합니다.연결을 마쳤을 때

기본값을 정할 권한이 없으면 창에 "이 도구의 기본값을 설정할 권한이 없습니다."가 보입니다. 저장이 실패하면 "기본값을 저장하지 못했습니다. 파라미터와 시크릿 키를 확인한 뒤 다시 시도하세요."가 나옵니다. 도구 상세 화면의 다른 항목은 도구와 스킬 구성에서 설명합니다.

API 키 탭​

API 키는 사내 다른 시스템이 내 에이전트를 부를 때 쓰는 열쇠입니다. 예를 들어 사내 그룹웨어가 매주 금요일 주간 업무 보고서 도우미를 호출하게 하려면, 그룹웨어 담당자에게 API 키와 코드 스니펫과 외부 API의 예제 코드를 함께 넘깁니다. 에이전트 설정 탭의 Webhook도 이 키로 호출합니다.

에셋 화면에서 API 키 탭을 엽니다. 키를 하나도 만들지 않았으면 "생성된 API 키가 없습니다."와 ""API 키 추가"를 눌러 첫 API 키를 생성하세요."가 보입니다.

API 키 탭

번호메뉴기능이런 때 사용하세요
1API 키 탭내가 만든 API 키 목록을 보여 줍니다.지금 살아 있는 키가 몇 개인지 볼 때
2검색란이름으로 키를 찾습니다. 안내 문구는 "도구 검색..."으로 보입니다.키가 많아졌을 때
3API 키 추가API 키 생성 창을 엽니다.새 연동에 쓸 키가 필요할 때
4이름키 이름과 그 아래 키 값의 앞부분입니다. 그림에서는 앞부분을 가렸습니다.어느 시스템용 키인지 확인할 때

표의 나머지 열은 다음과 같습니다. 행 끝 작업 열의 휴지통(삭제)은 그 키를 지우는 확인 창을 엽니다. 연동을 끝내거나 키가 새었다고 의심될 때 씁니다.

번호메뉴기능이런 때 사용하세요

2마지막 사용키가 마지막으로 쓰인 때입니다. 한 번도 쓰지 않았으면 "-"로 보입니다.오래 쓰지 않은 키를 찾아 정리할 때

이럴 때 쓰세요: 김그루 사원은 분기마다 API 키 탭을 열어 마지막 사용과 사용량을 훑어봅니다. 한 번도 쓰이지 않아 "-"로 남은 시범용 키는 지우고, 만료가 다가온 그룹웨어 주간보고 연동 키는 그룹웨어 담당자와 교체 날짜를 정한 뒤 새 키를 먼저 만들어 넘기고 나서 옛 키를 지웁니다. 이 순서를 지키면 삭제 확인 창의 경고대로 이 키를 쓰던 연동이 바로 끊기는 일을 피할 수 있습니다.

API 키 생성 창​

API 키 추가를 누르면 "외부 시스템에서 에이전트에 접근할 수 있도록 새 API 키를 생성합니다."라는 안내와 함께 API 키 생성 창이 열립니다. 창에는 위에서부터 네 칸이 있습니다.

  • 이름: 키 이름입니다. 이름 옆에 별표가 붙은 필수 칸으로, 최대 100자이고 비어 있으면 생성을 누를 수 없습니다. 예시 문구는 "프로덕션 API 키"입니다. "그룹웨어 주간보고 연동 키"처럼 어느 시스템에서 쓰는지 드러나게 짓습니다.
  • 설명: 키의 용도를 적는 칸으로, 비워 둬도 됩니다. 예시 문구는 "선택 설명..."입니다.
  • 만료 (일): 며칠 뒤 만료될지 1부터 365 사이 숫자로 적습니다. 칸 아래에 "1-365일, 또는 비워두면 만료 없음"이 보이며, 비워 두면 만료되지 않는 키가 됩니다. 처음에는 비어 있습니다.
  • 스코프: 키로 할 수 있는 일을 체크 상자로 고릅니다. invoke(에이전트를 동기 호출), stream(에이전트 응답 스트리밍), background(에이전트를 백그라운드에서 실행)는 처음부터 체크되어 있고, read(읽기 전용 접근)는 체크되어 있지 않습니다. 외부 시스템이 실제로 쓰는 기능만 남깁니다.

창 아래의 취소는 키를 만들지 않고 창을 닫고, 생성은 키를 만든 뒤 키 값을 한 번 보여 줍니다.

API 키 생성 창

번호메뉴기능이런 때 사용하세요
1이름키 이름입니다. 필수 항목이라 이름 옆에 별표가 붙어 있으며 최대 100자입니다. 예시 문구는 "프로덕션 API 키"입니다."그룹웨어 주간보고 연동 키"처럼 어느 시스템에서 쓰는지 드러나게 지을 때
2설명키의 용도를 적습니다. 넣지 않아도 됩니다.나중에 정리할 때 누가 왜 만든 키인지 알아볼 수 있게 남길 때
3만료 (일)1~365 사이 숫자로 며칠 뒤 만료될지 정합니다. 비워 두면 만료되지 않습니다.시범 운영 기간인 90일만 쓰는 키를 만들 때
4스코프키로 할 수 있는 일을 고릅니다. invoke(에이전트를 동기 호출), stream(에이전트 응답 스트리밍), background(에이전트를 백그라운드에서 실행)는 처음부터 체크되어 있고 read(읽기 전용 접근)는 꺼져 있습니다. 그림은 invoke만 남긴 모습입니다.외부 시스템이 실제로 쓰는 기능만 남길 때

키가 만들어진 뒤​

생성을 누르면 "API 키가 생성되었습니다" 창이 열리고 키 값 전체가 보입니다. 노란 안내 "이 API 키는 한 번만 표시됩니다. 지금 복사하여 안전하게 보관하세요."대로, 창을 닫으면 전체 값을 다시 볼 수 없습니다.

생성된 API 키

번호메뉴기능이런 때 사용하세요
1안내 문구키 값이 지금 한 번만 표시된다는 경고입니다.키를 어디에 보관할지 먼저 정할 때
2API 키방금 만든 키 값입니다. 그림에서는 값을 가렸습니다.연동 담당자에게 넘길 키를 확인할 때
3복사키 값을 클립보드에 복사합니다.연동 시스템 설정 화면에 바로 붙여 넣을 때

따라 해 보기​

김그루 사원이 그룹웨어 시범 연동에 쓸 키를 90일짜리로 만드는 순서입니다.

  1. 사이드바 에셋설정을 눌러 에셋 화면을 열고 API 키 탭을 누릅니다.
  2. API 키 추가를 누릅니다.
  3. 이름에 "그룹웨어 주간보고 연동 키", 설명에 "그룹웨어에서 주간 업무 보고서 도우미를 호출할 때 사용"을 적습니다.
  4. **만료 (일)**에 "90"을 적습니다. 스코프는 invoke만 남기고 stream, background의 체크를 풉니다.
  5. 생성을 누르고, 나온 키 값을 복사 버튼으로 복사해 그룹웨어 담당자에게 사내 보안 절차에 따라 전달합니다.
  6. 완료를 누른 뒤 목록에서 이름, 스코프(invoke), 만료 날짜가 맞는지 확인합니다.

팁: 키 값을 메신저나 메일 본문, 라운지 게시글에 붙여 넣지 마세요. 창을 닫은 뒤 키 값을 잃어버렸다면 그 키를 지우고 새로 만드는 편이 안전합니다.

권한이 없을 때 보이는 문구​

Deep Agent Builder는 사용자마다 할 수 있는 일을 권한으로 나눕니다. 권한이 없는 버튼은 흐리게 보이고, 마우스를 올리면 이유가 나옵니다. 화면에서 자주 만나는 문구와 그때 할 일은 다음과 같습니다.

화면에 보이는 문구어디서 보이나요무엇이 없는 것인가요이렇게 하세요
에이전트 생성 권한이 없습니다. 관리자에게 문의하세요.대화로 만들기 첫 화면의 입력창 아래, 에이전트 직접 만들기와 에이전트 가져오기의 흐린 버튼, 에이전트 템플릿의 템플릿으로 제작에이전트를 새로 만들 권한. 사이드바 새 에이전트에는 "생성 권한이 없습니다. 관리자에게 문의하세요."로 보입니다.관리자에게 에이전트 생성 권한을 요청합니다. 그동안은 워크스페이스 에이전트에 공유된 에이전트를 씁니다.
설치 권한이 없습니다. 관리자에게 문의하세요.유틸리티의 설치 버튼도구·모델·미들웨어·스킬을 내 에셋에 설치할 권한설치하려던 항목 이름을 적어 관리자에게 요청합니다.
이 게시판에 글을 작성할 권한이 없습니다라운지의 공지사항, 사용 가이드, 유즈케이스, FAQ 게시판에서 자물쇠가 붙은 흐린 글쓰기 버튼에 마우스를 올렸을 때그 게시판의 작성 권한. 이 네 게시판은 관리자만 씁니다. 문의 및 오류, 기능 개선 제안, 커뮤니티 게시판에서는 작성 권한이 없으면 문구 없이 글쓰기 버튼이 아예 보이지 않습니다.질문은 문의 및 오류, 의견은 기능 개선 제안, 소개 글은 커뮤니티 게시판에 씁니다. 이 세 게시판에도 글쓰기가 보이지 않으면 관리자에게 글쓰기 권한을 요청합니다.
권한 없음: 리소스 이름내 에이전트 대화 화면의 입력창 바로 위. 입력창에는 "리소스 권한 부족으로 채팅이 비활성화됨"이 보입니다.이 에이전트가 쓰는 리소스 가운데 일부(예를 들어 도구나 모델)의 사용 권한. 이름이 많으면 "외 N건"으로 줄여 보입니다.표시된 리소스 이름을 그대로 적어 관리자에게 사용 권한을 요청하거나, 에이전트 편집 화면에서 그 리소스를 빼거나 바꾼 뒤 다시 대화합니다.
사용 권한이 없습니다. 관리자에게 문의하세요.도구함·미들웨어 칸의 노란 방패 표시, 추가 창의 흐린 항목그 도구나 미들웨어를 쓸 권한다른 항목으로 바꾸거나 관리자에게 요청합니다.
생성 권한이 없습니다. / 수정 권한이 없습니다. / 삭제 권한이 없습니다. (뒤에 "관리자에게 문의하세요.")에셋 화면의 추가·수정·삭제 버튼그 자원을 만들거나 고치거나 지울 권한어느 화면의 어떤 버튼인지 적어 관리자에게 요청합니다.
이 리소스의 설정을 수정할 권한이 없습니다.도구·미들웨어 설정 창 위쪽설정 수정 권한(창은 읽기 전용으로 열림)바꿀 값을 정리해 관리자에게 요청합니다.

이 에이전트를 실행할 권한이 없습니다. 관리자에게 문의하세요.워크스페이스 에이전트 대화 화면의 입력창 근처공유된 그 에이전트의 실행 권한관리자에게 실행 권한을 요청합니다.
이 에이전트의 모델을 사용할 권한이 없어 메시지를 보낼 수 없습니다.워크스페이스 에이전트 대화 화면의 입력창 근처공유된 에이전트가 쓰는 모델의 사용 권한에이전트 이름과 함께 모델 사용 권한을 관리자에게 요청합니다.

이럴 때 쓰세요: 영업팀 동료가 김그루 사원이 공유한 주간 업무 보고서 도우미에서 "이 에이전트의 모델을 사용할 권한이 없어 메시지를 보낼 수 없습니다."를 보고 물어 오면, 김그루 사원은 이 표에서 문구를 찾아 에이전트 설정이 아니라 모델 사용 권한 문제임을 먼저 짚어 줍니다. 그다음 동료에게 문구 전체와 에이전트 이름을 적어 관리자에게 요청하라고 안내하므로, 원본 에이전트를 괜히 고쳐 다시 배포하는 일을 줄일 수 있습니다.

누구에게 요청하나요​

권한은 Deep Agent Builder를 운영하는 관리자가 정합니다. 문구에 "워크스페이스 관리자"라고 적혀 있으면 그 워크스페이스를 맡은 관리자에게, 그 밖에는 사내 플랫폼 관리자에게 요청합니다. 요청할 때는 다음을 함께 적으면 빨리 처리됩니다.

  1. 화면에 나온 문구 전체(복사해서 붙여 넣기)
  2. 어느 메뉴에서 무엇을 하려다 막혔는지(예: "에셋 화면의 시크릿 탭에서 시크릿 추가")
  3. 대화 화면이라면 에이전트 이름과, 입력창 위에 나온 리소스 이름

요청 글은 라운지의 문의 및 오류 게시판에 남겨도 됩니다. 이때 시크릿 값이나 API 키는 절대 적지 않습니다.

팁: 권한을 받은 뒤에도 같은 문구가 보이면 화면을 새로고침하거나 로그아웃한 뒤 다시 로그인해 봅니다.
